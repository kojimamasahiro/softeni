# insight-agent

`tournament-insight` スキルのうち、**機械が担える検査**をスクリプトに寄せるためのツール。
`scripts/venue-agent/` と同じ思想（決定的なチェックは人にもLLMにも任せない）を
インサイト執筆の側に適用したもの。

Claudeが使えなくなってローカルLLM（9〜14Bクラス）に書かせる場合に備えた土台でもある。
設計と実測は `docs/raw/2026-08-14-idea-local-llm-skill-replacement.md`。

## なぜ要るのか

`scripts/verify-story-text.mjs` が見るのは**事実**（年×成績・連続年数・連覇・スコア・固有名詞）だけで、
修辞・推測・出典の併記は素通りする。それらは `docs/story-yaml/PROMPT.md` に文章で書いてあるだけだった。

クラウドのClaudeは指示を守れていたので穴が表面化しなかったが、実測すると
守られていること自体が運任せの構造だと分かる。

| 実測（公開済みインサイト24本・417主張） | 値 |
|---|---|
| 実データと事実を突き合わせている主張の割合 | **26.4%**（残りは固有名詞の存在確認と年の範囲確認） |
| 記事の主語「今年誰が優勝したか」が照合されていた本数 | **0 / 24**（→ 照合器にパターン(a2)を追加して 23/24 に修正済み） |
| 逸脱を注入して機械が落とせた種類 | 8種のうち2種 |

特に**存在しない固有名詞の捏造は、警告ゼロで通る**。照合器は既知の名前と一致した語しか
主張として抽出しないため、知らない名前は主張にすらならない。

## ファイル

| ファイル | 役割 |
|---|---|
| `lint.mjs` | 本文の作法チェック（評価語・推測・`used:`・未知の固有名詞・照合カバレッジ） |
| `genre-vocab.txt` | 固有名詞でない語彙の追加分。**足すと検出力が落ちる**ので目視してから足す |

`insight_agent.mjs`（Ollama呼び出し本体）と `prompts.mjs` は未実装。
先に照合の網を広げる方針にしたため（理由は設計メモ）。

## 使い方

```bash
CATS=team-none-boys,team-none-girls,doubles-none-boys,doubles-none-girls

# 公開済みインサイトを検査する
node scripts/insight-agent/lint.mjs \
  --insight data/tournament-insights/highschool-championship/2025/team-none-boys.json -c $CATS

# markdown下書きを検査する（`## 投稿N` 節か引用ブロックを本文とみなす）
node scripts/insight-agent/lint.mjs -t highschool-championship -y 2025 -c $CATS draft.md

# 文字列を直接
node scripts/insight-agent/lint.mjs -t highschool-championship -c $CATS --text "..." --no-coverage
```

| オプション | 意味 |
|---|---|
| `--no-coverage` | 照合カバレッジ検査を省く（1文ずつ照合器を呼ぶので遅い） |
| `--no-names` | 未知の固有名詞の検査を省く |
| `--whole` | markdownの本文抽出をせず、ファイル全体を検査する |
| `-q` | ERROR だけ表示する |
| `--learn-vocab` | 既に正しいと分かっている本文から定型語彙を洗い直す |

終了コードは ERROR が1件でもあれば 1、WARN のみなら 0。

## 検査の内訳

| 検査 | 水準 | 内容 |
|---|---|---|
| 評価語 | ERROR | PROMPT.md の禁止例を核に43語。「強豪」「悲願」「圧巻」「優勝候補」「死闘」等 |
| 推測 | ERROR | 「とみられる」「期待される」「来年」「今後」「悔し」等。PROMPT.md の「推測を書かない」の機械化 |
| used | ERROR | story id の併記が無い本文を弾く（ADR-012 が公開の必須条件にしている） |
| 未知の固有名詞 | WARN | 既知の固有名詞と定型語彙を伏せた残りを報告する。捏造の検出 |
| 照合カバレッジ | WARN | 各文を1文ずつ照合器にかけ、「実データと突き合わせた主張が0件の文」を名指しする |

最後の2つが主眼。1〜3は既知の制約を機械に移しただけだが、後ろ2つは
**「この文は機械が守っていない」を書き手に見せる**もので、照合の網が広がるまでの防波堤になる。

### 未知の固有名詞の仕組み

1. `verify-story-text.mjs --list-names` に実在する人名・所属・姓名の断片を聞く
2. 本文からそれらを最長一致で伏せる
3. ひらがな・数字・記号を落とす
4. 残った漢字・カタカナのうち、`GENRE_CHARS`（公開済み24本から導出した93文字）と
   `genre-vocab.txt` に無い文字を「知らない固有名詞かもしれない」として報告する

記事の語彙が極端に狭いこと（固有名詞を除くと93文字しか使っていない）が、そのまま検出力になっている。

## 実測（誤検出の確認）

| 対象 | 結果 |
|---|---|
| 公開済みインサイト24本（正解コーパス） | ERROR 0 / WARN 19。うち未知の固有名詞は**0件** |
| 天皇賜杯2025の投稿案（別大会の正しい本文） | 語彙表を整える前 676件 → **1件**（`used:` 欠落のERRORは正しい指摘） |
| 「青雲飛翔館が優勝」（捏造を注入） | 検出 |

WARN 19件の中身はほぼ全部が「当サイト掲載範囲では初優勝です。」で、
**この定型文は24本中17本に出てくるのに機械では検証されていない**。
「初優勝」は照合器の主張型に無いため、ここが誤ると誰も気づけない。
掲載範囲内の初優勝は決定的に計算できるので、照合器の主張型に加えるのが次の一歩。

## 既知の限界

- 未知の固有名詞の検査は**文字単位**なので、既知の文字だけで組んだ架空の名前
  （例: 実在する漢字の組み替え）は素通りする。
- `genre-vocab.txt` は検出力を落とす方向にしか働かない。捏造された名前の文字を
  うっかり足すと、その名前は以後ずっと通る。追加時は必ず中身を見ること。
- 1文に複数の主体が出るとき、照合器の「1人でも一致すれば OK」という規則が働き、
  誤った帰属が通る（ダブルスのペアのための意図的な設計）。lint 側では検出できない。
- スコアは「その数字の試合が登場人物の関わる形で実在するか」までしか照合されない。
