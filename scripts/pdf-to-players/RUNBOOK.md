## 0. 準備（初回だけ）

```bash
pip3 install --break-system-packages pdfplumber
```

これだけで動きます。**Ollama（ローカルLLM）は無くても構いません。**
入れておくと、規則ではうまく取れない未知の様式のときだけ自動で助けを借ります。

```bash
# 入れる場合（任意）
brew install ollama
ollama serve &                      # 既に起動していれば address already in use と出る。それでOK
ollama pull qwen2.5:7b-instruct     # 約4.7GB
```

`address already in use` は**すでにOllamaが動いている**という意味なので、
`ollama serve` は飛ばして `ollama pull` だけ実行してください。

モデル名を間違えると `pull model manifest: file does not exist` と出ます。
qwen2.5 にあるのは 0.5b / 1.5b / 3b / 7b / 14b / 32b / 72b で、**9b はありません**。
16GB機なら 7b、品質を上げたいときは 14b（約9GB）。

状態が怪しいときは、スクリプトが理由を教えてくれます。

```bash
python3 -c "import labeling; print(labeling.probe_ollama() or 'OK')"
```

動作確認:

```bash
cd scripts/pdf-to-players
python3 test_regression.py
```

`103/103 passed` と出れば準備完了です。**ここが通らないうちは本番のPDFを流さないでください。**
何かを壊したまま作業すると、壊れたことに気づけません。

## 1. まず1ページだけ出す

```bash
cd scripts/pdf-to-players
python3 extract_tournament.py /path/to/DRAW.pdf --pages 1 --out /tmp/page1.json
```

いきなり全ページ流さないでください。**1ページ目で崩れに気づくのがこの作業の肝**です。

出力の読み方は次の3ブロックだけです。

### ① 自動調整の行

```
自動調整: 1通り試し、gap=6 y-tol=3 を採用（点数 1.00 / 33件）
    都道府県が辞書に当たる割合: 1.00
    所属が入っている割合: 1.00
    姓と名の両方が入っている割合: 1.00
    ペアが2名そろっている割合: 1.00
```

**点数だけ見れば十分です。**

| 点数 | 意味 |
|---|---|
| 0.95 以上 | ほぼ間違いなく取れています |
| 0.75 〜 0.95 | 取れてはいますが、内訳の低い項目を確認してください |
| 0.75 未満 | うまく取れていません。下の「困ったとき」へ |

`gap` や `y-tol` の数字の意味は**知らなくて構いません**。スクリプトが何通りか試して
いちばん点数の高いものを選んでいます。人が指定するものではありません。

### ② 検出した列

```
  列 1 [left ] x   76.0– 107.0 → 姓
  列 2 [left ] x  123.0– 154.0 → 名
  列 3 [left ] x  166.0– 223.0 → 所属と都道府県が交互（行ごとに判定）
          例: 近畿・滋賀県 | 朝桜中学校 | 九州・長崎県 | 長崎南山中学校
```

**「→」の右のラベルと、その下の「例」が合っているかだけ見てください。**
`姓` の例に名前らしい値が、`所属` の例に学校名が入っていればOKです。
x の数字は無視して構いません。

### ③ 検証レポート

```
種目: doubles / 抽出件数: 33 / clean: False
  [要確認] 同じ顔ぶれの重複 (duplicate_players): 1件
      {'id': 33, 'same_as_id': 23, 'name': '前田・石田（姫路ふぁみりー）'}
```

`clean: true` でも**件数は必ず自分で数えてください**。PDFのエントリー番号の最大値と
突き合わせるのがいちばん確実です。

要確認の項目の意味:

| 項目 | 出たらどうするか |
|---|---|
| 同じ顔ぶれの重複 | ドロー表下部の「決勝進出ペア」再掲枠です。**そのidを消してください**（機械は消しません） |
| 姓名分割の目視推奨 | そのidの姓名をPDFと見比べる。3文字姓やひらがな名は割れ方が怪しいことがあります |
| ペアの2人目が無い | 抽出漏れです。そのidをPDFで確認 |
| 都道府県辞書に無い | 列がずれているか、OCRの誤認か、実在する所属連盟名（`日本学連` 等）か |
| id重複 / id欠番 | 番号が連番であるはずの種目なら抽出漏れ |
| 所属が空 | 列がずれています |
| 番号と行順の食い違い | PDFの番号と、行の並びから振ったidが違います。どちらが正しいかPDFで確認 |

「（表の外として除外）」と表示された行は、見出しや下部の再掲枠として落としたものです。
**本物のエントリーが混ざっていないか目を通してください。**

## 困ったとき

### 点数が 0.75 未満だった

**まず、もう一度そのまま実行してください。** Ollamaを入れているなら、点数が低いときだけ
自動でローカルLLMに列の判定を聞きにいきます。1回で駄目なら、どこが外れたかを伝えて
**最大3回まで直させます**。改善したものだけが採用されます。

```
点数が低いため、ローカルLLM(qwen2.5:7b-instruct)に列の判定を聞きます（最大3回）…
  → LLMの提案 1回目: 点数 0.62（現在 0.56）
  → LLMの提案 2回目: 点数 0.91（現在 0.62）
  → 採用しました（点数 0.91）。
```

（`--llm` というオプションはありません。自動です。止めたいときだけ `--no-llm`、
回数を変えたいときは `--llm-rounds`。）

**Ollamaを入れていない場合はここが効きません。** 未知の様式に当たることが多いなら、
入れておくと手作業が減ります。

```
点数が低いため、ローカルLLM(qwen2.5:7b-instruct)に列の判定を聞いてみます…
  → LLMの判定のほうが良い（0.62 → 0.91）。こちらを採用します。
```

それでも駄目なら、診断メッセージが次の一手を書いています。

| 診断 | 意味と対処 |
|---|---|
| 都道府県として読めた値がほとんどありません | 列の対応がずれています。②の「例」を見て、都道府県が別のラベルに付いていないか確認 |
| 所属がほとんど空です | 同上。所属の列が `無視` になっていないか |
| 姓と名のどちらかが空の選手が多い | 氏名が1列にまとまった様式かもしれません。`--roles` で `name` を指定 |
| ペアが2名そろっていません | 行のまとまり方が違います。個人戦でないか（`--category` を確認） |
| エントリー番号が連番として読めません | 番号でない列を番号と見なしています。`--roles` で `ignore` に |

**実例（2023年の全中ドロー表）**: 点数0.56で「都道府県として読めた値がほとんどありません」
「所属がほとんど空です」が出た。②の列を見ると、`列3` の例が
`東北・福島県 | 西郷第一中 | 近畿・滋賀県 | 朝桜中` なのにラベルが `名` になっていた
＝**所属と都道府県が交互に入る列**の取り違え。対処は `--roles "2=firstname,3=team_prefecture"`。
このケースは原因（学校名の略称に対応していなかった）を直したので、いまは自動で通る。

### 列のラベルだけが違う

②で「例」は正しいのにラベルが違う場合は、番号を指定して直せます。

```bash
python3 extract_tournament.py DRAW.pdf --pages 1 \
  --roles "0=entry,1=surname,2=firstname,3=team,4=prefecture"
```

使えるラベル: `entry`（番号）/ `surname`（姓）/ `firstname`（名）/ `name`（姓名が同じ列）/
`team`（所属）/ `prefecture`（都道府県）/ `team_prefecture`（所属と都道府県が交互）/ `ignore`（無視）

### 種目の判定が違う

```bash
python3 extract_tournament.py DRAW.pdf --category team    # または doubles
```

### 表がどう見えているのか分からない

```bash
python3 extract_tournament.py DRAW.pdf --pages 1 --dump-table
```

抽出はせず、列と行の検出結果だけ出します。

### `{"error":"no_text_layer"}` と出た

画像やスキャンのPDFです。テキスト層を付けてから同じ手順に戻ります。

```bash
brew install tesseract tesseract-lang
pip3 install --break-system-packages ocrmypdf
ocrmypdf -l jpn INPUT.pdf OUTPUT.pdf
```

**OCR経路は未検証です。** 誤認（髙↔高、﨑↔崎、数字）が起きやすいので、1ページ目の
目視をいつもより慎重にやってください。

### どうしても通らない

無理に自動化しないでください。**この作業は「間違ったデータを入れない」ことが目的**で、
全部を機械で取ることが目的ではありません。通らない様式は、ページ画像を見ながら
手で作るほうが速くて安全なことがあります。

`scripts/pdf/calibrate.py` にレイアウトを画像で可視化する道具があります。
原因を目で確かめたいときに使えます。

```bash
python3 ../pdf/calibrate.py /path/to/DRAW.pdf --page 1
```

## 何かを壊してしまったら

```bash
python3 test_regression.py
```

失敗したテスト名が、壊した箇所を指しています。テストは実際のPDF3種類
（2段組の一覧・ブラケット表の個人戦・ブラケット表の団体戦）で
件数と中身を固定しているので、**直したつもりが別を壊したときに必ず気づけます**。

新しい様式のPDFが通るようになったら、そのPDFを `fixtures/` に置いて
`test_regression.py` にケースを足しておくと、次に何かを変えたときに守られます。
