# pdf-to-players

大会ドロー表（組み合わせ表）PDF → `initialPlayers` 形式JSON。
`tournament-pdf-to-players` スキルの手順を、Claudeが居なくても回せるようにしたもの。

> **作業をするだけなら [RUNBOOK.md](./RUNBOOK.md) を読んでください。**
> この README は仕組みの説明です。

## 設計方針

抽出も検証も決定的なスクリプトが担い、**ローカルLLMには「この列は何の列か」という
一点だけ**を聞く。`scripts/venue-agent/` と同じ流儀で、ツール呼び出しはさせない。

```
PDF →(決定的: geometry.py)→ 行×列の表 ★ここで必ず人に見せる
   →(判断: labeling.py / LLMは任意)→ 各列の意味
       →(決定的)→ initialPlayers JSON
           →(決定的: checks.py)→ 検証レポート
               →(人)→ tool へ投入
```

**Ollamaが無くても最後まで通る。** 判断の対象が「数十件のサンプルから列の種類を当てる」
という狭い問題なので、ヒューリスティックでかなり当たるため。
LLMは**規則がうまくいかなかったときだけ**呼ばれる（下の「自動調整と採点」）。

### なぜ scripts/pdf/ と別に作ったか

`scripts/pdf/` には既に15本のpdfplumber抽出スクリプトがあり、
`master.py` に8種類の抽出戦略、`convert.py` に initialPlayers 生成、
`calibrate.py` に座標の自動検出がある。**中核は既にあった。**

分けたのは、`master.py` が座標をモジュール定数で持ち、使う戦略も
ソース中に直書き（`extraction_strategy = team_extraction_strategy`）していて、
**大会ごとにソースを書き換える運用**になっているため。量をこなす前提だとここが詰まる。
このディレクトリは座標を定数で持たず、すべて検出値か引数で受ける。

`calibrate.py` は今も有用（デバッグ画像つきで座標を目視確認できる）。
崩れたときはそちらを併用する。

## 使い方

```bash
cd scripts/pdf-to-players

# 1. まず1ページだけ出して確認する【必ず最初にこれ】
python3 extract_tournament.py DRAW.pdf --pages 1 --out /tmp/page1.json

# 表の見え方だけ確認したいとき
python3 extract_tournament.py DRAW.pdf --pages 1 --dump-table

# 2. 確認できたら全ページ
python3 extract_tournament.py DRAW.pdf --out entries.json
```

出力の前に必ず「検出した列」と「検出した行」が表示される。
**列のラベルが間違っていないかをここで見るのが、この作業のいちばん重要な一手。**

| オプション | 用途 |
|---|---|
| `--pages 1` / `1-3` / `1,3,5` | ページ指定（既定は全ページ） |
| `--category doubles\|team` | 種目の自動判定を上書き |
| `--model` | 既定 `qwen2.5:7b-instruct`（qwen2.5に9bは無い） |
| `--gap` / `--y-tol` | 検出パラメータを人が固定する。**省略時は自動調整**なので普通は使わない |
| `--no-llm` | うまく取れないときのローカルLLMへの問い合わせをしない |
| `--roles "0=entry,1=surname"` | 列の意味を手で指定する（最後の手段） |
| `--dump-table` | 列・行の検出結果だけ出して終了 |

崩れたときは、まず**そのまま再実行**する。パラメータはスクリプトが自分で振り直し、
それでも点数が上がらなければローカルLLMに列の判定を聞きにいく。
人が手を出すのはその次（`--roles` でラベルを指定）。ソースは触らない。

## 出力フォーマット

### 個人戦ダブルス
```json
{"id":1,"name":"柏・村上（東北）","information":[
  {"lastName":"柏","firstName":"春花","team":"東北","prefecture":"宮城県","playerId":null,"tempId":"柏_春花_東北"}
],"category":"doubles"}
```

### 団体戦
```json
{"id":1,"name":"ヨネックス（東京都）","team":"ヨネックス","prefecture":"東京都","category":"team"}
```

> **`tempId` は `姓_名_学校` の3項目。**
> SKILL.md は `姓_名_学校_都道府県`（4項目）と書いているが、`tools/` 配下の実ファイルは
> 新旧すべて3項目だった（`上岡_俊介_Up Rise` / `濵田_英明_練馬ソフト` 等）。
> 実データに合わせている。経緯は `docs/raw/2026-08-14-idea-local-llm-skill-replacement.md`。

## 検証レポート

SKILL.md の項目に対応。**自動では何も直さない**（直すと直した箇所が人の目から消えるため）。

| 項目 | 意味 |
|---|---|
| `duplicate_ids` / `missing_ids` | id連番の重複・欠番 |
| `prefecture_not_in_dict` | 47都道府県辞書に無い＝列ズレやOCR誤認のサイン |
| `entries_missing_2nd_player` | ペアの2人目が空＝抽出漏れ |
| `review_name_split` | 姓4文字以上/名が空。珍しいので目視推奨 |
| `order_mismatch_warnings` | PDFの番号と行順推定の食い違い |
| `empty_team` | 所属が空 |

`clean: true` でも件数は必ず口頭確認すること。

## テスト

```bash
python3 test_regression.py    # Ollama不要
```

現在 **130/130 pass**（fixtures が全部そろっている場合）。内訳:

- **団体戦は実PDFで丸ごと突合**。`scripts/pdf/tournament.pdf` から抽出した49件が、
  人が作った `tools/tournament3/initialPlayer.js` の49件と**全項目一致**する。
- **個人戦ダブルスも実PDFで検証済み**。`fixtures/zenchu-2024-draw.pdf`
  （全中2024のブラケット表）の個人戦4ページを、各ページ33件（32エントリー＋
  下部の再掲枠1）・先頭と32番目の姓名・所属・都道府県まで固定している。
- **団体戦のブラケット表も実PDFで検証済み**。同fixtureの p5-6 で25チームずつ、
  チーム名・都道府県・長いチーム名の1文字目まで固定している。
- **氏名が1つの枠に入る様式も実PDFで検証済み**。`fixtures/intercollegiate-2026-men-doubles.pdf`
  （2026年インカレ男子ダブルス・全8ページ）で585エントリーと、姓名の分割が
  1170名中1168名まで決まることを固定している。`fixtures/intercollegiate-2026-women-doubles.pdf`
  （女子ダブルス）は**字間に信号が無い様式**で、332エントリーと所属連盟の入り方を固定している。
- 合成データのテストも残している（ペアの束ね方・3文字姓・tempIdの形・警告の発火・
  姓名分割の判断）。字間の実測値をそのまま書いてあるので、PDFが無くても回る。

## 対応しているレイアウト

| 種類 | 例 | 状態 |
|---|---|---|
| 2段組の一覧（番号・チーム名・都道府県） | `scripts/pdf/tournament.pdf` | ✅ 正解データと全項目一致 |
| ブラケット表・個人戦（氏名が文字ごとの固定スロット、所属と都道府県が縦に交互） | 全中2024 p1-4 | ✅ 4ページとも32エントリーを正しく抽出 |
| ブラケット表・団体戦（チーム名と都道府県が同じ列に行ごとの交互） | 全中2024 p5-6 | ✅ 25チームを clean で抽出 |
| ブラケット表・個人戦（氏名が1つの枠に均等割り付け、都道府県欄なし） | インカレ2026 男子D 全8p | ✅ 585エントリー / 姓名は1170名中1168名を自動で分割 |
| 同上（ただし氏名全体が等間隔で字間に信号が無い） | インカレ2026 女子D 全8p | ✅ 332エントリー / 姓名は664名中634名を自動で分割 |
| ブラケット表・団体戦（1行1チーム、都道府県欄なし） | 大学対抗2026 男子 全2p | ✅ 96チームを clean で抽出 |
| 同上（女子・1ページ） | 大学対抗2026 女子 1p | ✅ 59チームを clean で抽出 |
| 2段組の一覧・シングルス（1行に「番号 氏名(所属)」、長い所属は次行に溢れる） | 学生S2026 男子 1p | ✅ 92エントリーを clean で抽出 |
| 同上（女子） | 学生S2026 女子 1p | ✅ 84エントリー / 姓名は84名すべて字間で分割 |

ブラケット表で効いている処理:

- **左右の境目も列も「行ごとの投票」で決める。** 文字の占有幅を union すると
  見出しの1行がページを横断しているだけで列が全部融合する。行単位で数えれば見出しは1票。
- **姓と名の境目は「右端の列だけが明らかに広い」ことで決める。** 姓は1文字ずつの
  狭いスロット（7〜16pt）、名はまとめて広い枠（30pt前後）に入る。
  決め手が無い側は、反対側の境目を鏡像で写す（ブラケット表は左右対称のため）。
- **所属と都道府県が1つの列に交互で入る**場合は行ごとに中身で振り分け、ペア内で共有する。
- **`近畿・滋賀県` のようなブロック付き表記**は後ろの県名だけを取る。
- **下部の再掲枠**（決勝進出ペア・優勝チームの再掲）の扱いは2通り。
  再掲枠にエントリー番号が付いている場合（個人戦）は本体として拾い `duplicate_players` で報告する。
  番号が無い場合（団体戦の「優勝」枠）は**エントリー番号の並びの外**なので落とし、
  落とした行を必ず表示する。
- **団体戦は2行で1エントリー**（1行目にチーム名、2行目に都道府県）。
  1行1エントリーとみなすと件数が倍になり県が全部欠ける。
- **見出しの判定は「大きく、かつ全体のごく一部」**で行う。「本文より大きい」だけを条件にすると、
  表の中で使われている大きめの字まで落ちる（全中の女子団体戦はチーム名12.7pt・都道府県8.2ptで、
  最頻の1.5倍という条件だとチーム名が丸ごと消えていた）。

## 大会プロファイル

自動調整は**未知の様式に対する保険**であって、既に分かっている大会まで毎回探索させる必要はない。
`profiles.py` に大会ごとの設定を書いておくと、PDF本文の署名（大会名）で自動的に選ばれる。

| プロファイル | 署名 | 設定 |
|---|---|---|
| `zenchu` | 全国中学校ソフトテニス大会 | gap=6 / y-tol=3 / 括弧切りなし / 種目は自動 |
| `intercollegiate_singles` | 全日本学生シングルス | gap=4 / y-tol=3 / 種目は singles 固定 / 氏名は1つの枠 / prefecture=日本学連・tempId4項目 |
| `university_team` | 文部科学大臣杯・全日本大学対抗 | gap=6 / y-tol=3 / 種目は team 固定 / 都道府県欄なし / prefecture=日本学連 |
| `intercollegiate` | 三笠宮賜杯・全日本学生 | gap=4 / y-tol=3 / 括弧切りあり / 種目は自動 / 都道府県欄なし / 氏名は1つの枠 / prefecture=日本学連・tempId4項目 |

**「共有ロジックに大会固有の語彙を継ぎ足す」やり方とは別物**である点が肝心:

- 宣言的なデータで、他の様式のふるまいを一切変えない
- 大会ごとに独立していて、増やしても既存が壊れない
- どの大会にどの設定を使ったかが1か所を見れば分かる
- `has_prefecture` / `splits_name` で**その様式に無い項目を検証レポートから外せる**
- `name_in_one_column` で**列検出の結果に関わらず氏名を1つの枠として扱える**
- `prefecture_default` / `tempid_includes_prefecture` で**ドロー表に書いていない所属連盟**を入れられる
  （都道府県欄の無い大会で全件が要確認に並ぶと、本当に見るべき警告が埋もれる）

`--profile <名前>` で明示、`--no-profile` で使わず自動調整だけにできる。

### プロファイルの増やし方

1. `--no-profile` で実行し、`--gap` / `--y-tol` / `--roles` を振って正しく出る組み合わせを見つける
2. `profiles.py` に1件足す（署名はPDF本文に必ず入る大会名）
3. そのPDFを `fixtures/` に置き、`test_regression.py` にケースを足す

3が肝心。**次に何かを変えたときに壊れたことへ気づける**ようになる。

## 自動調整と採点

`--gap` / `--y-tol` を人が試行錯誤するのをやめるための層（`tuning.py`）。
何通りか抽出して**結果を採点し、いちばん良かったものを採る**。採点にLLMは要らない:

- 都道府県の欄が47都道府県辞書に当たるか（列が1つずれると当たらなくなる）
- エントリー番号が連番として素直か
- 所属が空でないか
- ダブルスなら、ペアが2名そろっていて姓と名の両方が入っているか

列がずれた抽出はこれらがまとめて崩れるので、点数が素直に効く。
既定値で0.95以上出たら残りは試さない（検証済みのPDFはいずれも1通りで即決する）。
実測では、ドロー表でない書類（STリーグの結果表）に当てたとき15通り試して最高0.71となり、
「所属がほとんど空です」という診断が出た。

点数が目安（0.75）を下回ったときだけ、ローカルLLMに列の判定を丸ごと聞く。
**一発勝負にしない**。提案を機械が採点し、届かなければ
「都道府県として読める値が取れていません。都道府県を含む列に prefecture を付けてください」のように
**採点の内訳をフィードバックしてもう一度提案させる**（既定3回まで、`--llm-rounds`）。
9〜14Bクラスは一度で当てるより、どこが外れたかを見せて直させるほうが当たるため。

**採否を決めるのは常に機械**で、LLMの自己申告は使わない。改善しなければ規則の結果をそのまま使う。
Ollamaが無ければ黙って規則の結果で続ける。

### 語彙を足して対応しない

`_TEAM_HINT`（所属らしい語の一覧）のような**語彙表に語を足して個別のPDFに対応する運用はしない**。
大会ごとに書き方が違うので足し続けることになり、それは避けたい運用そのもの。

代わりに、決定的な層は**構造的な手掛かり**だけで判断する。例えば
「所属と都道府県が交互に入る列」は、所属側の語彙を知らなくても
**都道府県が半分程度しか当たらないこと自体**で判定できる（都道府県だけの列なら1.0近くまで当たる）。
これなら `西郷第一中` でも `ABC ソフテニ` でも `みなみ` でも同じように効く。

語彙に頼らないと決まらない判断は、規則で書かずに**LLMの担当**にする。

低い点数のときの診断は、座標の話をせずに次の一手だけを出す（`tuning.diagnose`）。

## 既知の限界

- **表の本体の外にある行は「エントリー番号の並びの範囲」で判定している。** 番号が
  まったく無いレイアウトでは効かない。数えるのは「番号として読める値が入っている行」で、
  非空かどうかで数えると見出しが本体に紛れ込む。
- **シングルスは自動判定しない。** `--category singles` かプロファイルで明示すること。
- **プロファイルの署名は「その大会だけに出る語」にする。** `detect()` は先に一致したものを
  返すので、包含関係のある署名を並べると順序に依存して壊れる。
- **エントリーのidはPDFの番号でなく行順で振る。** 再掲枠が混ざるとPDFの番号と1つずれる。
  `duplicate_players` に挙がった行を人が消してから使うこと。
- 姓名が1つの枠にまとまっているレイアウトは、**均等割り付けが姓と名それぞれに
  掛かっている**ことを使って字間から割る（`namesplit.py`）。字間が完全に均一で
  本当に境目が座標に無い行だけ、リポジトリの既存選手データと姓名の辞書に落とす。
  そこでも決まらなければ**分割しない**（姓だけ埋めて `review_name_split` に載せ、
  人に回す）。**推測では割らない。**
- 検出できるのは2段組までで、3段以上のレイアウトは未対応。
- テキスト層が無いPDFは `{"error":"no_text_layer"}` を返して止まる。
  `ocrmypdf -l jpn` でテキスト層を付けてから再実行する（OCR経路は未検証）。
- スコア欄が「0/1以外の数字」で構成されるドロー表では、エントリー番号との
  区別（値がほぼ全部違う・最大値2以上）が外れる可能性がある。

## ファイル

| ファイル | 役割 |
|---|---|
| `extract_tournament.py` | CLI本体 |
| `profiles.py` | 大会ごとのプロファイル（既知の大会は探索せず、分かっている設定で解く） |
| `namesplit.py` | 氏名が1つの枠に入る様式で、姓名の境目を字間→所属つき照合→氏名照合→辞書の順に決める |
| `substitutions.py` | 大会中の選手交代を抽出結果に上乗せする（`--substitutions`） |
| `tuning.py` | パラメータの自動調整と、結果の採点・診断（決定的） |
| `geometry.py` | 文字座標 → 行×列の表（決定的） |
| `labeling.py` | 列の意味づけ（ヒューリスティック＋任意でLLM） |
| `prefectures.py` | 47都道府県の略称→正式名称 |
| `checks.py` | 検証レポート（決定的） |
| `test_regression.py` | 回帰テスト（Ollama不要） |
