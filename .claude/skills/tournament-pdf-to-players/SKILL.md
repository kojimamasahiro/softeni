# 大会ドロー表PDF → initialPlayers JSON

大会の組み合わせPDFから、tool投入用の `initialPlayers` 形式JSONを作る。
**重要な前提**: 元PDFに誤植・列ズレ・OCR誤認があり得る。だから「小さく出して確認 →
問題なければ一気に → 最後に検証レポート」という進め方を必ず守る。人が途中で気づける
ようにするのが、この作業の肝。

CLIは `scripts/pdf-to-players/`。決定的な抽出・検証はすべてスクリプトが担い、
LLMは「検出した列が何の列か」の判定にだけ、しかも任意で使う（`--llm`）。
Ollamaが無くても最後まで通る。設計の経緯は
`docs/raw/2026-08-14-idea-local-llm-skill-replacement.md`、詳細は
`scripts/pdf-to-players/README.md`。

## 出力フォーマット

種目で構造が変わる。

### 個人戦ダブルス (`category: "doubles"`)
選手個人の情報を `information[]` に2名分持つ。
```json
{
  "id": 1,
  "name": "柏・村上（東北）",
  "information": [
    {"lastName":"柏","firstName":"春花","team":"東北","prefecture":"宮城県","playerId":null,"tempId":"柏_春花_東北"},
    {"lastName":"村上","firstName":"芹","team":"東北","prefecture":"宮城県","playerId":null,"tempId":"村上_芹_東北"}
  ],
  "category": "doubles"
}
```
- `name` = `"姓・姓（学校名）"`
- **`tempId` = `姓_名_学校`（3項目, アンダースコア連結）**。都道府県は入れない。
  `tools/` 配下の実ファイルは新旧すべて3項目
  （`上岡_俊介_Up Rise` / `原口_美咲_ワタキューセイモア` / `濵田_英明_練馬ソフト` /
  `北野_敏明_堺連盟`）。以前このskillは4項目（`姓_名_学校_都道府県`）と記載していたが、
  実データに一致しない誤りだった。
- `playerId` は常に `null`

### 団体戦 (`category: "team"`)
選手名は無く、学校名+都道府県のみ。`information[]` は持たない。
```json
{ "id": 1, "name": "高田商（奈良県）", "team": "高田商", "prefecture": "奈良県", "category": "team" }
```
- `name` = `"学校名（都道府県）"`
- 都道府県は正式名称に展開する（PDFが略称「奈良」でも `奈良県`。東京→東京都/大阪→大阪府/京都→京都府/北海道はそのまま）
- 全中のドロー表のように `近畿・滋賀県` とブロック名が前置きされる場合は、後ろの県名だけを取る
- 一般・学生カテゴリでは `prefecture` に所属連盟（`日本学連` 等）が入ることがある。これは誤りではない

### 置き場所

結果（`matches`/`results`）がまだ無い段階では **`data/tournaments/details/` には書かず、
`tools/<大会slug>-<年>/` にステージングする**。ファイル名は
`{doubles,team}-none-{boys,girls}.initialPlayers.json`。この4ファイルを `tools/tournament3`
に貼り付け、PDFを見ながら人がスコアを入力する運用。
既存例: `tools/highschool-championship-2012` 〜 `-2019`。
インデントは2スペース・末尾改行あり（既存ファイルと揃える）。

## ワークフロー（必ずこの順で）

### 0. 入力の種類を確認
`scripts/pdf-to-players/extract_tournament.py` はテキスト埋め込み型PDF専用。まず判定する:
- PDFにテキスト層があるか（`pdfplumber`で文字座標が取れるか）。無ければスクリプトは
  `{"error":"no_text_layer"}` を返す → **画像/スキャンPDF**。その場合は
  下の「スキャンPDF経路」へ（検証済みの別手順。`extract_tournament.py` は使わない）。
- 種目(`doubles`/`team`)は氏名の列に値が入っているかで自動判定される。誤判定時は
  `--category` で明示する。

### 1. まず1ページ目だけ抽出して確認【チェックポイント】
```
python3 scripts/pdf-to-players/extract_tournament.py INPUT.pdf --pages 1 --out /tmp/page1.json
```
出力JSONと、標準出力の**「検出した列」と検証レポート**をユーザーに見せる。
特に見てほしい点を明示する:
- **列のラベルが合っているか**（`姓` `名` `所属・学校名` `都道府県` `エントリー番号`）。
  ここが最重要。ラベルが1つずれると以降が全部ずれる
- 姓名の分割が妥当か（`review_name_split` に挙がったidは要目視。3文字姓やひらがな名など）
- 学校名・都道府県が正しく紐づいているか
- 件数・id範囲が想定と合うか
- 「表の外として除外」と表示された行が、本当に見出しや再掲枠か

ここでユーザーの「OK」をもらってから次へ進む。**承認前に全ページを流さない。**

崩れているときの手当ては、この順で試す。**スクリプト本体は書き換えない。**

| 症状 | 打ち手 |
|---|---|
| 列がくっつく／割れすぎる | `--gap`（既定6pt）を上下させる |
| ペアが1行に潰れる／2行に割れる | `--y-tol`（既定3pt）を上下させる |
| ラベルだけが違う | `--roles "0=entry,1=surname,2=firstname,3=team,4=prefecture"` |
| 表の見え方だけ確認したい | `--dump-table` |
| 判定に自信が無い列がある | `--llm`（Ollama。無ければ黙ってヒューリスティックで続行） |

### 2. 承認後、全ページを一気に抽出
```
python3 scripts/pdf-to-players/extract_tournament.py INPUT.pdf --out OUTPUT.json
```
ページごとに独立して列を検出するので、ページで様式が変わっても通る。
id はページをまたいで通し番号で振り直される。

### 3. 最終検証レポートを提示【チェックポイント】
スクリプトが返すレポートを必ずユーザーに示す。`clean: true` でも件数は口頭確認する。
`clean: false` の項目は具体的にどのidが引っかかったか伝え、原データ由来か抽出由来かを
一緒に切り分ける。レポートの各項目の意味:
- `duplicate_ids` / `missing_ids` … id連番の重複・欠番（ある種目は連番が正のはず）
- `prefecture_not_in_dict` … 47都道府県辞書に無い＝列ズレやOCR誤認のサイン
- `entries_missing_2nd_player`（doubles）… ペアの2人目が空＝抽出漏れ
- `review_name_split`（doubles）… 姓4文字以上/名が空。珍しいので目視推奨
- `order_mismatch_warnings`（team）… PDF番号と行順推定の食い違い
- `empty_team` … 所属が空
- `duplicate_players` … 同じ顔ぶれが2回出る。**ドロー表下部の再掲枠**（決勝進出ペア・
  優勝ペア）が拾われた場合に出る。元データ由来なので機械は消さない。人が判断して削る

**同じ大会の別年度データが既にあるなら、必ず「姓+名」完全一致の照合も掛ける。**
テキスト層PDFでも有効な独立検証で、校名変更の検出にもなる。詳細は下の
「既存年度データとの『姓+名』完全一致照合」。

## 抽出の仕組み（なぜこう作っているか）

ドロー表はブラケットや2段組の表で、素朴なテキスト抽出だと順序が崩れる。そこで文字の
x/y座標から行・列を復元している。要点:

- **左右の分割も列の検出も「行ごとの投票」で決める。** 文字の占有幅を単純に union すると、
  **見出しの1行がページを横断しているだけで列が全部融合する**。行単位で数えれば
  見出しは1票にしかならない。左右の境目は「ほぼ全部の行が空けている帯のうち、
  いちばん幅の広い帯」を採る（幅の狭い帯を選ぶと氏名を途中で切る）。
- **見出しの判定は「大きく、かつ全体のごく一部」。** 「本文より大きい」だけを条件にすると、
  表の中で使われている大きめの字まで落ちる（全中2024の女子団体戦はチーム名12.7pt・
  都道府県8.2ptで、最頻の1.5倍という条件だとチーム名が丸ごと消えた）。
- **姓名分割(doubles)は座標で解けることが多いが、大会PDFによってやり方が違ううえ、
  そもそも座標では分けられないPDFもある。**「このロジックを当てはめれば大丈夫」と
  決め打ちしないこと。これまでに確認できているパターンは3つ:

  1. **狭姓広名スロット型**（`scripts/pdf-to-players/extract_tournament.py`で採用、
     全中2024で検証済み）: 姓は1文字ずつの狭いスロット（7〜16pt）に、名はまとめて
     広い枠（30pt前後）に入る。見分け方: 名前欄を2分割したとき、右端の列だけが
     明らかに広い。判定できる側が片方しか無ければ、もう片方はブラケット表の
     左右対称性を使って境目を鏡像で写す。これで「柏|春花」「村上|芹」「後藤|千尋」
     「松野下|夏穂」のように3文字姓もひらがな名も正しく割れる。
  2. **固定テンプレートスロット型（ブラケット表）**（`scripts/pdf/highschool_championship_entries.py`
     の`_split_name_by_x`＝インターハイ2018/2019、`scripts/pdf/zenshakai_entries.py`の
     `_dynamic_name_split_x`＝全日本社会人2022/2023の`general`/`female`/`age`/`2022`
     全レイアウトで検証済み）: 氏名欄が「姓2枠+名2枠」の固定グリッドに均等割り付けされ、
     3文字になった側だけ中間の空白枠へ内側にあふれる（姓の先頭文字は常に一番左、
     名の末尾文字は常に一番右——姓名合計2文字の1+1のケースも例外なくこれで解ける）。
     **落とし穴**: 姓名境界の字間は内部の字間と全く同じ大きさになるため、字間の大小
     では境界を判別できない（パターン3とは逆）。しかもグリッドの絶対X座標は同じ
     レイアウト内でもページごとに数ptずれるため、レイアウトごとの固定しきい値でも
     対応できない。**解き方**: そのページ・列で実際に使われた氏名文字のX座標の
     最小値（＝姓の1枠目）と最大値（＝名の最終枠）の中点を、ページ・列ごとに毎回
     計算してしきい値にする。
  3. **ラウンドロビン表（表形式）**（`scripts/pdf/zenshakai_entries.py`の
     `_split_name_by_max_gap`＝全日本社会人2022/2023で検証済み）: パターン2と逆に、
     姓名境界の字間は内部の字間よりはっきり大きい（実測で境界≈9〜22pt、内部≈6〜13pt。
     絶対値は年度・ページで変わるが境界が常に最大）。**解き方**: 行ごとに独立して、
     氏名列の文字間で最大の字間を境界とみなして分割する（ページ単位の事前計算は不要）。

  **どのパターンかは必ず手順1のチェックポイントで実データを見て確認する**（決め打ち
  禁止）。姓名が確定済みの行を数件選び、文字ごとのx座標と字間を生で見て、
  「均一な字間の中にページ単位で安定した最小/最大がある→パターン2」
  「1箇所だけ明確に大きい字間がある→パターン3」「片側の枠幅だけ明らかに広い→
  パターン1」のどれに当てはまるか判定する。**どれにも当てはまらない場合**
  （連続した可変幅の組版で、姓名境界に座標上の手がかりが無いPDFも実在する）は、
  無理に座標分割をせず、この項目のフォールバックである文字数ヒューリスティック
  （姓=先頭2文字・残りが名、氏名が2文字なら姓名1文字ずつ）にとどめ、`review_name_split`
  で全件を目視対象としてユーザーに示す。パターン2・3の詳細な実測根拠は
  `docs/raw/2026-08-26-zennihon-workers-2022-name-split-coordinate-fix.md`、
  恒久的な要約は`docs/wiki/data-import.md`（`zenshakai_entries.py`の節）を参照。
- **都道府県**: PDF表記を47都道府県辞書で正式名称に展開。辞書に無ければ検証で顕在化。
- **所属と都道府県が同じ列に入る様式がある。** 2段組の一覧は `ヨネックス(東京都)` と
  括弧で併記し、ブラケット表は**同じ列に行ごとの交互**で入れる（1行目に県、2行目に学校）。
  後者は行ごとに中身で振り分け、ダブルスはペア内で共有する。
- **団体戦のブラケット表は2行で1エントリー**（1行目にチーム名、2行目に都道府県）。
  1行1エントリーとみなすと件数が倍になり県が全部欠ける。
- **エントリー番号とスコア欄の区別**: どちらも数字だけの列になる。エントリー番号は
  「値がほぼ全部違う」「最大値が2以上」で見分ける。スコアは丸数字（④）が混ざる。
- **番号は行順を正とする**: 番号セルは縦位置がずれて行クラスタから漏れることがあるため、
  idは行順(左列→右列)で確定し、拾えた番号と突き合わせて食い違いを警告する（団体戦）。
- **表の本体の外**（見出し・下部の再掲枠）は**エントリー番号の並びの範囲**で判定して落とす。
  落とした行は必ず表示する。番号が付いている再掲枠（個人戦に多い）は本体として拾われ、
  `duplicate_players` で報告される。

座標は**モジュール定数で持たない**。すべて検出値か CLI 引数で渡す。大会ごとに
ソースを書き換える運用にしないため。別レイアウトで崩れたら手順1の表で調整する。

### 既存の scripts/pdf/ との関係

`scripts/pdf/` には先行する抽出資産がある。用途で使い分ける。

- `scripts/pdf/master.py` … 大会ごとに座標定数と抽出戦略をソースに書いて使う方式。
  8種類の戦略が既にあるので、様式が既知の大会はこちらが早いことがある。
- `scripts/pdf/calibrate.py` … 座標を自動検出してデバッグ画像つきで見せる補助ツール。
  レイアウトが崩れて原因が分からないときは、これで目視するのが速い。
- `scripts/pdf/convert.py` … CSV → initialPlayers JSON。
- `scripts/pdf/highschool_championship_entries.py` / `scripts/pdf/zenshakai_entries.py` …
  インターハイ・全日本社会人専用の独立スクリプト（`master.py`の戦略群には未統合）。
  上の「姓名分割(doubles)」パターン2・3の実装元。座標分割の実測方法自体は汎用的な
  参考になる。

## スキャンPDF経路（テキスト層が無い画像PDF）

`pdfplumber` の文字数が0のPDFが対象。**インターハイ2012・2013年度の男女4本
（各13-14ページ、300dpi・1bpp CCITT、計1270エントリー）で検証済み**。実施記録は
`docs/raw/2026-08-30-interhigh-2013-scanned-pdf-entries-import.md` と
`docs/raw/2026-08-30-interhigh-2012-scanned-pdf-entries-import.md`、恒久的な手順は
`docs/wiki/data-import.md` の「スキャンPDF（テキストレイヤー無し）のエントリー抽出」。

**tesseract に氏名を読ませないこと。** `-l jpn` で姓・名をまとめて `--psm 7` にかけるのが
1文字ずつ `--psm 10` より明確に良いが、それでも**姓名単位の正答率は6〜7割**
（`雅也`→`雅包`、`浦川`→`浦月`、`諒樹`→`詠樹`）。氏名データとしては使えない。
`ocrmypdf` でテキスト層を付けて手順1に流す案も、この精度のテキスト層を作るだけなので
**採用しない**。tesseract が有効なのは**ページ見出しの判別**
（「男子個人戦(2)」等でページ範囲を裏取りする用途）に限る。

代わりに、**座標でセルに切り分け → その画像をLLMが直接読む → 既存年度データと機械照合**
の3段構えを使う。

1. **傾きを実測して deskew の要否を決める。結論は年度・ファイルごとに変わる。**
   回転角を粗0.05度刻みで振り、行方向射影の一階差分二乗和が最大になる角度を探し、
   その周辺を0.01度刻みで細探索する。判断基準は「ページ幅×tan(角度) が文字高を超えるか」。
   - 2013年度: 全ページ0.35度以下（2150pxで約13px、文字高30px）→ **deskew なし**
   - 2012年度: 最大0.85度（約32px）→ **ページごとに `cv2.warpAffine`
     （INTER_CUBIC・余白は白）で deskew してから切り出し**
   「傾いて見える」も「前年度が不要だった」も当てにならない。必ず実測する。
2. **長い横線・縦線をモルフォロジーで除去してから連結成分を取り、行ごとの投票で列を出す。**
   ブラケット線を先に消さないと文字と繋がって成分が壊れる。考え方は
   「左右の分割も列の検出も行ごとの投票で決める」（座標経路と同じ）。
3. **氏名欄は「固定枠数」ではなく「固定幅フィールド」。枠数を決め打ちしない。**
   インターハイ2012/2013は `姓フィールド + 空白帯 + 名フィールド` で、通常は姓3枠・名3枠に
   見える（2文字なら両端、1文字なら中央: `大久保`=3枠／`立木`=1・3枠／`籬`=2枠）。
   だが実体は固定幅で、**入りきらない文字数は内部で圧縮して収まる**
   （2012年度女子に `シュレスタ／メガ` = 姓カタカナ5文字）。
   **この様式では姓名分割が空白帯のX座標だけで確定する**（「姓名分割(doubles)」の
   パターン1〜3のような動的計算すら要らない）。カタカナ氏名も同じ規則で入るので、
   漢字前提の文字数ヒューリスティックを持ち込まない。
   **枠のピッチと切り出し窓は年度ごとに実測し直す**（左ブロック姓1枠目が
   2013年 x=218-248・1行目 y=473、2012年 x=275-303・y=550。枠中心間隔も44px→37px）。
4. **セル帯を切り出してLLMが直接読む。** エントリー10件ぶん（`No.`列＋氏名フィールド＋
   都道府県/学校名列）を等倍660-720px × 1080px前後で切ると、300dpiの明朝体印刷は等倍で
   十分読める。判読に迷う字はその1文字だけを6-8倍に拡大して個別確認する。
5. **既存年度データと機械照合する（最重要・下記）。**

**チェックポイントの原則はこの経路でも同じ。** CLIの検証レポートが使えないぶん、
自前で同じものを出す。**1ページ目（40エントリー前後）だけを読んで、抽出結果と照合結果を
ユーザーに見せ、OKをもらってから残りを流す。** 承認前に全ページを読まない。
このとき**方針の判断が要る論点は必ず一緒に出す**（インターハイ2013では
「スキャンは `髙` と `高` を描き分けているが、同一人物が2014年データでは `高` 。
どちらに寄せるか」をここで確認し、ユーザーが「既存データに寄せる」を選んだ）。

### 既存年度データとの「姓+名」完全一致照合

スキャンPDFに限らず、**抽出結果を自己申告に頼らず独立に検証する**汎用手段。
高校生は3年で入れ替わるので、**参照が2年以上離れると急に当たらなくなる**。
だから**年度を1つずつ遡り、確定した年度を次の参照に加える**。

実績（インターハイ）: 2013年度 男子628名中180名・女子628名中196名、
2012年度 男子178名・女子207名が姓名完全一致。いずれも矛盾する一致はゼロ。
2012年度男子p2は2014-17だけを参照にすると6名しか当たらなかったが、直前に完成させた
2013年度を足すと同じページで24名に増えた。

照合スクリプトが見るもの:

- `tools/highschool-championship-<年>/doubles-none-<性別>.initialPlayers.json` に対する
  「姓+名」完全一致（学校名まで一致するかも出す）
- `data/teams/teams.json`（約4900件）に対する学校名×都道府県の整合
- 47都道府県辞書、id連番・重複・欠番、氏名/学校/都道府県の空欄
- 都道府県ごとのペア数分布（インターハイは「6ペアの県」と「8ペアの都道府県」しか無く、
  合計が総数と一致するはず。開催地の県だけ団体戦が2校になる）

副次効果が2つある。どちらも読み取りの正しさの傍証になる。

- **学校名の不一致が校名変更を検出する。** `三島`→`知徳`、`貞光工`→`つるぎ`、
  `能代商`/`能代北`→`能代松陽`、`信愛女短附`→`和歌山信愛`、`盛岡女子`→`盛岡誠桜`、
  `淀之水昇陽`→`昇陽`、`聖カタリナ女`→`聖カタリナ`、`千代田女`→`千代田女学園`。
- **後の年度に同一人物を見つけると、1bppスキャンで判別しきれない字形が確定できる。**
  2013年の `粉澤キララ` の `粉`/`紛` は、2012年の同一人物 `粉沢キララ` の印字で決着した。

### 異体字と表記ゆれ（スキャンでも判別はできるが、原典どうしが食い違う）

スキャンは `高`/`髙`、`崎`/`﨑` を明確に描き分けている。しかし同一人物が別年度の
テキスト層PDFでは別の字になっていることがある（`髙木泰佑`(2013) / `高木泰佑`(2014)）。
**姉妹年度と結合できることを優先し、既存データの多数派に寄せる**のが既定方針
（インターハイではユーザーが明示的にこの方針を選んだ）。

- `髙→高`、`﨑→崎` … `tools/highschool-championship-2014〜2017/` に1件も無いため正規化
- `濱/濵` `邉/邊` `澤` `齋` `德` `桒` … 既存データにも混在しているのでスキャンのまま
- 学校名も同様に多数派へ: `済々黌`→`濟々黌`、`佐賀濟和`→`佐賀清和`、
  `茅ケ崎北陵`→`茅ヶ崎北陵`（`teams.json` は `茅ヶ崎`、リポジトリ全体でも小書き `ヶ` が優勢）
- **「高校」付きの学校名は落とす**: `多久高校`→`多久`、`星城高校`→`星城`、`幡多農高`→`幡多農`。
  同じPDF内でも一部エントリーだけ「高校」が付くことがある

### スキャンPDFで実際に出た原典側の不備

機械では直せない。**そのまま出してユーザー判断に委ねる**（勝手に消さない）。

- **同一ペアが2回印字されている**（2013年男子 entryNo 136 と 277 が
  `長友祐人・寺田侑世／宮崎 日向` で完全一致。画素を並べて読み取り誤りでないことを確認）。
  都道府県ごとのペア数から、本来入るはずの別ペアが1組失われていると分かる
- **都道府県のセルが空**（2013年男子 entryNo 257。学校名だけが2行の中央に印字）。
  学校の所在県で補完し Assumption として明示する
- 同じPDF内での表記不統一（`佐賀濟和`/`佐賀清和`、`今井希望`/`いま井希望`）

### ページ構成は年度で変わる。見出しのOCRだけでページを決めない

2013年度は13ページで団体戦の本ドローが p11 の1枚。2012年度は14ページで団体選手権が
p12/p13 の2ページに分かれている（**48チームの本ドローは p12**、p13 は後半ラウンド）。
「団体戦」というOCR見出しだけで飛びつくと後半ラウンドのページを掴む。中身を見て決める。
