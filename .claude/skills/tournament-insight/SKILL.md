# 大会インサイト（生成 → 執筆 → 照合 → 公開）

大会データから確定した事実だけを抽出し、読み物に仕立ててサイトとSNSに出す一連の作業。

**この工程が守ろうとしているのはただ一つ、「誤った事実を公開しない」こと。**
ADR-005 が当初LLMを排除したのもこれが理由で、ADR-012 が解禁できたのは
機械照合という代替手段ができたから。手順の各ステップはこの一点に紐づいている。

役割分担を最初に押さえておくと迷わない。

| 工程 | 担当 | なぜ |
|---|---|---|
| 事実の抽出 | スクリプト（決定的） | LLMに数えさせると間違える |
| 読み物への編集 | LLM | テンプレ文では複数年の文脈が書けない |
| 事実の検証 | スクリプト（決定的） | 人のレビューは「もっともらしい誤り」を素通りする |
| 公開判断 | 人 | 最終責任 |

決着した種目では、これに **OGP画像の生成**（工程5）が付く。

## 0. まずデータの健全性を確かめる

```bash
npm run check:orphans -- -t <tournamentId> -y <year>
```

「エントリーには居るのに、どの試合にも現れない」組を洗い出す。
**ここを飛ばすと、消えた組が分母から落ちて誤った断定に繋がる。**

実例: 入力ツールの出力バグで不戦勝どうしの2回戦70試合が JSON に出ておらず、
敗者70組がエントリーごと消えていた。その結果「就実は勝ち残りが無くなった」という
記事を公開してしまった（3組出場のうち1組の勝敗が不明だった）。
`type` が `seed` / `extra` に偏っていたらツールのバグを疑い、**再エクスポートしてもらう**。
詳細は `docs/raw/2026-08-01-bug-bye-derived-matches-not-exported.md`。

引っかかったら先に進まず、まず人に伝えること。

## 1. ストーリーYAMLを生成する

```bash
# 完了した大会（全種目を束ねる。これが記事の単位）
npm run story:generate -- -t <tournamentId> -y <year> -o docs/story-yaml/<tid>-<year>.yaml

# 開催中の大会
npm run story:generate -- -t <tournamentId> -y <year> --in-progress -o /tmp/dayN.yaml

# LLMに渡す用（records を落とす）
npm run story:generate -- -t <tid> -y <year> --no-records -o /tmp/for-llm.yaml
```

ここは決定的なロジックのみでLLMは使わない。検出できた候補を絞らずに全部出す
（抽出とキュレーションの責務を分けるため）。

実装済みのkindと閾値の根拠は `docs/story-yaml/README.md`。

**完了大会と進行中で使えるkindが全く違う**。順位（ベスト8以上）が確定するのは準々決勝以降で、
それ以前は `rank.kind: 'ongoing'` のまま（ADR-007）。男子ダブルスは315試合のうち順位が付くのが
最後の7試合だけなので、**大会の98%の期間は経年kindが1つも計算できない**。
進行中に語れるのは「誰が勝ち残っていて、誰が消えたか」だけ。

## 2. LLMに渡して書かせる

`docs/story-yaml/PROMPT.md` のテンプレートをそのまま使う。渡し方の要点だけ再掲する。

- **YAMLは丸ごと貼る**。13〜18KBで元データの1/260しかない。抜粋すると `related` で
  結ばれた相手が欠けて、繋がった筋が書けなくなる。
- **`records` は渡さない**（`--no-records`）。リスト表示用で執筆対象ではないため、
  渡すとそこから文章を作ろうとしてノイズになる。
- **出力に story id を併記させる**。照合が警告を出したとき原因を特定できる。
- **評価語を明示的に禁止する**。「強豪」「名門」「王者」「悲願」「圧巻」。
  LLMの最頻の逸脱で、ADR-005 の「事実のみ」に直接反する。

### 構成が読み物の成否を決める

年表の読み上げにせず、小規模なニュース記事の順序で書く。

1. **今年（今日）何が起きたか** — 完了大会なら `title-won`、進行中なら `watched-eliminated`
2. **その具体** — 決勝・準決勝の相手とスコア、番狂わせ
3. **過去との関係** — 連続記録、学校の継続。**ここで初めて経年の話に入る**

**主役は1組（1校）に絞る。** 複数の主語を並列に並べると年表になって記事にならない。

これは実際に失敗した箇所。初稿は「5年連続ベスト8以上は尽誠学園・高田商・東北の3校です」から
始めて3校の年別成績を並べただけになり、表を散文にしたものになった。原因は書き方ではなく、
**YAMLに「今年何が起きたか」が入っていなかった**こと。主語が無ければどう書いても年表になる。

## 3. 照合する

```bash
npm run story:verify -- -t <tid> -c <cat1>,<cat2>,... draft.md -q
```

**種目はカンマ区切りで全部渡す。** 1種目だけ指定すると他種目の事実が全部不一致になる。

`ERROR` は実データと食い違う。`WARN` は照合できなかったもので、掲載範囲外の事実か
機械が主語を特定できなかったかを人が判断する。

### 検証が効くように書く

照合の抽出パターンは `(\d{4})年...` なので、**年を省略したり修飾を挟むと網から漏れる**。

- ✅ `2023年ベスト8` / `2024年は準優勝` / `2025年も優勝`
- ❌ `2023ベスト8`（年が無い）
- ❌ `2023年もこの種目で優勝`（年と成績の間が離れすぎ）→ `この種目で2023年も優勝` と語順を変える

漏れてもエラーにはならず**黙って未検証になる**ので、書き手が気をつけるしかない。

**主語のない文は直前の文から主語を引き継ぐ。** 照合は本文を `[\n。]` で切り、固有名詞の
出てこない文には直前の文の主語をそのまま持ち越す。そのため
「◯◯が優勝しました**。**決勝は△△に5-4**。**2連覇になります」と書くと、
**3文目の主語が対戦相手の△△になる**（インカレ2026 女子ダブルスで実際に踏み、
「江口咲礼紗/吉木理彩/岩田愛美/西村ひよ 2連覇 — 実データは連続優勝0回」と報告された）。
**「N連覇」「N年連続」の文には主語を書く。**

**`-c` に種目を並べるほど、主語の誤りは隠れる。** 上の誤った1文は、同一テキスト・同一データで
`-c` に全6種目を渡すと `未検証 1`、`-c doubles-none-girls` 単独では `ERROR` になった。
`未検証` は「掲載範囲外の事実」だけでなく**「主語が広がって判定できなかった」ときにも出る**。
「種目は全部渡す」は年×成績の取り違えを防ぐための指示で、主語の誤りには逆に働く。
したがって **最終ゲートは工程4の `check-tournament-insights.mjs`（種目単位）**であって
`story:verify` の全種目実行ではない。全種目実行で `未検証` が出たら、その文を単一種目で
verify し直すこと。

### 照合が万能ではないことを忘れない

検証できるのは年×成績・連続年数・連覇・スコア・固有名詞だけ。
**「何組残っているか」のような集計値は照合の対象外**で、素通りする。
実際に「就実は勝ち残りが無くなった」は照合20件すべて OK のまま公開され、後から誤りが判明した。

照合は捏造を防ぐが、集計ロジックの取りこぼしは防がない。
**断定的な表現を書くときは、その根拠が本当にデータにあるか自分で確かめる。**

## 4. 公開する

`data/tournament-insights/<tournamentId>/<year>/<categoryId>.json` に置く。

```json
{
  "tournamentId": "...", "year": 2026, "categoryId": "...",
  "state": "published",
  "paragraphs": ["...", "..."],
  "usedStoryIds": ["..."],
  "scopeNote": "3回戦終了時点。成績は当サイト掲載大会分（2021年〜）の集計に基づきます。",
  "writtenBy": "ChatGPT",
  "verifiedAt": "2026-08-01"
}
```

```bash
node scripts/check-tournament-insights.mjs
```

prebuild がこれを走らせ、**`verifiedAt` の値を信用せずその場で照合し直す**。
本文を書き換えて `verifiedAt` を残す事故を防ぐため。`draft` / `review` はスキップされる。

表示は年度別結果ページの「注目ポイント」（`ResultContextBlocks`）。
**新規URLは作らない**のでADR-010（同一実体の二重ページ禁止）と抵触しない。

## 5. 決着した種目は OGP 画像も生成する

決勝が確定している種目は、年度別結果ページの OGP を**ベスト16のトーナメント表**にできる
（設計は `docs/wiki/public-pages.md`「大会 年度別結果ページの OGP 画像」）。
**インサイトを完了版で出せる条件と同じ**なので、公開と同じタイミングで生成する。
進行中の種目では生成されないので、この工程は「試合が終わっているときだけ」走る。

```bash
# dry-run（何件対象になるかだけ見る）
.venv/bin/python tools/sns-images/tournament_og.py --only <tid>/<year>/<categoryId>
# 生成して書き込む
.venv/bin/python tools/sns-images/tournament_og.py --apply --only <tid>/<year>/<categoryId>
```

- **`python3` 直打ちと `npm run og:tournaments` は落ちる。** Pillow は `.venv` にしか
  入っていないので `ModuleNotFoundError: No module named 'PIL'` になる。
  `.venv/bin/python` を使うか、先に `source .venv/bin/activate` する
- **`--only` の `tournamentId` は前方一致。** `--only zennihon-university` は
  `zennihon-university-indoor` / `zennihon-university-ouza` まで巻き込む。
  `<tid>/<year>/<categoryId>` と種目まで書いて絞ること
- 生成物は `public/og/tournaments/<tid>-<year>-<cat>-<hash8>.png` と索引
  `data/tournaments/og-images.json`（既存索引にマージされる）。**両方コミットする**
  ——本番ビルドに画像生成の依存を増やさない方針のため、PNG は git に載せる
- **決勝が未確定の種目には生成されない。** `render()` が None を返し、出力の
  「対象外（決勝が未確定）」に計上される。ページ側は `lib/tournamentOgImage.ts` が
  索引を引き、無ければ既定の summary カードへフォールバックする
- **生成した PNG を必ず目で見る。** 左上に優勝ペアが太字で来ているか、決勝のスコアが
  結果と一致しているかを確認する。インサイト本文と同じ事実を別経路（`matches` から直接）で
  描いているので、**食い違っていればどちらかが誤り**という検算になる
- 反映確認（dev サーバで）:

  ```bash
  curl -s "http://localhost:<port>/tournaments/<gen>/<tid>/<year>/<cat>/<age>/<gender>/" \
    | grep -oE '<meta (property|name)="(og:image|twitter:card)" content="[^"]*"'
  ```

  決着済みなら `twitter:card` が `summary_large_image` に、未決着なら `summary` のままになる

- **進行中版のインサイトを完了後に差し替えるときは、OGP画像もこのとき生成する。**
  差し替えが種目単位なのと同じで、生成も種目単位

## 落とし穴（すべて実際に踏んだもの）

**卒業で選手単位が枯れる。** 高校は3年で入れ替わるため、前年ベスト8以上の選手が翌年ほぼ残らない
（インターハイ2026女子ダブルスは16人中3人）。学生カテゴリでは**学校を主語にする**。
ただしペア単位で1ストーリー出すと1種目23件になるので、学校ごとに集約する（`watched-school-progress`）。

**混成ペアがあると「学校が優勝」と書けない。** 一般カテゴリでは所属の異なる選手同士のペアが実在する
（天皇賜杯2022年優勝は稲門クラブとNTT西日本の混成）。生成側で主語を「◯◯所属の選手」に
切り替えている。インターハイの個人戦は混成ペア0.00%なので「◯◯高が」と書いてよい。

**年をまたぐ本文に所属を書かない。** 選手の所属は変わる（丸山海斗は Up Rise → one team）。
所属は単年の事実にのみ添える。

**団体戦の主語は学校名。** 選手名で照合するとメンバーが毎年替わるため再戦を1件も検出できない。
生成側・照合側とも対応済みだが、自分で分析を書くときは注意。

**個人戦は材料が薄い。** インターハイ2025は団体38件に対しダブルス4件。選手単位の継続が出ず、
ペアの再戦も成立せず、番狂わせも `upsets.json` に高校全国大会が1件も無い。
**当年の決勝を軸にするしかない**ので、`title-won` の充実がそのまま記事の成否になる。
