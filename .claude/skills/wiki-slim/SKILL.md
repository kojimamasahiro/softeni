# wiki-slim（現在の仕様だけへ圧縮する）

wiki は毎回エージェントが読むので、文字数がそのまま読むたびの LLM コストになる。目的は2つ:
(1) 読むたびにかかるコストを減らす、(2) 他競技へ持ち出せる部分を見分けやすくする。
背景は `docs/raw/2026-09-18-wiki-slimming.md`、見本は圧縮済みの `docs/wiki/seo.md`（39,029字 → 9,245字）。
設計は [ADR-024](../../../docs/adr/ADR-024-llm-wiki-operating-model.md)。

## 手順

1. **対象を選ぶ**: `npm run check:wiki` で**「圧縮」印のページ（15,600字超）**を選ぶ。
   目安を少し超えただけの「超過」印は**触らない**。ぎりぎりまで削る作業（全文の読み直し・退避・測り直し）のトークンが、
   読むたびに浮く分を上回るため。`open-questions.md` は対象外。
   `git status` で**別の作業が編集中のページは避ける**（並行して書き換えると衝突する）。
2. **全文を読む**。途中で切れたら続きも読む。読まずに圧縮しない。
3. **外から張られた見出しアンカーを調べる**:
   `grep -rnE "<page>\.md#" docs .claude AGENTS.md src lib scripts`
   raw からのアンカーは raw を書き換えられないので、**その見出しは文字列を変えずに残す**。
   wiki からのアンカーは、見出しを変えるなら参照元も直す。
4. **退避する**: 圧縮前の全文を `docs/raw/YYYY-MM-DD-wiki-archive-<page>.md` にそのまま写す。
   冒頭に「いつ・なぜ圧縮したか」とこの skill への言及を書き、本文中の `](./` は `](../wiki/` に置き換える
   （`docs/raw/2026-09-18-wiki-archive-seo.md` の冒頭が見本）。
5. **書き直す**（下の「残すもの / 移すもの」と「ページの形」に従う）。
   先頭の **frontmatter は残す**。`summary` が書き直した内容とずれたら直し、`code:` のパスが実在することを確かめる。
   `code:` はそのページが定義・決定している対象だけ（`wiki-compile` の `references/page-types.md`）。
6. **実装と照合する**: 「未修正」「未公開」「未着手」のような状態は、書き写す前に実装で確かめる
   （古い記述をそのまま圧縮すると、誤りが短く読みやすくなって残るだけ）。
7. **確認する**: `npm run check:wiki -- --strict` が通ること（リンク切れ0件・frontmatter・`index.md`）。
   文字数は目安（12,000字）前後まで下がれば十分で、字単位で詰めない。`index.md` の説明が変わったら `npm run wiki:index`。
8. **記録する**: 作業ノート（例 `docs/raw/2026-09-18-wiki-slimming.md`）の Compile Log に、
   ページ名・前後の文字数・**意図して落としたもの**を書く（書式は `wiki-compile` の `references/compile-log.md`）。

## 残すもの / 移すもの

| 残す（wiki） | 移す（raw アーカイブにだけ残る） |
|---|---|
| 今の挙動、閾値と定数名、実装ファイルへのポインタ | 「追記（YYYY-MM-DD）」の本文、経緯、途中で変わった判断の流れ |
| **守ること**（「必ず〜」「〜しない」） | 実測値の詳細、表、検算ログ、サンプルの個票 |
| 判断の結論1行＋ADR/raw へのリンク | 却下案の比較、議論 |
| **棄却済みの事実**（1行。再調査を防ぐため） | 解決済みの Open Question（1行の結論は「経緯」節に残してよい） |
| 未着手・未修正の残り（期限があれば期限） | 撤回した施策の詳細（撤回した事実と理由は1行で残す） |
| Idea Backlog の表（セルは200字以内） | 重複した段落 |

数値は「判断を変える数」だけ残す（例: 圏外72.5%）。「どう測ったか」は raw へ。

## ページの形

```markdown
---
type: ...        ← frontmatter は残す（type / scope / status / summary、任意で code:）
---
# <タイトル>

> **適用範囲: 混在**。<混在のときだけ、どの節がどれか1〜2行。他は frontmatter の scope で足りる>
> **YYYY-MM-DD に現在の仕様だけへ圧縮した。** 経緯・実測値は [raw/...-wiki-archive-<page>.md](...) にある。

## 概要            … 何のページか、2〜3行
## <汎用の仕組み>   … 競技に依存しない部分を先に書く
## 守ること         … 箇条書き
## <このサイト固有の適用> … 個別の大会名・カテゴリ・URL はここ
## 発展候補アイデア一覧（Idea Backlog）  … あれば
## Open Questions   … open-questions.md の該当節へのリンク1行だけ（問い自体はそちらに書く）
## 経緯             … アーカイブと主要 raw/ADR へのリンクだけ
```

見出しに日付を付けない（外からアンカーが張られている見出しは例外。手順3）。
本文の「適用範囲」の行は任意（混在ページの内訳を書くときに使う）。あるなら frontmatter の `scope` と食い違わせない。

## 適用範囲の決め方（他競技展開のため）

他競技へ仕組みを持ち出すとき（`docs/raw/2026-09-18-idea-multi-sport-expansion.md`）に、
どのページをそのまま使えてどれを書き直すかを見分けるための印。frontmatter の `scope`（`汎用` / `学校` / `固有` / `混在`）と対応する。

| 区分 | 意味 | 例 |
|---|---|---|
| **汎用** | どの競技でもそのまま使える | デプロイ、sitemap、UI 文言、事実照合の仕組み |
| **学校スポーツ共通** | 日本の部活競技（小中高大・インターハイ・全中）なら共通 | 高校/中学カテゴリ、進路、会期中SEO |
| **ソフトテニス固有** | 競技のルール・団体・大会に依存 | STリーグ、score 機能（ポイント記録）、ダブルス前提の集計 |
| **混在** | 節によって違う | 冒頭の注記でどの節がどれかを書く |

「学校スポーツ共通」を分けるのは、バドミントン・卓球なども同じインターハイ/全中の枠組みを持つため（Assumption）。
