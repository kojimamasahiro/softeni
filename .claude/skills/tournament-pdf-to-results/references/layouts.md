## 共通の原理

### スコアは「自分のライン」の脇に置かれる

ドローは1エントリー1本の水平線で描かれ、勝つと合流して新しい高さの線になる。
スコアはその競技者のラインの**上または下に7pt前後ずれて**、そのラウンドの列に印字される
（上側の競技者は線の上、下側は線の下に置かれることが多い）。

重要なのは、**2つのスコアのy順序が競技者のy順序と一致する**こと。
だからラウンドごとにy昇順で2つずつ組めば対戦が確定する。
ずれの向きを当てにいく必要は無い。

### ラウンドの切り分けは「個数」で行う ― x座標ではない

スコアはラウンドごとの列に並ぶので座標で切りたくなるが、
**ページ最終戦のスコアが1つ手前の列に置かれる**ことがある（天皇杯2019女子p6で実際に発生）。

代わりに枠数から各ラウンドのスコア個数を先に決める:

```
行数 n、枠数 S = n以下で最大の2の冪
1回戦の試合数 = n - S      （両者に印字される様式ならスコアは2倍）
2回戦 = S/2, 3回戦 = S/4, ... 最後は1
```

x順に並べてこの個数ずつ切る。ページ最終戦のぶんが1個（敗者のみ印字なら片側に1個）余るので、
**「その1個を除くと全ラウンドが破綻なく組める」候補を総当たり**で探す。
候補が複数残るときの追加条件:

- 左右で**同じyの候補**が1組だけになること（ページ最終戦は左右の勝者が同じ高さで合流する）
- その半分の**最終試合の2つのスコアの間の高さ**にあること（合流後のラインは2本の間に来る）
- ページ中央で突き合わさる**水平線のy（junction）**の近くにあること

### 誰のスコアかは「部分ブラケットの行range」で決める

競技者を「担当する行の範囲（lo, hi）」を持つ塊として扱い、勝つたびに範囲を結合していく。
スコアのyがどの塊の範囲（±20pt程度）に入るかで持ち主が決まる。
塊の範囲は互いに重ならないので一意に定まる。ラインの正確なyを追う必要が無い。

### 勝者スコアが無い様式では1回戦の組が数字だけでは決まらない

敗者にしかスコアが無いと、1回戦で負けた行は分かるが**相手が上の行か下の行かが決まらない**
（行1,2,3で2が敗者なら (1,2) でも (2,3) でも枠数は合う）。

ここはラインの描き分けを使う。**ラインは自分が負ける合流まで点線、勝ち上がる区間は太い実線**で、
どちらであれ**最初の合流点で終わる**。帯の端から始まる線分をx方向に連結していけば
その行が最初に合流する列が確定し、1回戦の列で終わる行だけを隣どうしで組めばよい。

> **罠**: 点線のダッシュはほぼ正方形（0.9×0.96pt）で、幅と高さの大小では横線/縦線を
> 判定できない。大小で分類すると、ある行の点線が丸ごと落ちて17pt先の別の点線列を
> 合流点と誤認する。「y方向に薄いもの」を横線候補にして、x方向の連結だけで辿ること。

### ベクター矩形を幾何的に追跡する方法（もう一つのやり方）

`highschool_championship_results.py` はドローの実線を `page.rects` から拾って追跡する。
水平＝競技者のライン、垂直＝合流。**垂直線は「出力ライン（勝者の新しいライン）が始まる高さ」で
分割されて描かれる**ので、連続する垂直片を連結すると入力2本・出力1本が確定する。

> **罠**: 出力ラインの高さは入力2本の中点とは限らない（席順の都合でずれる）。
> 中点を計算せず、垂直片の切れ目に始まる水平線を出力として拾う。

> **罠**: 「ペアの2人を束ねる枠」やベスト8ページの表組みが、試合の合流と同じ形
> （入力2・出力1）で存在する。エントリー番号に紐づかない合流は読み飛ばす。

この方式は座標のブレに弱い（垂直線が数字を避けて途切れる年度がある）ので、
**まずは個数で切る方式を試すほうがよい**。

## 既知の様式

### 天皇賜杯・皇后賜杯 全日本選手権（zennihon-championship）

| 年度 | ドローページ | 1ページ | 勝者スコア | ページ最終戦 | 準々決勝以降 |
|---|---|---|---|---|---|
| 2019(第74回) | p1-4男子 / p6-9女子 | 46-47人 | 丸数字⑤ | 準々決勝 | p5 / p10 スコア表 |
| 2018(第73回) | p1-8男子 / p10-17女子 | 22-23人 | 丸数字⑤ | 5回戦 | p9 / p18 スコア表 |
| 2017(第72回) | p1-4男子 / p7-10女子 | 47-48人 | **なし** | 準々決勝 | p6 / p12 スコア表 |

- 2018はドローの下に「ページ勝者の小箱」＋「準々決勝の別ボックス」が付く。
  **帯の中央にある番号の小箱**を見つけてそこから下を切る。
- 2017はページ勝者の準決勝・決勝の本数が最終行より下の抜け線の脇に1-2個印字される。
  最終行より下のスコアは落とす。
- 2017の「ベスト64」ページ（p5/p11）は**ドローページと内容が重複する再掲**で、
  取り込みには不要。ページの役割を数字の個数から推定すると誤る（実際に一度誤った）ので、
  各ページを画像で見て役割を確定させること。

### 全国高等学校総合体育大会（highschool-championship）

- 2014-2019: ベクター矩形あり。**敗者のスコアだけ**が敗者のラインの高さに、
  そのラウンドの列に印字される（左半分は合流点の右、右半分は左）。
  つまり「数字が乗っている側＝敗者」。勝者は個人戦ダブルスなら常に4本。
- ページ最終戦だけは左右の勝者のラインが同じ高さで中央に突き合わされるため
  y座標で敗者を決められない。**数字は敗者の側に置かれる**（中央より左なら左半分の勝者が敗れた）。
- 個人戦ドローページには、ページ勝者が次の準々決勝で喫した敗戦のスコアが
  **ページ下端**にも印字されている（優勝ペアのページだけ無い）。
- 団体戦ページは敗者ラインが2.2×0.7ptのダッシュ群なので、近接ダッシュを連結してから追跡する。
- **団体戦の勝者スコアは年度ごとに検算が必要**。2014年男女96試合では
  1・2回戦=3試合すべて消化（3-0 / 2-1）、3回戦以降=2勝先取（2-0 / 2-1）で例外ゼロだった。
- 2013年以前はスキャン画像（下記）。

### 全国中学校大会（secondaryschool-championship）

`scripts/pdf/zenchu_results.py`。2018年度（第49回）と2019年度（第50回）で検証済み。

| 年度 | 構成 | テキスト層 | 読み方 |
|---|---|---|---|
| 2018 | p1-4個人ドロー / **p5-6結果一覧** / p7-8団体 | あり | 結果一覧を本体、ドローで検算 |
| 2019 | p1-4個人ドロー / p5-6団体 | **無し（スキャン）** | 赤インクを色分離して幾何で読む |

- **結果一覧ページ（1行1試合＋エントリー番号＋スコア）がある年度は、それが本体。**
  ブラケットの幾何を追わずに全試合が出る。ドローページは独立に読んで突き合わせる検算に回す。
- 個人戦は64エントリーを2ページに分け、**左1-16／右17-32が同じ行yを共有する鏡像配置**。
  ページ最終戦（準決勝）は左右の勝者が同じ高さで突き合わさる。
- 団体戦は25校で不戦勝あり。席順は2018と2019で同一だった。
- 2019の団体戦は**敗者の本数しか印字されない**。全中の既存データでは
  1・2回戦=3試合すべて消化（3-0 / 2-1）、準々決勝以降=2勝先取（2-0 / 2-1）が
  2018年度48試合で100%、2021-2026年度288試合で98%成立する。補完の根拠に使える。

## パーサのフラグ

`scripts/pdf/zennihon_championship_results.py`:

| フラグ | 意味 | 使う年度の例 |
|---|---|---|
| （既定） | ページ最終戦=準々決勝、勝者=丸数字 | 天皇杯2019 |
| `--page-final-round 5` | ページ最終戦が5回戦 | 天皇杯2018 |
| `--drop-last-row` | ドロー下の別ボックスを無視 | 天皇杯2018 |
| `--loser-only` | 勝者スコアが印字されない | 天皇杯2017 |
| `--winner-score N` | `--loser-only` のとき勝者に入れる本数（既定5） | |
| `--pad N` | 持ち主判定のy許容（既定20） | 行ピッチが極端な年度 |

`scripts/pdf/highschool_championship_results.py`:

| フラグ | 意味 |
|---|---|
| `--kind doubles --pages 1-8 --final-page 9` | 個人戦ドロー＋ベスト8ページ |
| `--kind team --pages 10` | 団体戦概況ページ（点線をダッシュ連結） |
| `--team-all-three N` | 団体戦で3試合すべて消化するラウンド数（既定2） |
| `--compare <既存json>` | 書き込まず差分だけ出す（**入力済みデータの検算に使える**） |

## スキャンPDF（テキストレイヤーなし）

2013年以前のインターハイ（300dpi・1bppの白黒画像）と、全中2019（200dpiカラー）。
座標ベースの手法は使えず画像処理が必要になるが、**結果の読み取りは実際に成立している**
（全中2019で全4種目・174試合。`scripts/pdf/zenchu_results.py --year 2019`）。

### 色が付いているスキャン（全中2019で確立した経路）

勝ち上がりの太線とスコアが赤で印字されている様式なら、色だけで地の文字から切り離せる。

1. 300dpiでレンダリングし、`(R+G+B)<620` を暗部、そのうち `R-G>50 かつ R-B>50` を赤とする。
2. `binary_opening`（1×30）で**水平線分の連結成分**を取る。1本＝1ユニットのライン。
   高さ25px超の塊は文字なので落とす。
3. 行のy（＝最外列の線分）からユニット木を作る。
   **ユニットのラインyは入力2本の中点**と1px以内で一致した。
4. **勝者は合流点の縦線の色で決まる。水平線の色ではない。**
   赤は「1つでも勝った競技者の経路」を敗退まで塗るので、2回戦で負けた競技者の
   2回戦の区間も赤い。水平線で判定すると1回戦だけ正しく出て2回戦以降が静かに壊れる。
   入力ライン→出力ラインの縦線は勝者側だけが赤く（実測0.81-0.99）敗者側は黒（0.00）。
5. 丸数字（勝者）と裸の数字（敗者）は**bboxの幅**で分離できる（実測22-32px 対 5-16px）。
   「合流の色から出した勝者」と「丸数字の側」の一致を全試合 assert すれば、
   値を読まずに勝敗の独立検算になる。
6. **不戦勝の行は1回戦の列を素通りするので線分が2列ぶんの長さになる。**
   これで不戦勝を機械判定でき、1回戦の組も決まる。
7. 数字の値だけは辞書で持つ（`<大会>-<年>-score-glyphs.json`、`"p<ページ>:<x0>:<y0>" → 数字`）。
   **同定はクラスタリングを正、目視は「クラスタ代表の同定」と「外れ値の確認」だけ**にする。
   コンタクトシートを通し読みすると行内で位置がずれて写経ミスをする（実際に起きた）。
   正規化は**アスペクト比を保ってパディング**する（正方形に引き伸ばすと細い「1」が黒い塊になる）。

### 白黒のスキャン（インターハイ2012/2013、未実装）

`docs/raw/2026-09-02-interhigh-2014-results-from-pdf-verification.md` に実現可能性の検証がある:

- エントリー行は「（…）」の括弧のコネクテッドコンポーネントで確実に取れる
- 勝者は**丸数字**、敗者は裸の数字。中心から半径14.5pxの24点にインクがあるかで
  丸の有無を判定でき、スコア0.29以下と0.83以上に完全に分離した
- 字形はクラスタリングすると数種に収束する（テンプレートマッチで読める）
- ラウンドの割り当ては列クラスタリングだと外れ値に弱いので、
  **枠数から個数を出してx順に切る**方式が有効（ベクターPDFと同じ考え方）

残課題: 棄権の「R」表記、丸と数字が繋がって1コンポーネントになる個体、
年度によるページ構成の違い。
