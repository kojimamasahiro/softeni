# PDF からの取り込み

> **適用範囲: 汎用**。「テキスト層の有無をまず数える」「別ページ・別種目・既存データで独立に検算する」
> 「推測で埋めず人へ回す」は競技に依存しない。大会名と座標の具体はソフトテニス固有。
> **2026-09-18 に [data-import.md](./data-import.md) から分割し、現在の仕様だけへ圧縮した。**
> 年度ごとの実施記録・座標の実測値・調査の経緯は
> [raw/2026-09-18-wiki-archive-data-import.md](../raw/2026-09-18-wiki-archive-data-import.md)。

大会の PDF（ドロー表・記録報告書）から `data/tournaments/details/**` や入力ツール用 JSON を作る道具と、
繰り返し踏んだ落とし穴。取り込み後の運用は [data-import.md](./data-import.md)。
手順そのものはスキル `tournament-pdf-to-players` / `tournament-pdf-to-results` / `team-match-order`（`.claude/skills/`）にある。

## 最初にやること

1. **`pdfplumber` でページごとの文字数を数える**。**同じ大会でも年度でテキスト層の有無もページ構成も変わる**
   （前年度のページ割りで当てにいくと結果一覧を団体戦と取り違える）。
2. テキスト層が無いなら、**OCR の前に `len(page.get_drawings())` を数える**。
   文字数と同じオーダーなら**スキャンではなくアウトライン化**（文字がベクターパスになっている）で、
   **ここで OCR を使うのは PDF に残っている情報を捨てる行為**。`even_odd` の fill path 1個＝1文字で、
   外接矩形がそのまま切り出しになる。
3. **重い手順が要るかを見極める**（deskew・線除去・スロット検出はいつも要るわけではない）。
   全景を1ページ見て (a) 行が傾いていないか (b) 姓名が空白で分離しているか を確認し、
   両方 YES なら 300dpi レンダリング＋固定オフセットのクロップだけで通ることがある。
4. **1ページ目だけ出して人が確認 → 承認後に全ページ**。元 PDF に誤植・列ズレがあり得るので一気に変換しない。

### `tournament_results_common.py`（組み立ての共通処理）

PDF の読み方は大会・年度ごとに違うが、**読み終わったあとの組み立ては全大会で同じ**。

- `build(initial_players, matches)` が `matchId` の採番、`nextMatchId`/`prevMatchIds`、
  `entries[].type`（seed/packing/extra）の逆算、`results[]` のラベル、`participants[]` の生成を引き受ける。
  **ここを大会ごとに書き直さないこと**——特に `type` の逆算を間違えるとブラケット表が静かに従来方式へ落ちる。
- `check(data)` がリンク整合・勝者の進出・同一ラウンドの重複まで検査する。パーサ側で `assert not check(data)` して止める。
  **`check()` はこのモジュールを通した場合しか走らない**（入力ツール経由のデータは同じ検査を受けない）。
- 勝者スコアが PDF に無い様式は `build(..., winner_score_default=N)`。**その値は仮定なので根拠を必ず残す。**
- **予選リーグを含む大会は対象外**（決勝Tの枠がリーグ順位で決まり entryNo と対応しない）。
  **本戦前に「予選」を1試合だけ置く形式も対象外**（`type` が `preliminary` になり枠数が2の冪にならない）。
- **details を書いたら `node scripts/normalize-team-names.mjs --scope=<大会ID>` を必ず通す**（冪等）。

## 姓名の分割

- **座標で決める**のが基本。均等割り付けの様式なら、姓と名それぞれに割り付けが掛かるので**境目の字間だけが広い**。
- **「姓/名内部の字間」だけで境界を判定してはいけない**（2文字姓の内部字間が姓名境界とほぼ同じになる実例がある）。
  固定座標のしきい値か、その列で実際に使われた X の最小・最大の中点を**ページごとに計算する**。
- **スロット数・ピッチ・切り出し窓は年度ごとに実測し直す**。決め打ちは壊れる
  （`出現数の多い上位N本を採る` も不可。低頻度のスロットが落ちて名が所属列へ流れる）。
- 字間で決まらない行は、既存の `lastName`/`firstName` を **(氏名, 所属) → 氏名 → 姓と名の辞書**の順に引く。
  所属まで見るのは同姓同名を避けられるうえ、**既存の `playerId` と結びつけるにはその所属の綴りに揃える方が正しい**から。
- **辞書を作るときは `count: 0` の行を除く**（正準化で使われなくなった綴りが残っており、誤りを正例として学習する）。
  `data/players/index.json` をそのまま語彙にしないこと。除外には `name-split-aliases.json` の `aliases` を使う。
- **そこでも決まらなければ推測せず未分割**にし、`firstName` を空のまま `review_name_split` に出して人へ回す。
- 割り方の正準は `data/players/name-split-aliases.json`（[player-name-identity.md](./player-name-identity.md)）。
  **PDF の座標は、正準化の検出器が届かない誤りに届く**（誤った綴りが1通りしか無い氏名は検出器では気づけない）。
- カタカナ氏名にも同じ座標規則が効く。**漢字前提の文字数ヒューリスティックを持ち込まない。**

## 検算（独立した経路で確かめる）

- **同じ PDF の中に別様式の表があれば、それが最良の検証**（ブラケットと結果一覧、ドローとベスト64表、
  予選リーグと決勝Tの「Nブロック1位」欄）。組版が違う表どうしなので、列の取り違えは必ず差分に出る。
- **同じ大会の別種目 PDF は、既存年度データより近い参照**（シングルスとダブルスは出場者の大半が重なる）。
  **先に読んだ種目を次の種目の参照に加える**こと。**種目をまたぐと大学・学校が増える**ので、片方だけでマスタを作らない。
- **既存年度データとの「姓+名」完全一致で機械照合する**。年度は1つずつ遡り、確定した年度を次の参照に加える。
  **高校は2年以上離れると急に当たらなくなる**（実績28%程度）が、**大学は4年離れても7割当たる**
  （在籍4年＋卒業後も実業団で追跡できるため）。学生カテゴリではこの照合は事実上の答え合わせになる。
- 学校名の不一致は**校名変更の検出**にもなる。後の年度に同一人物を見つけると、**判別しきれない字形も確定できる**。
- **スコアの分布で検算する**（9ゲームマッチなら全試合が勝者5本・敗者0〜4本になるはず）。
- **「欠番0」はブロックの取りこぼしを検出できない**（番号がブロック単位の連番だと、末尾のブロックが丸ごと落ちても
  欠番にならない）。ブロックごとに「開き括弧の数＝エントリー数」を突き合わせ、紙面の最終番号と件数も目視する。

## 繰り返し踏んだ落とし穴

- **ラウンドの切り分けを x 座標でやってはいけない**（ページ最終戦のスコアが1つ手前の列に置かれることがある）。
  枠数から各ラウンドのスコア個数を出して x 順に切り、ページ最終戦のぶんを総当たりで決める。
- **勝敗は合流の縦線の色で決まる。水平線の色ではない**（赤は「1つでも勝った競技者の経路」を敗退まで塗るので、
  水平線で判定すると1回戦だけ正しく出て2回戦以降が静かに壊れる）。
- **出力ラインの高さは入力2本の中点とは限らない**（様式による）。中点を仮定せず「垂直片の切れ目に始まる水平線」を拾う。
- **印字されるのは敗者のスコアだけ**という様式がある（数字が乗っている側＝敗者）。勝者は規定値で補完し、**その仮定を記録する**。
- **ドローの外に「ページ勝者のその後」の本数が印字される年度がある**。最終行より下は落とすが、
  **本物の試合のスコアも下へずれることがある**ので、**足りないときだけ最終行に近いものから必要な個数だけ戻す**
  （総当たりに任せると「その後」を試合として消費し、有り得ない試合が静かにできる）。
- **3文字の都道府県（北海道・和歌山・鹿児島・神奈川）だけが列の端で切れる**ことがある。
  `prefecture: None` がその県に偏っていたら列幅を疑う。47都道府県と完全一致するか検証して補正パスを入れる。
- **フォントに無い字が豆腐（□）で印字される PDF がある**。`data/players/index.json` を「欠けた形」で引くと
  一意に決まることが多い（**既存の選手名簿は豆腐文字の復元辞書として使える**）。学校名の豆腐は名簿では解けない。
- **文字の二重描画**がある年度がある（同一座標に2回描画され「猪猪本本」のようになる）。同一 `(x0,top,text)` を畳む。
- **ページ下部の再掲枠**に注意。見出しが無い年度があり、**再掲枠の番号が本体の所属列に入って直上のエントリーの
  所属を上書きする**（件数の検算では気づけない）。所属欄が数字だけ・1文字になっていないか別に確認する。
- **行の組み立ては文字の上端でなく上下中心で行う**（列幅に収まらないとフォントが小さくなり、上端で揃えると行が流れる）。
- **所属名の折り返しは座標では選別できない**。意味的な条件（次行が `・` で始まる／直前行が `附属` で終わる／
  **連結が既知のチーム名**／次行が1文字）で決める。「1文字の所属名は無い」という条件を他大会へ持ち込まないこと
  （`teams.json` には1文字チームが実在する）。
- **見出しの照合は完全一致で**（`男子準々決勝` は `決勝` を含むので、包含判定にすると準々決勝が決勝になる）。
- **棄権表記 `R` は `4R` のように数字の後に来る**（1文字前提で弾かない）。`R0` の並びは未対応で黙って読み飛ばされる。
- **表の本体はエントリー番号の並びの範囲で判定する**（非空で数えると見出しがエントリーとして紛れ込む）。
- **プロファイルの署名は「その大会だけに出る語」にする**（包含関係のある署名は順序依存で壊れる）。
  **同じ週に開かれる大会でもプロファイルは分ける。**
- **シングルスは自動判定しない**（`--category singles` かプロファイルで明示。ドロー表の見た目はダブルスと同じで、
  行のまとまりが崩れているときも同じ形に見える）。
- **`extract_tournament.py` は固定スロット様式（インターハイの個人戦ドロー）に使わない**。
  列の自動検出はページ間で列数が変わり、`--roles` が別ページに誤った役割を割り当てる。座標を直接使うパーサの方が安全。

### スキャン PDF

- **傾きを実測してから deskew を判断する**（結論は年度ごとに変わる）。回転角を振り、行方向射影の一階差分二乗和が
  最大になる角度を探す。ドリフトが文字高を超えるなら `cv2.warpAffine` で補正する。
  **傾きは列単位で効く**——セル単位の切り出しは無害でも、列全体を集計するスロット検出は壊れる。
- **長い横線・縦線をモルフォロジーで除去してから連結成分を取る**（ブラケット線を先に消さないと文字と繋がる）。
- **tesseract 単体で氏名を取ろうとしない**（姓名単位の正答率6〜7割）。切り出したセル帯を LLM が直読する方が精度が出る。
  見出しの判別には十分使える。
- **1エントリー＝1セルに切り出し、セル間に区切り線を入れた縦長シートを読ませる**（帯のまま読ませると隣の行の字を
  自分の行だと誤読する）。画像の長辺は 1568px 以下に収める。
- **RGB スキャンなら赤ペンは色で分離できる**（`redness = R - max(G,B)`）。ただし**棄権の検出を赤い取り消し線だけに
  頼らない**（本体は赤ペンの「R」で、線が引かれないことがある）。**消すときは `min(R,G,B) > 85` を条件に足す**
  （`redness` だけだと線と重なった黒文字まで白くなり字が欠ける）。
- **不戦勝の行は1回戦の列を素通りするので線分が2列ぶんの長さになる**。これで不戦勝を機械判定でき、1回戦の組も決まる。
- **丸数字（勝者）と裸の数字（敗者）は bbox の幅で分離できる**。「合流の色から出した勝者」と「丸数字が付いている側」の
  一致を全試合 assert すると、値を読まずに勝敗を独立検算できる。
- **数字の値だけは辞書で持つ**（`"p<ページ>:<x0>:<y0>" → 数字`）。同定は**クラスタリングを正、目視は
  クラスタ代表の同定と外れ値の確認だけ**に使う（コンタクトシートの通し読みは写経ミスをする）。
  正規化は**アスペクト比を保ってパディング**する（正方形に引き伸ばすと細い「1」が黒い塊になる）。
- **見開きスキャンは1画像に4サブ列**になることがある（1ページ＝冊子の見開き2ページ）。1サブ列を1単位として扱う。
  **大学名とエントリー番号は「ペアの1行目の高さ」に置かれる**（2行の中央ではない）。
- **姓＝左詰め・名＝右詰めの4スロット型なら、スロット占有で転記を機械検算できる**
  （`s2に字がある ⟺ 姓が2文字以上` / `s3に字がある ⟺ 名が2文字以上`）。

### アウトライン化 PDF

- **別ページの正解セット（通常のテキスト層を持つベスト64表など）でブートストラップする**。
  エントリー番号つきで載っていれば位置で突き合わせるだけで大量の文字が確定する（実績で氏名欄の77%）。
- **土/士・末/未 は形状の正規化では分離できない**（横棒の長さの比だけが違う）。ベクターがあるので**実寸を測って**決める。
  確認画像を作るときも**幅ではなく字高で正規化**する。
- **正解セットにも誤記はある**。実測・既存辞書との三点照合で決めること。

## 表記の扱い

- **読むときは各ページの印字どおりに取り、JSON 生成の段で既存データの多数派へ寄せる**
  （読み取り段階で寄せると原典が何と書いてあったか分からなくなる）。同じ冊子でもページごとに表記が揺れる。
- **異体字は「既存データに同一人物が別字で居るときだけ」寄せる**。一律の正規化はしない（異体字が正しい人が実在する）。
  **寄せ先は大会ごとに逆になる**——「その大会の既存データの多数派」で毎回決める。
- **異体字ゆれと校名変更は分けて扱う**。多数派に寄せるのは表記ゆれまでで、**校名変更後の名前に遡って寄せない**
  （当時の表記としては原典が正しい）。
- **`tempId` は `姓_名_学校_都道府県` の4項目**。details 生成経路は tempId を見ないので3項目でも通るが、
  **入力ツールに貼って人が入力した結果を書き出す経路だけ**は tempId が識別子になり年度間でずれる。
- **団体戦エントリーは `校名_都道府県` の2項目**。`prefecture` を **null のままにしない**
  （都道府県別集計やトーナメント表の所属表示が空になり、他大会の同じ学校と別チーム扱いになる）。
  大学連盟の大会は **`日本学連`** を入れる。
- 実行後は `node scripts/normalize-prefectures.mjs --scope=<大会ID>` で接尾辞を補完する。
  **省略される範囲は年度で違う**ので「団体戦だけ」と決め打ちしない。

## 同一人物が複数エントリーに出るのはデータ破損ではない

片方のエントリーが棄権し、その選手が別のエントリーに選手変更で入るのは競技上ふつうに起きる。
同一人物が別の相方と2枠、原典が同じペアを2回印字、という型もある。扱い:

1. **`entries` は両方残す**（枠は2つ実在するので `playerIds` に同じ id が入るのが正しい）
2. **`participants` は1行に畳む**（participants は**人の一覧**であってエントリー枠の一覧ではない）
3. 棄権側は `matches` に `retired: true`、`results` は「N回戦敗退」
4. 参照は壊れない（`playerIds` は id 文字列、`matches`/`results` は entryNo で参照している）

**未修正点**: `tournament_results_common.py` の `build()` は participants を **entryNo で dedupe している**ため、
同じ選手が2エントリーにいると participants に同一行が2つ出る（`rec["id"]` で dedupe すれば直る。それまでは手で畳む）。
