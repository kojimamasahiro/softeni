# SEO カニバリゼーション / 重複制御

> **適用範囲: 混在**。「制御手段」「守ること」「計測の原則」「sitemap」は競技に依存しない。
> 「重複マップ」の各行はこのサイトのページ構成に固有。
> **2026-09-18 に現在の仕様だけへ圧縮した。** 日付つきの追記・実測値・検算は
> [raw/2026-09-18-wiki-archive-seo.md](../raw/2026-09-18-wiki-archive-seo.md) にある。

## 概要

同じデータから複数の切り口でページを作るため、ページ種別の間で検索語が重なる。このページは
「どの種別が重なり、どう棲み分けるか」を横断で一覧にする。各ページの実装は個別の wiki ページが正。

## 制御手段（汎用）

| 手段 | 使うとき |
|---|---|
| **インテント分割** | 狙う検索語（年あり/なし、解説/結果 等）を分け、本文・title・description を変える |
| **canonical 統一** | 同じ実体に複数 URL がある |
| **noindex / 生成しない** | 薄いページや重複ページをインデックスから外し、厚いページへ枠を集める |
| **内部リンク集約** | 解説や入口を1ページにまとめ、重複ページ自体を作らない |

## 守ること（汎用）

- **実害は GSC で判定する**。実害が見えないうちは canonical 統一や 301 を急がない（移設で評価を落とすリスク）。
- **noindex にしたら、そのページへの内部リンク数を数える**。内部リンクが集中するページを noindex にすると
  `follow` でも評価が減衰する。リンク元を index 側へ振り替えるまでが対策。
  数え方: `grep -rl 'href="<パス>"' out --include="*.html" | wc -l`
- **新しい URL を作るより、既存ページに検索語を literal で置く**（略称・通称・「組み合わせ」等）。
  正式名称は置き換えず併記する。
- **略称は、その語がそのページの対象を指すときだけ付ける**。SERP に混同した表記があっても再生産しない
  （王座決定戦に「インカレ」を付けて撤回した実例あり）。
- **title は表示枠（概ね28〜32全角）を完成形の幅で予算化する**。狙う語（年・「歴代」等）を先頭30字以内に置く。
- **速報クエリでは量産サイトと正面勝負しない**。当サイトは「歴代・通算・学校名/選手名×大会名」の
  ロングテールで取る。ただし「組み合わせ（ドロー）」は構造化データで勝てるので正面から取る。
- **結果が1件も無い種目は「結果」「途中経過」と名乗らず「組み合わせ」とする**（ADR-007）。
- **同じフレーズを多数ページで機械的に反復しない**（テンプレ重複と見なされうる）。
- **大会ハブへのリンクは必ず `getTournamentHubHref()`（`lib/highschoolNationalTournamentMeta.ts`）を通す**。
  高校全国大会だけ `/highschool/tournaments/{slug}/` を返す。

### #2 / #12 薄いページの noindex 選別

- **選手結果**: `totalMatches >= 15`（`PLAYER_INDEX_MIN_MATCHES`）または全国高校大会の出場歴があれば index、
  どちらも無ければ `noindex, follow`。
  - 「全国高校大会」は **`index.json` 収録の大会に限る**（`loadNationalTournamentIds()`）。
    `loadTournamentIndex()` は `local_index.json` も連結して返し、地区大会にも `generationId: 'highschool'` がある。
    **`generationId` 単独での判定は不十分**。新しいカテゴリを `local_index` に足すときは既存の判定を確認する。
  - 全国大会優勝者は title / description に大会の通称を literal で出す（「{選手名} インターハイ 優勝」狙い）。
    **SEO 文言は優勝のみ、UI の勲章カードはベスト8以上**。社会人の全国大会は含み、国際大会は含まない。
    詳細は [players-pages.md](./players-pages.md)。
- **チーム**: 収録試合数が `TEAM_INDEX_MIN_MATCHES`（5）未満なら noindex（`lib/teamIndexing.ts`）。
  所属選手が1人でも出た試合を1と数える。ハブは大会＋STリーグの全年度合算で判定。
- sitemap は `scripts/filter-noindex-from-sitemap.mjs` が生成 HTML を見て自動で追従する（判定を二重に持たない）。

### #3 高校全国大会は高校歴代ページへ集中

- 汎用ハブ（`/tournaments/highschool/highschool-championship` 等）は `noindex, follow`＋誘導バナー。
  判定は `getHsNationalSlugByTournamentId()`。対象はインターハイ・ハイジャパ・高校選抜。
- 同じ扱いを `data/tournaments/index.json` の **`featurePath`** で汎用化している（例: STリーグ → `/st-league/`）。
- 略称（ハイジャパ等）は専用ページを作らず `HsNationalTournamentMeta.aliases` で title・h1・description・FAQ に出す。
  alias が `shortLabel` / `label` と同じなら併記しない（`displayAlias`）。「センバツ」は野球と衝突するので使わない。
- title の先頭は通称（`titleLeadName`）、正式名称は後ろ。略称の併記は通常モードのみ。
- パンくずと canonical は URL 階層どおり（リンク振り替えの対象外）。
- **最も効果が大きい未着手施策**: 収録が2021年以降しかない。年・優勝・準優勝だけの champions-only レイヤーを
  過去へ足す（先例 `src/pages/st-league/champions.tsx`）。出典の確保と検算が要る。

### #11 開催中の大会

- **新規 URL は作らない**。会期中は大会ハブ（高校歴代）・都道府県ページ・学校ページに「開催中」節を出し、
  title を「{通称}{年} 結果・途中経過」に切り替える（`lib/highschoolInProgress.ts`）。
- **優勝が確定すると自動で歴代モードに戻る**（`inProgress` が null になる）。
- 更新は1日1回（その日の全種目終了後、`npm run story:generate -- --in-progress` と同時）。
- sitemap の `lastmod` は `clampToBuildDate()` でビルド日を上限にする（未来日は無視されるため）。
- **汎用ハブには未移植**（インカレ・全中・全日本選手権などは会期中モードが無い）。

### #13 / #14 中学・小学生カテゴリ

- `/teams/[teamId]` との重複は無い（`/teams/` が作られるのは `team-name-mappings.json` のキーと STリーグ出場チームだけ）。
- 高校と中学の同名校は名寄せで別エンティティ（[ADR-013](../adr/ADR-013-scoped-team-name-aliases.md)）。
- 小学生と中学の同名団体は同一団体の別の部。URL ツリーが別で内容も別。
- **大会軸のページを作らない**（全中・全小は汎用大会ハブに集約）。**順位づけのページを持たない**（県ごとの出場枠が違い比較できない）。
- **出場延べ5件未満のチームはページ自体を作らない**（noindex ではない）。
- `/secondaryschool/pathways/[gender]/` は男女別 URL で**高校起点**（高校名の検索需要に合わせる。県外進学の集約が見える）。
  高校の学校ページ「出身中学」節とは粒度と検索意図が違うのでカニバリとは扱わず、一覧→学校ページへリンクを寄せる。
- 小→中→高の進路リンクは `getSchoolResolver()`（`summary.json` が正）で解決し、デッドリンクを出さない。
- 未対応: 同名同県の3団体（`田辺STC` `向原JST` `岩見沢少年団`）は小学ページと中学ページが相互リンクしていない。
- 仕様は [secondaryschool.md](./secondaryschool.md)・[primaryschool.md](./primaryschool.md)。

### #15 団体戦のオーダー

オーダー（[ADR-020](../adr/ADR-020-team-match-rubber-details.md)）は 28 ページ（団体の年度別結果）に
785試合・2,355対戦ぶんある。**新規 URL は作らず**、既にインデックスされている 2 種類のページで受ける。

- **年度別結果ページ**: 対戦詳細の表に加えて、`lib/teamMatchOrderSummary.ts` が
  「決勝のオーダー」を1文にした FAQ を出す（オーダーを持つ種目だけ）。**画面に出している文面と
  同じものを FAQPage に入れる**（表示していない答えを構造化データにだけ持たせない。`offers` と同じ側）。
  決勝の記録が無い大会では決勝の問いごと出ない。
- **学校ページ**: オーダーに出た選手を年度別メンバーに足す（`lib/highschoolTeamMatchMembers.ts`）。
  団体戦の `participants` は学校単位なので、これが無いと団体戦のレギュラーがメンバーに出ない。
  実測で 551 の学校×年・延べ3,948名、うち約1,286名が新規（[highschool.md](./highschool.md)）。
- **棄却済み（再調査しない）**: 「オーダーを選手ページに出すと noindex が index に変わる」は誤り。
  対象934人のうち933人が既に index（2026-09-19 実測）。出す価値は厚みとロングテールであって掲載数ではない。
- **未着手**: 団体ページの title に「オーダー」を足すか（字数予算が先）。選手ページへの「団体戦の出場」節。

## 大会名の表記と検索語の乖離（missing literal）（2026-08-28 追加）

正式名称でページを作った結果、**検索する人が使う語がページに1回も無く圏外になる**型。

- 仕組み: `data/tournaments/index.json` の `searchLabel` / `searchAliases` / `searchNote` と
  `lib/tournamentSearchNames.ts`。データを足すだけで title / h1 / description / FAQ に反映される。
- 適用済み: インカレ（`zennihon-university`。`searchLabel`「全日本学生ソフトテニス選手権大会」＋alias「インカレ」）。
  王座決定戦は「インカレ」ではないので alias を付けない（`searchNote` で別大会と明記）。
- **適用済み: 全中**（2026-08-28）。`searchLabel`「全国中学校ソフトテニス大会」＋alias「全中」。
  狙いは「全中 歴代」。効果は2027年の会期（8月）前後に GSC で見る。
  選手ページの勲章・title 側（`nationalTitles.ts` の `shortLabel`「全国中学校大会」）には「全中」が出ない。
- 略称マスタが3つに分かれている（`tournamentSearchNames.ts` 冒頭）。高校大会の news 記事は
  `index.json` 側の略称が空なので「インターハイ」が title に出ない。
- **適用済み: 「オーダー」**（2026-09-19）。団体戦の出場ペアを出しているのに、画面の語は
  「対戦ごとの記録」「第N対戦」だけで **`src` / `lib` に「オーダー」が2件しか無かった**。
  対戦詳細の注記・description・FAQ に literal で置いた（#15）。大会名だけでなく**機能の呼び名**でも
  同じ型が起きる。
- 未着手: 内部リンクのアンカーテキストはほぼ正式名称のみ（「インカレ」0本）。展開するなら機械的な反復を避ける設計が要る。

## title の字数予算

- **大会ページ（対策済・監視）**: 汎用ハブは `{titleLeadName}{最新収録年} 結果・歴代優勝者`
  （年は前年以降のときだけ。ビルド年は `getStaticProps` で確定させ hydration mismatch を避ける）。
  年度別結果は `{titleLeadName}{年} {種目} {結果・組み合わせ}`。展望記事も `titleLeadName` を使う。
- **開催前の大会ハブ（対策済・監視）**: 結果が1年も無ければ `{titleLeadName}{年} 日程・会場・実施種目`。
  過去の結果があり次回が**会期前**なら `{titleLeadName}{次回年} 日程・会場｜歴代優勝者`、description の先頭に
  次回の会期・都道府県・会場。会期に入ると通常の title に戻る。年は information の年度
  （全日本インドアは「2026」で会期2027年2月。**Assumption**: 年の表記が検索語とずれうる）。
  高校全国大会の歴代ページには開催前ブロックが無い（未移植）。
- **選手ページ（対策済・監視）**: 全国優勝者は `composePlayerResultsTitle()`（`lib/nationalTitles.ts`）が
  **完成形の幅 32全角**で候補を上から試す。守る優先順は 選手名 ＞ 直近の優勝大会の通称 ＞「ソフトテニス」＞ 所属 ＞ 優勝総数。
  どれも入らなければ最短形（所属なし）。規則は `npm run player-title:test`（CI）。
  旧実装は実績フレーズだけを予算化しており、全国優勝者のほぼ全員が32全角を超えて Google に書き換えられていた。

## 計測の原則（2026-08-28 追加）

- **GSC に出ない＝需要が無い、ではない**。GSC は表示回数0のクエリを出さない。圏外かどうかは SERP を直接見る。
  エクスポートの絞り込み条件は数値と一緒に書く。
- **GSC の順位分布で「攻めるべきか」を判断しない**。表示済みのクエリに条件づけられた分布だから。
- **選手名クエリは「3位以内か圏外か」の二値**。無作為40件で掲載27.5%・圏外72.5%、掲載時は全件3位以内。
  成長の余地は圏外側にある。
- **圏外はインデックスの問題でもページの厚さの問題でもない**（掲載/圏外で試合数・HTML量・内部リンク数に差が無い）。
  「ページを厚くすれば順位が付く」を前提にしない。次に調べるのは被リンク等の外部要因。
- **選手名クエリは2つの母集団に割れる**: 本人資産（Wikipedia・公式 SNS 等）がある選手は上位が埋まり天井がある。
  無い選手は当サイトが最も構造化された情報源になれる。
- **棄却済み（再調査しない）**: 氏名の旧字体（廣/広 等）は Google が同一視する。所属名の表記ゆれも対象外の規模。
- **Google Trends は競技をまたぐ略称（全中・インカレ）に使えない**。完全に圏外の語の需要を見る補助としてだけ使い、
  「急上昇」は絶対量の根拠にしない。

## 構造化データの決めごと（`SportsEvent`）

共通ヘルパー `lib/sportsEventJsonLd.ts` に集約し、4箇所（年度別結果・大会ハブの歴代優勝者・試合詳細・STリーグ）で使う。

- 常に付ける: `eventStatus = EventScheduled` / `eventAttendanceMode = OfflineEventAttendanceMode` / `image`。
  `endDate` が無ければ `startDate` で補完。`location` は常に出し、最低限 `addressCountry: 'JP'` を含む。
- `performer` は**出演者が一意に定まるページだけ**（試合詳細・歴代優勝者）。年度別結果ページには付けず警告を許容する。
- **`offers` は付けない**（無料の結果ページにチケット情報を付けるのは実態とずれ、虚偽の構造化データは手動対策リスク）。

## sitemap 生成の運用

3つに分かれている。触るときは3つまとめて確認する。

1. `next-sitemap.config.js` — 列挙・`exclude`・`lastmod`・`additionalPaths`。**`outDir: 'out'` を明示**
   （理由は [deployment.md](./deployment.md#sitemap-の出力先2026-08-05-修正)）。
2. `scripts/sort-sitemaps.mjs` — loc 順に並べ、**同じ `<loc>` を1件にまとめる**（`<lastmod>` を持つ方を残す）。
   `additionalPaths` の明示追加は、自動列挙から漏れたときの保険として残す。
3. `scripts/filter-noindex-from-sitemap.mjs` — 生成 HTML を正として、(a) noindex、(b) canonical が自分以外、を除く。
   **判定はページ側に置き、ここは追従するだけ**。`/matches/*` をパスで一律に除外しないのは、
   野良試合では `/matches/<id>/` が正の URL だから。

## 新規ページ追加時の運用

新しいページ種別を足すときは、既存種別との重なりを重複マップに追記し、制御手段を1つ選んで書く。
noindex を選んだら内部リンク数を数える（「守ること」参照）。
