# UX Writing（UI文言ルール）

公開ページに出す日本語の書き方を1箇所に集約する。対象は **公開ページの UI**
（`src/pages/**`・`src/components/**` のうち `beta/` 配下を除く）と、そこから参照される
`lib/**` の文言定数。`/beta/**`（内部ツール・noindex）と `scripts/**`（CLI出力）は対象外。

表記の一部は eslint で機械的に強制している（絵文字禁止＝ [AGENTS.md](../../AGENTS.md)）。
それ以外は本ページを参照してレビューする。

関連: [public-pages.md](./public-pages.md) / [docs/ui/glossary.md](../ui/glossary.md)（用語の正）/
[seo.md](./seo.md)（title・description の文言方針）/
[tournament-insights.md](./tournament-insights.md)（インサイトの `scopeNote` もこのルールに従う）

策定の経緯と、監査時点で何がどれだけ壊れていたかは
[docs/raw/2026-09-02-ux-writing-audit.md](../raw/2026-09-02-ux-writing-audit.md)。

## 1. 文体

| 対象 | 文体 | 例 |
|------|------|-----|
| 本文・説明・注記・空状態 | です・ます | 収録している大会結果から検索できます。 |
| 見出し（h1〜h3） | 体言止め | 選手一覧・選手検索 |
| ボタン・リンク・タブ・バッジ・表のセル | 体言止め または 動詞 | 検索をクリア / 大会一覧を見る |

- **命令形（〜せよ・〜すること）は使わない**。依頼は「〜してください」。
- 空状態の次の行動は、可能なら**文ではなくボタン/リンク**で出す（[§5](#5-空状態)）。

## 2. 句点

- **文には句点をつける**。主語＋述語がある1文以上なら、短くても文。
- **見出し・ラベル・ボタン・タブ・バッジ・表のセル・統計値のキャプションには句点をつけない**。
- 空状態は文なので句点をつける（例: `該当する大会がありません。`）。

判断に迷ったら「読み上げたときに文として終わるか」で決める。

## 3. 記号

| 記号 | ルール |
|------|--------|
| 括弧 | 全角 `（）`。半角 `()` は**中身が英数字・記号のみ**のときだけ可（例: `STリーグ (I)`）。日本語が1文字でも入るなら全角 |
| 三点リーダ | `…`（U+2026）。ASCII の `...` は使わない |
| 中黒 | `・`。並列は `A・B・C` |
| 注記 | `※` の直後に**半角スペース1つ**（`※ 公式ランキングではありません。`） |
| 矢印 | `→`。装飾目的の矢印はリンクテキストに含めない（行き先は語で示す） |
| 絵文字 | 禁止（AGENTS.md「UI の表記ルール」・eslint 強制） |

## 4. 用語

**正は [docs/ui/glossary.md](../ui/glossary.md)**（approved・D-008）。UI にもそのまま適用する。
よく間違えるもの:

| 使う | 使わない | 備考 |
|------|----------|------|
| 選手 | プレイヤー, プレーヤー | glossary で使用禁止 |
| 記録試合 | マッチ, ベータ試合, スコア試合 | |
| 大会 / 大会年度 | 開催回 | |
| チーム | 学校, 実業団（エンティティ名として） | 文脈上の言い換えとしてはよい |

### 収録 と 掲載

同義に見えて混在していたので、以下で使い分ける。

- **収録** = サイトがデータとして持っている**範囲・母数**。
  「収録大会」「収録試合数」「当サイト収録の全国大会」「収録年度」
- **掲載** = そのページに**表示している／公開している**という行為・状態。
  「結果を掲載しています」「掲載中」「結果未掲載」「掲載を停止する」

集計の断り書き（母数の話）は必ず **収録** 側。共通文言は `lib/uiText.ts` に置く（[§6](#6-注記スコープの断り)）。

## 5. 空状態

**「無い」で終わらせない。** 次の3つを、この順で書く。

1. **状況** — 何が無いのか（`〜がありません。`）
2. **理由** — なぜ無いのか（データ未収録／条件に一致しない／これから起きる）
3. **次の行動** — ユーザーが今できること（リンク・ボタン。無ければ「いつ出るか」）

理由と次の行動は、状況より一段小さい文字（`text-xs text-text-muted`）で添える。

手本: [src/pages/players/index.tsx](../../src/pages/players/index.tsx) の検索0件
（一致しなかった旨 → 漢字登録という理由 → 語を減らす案内＋「検索をクリア」ボタン）。

助詞は **`〜がありません`** に統一する（`〜はありません` は対比の含みが出るため、
「他と違ってこれは無い」と言いたいときだけ）。

## 6. 注記（スコープの断り）

「当サイトが持っているデータの範囲での集計です」という断りは同じ意味で6通りに割れていたため、
`lib/uiText.ts` の定数を使う。直書きしない。

| 定数 | 用途 |
|------|------|
| `SCOPE_NOTE_SHORT` | バッジ・カード脇の最小注記 |
| `SCOPE_NOTE_MATCHES` | 試合データ由来の集計 |
| `SCOPE_NOTE_TOURNAMENTS` | 大会成績由来の集計 |
| `SCOPE_NOTE_RANKING` | ランキング（非公式・年度間比較不可を含む） |

代表選手の断り（`PLACEMENT_DISCLAIMER`）は `lib/qualifierFinishers.ts` のまま。

`lib/**` が算出して渡す `scopeNote`（`careerRecord` / `milestones` / `playerStats`）と、
`data/tournament-insights/**` の `scopeNote` も同じ使い分けに従う（文なので句点をつける）。
描画側で `※ ` を前置するので、`scopeNote` の文字列自体に `※` は入れない。

## 7. リンクテキスト

- **「こちら」単独をリンクにしない。** リンクテキストだけを読んで行き先が分かるようにする
  （スクリーンリーダーのリンク一覧は文脈なしで読み上げられる）。
- 「詳細を見る」のような一般語も避け、**何の詳細か**を入れる
  （例: 「成績を詳しく見る」→ [players-pages.md](./players-pages.md) の決定に準拠）。
- 本文で「このページ」を指すときは **「このページでは」**。「こちらは」と書かない。

| 使う | 使わない |
|------|----------|
| 大会一覧を見る | 過去の大会一覧はこちら |
| 選手一覧を見る | 掲載中の選手一覧はこちら |
| このページでは、… | こちらは、… |

## 8. 進行中・エラー

- 進行中: **`読み込み中…`**（`Loading...` は使わない）。何を読んでいるか言えるなら言う
  （`検索データを読み込んでいます…`）。保存中は `保存中…`。
- エラー: **何が起きたか＋次にできること**。原因だけで終わらせない。
  例: `削除に失敗しました。` → `削除できませんでした。通信状況を確認して、もう一度お試しください。`

## 対象外

- `/beta/**`: 内部ツール（noindex・開発サーバー限定）。`alert()` での通知や `Loading...`、
  用語「マッチ」が残っているが、公開面ではないため本ルールの適用対象外とする（2026-09-02 時点）。
- `scripts/**`: CLI 出力。人が一度読むだけのため対象外（AGENTS.md と同じ線引き）。
  ただし公開ページに出る文字列を**生成する**箇所は例外で、本ルールに従う
  （例: `scripts/generate-story-yaml.mjs` の `scopeNote` テンプレ）。
