## 試合で分かったこと（試合詳細ページの上段）

試合詳細ページの一番上に、その試合の事実を**最大3行の文**で出す。見せたいのはスコアの一覧ではなく
「データから分かること」だから（決定の経緯は [raw/2026-09-27-idea-match-detail-charts.md](../raw/2026-09-27-idea-match-detail-charts.md)）。
実装は `lib/matchAnalysis/matchFindings.ts`（`buildMatchFindings`）、テストは `npm run match-findings:test`。

- 文は**事実だけ**。「強い」「崩れた」などの評価語は使わない。数は件数で出す。
- 優先の高い順に最大3行。どれにも当たらなければブロックごと出さない（ポイントの並びだけ出す）。
- スコアの再構築が既存スコアと食い違う試合（`scoreIntegrity.ok = false`）では出さない。
- 場面がある文には「その場面を見る」を付け、そのポイントへ移動して動画を再生する。

| 優先 | 種類 | 条件 | 移動先 |
|---|---|---|---|
| 1 | 逆転 | 勝った側がゲームカウントで**2ゲーム差以上**負けていた | 最大差になった直後のゲームの1本目 |
| 1 | もつれた試合 | 逆転に当たらず、ファイナルゲーム（7点先取）まで行った | ファイナルゲームの1本目 |
| 2 | デュース | デュースになったゲームが**2つ以上**あり、片方が**全部**取った | 最初のデュースの1本 |
| 3 | 連続得点 | ゲームをまたいで**6連続以上**（最長の1つ） | 連続の1本目 |
| 4 | 決め球の差 | 自分で決めた点（`WINNER_RESULT_TYPES`）の差が**5点以上** | なし |
| 4 | ミスの差 | ミスで失った点（`ERROR_RESULT_TYPES`）の差が**5点以上** | なし |
| 5 | ラリーの長さ | ある区切り（1-2 / 3-4 / 5-8 / 9本以上）で**8本以上**あり、片方が**75%以上**取った（最も偏った1つ） | なし |

同じ優先の中は表の上から。連続得点は5点だと27試合中23試合で出て珍しくないので6点にした（2026-09-27）。

その下に**ポイントの並び**（`src/components/matches/MatchFlowChart.tsx`）を置く。1ゲーム1行で、1本ごとに取った側の色の四角を左から並べ、
行の右にゲームスコアを出す。先行・連続得点・デュースの長さを色の並びで読む。

- 行そのものがボタンで、押すと下の「試合の流れ」でそのゲームを開く（押す単位はゲーム。四角は小さく指では押し分けられない）。
- 長いゲームは**折り返して2行**にする（例: 24本のデュースゲームは幅360pxに収まらない）。
- 四角にマウスを載せると、その1本の内容（スコア・取った側・決まり方・ラリー数）を下に出す。
- 棄却: 試合全体の累計の点差の折れ線（負けた側が総得点で上回ることがあり、27試合中1試合、「リード」と読めてしまう）／
  ゲームごとに0へ戻す折れ線（線が途切れて読みにくい）／ゲームごとの小さなグラフ（9ゲームだとスマホで小さすぎる）／
  1本ごとの上下の棒（1本の幅が3〜4pxで細すぎる）。

### 上段の並びと重なりの整理

上段は「試合結果 → この試合で分かったこと → ゲームスコア → ポイントの並び → 見どころの場面」の順。

- **ゲームスコア**（`src/components/matches/GameScoreboard.tsx`）は、どのゲームを誰が取り、何ゲーム取って勝ったかを読む表。
  チーム×ゲームで、右端に取ったゲーム数（計）。取った側のマスはチームの色＋太字。名前は名字だけ・列幅固定で、9ゲームでもスマホ幅に収める。
- **ポイントの並び**はゲームの中の流れだけを受け持ち、行にスコアを出さない（スコアは上の表）。
  - 棄却: 表を消して並びの行の右にスコアを出す形（2026-09-27 に一度採用）。「4-2」がどちらの得点か、どちらがゲームを取ったかが分かりにくかった。
- **見どころの場面**: 名場面（[rare-events.md](./rare-events.md)、サイト内で希少な1本）と勝敗を分けた局面候補（`decisiveMoments`）を1つの一覧にまとめる。
  - 同じ1本が重なれば名場面を残す。「この試合で分かったこと」の「その場面を見る」と同じ1本は一覧から外す。
  - 名場面は種類名のタグ（黄）、局面候補は「勝敗の分かれ目」のタグ（灰）。名場面の行は「第Nゲーム #n」を付ける（同じ種類が複数あると区別できないため）。

### 下段のグラフ

「得点・失点の内訳」（決定打／相手ミス等の件数の縦並び）を置き換えた。集計は `lib/matchAnalysis/matchCharts.ts`。

- **決め球とミス**（`PointSourceChart`）: 左右に分かれた横棒。**左はチームA、右はチームBが自分でしたこと**を並べる。
  上段は自分で決めた点（決まり方別）、下段はミスで失った点（**自分のミスの種類別**）。行の並びは固定順（件数順にしない）で、0件の種類は出さない。
  左右の合計はそのチームの得点ではない（上段は得点、下段は失点）。
  - 棄却: 下段を「相手のミスでもらった点」（得点した側に、相手のミスの種類で数える）にする形。左側に相手のミスが並び、誰のミスか分かりにくかった。
- **ラリーの長さ別**（`RallyLengthChart`）: 1〜2本 / 3〜4本 / 5〜8本 / 9本以上 の区切りごとに、どちらが取ったかを100%の横棒で出す。
  **8本未満の区切りは「参考程度」と添える**。ダブルフォルトなどラリーの本数に入らない点は別に件数だけ出す。
- 数は棒の外に必ず文字で出す（色だけに頼らない）。

## 生成と更新タイミング

成長分析レポートは閲覧時計算ではなく、**ビルド時に静的 JSON として書き出される**。

- `package.json` の `prebuild` → `scripts/generate-beta-matches-json.mjs` が
  Supabase から `matches` を全件取得し、`buildGrowthReports()` の結果を
  `public/data/beta-matches/growth/reports/*.json` と `growth/targets.json` に出力する
- したがって試合を入力しても、**次のビルドまで成長分析には反映されない**
- 検証用の単体実行は `npm run check:growth`（`scripts/check-growth-analysis.mjs`）
- Supabase の環境変数が無い環境では、既存スナップショットから再生成にフォールバックする

公開対象 match の抽出条件は「`matches` テーブルの全件」。ステータスによる絞り込みは無く、
公開に出さない情報は `toPublicMatchSnapshot()` の**列レベルの間引き**で落としている。

## 責務境界（`matchAnalysis` と `growthAnalysis`）

- `lib/matchAnalysis/` … **1試合の中**を見る。チーム A / B の対比、局面別レート、
  流れ（streak）、ラリー傾向。試合詳細ページ向け
- `lib/growthAnalysis/` … **複数試合をまたぐ**。選手/ペアを target とし、期間・勝敗・
  相手などの条件で current / previous を比較する。成長分析ページ向け
- 両者は `lib/matchRules.ts`（先取点・2点差）を共通の土台にする

（正式定義として文書化するかは Open Question のままだったが、実装側で
`lib/growthAnalysis/index.ts` の冒頭コメントに分割意図が書かれており、上記はその要約。）

- **ラリーの区切りは両者で同じ**（1〜2 / 3〜4 / 5〜8 / 9本以上）。`growthAnalysis` は `matchAnalysis` の `getRallyBucket` を使う。
  以前は成長分析だけ 1-2 / 3-5 / 6本以上で、試合詳細と数字を見比べられなかった（2026-09-27 にそろえた）。

## 成長記録の表示（`/growth/[slug]` と `/matches/growth` で共通）

表示部品は `src/components/growth/GrowthReportView.tsx`、節の組み立ては `lib/growthAnalysis/comparisons.ts` の `buildSections`。

**「最近の成長」の比べ方**（`getRecentPeriodComparison`、2026-09-27 にユーザー確認のうえ変更）:

| 記録した試合数 | 比べ方 |
|---|---|
| 2〜5試合 | **最新の1試合** と **それ以前の全試合をまとめた値** |
| 6〜9試合 | 直近3試合 と その前の3試合 |
| 10試合以上 | 直近5試合 と その前の5試合 |

- 5試合までを「最新 vs それ以前」にしたのは、記録を全部使い「今回はいつもと比べてどうか」を見るため。同じ相手・同じ大会などの比較と同じ考え方。
- 棄却: 5試合まで「直近1試合 vs その前の1試合」（以前の方式）。相手の強さだけで数字が大きく動き、3〜5試合あっても古い試合を使っていなかった。
  当時の比較が出る11対象のうち9がこの方式だった。

- **比べているものを上に1回だけ書く**（`ComparisonBasis`）: 「前の期間（灰の点）→ 今の期間（青の点）」と試合数、比較の説明。
  どちらかが2試合以下なら「数字は参考値です」と添える。各行には「参考値」を付けない（件数不足の行だけ「データ不足」）。
- **節**: まとめ → サーブとレシーブ → 重要局面 → 流れ（連続失点）→ ラリーの長さ別 → 練習テーマ。**各指標は1回だけ出す**。
  「まとめ」は数字を持たず、伸びた指標と次に見ておきたい指標を**名前だけ**2つずつ挙げる（数字は各行にあるので繰り返さない）。
  他の比較（勝ち負け・同じ相手など）の文も同じく名前だけ。
- **1指標1行**: 名前 ／ 前 → 今 ／ 差。率の指標は下に前後の2点を結ぶ線を引く（0〜100%）。回数の指標は線なし。
- 棄却: 1指標を「名前・説明文・今回・比較・差」で縦に積む形（スマホで約10画面、同じ数字を1行に2回・ページで最大3回出していた）／
  「最近の成長」「改善トラッキング」の節（下の分類別の節と同じ指標を繰り返していた）。
