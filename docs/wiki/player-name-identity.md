選手を氏名で一意に識別するための仕組みと運用。チーム側（表記ゆれ・統合の判断）は
[team-player-identity.md](./team-player-identity.md)。

## 姓名の分割ゆれ `data/players/name-split-aliases.json`

大会 PDF では氏名が1つの文字列で現れ境目は推定になるので、取り込みごとに切り位置がぶれる。
**実害**: 選手 id の解決は `姓::名` の完全一致なので、割れると1人の戦績が2つの id に分かれ、
`count>=5`（結果ページ生成の閾値）を**両方とも下回って結果ページが消える**（壊れ方は「2ページに分裂」ではなく「片方が沈む」）。

1. **検出** `scripts/check-name-splits.mjs`（`temp/` は除外。**`--strict` で prebuild のゲート**）。検出器は3つ:
   - **A 分割衝突**: 同じ氏名が2通りの切り方で同居。確実だが**2通り無ければ気づけない**
     （1シリーズの大会にしか出ない氏名が全体の64%）。
   - **B 辞書照合**: 現在の切り方の片側がコーパスに1例も無く、別の切り位置なら両方に実例がある氏名。
     **1度しか出ない氏名にも効く**ので新規取り込み直後はこちらが主役。ヒューリスティックなので `--strict` のときだけ落とす。
   - **C 既知の誤分割の再混入**: 表で誤りと決めた綴りがデータに入っている。**A も B も人が判断済みの氏名は見ない**ので、
     一度直した誤りが1件だけ戻った状態は C が無いと誰も検出できない。常にエラー。
2. **判断**（人手）→ `{ canonical: [姓, 名], aliases: [[誤った姓, 誤った名], …], reason }` を蓄積。
3. **適用** `scripts/normalize-name-splits.mjs`（冪等・`--dry-run` 可）: `participants[]` の姓名・`id`・
   `playerIds` / `pair`、団体戦の対戦ごとの記録（`matches[].matches[].playersA/B`）を書き換える。
   **`lastName` と `firstName` は隣接ペアとしてまとめてマッチさせる**（姓だけ一致する別人への誤爆を構造的に防ぐ）。
   続けて該当氏名の `count` だけを数え直し、`count>=5` を跨いだ選手を報告する。

判断の物差し:

- **多数決は誤る**（1回の取り込みが複数ファイルに分かれると件数は簡単に水増しされる）。見るのは**出典の系列数**。
- **姓の頻度・名の頻度は単独では逆の結論を出す**（右にずらした誤りは「存在しない姓＋よくある名」、
  左にずらした誤りは「よくある姓＋存在しない名」を作る）。必ず両方を見て、**別解が存在するか**まで確かめる。
- いちばん強いのは**別人による姓の裏づけ**。次に「もう一方が日本語の氏名として成立しない」こと。
- **裏づけが1件しかない別解は、その1件自体が壊れていないかを確かめる**（壊れたデータは自分の誤りの裏づけを作る）。
- 辞書は `details` の `participants` からだけ作る（`index.json` は誤分割側が `count: 0` で残るため、混ぜると誤りを学習する）。

注意:

- **`data/players/index.json` を `extract-players.mjs` で丸ごと再生成しない**。閾値未満の名前まで一気に採番され、
  対象は取り込みが進むほど増える。`normalize-name-splits.mjs` が該当名の `count` だけ更新するのでそちらを使う。
- **分割を直したときの index 行は「改名」でよい**（正しい分割の行がまだ無ければ、誤分割の行の姓名を書き換えて
  `count` を数え直す＝id を保てる。既にあるなら重複するので消すか `count: 0` で残す）。
  1行1エントリの整形を崩さないよう**文字列置換**で直す。
- `details/**/highschool-*` を書き換えたら `npm run highschool:pipeline` の再実行が要る。
- **ペアの境界ずれ**（`林楓|恋荒` ＋ `川|琴美` → `林|楓恋` ＋ `荒川|琴美`）は alias 表では表現できず、
  **検出器 A / B のどちらにも掛からない**。一回限りの修復スクリプトで直す。他に残っているかは不明。
- 分割を直すと**2人が1つの id に統合されてしまう**ことがある。切り位置の正しさと同一人物かは別問題なので、
  疑わしいものは直さず保留して [open-questions.md](./open-questions.md) に残す。

## 選手の登録名変更（改名）— 設計のみ・未実装

同一人物が**登録名そのものを変えている**ケース。`homonyms.json`（別人の記録）・`name-split-aliases.json`
（切り位置。**文字が変わる改名は assert を通せない**）・`team-name-aliases.json`（チーム専用）のどれでも扱えない。

決めたこと: ①対応表 `data/players/player-name-aliases.json` を新設し **`scope` を必須にする**
（人名は「別の場所に居る同名の別人」に当たる確率が高い）②**アプリ層ではなくデータ本体を書き換える**
（姓名で人を引く箇所が独立に5系統あり、1箇所直しても残りが割れる）③**正準は現行の登録名**に寄せ、
旧名は alias に残す（公開面では `information.json` の `formerNames` で併記）。

**検出は自動化できない**（同音異字＋所属・県・年がすべて変わると D/E/F は原理的に引っかからない）。
対応表の価値は「見つける」ことではなく**一度分かった判断を全系統へ効かせる**こと。残タスクは [open-questions.md](./open-questions.md)。

## 選手の別人判定 `data/players/homonyms.json`

基本は氏名ベース id（team 非依存）で、**同姓同名の別人だけ**分割する。生成は `scripts/build-player-homonyms.py`。
**別人とみなす根拠**（いずれか1つでも成立すれば登録）:

- **D**: 同一年に**非隣接の学校段階**が共存（小↔高 等＝物理的に不可能）。隣接段階（中3→高1）は同一人物として除外。
- **E**: **出生年の許容レンジが交差しない**（`generationId` ＋ `categoryId` の age 部から1観測ごとにレンジを引く）。
  レンジは**わざと広め**に取る（＝矛盾しにくい＝過小検出側）。
- **F**: **同一大会・同一年に異なる都道府県で出現**（1人が同じ大会で2県を代表することは不可能）。
  所属校名は略称ゆれがあるため**県のみ**で判定する。

- どの検出器が発火したかは `detectors` に残る。**識別キーはチーム**（1人＝氏名＋チーム集合）で、
  同一チーム／共通の相棒／段階進行で同一人物へ寄せ、衝突は別人。曖昧なものは `needsReview: true`。
- 名（`firstName`）が空の participant は「姓だけの一致」で根拠にならないため除外し、氏名分割の不備として別途報告する。
- **検出数は常に下限**。**同世代かつ同一都道府県の同姓同名**は D/E/F すべての盲点で原理的に検出できない。
- **`homonyms.json` への登録は「危険な名前の記録」であって id の分割ではない**。
  登録すると選手ページに「同姓同名の別選手の成績が含まれている可能性があります」の警告が出るようになるだけで、
  戦績は1つの id に融合したまま（アプリの選手解決へ統合する実装は残課題）。

## チームの年度別メンバー（pid の重複）

`generateTeamInfo()` の `players` は生の `participant.id`（`姓_名_チーム_都道府県`）をキーにするが、
県サフィックスや所属表記の揺れで**同一人物が複数の pid 変種として重複する**。
チームページの年度別メンバー（`buildTeamRosterByYearGender()`）は `normalizeJa(姓+名)` で dedup する。

- `results[].playerIds` / `matches[].pair` は**エントリー全員**の pid（他チームの相方を含む）。
  必ず `generateTeamInfo().players` の集合で交差を取る。
- 団体戦では pid が選手ではなくチームを指し氏名が `null` になるので、メンバー一覧から除外する。
- 同一年度・同一チームの本物の同姓同名は dedup で1人に潰れる（D/E/F は個人選手ページ向けで、名簿には適用していない）。
