# ADR-018: Cookie 同意を地域で分け、日本は公表ベース（バナー非表示）にする

## Status

Accepted

## Context

本サイトは GA4（Consent Mode v2）と AdSense を使っており、これまで**全ユーザーに**
Cookie 同意バナー（`src/components/CookieConsent.tsx`）を出し、`consent default` は
`ad_storage` / `analytics_storage` とも denied にしていた。

この運用には、実測上の問題があった。

- 同意しないユーザーが相当数いる。未同意でも cookieless ping でイベント自体は GA4 に届くが、
  `client_id` が安定しないため**セッション系の指標が読めない**（セッションあたりの表示回数、
  回遊の連鎖、直帰）。
- この制約は既に複数の検討をブロックしていた。[回遊検証ランブック](../wiki/circulation-verification.md)
  は主指標をセッション系ではなくイベント比（モジュールCTR）に置かざるを得ず、
  [public-pages.md](../wiki/public-pages.md) の「ユーザーの課題を体系的に見つける」でも
  「観測できないもの」としてセッション単位の指標が挙がっていた。
- 訪問者の大半は日本からである。

一方、日本ではオプトイン同意は法令上の要件ではない。

- **個人情報保護法**: Cookie 等の端末識別子は「個人関連情報」で、それ自体は個人情報ではない。
  自社サイトの分析目的で使う限り、本人のオプトイン同意は求められていない。
- **電気通信事業法の外部送信規律**（2023-06-16 施行、第27条の12）: 「同意 / オプトアウトの
  機会提供 / 通知・公表」の**いずれか**で足りる。オプトイン同意は必須ではない。

つまり、全ユーザーに同じバナーを出していたのは、最も厳しい地域（EEA/UK）の要件を
全地域に一律適用していたためであり、日本のユーザーに対しては過剰だった。

## Decision

**同意の扱いを地域で分ける。日本からのアクセスはバナーを出さず、プライバシーポリシーでの
公表をもって解析・広告 Cookie を利用する。EEA / 英国 / スイスは従来どおり事前同意を求める。**

1. **免除範囲は日本のみ**。米国その他も理屈上は同意不要だが、地域ごとの検討（LGPD 等）が
   必要になるため広げない。判定を外したときの影響範囲も小さく保つ。
2. **日本では `ad_storage` / `analytics_storage` の両方を granted** にする。日本では広告
   Cookie もオプトイン同意の対象ではなく、主収益である AdSense のパーソナライズド広告を
   止める理由がない。
3. **過去に「拒否する」を押した人の選択は地域に関わらず優先する**。免除地域でも
   `localStorage.cookieConsent === 'false'` なら denied のまま。法的要件ではないが、
   一度示された意思を後から覆すのは筋が悪い。
4. **地域判定は端末のタイムゾーンで行う**（`Asia/Tokyo` なら免除）。判定と根拠は
   `lib/consentRegion.ts` に集約する。
5. **`src/pages/privacy.tsx` に外部送信規律に基づく公表を置く**。バナー非表示は
   この公表とセットでのみ成立する。片方だけ変えてはならない。

## Alternatives

- **Cloudflare の国判定（`/cdn-cgi/trace` の fetch）**: 正確だが**非同期**で、初回
  `page_view` より前に同意状態を確定できない。「同意済みでも初回PVだけ denied 計測」という、
  以前 inline スクリプトでわざわざ潰した問題が再発する。
- **Cloudflare Pages Functions の `_middleware` で国別に出し分け**: サーバ側で確定できるが、
  静的書き出し（`out/`）の全 HTML を Worker 経由にすることになり、キャッシュとコストの
  前提が変わる。得られる精度に対して代償が大きい。
- **`navigator.language === 'ja'` で判定**: EEA 在住の日本語話者を免除してしまう。GDPR の
  適用は所在地で決まるので、言語は判定軸として誤っている。
- **現状維持（全員にバナー）**: 日本のユーザーに過剰な負担をかけ続け、セッション系指標が
  読めない状態も続く。

採用したタイムゾーン判定は精度で劣るが、**外れ方が安全側に倒れる**ことを重視した。
日本在住でも端末が `Asia/Tokyo` でなければバナーが出る（＝従来どおり）だけで、
EEA 在住者の端末が `Asia/Tokyo` になっていることは実質起こらない。

検討の詳細は [raw/2026-09-09-consent-banner-japan-exemption.md](../raw/2026-09-09-consent-banner-japan-exemption.md)。

## Consequences

- 日本からのアクセスでセッション系の GA4 指標が読めるようになる。回遊検証・ユーザー課題発見の
  両方で「観測できない」としていた制約が外れる。
- **同意率（`consent_accept` / `consent_decline`）の分母が変わる**。日本では両イベントとも
  発生しなくなるため、以後の同意率は「非免除地域で、かつバナーを操作した人の中での比率」になる。
  回遊検証のベースラインは、この変更の**後**に取る必要がある。前後のデータを混ぜない。
- プライバシーポリシーが法令対応の一部になる。送信先サービスを増減させたときは
  `EXTERNAL_TRANSMISSIONS`（`src/pages/privacy.tsx`）の更新が必須になる。
