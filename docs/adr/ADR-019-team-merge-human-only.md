# ADR-019: チーム名寄せの自動統合を廃止し、人が判断したものだけを適用する

## Status

Accepted

決定日: 2026-09-12（ADR 化は 2026-09-17）。現状仕様: `docs/wiki/team-player-identity.md`
「既定グループ分けの規則」「判断台帳のキーと、判断の引き継ぎ」。

## Context

チーム名寄せ（表記揺れの統合）は、次の2本の経路で alias 表へ反映されていた。

1. **機械の自動統合**: `apply-auto-merges.mjs` が、候補クラスタのうち
   「同一大会に同居していない」ものを自動OKとみなし、人の確認なしに alias 表へ書き込む
2. **人の判断**: レビュー画面（`npm run team:review`）で人が同一/別を決め、判断台帳
   （`data/teams/review-decisions.json`）に記録して反映する

2026-09-06〜11 には、この自動統合の誤り率を**抜き取り監査**で測る仕組みを作っていた
（[raw/2026-09-06-idea-autonomous-improvement-agent.md](../raw/2026-09-06-idea-autonomous-improvement-agent.md)）。
2026-09-12 に初回の抜き取りを回そうとして、前提が2つ崩れた。

- **母集団が成立しない。** 2026-09-06 以降に新しく自動OKになったクラスタは1件だけだった。
  抜き取り検査は、流入が多く全数を見ると高くつく場所でしか意味がない
- **自動OKは半分以上外れていた。** すでに機械だけで統合された49件から20件を無作為に選んで
  人が点検したところ、誤統合が11件（55.0%・95%区間 34.2〜74.2%）。残り22件も全数を点検し、
  通算で **24/42（57.1%・95%区間 42.2〜70.9%）**。自動OKは「機械にとって確信度の高い側」だった

誤統合の原因の一つは、既定のグループ分けが段階（小・中・高・クラブ）を
**出場大会のジャンルから先に推定し、名前は後回し**にしていたことだった
（`仙北STC` が「中学の大会にしか出ていない」ために中学校と同じ段階とされた）。
ただし規則を直しても、残る誤りの多くは規則では判定できない型
（`佐賀クラブ ← 佐賀ジュニア` は別、`淡路クラブ ← 淡路ジュニアクラブ` は同一）だった。

## Decision

1. **機械による自動統合を廃止する。** `apply-auto-merges.mjs` は、判断台帳に
   `decidedBy:"human"` かつ `verdict:"merge"` として記録された判断だけを alias 表へ反映する。
   機械の判定（`proposedAutoOK`）は、レビュー画面の初期表示と並び順にだけ使う
2. **チーム名寄せの抜き取り監査はやめ、全件を人がレビューする。** 抜き取り監査の仕組みは、
   流入の多い PDF 取り込みへ移す
3. **既定のグループ分けでは、名前から読める段階を出場大会のジャンルより優先する**
   （`level(name) ?? memGenre(member, context)`）。人が示した規則
   （小・中・高は同時に存在しない／「学校」とクラブは別／正式名称と略称は同一でよい）は
   `scripts/lib/team-grouping.test.mjs` に固定し、CI のゲートで回す
4. **判断台帳の不変条件はサーバ側で守る。** 中身が同じ再送信は記録しない。人の判断を
   機械の判断で上書きしない（human → auto の巻き戻しは拒否）
5. **誤って適用した統合は git 履歴から戻す**（`scripts/undo-team-merge.mjs`）。details の表記・
   alias 表・判断台帳の3つを必ず一緒に戻す

## Alternatives

- **自動統合を残し、抜き取り監査で誤り率を見張る（2026-09-06〜11 の方針）**: 母集団が1件で
  監査が成り立たない。しかも実測の誤り率が57%で、「見張れば使える」水準ではない。不採用
- **自動OKの条件を厳しくして自動統合を残す**: 残った誤りの多くは規則で判定できない型で、
  条件を厳しくしても外れる。現在の流入量なら全件を人が見るほうが安く、正確。不採用
- **規則（名前の段階の優先）だけ直して自動統合を続ける**: 規則で止まる型は第1回の点検で直したが、
  第2回の22件のうち19件は規則では判定できない型だった。不採用

## Consequences

- 利点: データが壊れる方向（誤統合）は、すべて人の確認を通る。2026-09-12 時点で台帳の
  `auto/merge` は0件（human/merge 154・human/separate 154・auto/separate 293）
- 利点: 人が「別チーム」と決めたものが、クラスタの顔ぶれの変化で再統合される事故を防げる
  （`findDecision()` による判断の引き継ぎと合わせて。実測で2件が該当していた）
- 欠点: 新しい候補は、人がレビューするまで統合されない。表記揺れが画面に残る期間が延びる
- 欠点: 残る事故の余地は、レビュー画面で中身を見ずに「確認済を反映」を押すこと。
  画面は機械の既定グループ分けを初期表示する
- 影響: `check-identity-health.mjs` の推奨手順は `apply-auto-merges.mjs` から
  `npm run team:review` に変わった
- 影響: `auto/separate` の293件（統合し損ねている方向＝安全側）は未確認のまま残る。
  全数は多いので、抜き取りが効くのはこちら
- 影響: [ADR-017](./ADR-017-team-merge-signal-player-overlap.md) の「選手共有シグナルは自動OKにしない」は、
  自動統合そのものが無くなったので、全シグナルに当てはまるようになった（シグナル自体は現役）
