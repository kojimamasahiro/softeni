# ADR-017: チーム名寄せの候補検出に「選手共有」シグナルを足す

## Status

Accepted。決定日: 2026-09-05。現状仕様: `docs/wiki/team-player-identity.md`「チーム名寄せの運用」。

## Context

チーム名の表記揺れ検出は、導入以来ずっと**名前の類似度**という単一のシグナルに乗っていた
（`scripts/lib/team-core.mjs`: 接尾辞を落としたコアの完全一致、県内ブロッキング）。
この設計は接尾辞の有無（`東北` / `東北高校`）や異体字（`米子松陰` / `米子松蔭`）には効くが、
**語中の文字が落ちる内部略称は原理的に拾えない**。

```
岡山理大附      -> コア: 岡山理大附
岡山理科大附高校 -> コア: 岡山理科大附     「科」1文字差で永久に不一致
```

この具体例は `docs/wiki/team-player-identity.md` の「既知の残課題」に
**手動残務として明記されたまま放置**されていた。`check-identity-health.mjs` も同じコアを使うため
「検出できないもの（信号が無い）」と自ら注記しており、気づくのは常に偶然だった。

実際 `岡山理大附`(187件) と `岡山理科大附高校`(11件) は、alias 表に**別々の canonical として
2本登録**されており（しかも正式名 `岡山理科大学附属高校` は前者の alias 側に入っていた）、
canonical 同士は統合されないので、どれだけ候補生成を回しても一生ペアにならない状態だった。

一方で、この2つが同一校であることを示す証拠はデータ内に十分あった:
旧 canonical 名義の8名中7名が `岡山理大附` 名義でも出場し、うち3名は**同一年度に両表記へ併存**する
（佐藤蒼真: 2025インターハイ「岡山理大附」/ 2025全日本ジュニア「岡山理科大附高校」）。
つまり**名前を一切見なくても、選手の重なりから同一性が言える**。

### このシグナル自体は repo 内に既にあった（ただし別パイプラインに閉じていた）

`scripts/highschool/03list/summary.py` は、まさに同じ規則（同年・同姓同名が別チーム名で出たら
同一校とみなす。同一大会内の同姓同名は除外）で `inferred-team-aliases.json` を生成しており、
**`岡山理大附 ← 岡山理科大附高校` はそこに証拠つきで既に載っていた**
（2016 上松俊貴・2016 本倉健太郎・2025 石灘蒼瑛）。

にもかかわらず本体の名寄せが直らなかったのは、この出力が

- 高校ページ（`/highschool/**`）の生成にしか使われず、`team-name-aliases.json` へ**還流しない**
- 高校カテゴリの大会しか見ないので、社会人・小学生の揺れは範囲外

だったから。`docs/wiki/open-questions.md`「高校カテゴリ」でも
「誤結合を許容した暫定運用」と位置づけられていた。
**シグナルの有効性は実証済みで、足りなかったのは適用範囲と還流経路**である、というのが今回の判断の前提。

## Decision

**「同一年度に、同じ氏名の選手が2チーム以上に出場している」を第2のマージ候補シグナルとして
採用する**（`scripts/lib/team-player-overlap.mjs`）。名前の類似度は一切使わない。

- なぜ「同一年度」か: 実在する別チームなら、進学・転校であっても同一年度に両方へ在籍することはない。
  同年共起は「表記揺れ」か「同姓同名の別人」のどちらかに絞られる。
- 同姓同名の混入を抑えるため **共有選手2名以上**を要求する（`MIN_SHARED_PLAYERS`）。
- 既存と同じ**県ブロッキング**（両者の prefecture が非 null かつ一致）を掛ける。
  大学・連盟系は prefecture が null になるため対象外。
- コアが一致するペアは既存シグナルの担当なので**除外**（二重計上しない）。
- 連結成分でクラスタ化する（`白鷗大足利` のように6表記へ割れているものを1件として扱う）。

**このシグナルのクラスタは自動マージしない**（`signal: "players"` は `apply-auto-merges.mjs` と
レビューHTMLの両方で常に `autoOK = false`）。既存の自動OK判定は「同一大会に同居しなければ自動OK」
だが、これは**名前が似ているという裏付けがある前提**の判定であり、名前を見ないシグナルには使えない。
実際、このシグナルの偽陽性は「同年に同じ選手が両方へ登録される別チーム」
（小学生の `大館ジュニア` と `大館市協会`、社会人の `兼六クラブ` と `能登町役場` 等）で、
大会同居の有無では切り分けられない。

`merge-candidates.json` の各クラスタは `signal`（`"core"` | `"players"`）を持ち、
レビューHTMLの見出しには `core: ...` の代わりに共有選手名と年が出る。

## Alternatives

- **部分列一致・編集距離でコア一致を緩める**: `鹿児島実` / `鹿児島商`、`岡山理大附` / `理大OB` のような
  別チームを誤結合する。既に wiki で「誤爆のため不採用」と結論済み。不採用
- **共有1名で候補にする**: 同姓同名の偶然が大量に混ざる。2名要求で実データ 618ペア → 104クラスタに絞れる。不採用
- **同年共起を条件にせず、単に選手が重なるペアを挙げる**: 中学→高校の進学で選手は当然重なるので、
  正常な別チームが大量に挙がる。同年条件がこのシグナルの核心。不採用
- **`alias` 表に「同一 canonical が2本ある」検出だけを足す**: 今回の1件は防げるが、
  そもそも2本登録される前の「候補に挙がらない」問題が残る。不採用（対症療法）

## Consequences

- 利点: 名前の類似度を使わないので、コア一致の盲点（語中の脱落・語順違い・全く別の略し方）に届く。
  初回実行で **104クラスタ / 216チーム**が新規に候補として挙がった。上位は
  `白鷗大足利`（6表記・共有27名）、`浜松商` / `浜松商業高校`（共有17名）、
  `北科大` / `北海道科学大学高校`（共有16名）など、いずれも実在の同一校。
- 104件のうち **55件は `inferred-team-aliases.json` に既出**（＝高校パイプラインは知っていたが
  本体へ還流していなかったもの）、**49件は新規**。新規側は高校カテゴリ外が中心で、
  `東大阪市ソフトテニス協会` / `東大阪市協会`、`Astemo` / `日立Astemo`、
  `堺市スポ少` / `堺市テニススポーツ少年団` のような社会人・小学生の揺れが並ぶ。
- **副産物: 表記揺れではなくデータ破損が見つかる**。
  `きのくに信用金庫` / `きのくに宿用金庫` / `きのくに用金庫`、
  `岩見沢市立光陵中学校` / `岩見沢光陵中学校拠` は取り込み時の誤字で、
  名寄せではなく元データの修正が要る。選手共有シグナルは
  「名前が似ていない」ケースを拾うので、この種の破損を掬い上げる副作用がある。
- 影響: ヘルスチェックの要対応シグナル合計が **201 → 305** に増える。これは品質低下ではなく
  **今まで見えていなかった残務が可視化された**もの。104件は人手レビュー待ちのバックログとして扱う。
- 影響: `findPlayerOverlapPairs` は `data/tournaments/details` を全走査する。
  候補生成とヘルスチェックがそれぞれ1回走査する（既存もヘルスチェック側で走査済み）。
- 監視: 新データ取り込み後にこの件数が跳ねたら、その大会の表記が既存 canonical と揃っていない合図。
- 限界: **同年に両表記へ出た選手が1人も居ない表記揺れは、依然どちらのシグナルにも掛からない**。
  検出数は下限であり、この点はヘルスチェックの注記にも明示した。

## Open Questions

- `scripts/highschool/03list/inferred-team-aliases.json` と本シグナルは**同じ規則の二重実装**になった。
  高校パイプライン側を本シグナルの出力に寄せるか、逆に還流経路だけ作るか（現状は放置＝二重管理）。
- 県ブロッキングを外すか。大学・実業団は prefecture が null なので現状このシグナルの対象外だが、
  `CROSSTYHOLDING` / `CROSSTYHOLDINGS` のように県が付くケースは拾えている。
- 104件のレビューをどう回すか（バッチで潰すか、新データ取り込みのたびに少しずつか）。
