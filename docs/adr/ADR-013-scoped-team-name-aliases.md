# ADR-013: チーム名 alias に大会スコープ（scope）を導入する

## Status

Accepted。決定日: 2026-08-12。現状仕様: `docs/wiki/team-player-identity.md`「チーム名寄せの運用」。

`data/tournaments/team-name-aliases.json` のスキーマを拡張する。既存エントリは無変更で動く（後方互換）。

## Context

`team-name-aliases.json` は `canonical ← aliases` の**文脈を持たない**対応表で、
`normalize-team-names.mjs` が大会データ本体（`participants[].team` / `id` / `playerIds`）へ適用する。
既定スコープは `highschool-japan-cup` で、全大会へ流すには `--scope=all` を指定する。

中学カテゴリの名寄せ（[raw/2026-08-12-idea-juniorhigh-category-pages.md](../raw/2026-08-12-idea-juniorhigh-category-pages.md)）
に着手して `--scope=all` を dry-run したところ、**表がそのままでは全大会に適用できない**ことが判明した。
文脈を持たないために、次の2種類の誤りが出る。

### 1. 中学・クラブの文脈でだけ正しいエントリが、高校データを壊す

- `日高中学校 ← 日高`: 実データの `日高` にはインターハイ・和歌山県の出場が2件ある
  （＝和歌山県立日高高校）。適用すると高校が中学校名に書き換わる
- `柏崎ジュニア ← 柏崎`: 同様にインターハイ・新潟県の出場が2件（＝柏崎高校）。
  高校が地域クラブ名に書き換わる

同型の危険は洗い出しで**17件**見つかった（`名寄` `阿波` `甲府西` など。多くは
全日本選手権系の `all` 区分にも出現する）。

### 2. 中高一貫校では、素の略称が世代によって別の学校を指す

`昇陽` は高校108件・中学41件の両方に出現し、別エンティティとして `昇陽中学校`（中学43件）も存在する。
つまり**素の略称は「高校」の canonical でありながら、中学の大会に出てくるときは中学校を指す**。
`京都光華` `就実` `明徳義塾` `明豊` `昭和学院` `札幌大谷` も同じ構造で、計7校。

さらにこの7校は `zennihon-junior`（全日本ジュニア選手権）にも出るが、
そこでの出場は**すべて u17 / u20 で u14 は0件**であり、高校生を指している。
したがって「generationId が junior なら中学校」という単純な規則では足りず、
**大会そのものを見る必要がある**。

### なぜ表を分割したり canonical を諦めたりしないのか

- 表を「中学用」「高校用」に分割する案は、大半のエントリが文脈非依存（全角半角の揺れ等）なので
  重複管理になる。文脈依存は27/632件＝4%にすぎない
- 素の略称を一律に中学校へ寄せる案は、既にインデックス済みの高校の学校ページ URL
  （`/highschool/[gender]/[prefectureId]/[teamId]`）を壊す

## Decision

**alias エントリに任意の `scope` を持たせ、その大会文脈でだけ適用する。**

```json
{
  "canonical": "昇陽中学校",
  "aliases": ["昇陽"],
  "scope": { "tournamentPrefix": ["secondaryschool-", "zennihon-secondaryschool"] },
  "note": "中高一貫校。素の「昇陽」は高校側のcanonicalなので中学校の大会に限って中学側へ寄せる"
}
```

- `scope.generation`: 大会の `generationId` がこの配列に含まれるときだけ適用
- `scope.tournamentPrefix`: 大会IDがこのいずれかで始まるときだけ適用
- `scope.prefecture`: **参加者の都道府県**がこの配列に含まれるときだけ適用（2026-08-12 追加）
- 複数あれば **AND**。`scope` が無いエントリは従来どおり全大会に適用（後方互換）

`prefecture` だけ粒度が違う（大会単位ではなく参加者単位）点に注意。
`normalize-team-names.mjs` は participants をループしながら `{...ctx, prefecture}` を渡して判定する。

**衝突の扱い**: 同じ別名を別の canonical へ割り当てることを、**双方が `scope` を持つ場合に限り許す**。
`scope` なし同士、および `scope` なしと `scope` ありの組み合わせは、どちらが勝つか決まらないので
従来どおりエラーにする。解決時は **`scope` 付きを先に評価**する（より限定的な指定を優先）。

`check-identity-health.mjs` も同じ規約で `scope` を解釈する。
`teamCore()` を共通化したときと同じ理由で、**片方だけ実装すると過少/過大報告になる**
（2026-07 に異体字対応を候補生成側だけに入れてヘルスチェックが 8件→2件 と過少報告した事故と同型）。

## Alternatives

- **`--scope=<tournamentId>` の実行時指定で運用する**: 「どの表をどの大会に流したか」が
  コマンド履歴にしか残らず再現できない。誰が見ても同じ結果になる宣言的な表に持たせるべき。不採用
- **表を中学用・高校用に分割する**: 文脈依存は4%しかなく、96%が重複管理になる。不採用
- **素の略称を中学校側へ一律に寄せる**: 既存の高校ページ URL を壊す。不採用
- **素の略称を大会データ側で書き換えず、読み出し時に解決する**: 消費側（teams.json 生成、
  選手統計、各ページ）すべてが世代を意識する必要があり、ロジック重複が増える。
  この repo は「alias を data 本体へ反映する」方式で統一されているのでそれに揃える。不採用

### 追記（2026-08-12）: `prefecture` スコープを足した

`朝日`（愛知）と `野木`（栃木）が、県内で `朝日中学校` `野木中学校` とスラッグ衝突していた。
選手名を突き合わせると**素の略称は中学校と同一**（`朝日`の5件は山田隆真・丹羽悠弦・杉田陽星ほかで
`朝日中学校`の顔ぶれと完全一致、`朝日STC`とは重ならない）と判明したが、
**同名の別チームが他県にもある**ため（`朝日`は兵庫・長野にも、いずれも別団体）
`tournamentPrefix` だけでは限定しきれなかった。そこで `prefecture` を追加した。

さらに `野木`（栃木）では、**同じ表記が大会の系統によって別の団体を指す**ことがわかった:

- 中学校の大会に出る `野木` → `野木中学校`（選手は鈴木大雅・別符湊都・鈴木佐禄）
- **小学生大会**に出る `野木` → `野木クラブ`（選手は別符楓都・上倉穂乃実・矢田部麗ほか）

`tournamentPrefix` × `prefecture` の組み合わせで2エントリに分けて解決した。
これは scope 機構が無ければ表現できないケースで、ADR-013 の設計が正しかったことの裏付けにもなっている。

## Consequences

- 利点: `--scope=all` が安全に流せるようになった。実際に流した結果、
  ヘルスチェックの「別名のまま残る出場」が 4→0、「自動OK可の未統合候補」が 29→3、
  要対応シグナル合計が 72→42 に改善した
- 利点: 中高一貫校7校の中学出場 107件が中学校エンティティへ正しく分離された
  （`zennihon-junior` の u17/u20 36件は高校のまま維持）
- 影響: alias 表の運用に「このエントリは文脈依存か」という判断が1つ増える。
  判断を誤ると静かに誤変換されるため、**素の略称を alias にするときは
  その名前が他の generation に出現しないかを必ず確認する**こと
- 影響: `apply-auto-merges.mjs` は `scope` を出力しない。自動マージが作ったエントリは
  引き続き人手確認が要る（本 ADR の作業でも、自動マージが
  `野木中学校 ← 野木STC`（クラブを学校へ統合）と
  `府中STC ← 府中クラブ`（wiki に「意図的に統合しない」と明記済み）を作ったため巻き戻した）
- 監視: `check-identity-health.mjs` の「別名のまま残る出場」が 0 のままであること
- **副産物**: 中学カテゴリの teamId 生成で「県内スラッグ衝突」が名寄せ漏れの検出器として働く。
  衝突すると `-2` が付くので、`-2` を潰す作業がそのまま名寄せの品質向上になる
  （2026-08-12 に `asahi-2` `nogi-2` の2件がこの経路で解決した）
