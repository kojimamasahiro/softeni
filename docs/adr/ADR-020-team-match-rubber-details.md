# ADR-020: 団体戦の対戦ごとの記録（オーダー）を試合の中に持つ

## Status

Accepted

決定日: 2026-09-18

## Context

団体戦・対抗戦のデータ（`data/tournaments/details/**/team-*.json` / `versus-*.json`、118ファイル・4,371試合）は
学校対学校の本数（`scores`、2-0 など）しか持たず、**どの対戦に誰が出て何ゲームだったか**が無かった。

- X では大会のたびに「決勝のオーダーは？」「第1対戦は誰と誰？」という問いが出ており、当サイトは答えられない
  （[X投稿から見たユーザーの課題](../raw/2026-09-17-x-posts-user-problem-findings.md)）。
- 団体戦の `participants[]` は学校単位（`校名_都道府県`）で選手を持たないため、選手ページに団体戦の出場・勝敗が出ない。
- 元資料には載っている: 全日本高校選抜の JSTA 記録 PDF は**全試合**の対戦別のペアとゲーム数を持つ
  （2022・2025 で確認）。インターハイの記録はベスト8以降だけで、ゲームごとのポイントまで載る。
- リポジトリ内に先行実装がある: STリーグ（`data/st-league/<年>/matches.json`）は1試合の中に
  `matches: [{ type, winner, scoreA, scoreB, playersA, playersB }]` を持つ（ADR-008）。

ユーザーの判断（2026-09-18）: 「STリーグの形に合わせる」「対戦の状態はできれば3種類を区別したい」
「記録がない選手は名前だけ持つ」。

## Decision

details の試合オブジェクトに、任意の `matches`（対戦ごとの記録の配列）を足す。型は `src/types/tournament.ts` の
`TeamMatchDetail`。

```json
{
  "entries": [2, 3],
  "scores": { "2": 3, "3": 0 },
  "matchId": "match-1",
  "...": "既存のフィールドはそのまま",
  "matches": [
    {
      "type": "D1",
      "status": "completed",
      "winner": "A",
      "scoreA": 4,
      "scoreB": 0,
      "playersA": [{ "lastName": "百目木", "firstName": "來杜" }, { "lastName": "秋山", "firstName": "想太" }],
      "playersB": [{ "lastName": "鈴木", "firstName": "瑛太" }, { "name": "川波 悠馬" }]
    }
  ]
}
```

- **形は STリーグの `MatchDetail` に揃える**（`type` / `winner` / `scoreA` / `scoreB` / `playersA` / `playersB`）。
  A は親の `entries[0]`、B は `entries[1]`。`type` は対戦の順（`D1` `D2` `D3`、シングルスは `S`）。
- **`status` で状態を区別する**。STリーグ側は「必ず決着」前提なので、ここだけ広げる。
  `retired` と `walkover` は 2026-09-18 に追加（末尾の追記4・追記5）。

  | status | 意味 | winner | scoreA / scoreB |
  |---|---|---|---|
  | `completed` | 決着 | `'A'` か `'B'` | 本数（勝者が多い） |
  | `retired` | 途中棄権 | `'A'` か `'B'`（棄権しなかった側） | 棄権時点の本数（**勝者が多いとは限らない**） |
  | `walkover` | 不戦勝（片側がペアを出さない） | `'A'` か `'B'`（出した側） | `null`（試合は行われていない） |
  | `unfinished` | 団体の勝敗が決まって途中で打ち切り | `null` | 途中の本数（例 3-3） |
  | `not_played` | 未実施（オーダーだけ出ている） | `null` | `null` |

  **`walkover` では、ペアを出さなかった側の `playersA` / `playersB` が空配列になる。**
  他の状態では両側とも人数ぶん（ダブルス2人・シングルス1人）入る。

- **選手の持ち方**: 同じ氏名・同じ学校の**個人戦の出場記録がある選手は姓と名**（`{ lastName, firstName }`。選手ページと
  同じ識別）、**無い選手は名前だけ**（`{ name }`）。名前だけの選手は `participants` に足さない
  （足すと `extract-players.mjs` が新しい選手として採番する）。STリーグは数値 ID だが、details の選手は
  氏名ベースで識別されるので ID は持たない。
- **勝者の数は親の `scores` と一致させる**（`completed` の A の数＝`scores[entries[0]]`）。
- **持つのは元資料にある試合だけ**。大会によっては一部の試合だけが持つ（インターハイはベスト8以降など）。
- 整合性は `scripts/check-team-match-details.mjs`（prebuild）で検査する。姓名の分割修正
  （`normalize-name-splits.mjs`）はこの記録の姓・名も書き換える。

## Alternatives

- **別ファイル（サイドカー）に持つ**: 入力ツールで details を作り直しても消えない利点があるが、
  details を走査する多数のスクリプトが `*.json` を拾うため、置き場所と形の取り決めが増える。
  STリーグと同じく試合の中に持つほうが読み手に素直。却下。
- **名前だけの選手も `participants` に足す**: 選手ページが作れるが、1回しか出ない名前が選手一覧に
  大量に採番され、分割ゆれの点検対象も増える。ユーザー判断で却下。
- **状態を持たず、打ち切り・未実施を省く**: STリーグと完全に同じ形になるが、「オーダーは出ていた」
  （未実施の第3対戦のペア）という情報が消える。ユーザー判断で却下。
- **数値の選手 ID を持つ**: `data/players/index.json` の id は氏名で引かれ、同姓同名の分割
  （`homonyms.json`）もあるため、氏名で持つほうが既存の識別と食い違わない。却下。

## Consequences

- 高校選抜 2025 の男女70試合・210対戦に記録が入った。選手は延べ 792 人を姓・名で、48 人を名前だけで持つ。
- **ページ表示はまだ無い**。`lib/packedPageData.ts` は必要な項目だけを詰めるので、この項目は現状ページに届かない。
  表示するときに詰め方を足す。（2026-09-18 同日に対応。末尾の追記を参照）
- **入力ツール（`tools/`）で details を作り直すと消える**。ツールは `matches` の中身を知らない。
  作り直した場合は取り込みスクリプトを再実行する（冪等・既存の記録は置き換え）。
- 選手の姓・名が分割修正から取り残されると、`check-team-match-details.mjs` が prebuild を止める。
- 名前だけの選手は、後で個人戦に出れば姓・名に置き換えられる（取り込みスクリプトの再実行で反映）。

## 追記（2026-09-18・同日）: 表示の場所と選手の成績集計

Decision 本文は変えず、同日のユーザー判断をここに記録する。

- **表示は試合詳細（`MatchResults`）**。各組のカードの試合行の下に、その組から見た向き
  （左が自分の組、右が相手）で「第N対戦・ペア・本数」を並べる。勝った側を太字、打ち切りは「打ち切り」、
  未実施は「未実施」と出す。並びは STリーグの対戦詳細（ADR-008）に揃えた。
  ページへは `lib/packedPageData.ts` が詰めて渡す（**記録がある試合にだけ**要素を足し、他のページの転送量は変えない）。
- **選手の成績集計は STリーグに合わせる**＝**Player Statistics Engine（ADR-011）には入れない**。
  STリーグの対戦も選手の通算成績には入っておらず、STリーグ内のページでだけ扱っている
  （[st-league.md](../wiki/st-league.md)「details に結果を複製しない理由」）。団体戦の対戦ごとの記録も、
  選手ページの勝敗・勝率・ランキングには数えない。選手名は、ほかの表示と同じく姓・名の完全一致
  （`count>=5`・同姓同名は先勝ち）で選手ページへリンクするだけ。
- データの誤り2件（高校選抜 2022）を公式記録どおりに直し、2022 年度も取り込んだ（計 140 試合・420 対戦）。

Open Questions のうち「表示の場所と形」は上記で決着。

## 追記2（2026-09-18・同日）: ゲームごとのポイント（`games`）を足す

Decision 本文は変えず、インターハイに対応するために決めたことをここに記録する。

インターハイの公式記録は、対戦ごとに**ゲームごとのポイント**（`④ － 1`、`⑩ － 8` など）まで印字している。
高校選抜は本数までしか無い。この差を落とさないよう、`TeamMatchDetail` に任意の `games` を足す。

```json
"games": [[6, 4], [4, 6], [3, 5], [3, 5], [4, 1], [6, 4], [6, 8]]
```

- `[A のポイント, B のポイント]` を**実施順**に並べる。A / B は親の `entries[0]` / `entries[1]`。
- **そのゲームを取ったのは多いほう**（同点は無い）。丸数字の情報は持たない（多いほう＝勝ちで復元できる）。
- デュースが続くとポイントは 10 以上になる（実測 `⑩ － 8`）。
- 元資料に無ければ持たない（高校選抜は持たない）。`not_played` の対戦は持たない。
- 検査（`check-team-match-details.mjs`）で、**ゲームの数え直しが本数と一致するか**まで見る。
  この様式だけで効く強い検算で、実際に丸数字の10以上を読めていない誤りをこれで見つけた。
- **表示はしない**（ユーザー判断 2026-09-18）。対戦詳細はこれまでどおりペアと本数だけ。
  データとして先に貯め、見せ方は別途決める。**→ 2026-09-19 に表示することを決めた（追記8）。**

投入: インターハイ 2026・2025・2024 の女子団体・男子団体（それぞれベスト8以降の7試合・21対戦）、
2023・2022 の男子団体・女子団体（**1回戦から**。2023 は各47試合・141対戦、
2022 は各46試合・138対戦＝不戦の1試合を除く。末尾の追記6・追記7）。
2025 は記録報告書がアウトライン化PDFのため別スクリプト（[data-import.md](../wiki/data-import.md)）。

## 追記4（2026-09-18・同日）: `status` に `retired`（途中棄権）を足す

Decision 本文の表を更新した（`retired` の行）。経緯をここに記録する。

アジア競技大会2026 男子団体B組 韓国-インドネシアの第3対戦で、**3-2 とリードしていた韓国が棄権した**
（公式サイトの表示は韓国側が `RET`、インドネシア側が `W`）。既存の3つでは表せない。

- `completed` にすると「勝者の本数が多い」という検査に落ちる（勝者インドネシアの本数は 2 で少ない）
- `unfinished` は勝者なしなので、団体の本数 2-1 と勝ち数が合わなくなる

```json
{ "type": "D2", "status": "retired", "winner": "B", "scoreA": 3, "scoreB": 2, "games": [[4,2],[4,0],[2,4],[2,4],[5,3]] }
```

- **勝者は棄権しなかった側**。本数からは決まらないので `winner` を必ず持つ。
  検査（`check-team-match-details.mjs`）でも `retired` だけ「勝者の本数が多い」を要求しない。
- 本数は**棄権した時点の本数**。
- `games` は**決着したゲームだけ**を持つ。中断されたゲーム（実測 `0-0`）は取った側が決まらないので入れない。
  ゲームの数え直し＝本数の検算はそのまま効く。
- 表示（`MatchResults`）は本数の下に「棄権」／相手が棄権した側では「相手が棄権」と出す。
  **本数だけでは勝敗が逆に読めるため、どちらが棄権したかを必ず書く。**
- 圧縮（`lib/packedPageData.ts`）は `status` を文字列表で詰めているので変更は不要。
  往復テスト（`lib/__tests__/packedTeamMatches.test.ts`）に「勝者の本数のほうが少ない」ケースを足した。

## 追記5（2026-09-18・同日）: `status` に `walkover`（不戦勝）を足す

Decision 本文の表を更新した（`walkover` の行と、選手が空配列になる注記）。経緯をここに記録する。

アジア競技大会2026 男子団体B組で、**ネパールが第3対戦にペアを出さなかった**（公式サイトの表示は `BYE`）。
団体の本数にはネパールの相手の1勝として入る（韓国-ネパールは 3-0）ので、対戦として書けないと
「勝った対戦の数＝親の `scores`」が合わず、その2試合はオーダーごと持てなかった。

```json
{ "type": "D2", "status": "walkover", "winner": "A", "scoreA": null, "scoreB": null,
  "playersA": [{ "name": "KIM Hyunsoo" }, { "name": "LEE Haneul" }], "playersB": [] }
```

- **試合は行われていないので本数は持たない**（`completed` で 4-0 のように書くと本数の捏造になる）。
  `games` も持たない。
- **ペアを出さなかった側は空配列**。`{ name: '—' }` のようなダミーを入れない（選手名として扱われるため）。
  検査は「空なのは片側だけ」「勝者はペアを出した側」まで見る。人数チェックは空の側だけ飛ばす。
- 表示は「不戦勝」／相手側の行では「相手が不戦勝」。空の側の選手欄は**「出場なし」**と書く
  （空欄にすると読み落とす）。
- 往復テストに「空配列のまま往復する（選手が湧かない）」ケースを足した。

これで ADR-020 の Open Questions から「不戦勝を表せない」が消え、アジア大会 2026 男子団体B組の
3試合すべてにオーダーが入った（対戦記録 45 → 51）。

## 追記6（2026-09-19）: 収録範囲は年度で変わる・打ち切りの本数が印字されない年度

Decision 本文は変えない。インターハイ 2023 男子団体を入れて分かったことを2つ記録する。

- **「インターハイはベスト8以降」は年度の性質で、決定ではない**。2023 の公式記録は**1回戦から**
  3対戦すべてを載せている（47試合・141対戦）。Decision の「持つのは元資料にある試合だけ」の
  とおりに増える。収録範囲を前提にした実装をしないこと。
- **`unfinished` の本数が印字されない年度がある**。2023 は「打ち切り」とゲームごとのポイントだけで、
  対戦の本数を印字しない（2024 は `2-2` のように印字する）。
  **印字が無いときだけ、印字されたゲームから数えて `scoreA`/`scoreB` を埋める**。
  status の表（`unfinished` は「途中の本数」）は変えない——埋める値はその「途中の本数」そのもの。
  印字がある年度は印字を正とし、数え直しは検算に残す。
  `not_played`（ゲームも本数も無い）は数えるものが無いので検査の対象外。
- 取り違えの検査に**同名の別人**の例外が要る（2023 男子の佐藤直輝＝中京と羽黒）。
  ファイルと氏名を明示した許可リスト（`check-team-match-details.mjs` の
  `SAME_NAME_DIFFERENT_PEOPLE`）で通す。氏名だけで緩めない。

実施記録: [男子](../raw/2026-09-19-interhigh-2023-boys-team-match-order.md) / [女子](../raw/2026-09-19-interhigh-2023-girls-team-match-order.md)。
女子では**オーダーが既存ブラケットの誤り（2回戦の勝者が逆）を見つけた**。`matches` は表示だけでなく、親の勝敗データの検算にもなる。

## 追記7（2026-09-19）: 不戦の試合・進行中のまま打ち切られたゲーム・状態の決め方

Decision 本文と status の表は変えない。インターハイ 2022（男女）を入れて必要になった線引きを記録する。

- **不戦の試合は `matches` を持たない**。2022 は見出しの本数が数字でなく `R` と印字され、
  **どちらのペアも・本数も・ゲームも印字されない**（男子 p28 昌平、女子 p18 名護）。
  Decision の「持つのは元資料にある試合だけ」に従い、`matches` を入れない。
  **`walkover` にはしない**——`walkover` は「出した側のペアが分かる」前提で、
  出さなかった側が空配列になる形。どちらも分からない不戦はこの形に当てはまらない。
  親の試合は既存どおり `retired: true` と本数で表す（`lib/bracketDrawing.ts` が "R" を描く）。
- **進行中のまま打ち切られたゲームは `games` に入れない**。Decision の「決着したゲームだけ」の
  とおりだが、2022 で初めて**印字される**ようになった（どちらにも丸数字が無い行。実測8件）。
  落とした行は取り込みのたびに表示する（黙って捨てない）。
- **状態は「ゲームの有無」で決めない**。上の2つを入れた結果、進行中のゲーム1つだけで打ち切られた
  対戦の `games` が空になり、本数 `0 － 0` だけが残って `not_played` と判定されて検査が鳴った。
  **本数・決着したゲーム・進行中のゲームのどれかが印字されていれば、その対戦は始まっている**
  （`unfinished`）。`0-0` は status の表の「途中の本数」にあたる。
  **status を導出で決めている箇所は、導出元を変えると壊れる**。検査（`check-team-match-details.mjs`）が
  形の矛盾として捕まえた。

## 追記8（2026-09-19）: ゲームごとのポイントを対戦詳細に出す

追記2 の「表示はしない」を覆す。Decision 本文と `games` の形は変えない。

**対戦行の直下に、全幅で1行**（`MatchResults.tsx` の `TeamMatchGames`）。検討した案と却下の理由:

| 案 | 却下の理由 |
|---|---|
| 本数セル（`w-16`）の下に縦積み | セルを広げるしかなく、狭い画面でペア名が潰れる。1対戦が5〜7行の高さになる |
| 本数を押すと開く | 「上位の組は開いた状態で出す」で減らした操作を対戦単位でまた増やす。閉じている間はページ内検索に出ない |

- **向きはカードの組から見る**（左がその組）。`gamesWon` / `gamesLost` と同じく B 側の行では左右を反転する。
- **そのゲームを取った側（多いほう）を太字**。公式記録の丸数字（`④`）は使わない——`⑩` 以上の字形と
  読み上げがフォント・環境で揺れるため。読み上げ用に `sr-only` で「第Nゲーム ◯対◯」を添える。
- **ファイナルゲーム（3-3 の第7ゲーム・7点先取）に印は付けない**（ユーザー判断）。何ゲーム目かは位置で分かる。
- **`games` が無い対戦は行ごと出さない**（高校選抜・`walkover`・`not_played`）。同じページで有無が混ざる年度がある
  （インターハイ 2025 は 21対戦中 18）。節の冒頭の注記も、ポイントがあるページでだけ1文足す。
- 中断されたゲームは元から `games` に入らない（追記4・追記7）ので、**表示されるゲーム数は必ず本数と一致する**。
  この点の注記は置かない。
- 転送量は `lib/packedPageData.ts` の `PackedTeamMatch` に8番目の要素として足す（**記録がある対戦にだけ**）。
  raw JSON で +0.7〜4.6KB（最大は全試合ぶん持つインターハイ2023）。団体戦の年度別結果ページだけが増える。

実測と検証: [2026-09-19-team-match-points-display.md](../raw/2026-09-19-team-match-points-display.md)。
