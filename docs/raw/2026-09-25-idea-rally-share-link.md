# アイデア: 試合詳細ページの「1本のラリー」を共有できるようにする

## 状況

Idea Backlog。**P0 実装済み**（2026-09-25。ブランチ `claude/share-rally-link`）。仕様は下の「決めたこと」。実装後は
[beta-matches-results.md](../wiki/beta-matches-results.md) の「ラリー共有リンク」節が正。

## 目的

試合詳細ページ（`/matches/[matchId]`、`/beta/matches-results/[matchId]`）を多くの人に見てもらう。
以前は「データを集めて傾向を見つける」方向（プレースタイル分析・成長のヒント）を考えたが、
今回は**ページそのものを活かす**方向。

ページの一番の資産は、**全ポイントに動画の開始・終了時刻（`video_start_ms` / `video_end_ms`）が
付いていること**。つまりこのページは動画から1本ずつのラリーを取り出せる索引になっている。
「このラリーすごい」を1本単位で広められれば、試合を最初から見る気のない人にも届く。

## ユーザーが興味を持った点

- 「試合詳細のページをみんなに見てもらう方法を考えたい。前はデータを集めて傾向を見つけることを
  考えたが、何かしらこのページ自体を活かしたい」（2026-09-25）
- 出した5案（A: ラリー単位の共有リンク / B: 名場面の連続再生 / C: 結果を隠して見るモード /
  D: 指導者向けの場面で絞った連続再生 / E: 大会インサイトの記事からラリーを引用）から **A を選んだ**。

## わかっていること（2026-09-25 時点）

- 公開試合は 27 件（すべて completed）。うち **14 件に YouTube 動画**。
- `?pointId=<uuid>` で該当ポイントへスクロールし動画を再生する仕組みは**すでにある**。名場面の
  SNS 投稿テンプレ（`lib/rareEvents.mjs` の `buildPostText`）と `/matches/highlights` もこの形式を使う。
- 足りなかったもの:
  1. 閲覧者がリンクを手に入れる手段（共有ボタン）がない。
  2. OGP は試合共通。静的 export（Cloudflare Pages）なのでクエリで差し替えられない。
  3. `?point=N` は `point_number`（**ゲームごとの番号**）で最初に一致したポイントへ飛ぶので、
     第何ゲームかを区別できない（第1ゲームに飛ぶ）。内部に `?point=` を使うリンクは無い。
  4. リンクから開くと自動でスクロール＋`playFrom`（止まらずに再生し続ける）。スマホでは音付きの
     自動再生が止められやすい。

## 決めたこと（2026-09-25 ユーザー確認済み）

- **OGP は試合共通のまま**。ラリーの中身は共有する文面で伝える。専用ページや CF Functions は
  反応を見てから（下の「次の候補」）。
- **共有ボタンは全ポイント＋名場面カード＋勝敗を分けた局面カード**に置く。
- **共有リンクから開いたら、上部に案内（どのラリーか）と再生ボタンを出し、タップで再生**。
  再生はそのラリーの終わり（`video_end_ms`）で止める（`playRange`）。自動スクロール・自動再生はしない。
- URL は既存の `?pointId=<uuid>` をそのまま使う（SNS 投稿済みのリンクと揃える）。
- `?point=N` は `?game=G&point=N` を受け付けるようにし、`game` なしのときは曖昧なので
  1ゲームだけの試合でしか解決しない。

## 課題・未解決

- 共有が実際に起きるか。GA4 に `share_point`（共有ボタン）と `shared_point_play`（リンクから
  開いて再生ボタンを押した）を送り、数週間後に見る。
- 動画なしの試合（13 件）でも共有はできるが、着地で見せられるのはスコア記録だけ。

## 次の候補（まだ発散フェーズ）

- 名場面だけビルド時に専用ページ＋OGP 画像を作る（反応があれば）。
- B（名場面の連続再生）・E（インサイト記事からの引用）は、この共有リンクを土台にできる。
