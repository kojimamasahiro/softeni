# club:verify の単調増加チェックが2018/2019投入以降ずっと落ちていた

## 状況

2026-09-13。`npm run -s club:verify` が `1件 失敗` で終わるのをユーザーが発見した。
小学生カテゴリの PR 作業中に見つかったが、**その PR とは無関係の既存不具合**。

## 何が落ちていたか

```
FAIL クラブ比率は年を追って単調増加している
```

全中の年度別内訳:

| 年度 | 全団体 | クラブ | 比率 |
|---|---|---|---|
| 2018 | 130 | 1（中之条クラブ） | **0.769%** |
| 2019 | 134 | 1（日野クラブ） | **0.746%** |
| 2021 | 114 | 1 | 0.877% |
| 2022 | 113 | 1 | 0.885% |
| 2023 | 117 | 12 | 10.3% |
| 2024 | 115 | 29 | 25.2% |
| 2025 | 106 | 39 | 36.8% |
| 2026 | 113 | 61 | 54.0% |

**2018 → 2019 で比率が下がる。** ただしクラブ数はどちらも1団体のままで、
増えたのは分母（全中の出場団体数 130 → 134）だけ。地域移行が後退したわけではない。

## いつから

| | |
|---|---|
| 2026-08-12 | `club:verify` を追加（`17b2dae6 中学`）。当時のデータは2022年度以降 |
| 2026-08-14 | 2021年度を追加（`b8e36338 全中 2021`） |
| **2026-09-03** | **2018・2019年度を追加（`0d92404e 全中`）← ここから失敗** |

判定を書いた時点では制度変更前のデータが2022年度しか無く、系列として1点だったので通っていた。
古い年度を遡及投入したことで、分母の揺れが見えるようになった。

## 直し方

単調増加の要求を**制度変更後（`policyYear` = 2023年度以降）だけ**に狭めた。

```ts
check(
  `クラブ比率は制度変更後（${data.policyYear}年度以降）に単調増加している`,
  after.every((y, i) => i === 0 || y.clubShare >= after[i - 1].clubShare),
);
```

**制度変更前の比率は系列として意味を持たない**（クラブ数が1で固定なので 1/N の揺れしか見ていない）。
一方、主張したいトレンドは2023年度以降の 10.3% → 25.2% → 36.8% → 54.0% で、これは狭めた判定で守られる。
制度変更の前後で跳ねたことは、既存のもう1つの判定「前の最大 < 後の最小」が引き続き守っている
（こちらは失敗時も通っていた）。

### 採らなかった案

- **比率でなくクラブ数の単調増加を見る**: クラブ数も全中の規模変動を受けるので、
  同じ問題を別の形で持ち込むだけ
- **許容誤差を入れる**（`>= prev - 0.01` など）: 閾値の根拠が無く、
  「どこまでの下降を許すか」という新しい Assumption を増やす
- **2018・2019年度のデータを外す**: 検算のために実データを捨てることになる

## 確認

`npm run -s club:verify` が `すべて通過`（exit 0）になった。
[1] の既知分類・[3] の unknown 一覧は変えていない。
