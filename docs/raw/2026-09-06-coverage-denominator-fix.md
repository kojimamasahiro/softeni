# 「現在の反映状況」の分母が決勝までの試合数になっていなかった

実施日: 2026-09-06
種別: 不具合修正（公開文言の数値誤り）
対象: `lib/tournamentCoverage.ts`（`computeResultCoverage`）
発端: ユーザー指摘「大会結果ページの上部に表示される『現在の反映状況』だが、決まっている試合での
消化率になっていて、決勝までの試合数ではないので感覚と違う気がするがどうか」

---

## 1. 事象

分母が `matches` に**存在する** `stage:'knockout'` のレコード数だった。
試合を実施したぶんだけ `matches` に追記していく大会では、分母が進行と一緒に増えるため、
決勝までの総試合数にならない。**感覚のズレではなく数値が誤っていた。**

修正前に本番相当（dev）で出ていた文言:

| ページ | 修正前 | 修正後 |
|---|---|---|
| 全日本学生2026 女子ダブルス（332エントリー） | 「組み合わせを掲載しています。結果はこれから随時反映予定です**(全76試合)**」 | 「…(全**331**試合)」 |
| 同 男子ダブルス（585エントリー） | 「(全73試合)」 | 「(全**584**試合)」 |
| 同 男子団体（96チーム） | 「3回戦まで結果掲載中(全**88**試合中80試合終了・**91%**)」 | 「(全**95**試合中80試合終了・**84%**)」 |
| 同 女子団体（59チーム） | 「(全51試合中43試合終了・84%)」 | 「(全**58**試合中43試合終了・**74%**)」 |

76 は1回戦の試合数。**332エントリーの大会が全76試合であるはずがない**という点で、
読者から見ても明らかにおかしい数字が出ていた。

## 2. なぜ気付きにくかったか

**大会によって挙動が変わる**。組み合わせ投入時にブラケット全体を `matches` に作る大会
（東海ブロック2026: 64エントリーで最初から60レコード）では分母がほぼ正しく、
実施ぶんだけ追記する大会（全日本学生2026）では大きく外れる。
同じ文言なのに、大会ごとに信頼度が違う状態だった。

また通知が出るのは `not_recorded` / `in_progress` / `abandoned` のページだけで、
**完了済みの大会では通知そのものが出ない**。完了大会はレコードが揃っていて分母も正しいので、
過去データを見ている限り不具合として顕在化しない。

## 3. 修正

分母を「決勝までの**想定総試合数**」にした。

シングルエリミネーションの試合数は**不戦勝の有無に関係なく「参加数 − 1」**で決まる
（毎試合ちょうど1組が敗退し、優勝の1組だけが残る）。参加数さえ分かれば、試合レコードが
1件も無くても総試合数は確定する——これが「結果が入る前から正しい分母を出せる」根拠。

参加数の取り方は形式で2通り:

| 形式 | 参加数 | 根拠 |
|---|---|---|
| 予選リーグ→決勝T（`knockoutDraw` あり） | 非 null の `slots` の数 | `entries` にはリーグだけの組も含むので数えると多すぎる。席は (組, 組内順位) で定義されるので**リーグが終わる前でも席数は確定**（ADR-015） |
| 純トーナメント | `entries` の数 | そのまま参加数 |
| 予選リーグを含むが `knockoutDraw` が無い | 算出しない | 根拠が無い。誤った分母を出すより従来どおりレコード数で代用（実測3ファイル） |

3位決定戦のようにレコードが想定を上回る場合は `Math.max(想定, レコード数)` でレコード数を採る。

`ResultCoverage` の変更:

- `totalKnockoutMatches` … **想定総試合数**（表示・進捗率はこちら）。意味が変わったフィールド
- `knockoutMatchRecords` … 新規。データに存在するレコード数
- `expectedTotalSource` … 新規。`'draw' | 'entries' | 'records'`（`records` は算出できず代用したことを示す）

`status` の判定ロジックは**一切触っていない**（`results` の `ongoing` 有無と decided 件数だけで
決まるため、分母を変えても状態は動かない）。

## 4. 検証

全データ470ファイル中、決勝Tを持つファイルで想定とレコード数を突き合わせた:

| 突合結果 | 件数 | 意味 |
|---|---|---|
| 一致 | 434 | **表示は1文字も変わらない**（完了済みでレコードが揃っている大会） |
| レコードが想定より多い | 4 | 3位決定戦等。`Math.max` でレコード数を採るので従来どおり |
| レコードが想定より少ない | 11 | 分母が増える。内訳は下記 |
| 算出不可 | 3 | 予選リーグ併用で `knockoutDraw` 無し。従来どおり |

「少ない」11件の内訳と表示への影響:

- 全日本学生2026 の6種目（`not_recorded` 4 / `in_progress` 2）… **今回直したかった対象**
- 全日本社会人2026 男子45歳（`in_progress`、117→119）… 微修正
- 東海ブロック2026 男女（`abandoned`、60→63）… 打ち切り文言は総数を出さないので**表示は不変**
- アジア競技大会予選2025 男女（`completed`、47→50 / 48→51）… 完了は通知非表示なので**表示は不変**

その他: `npx tsc --noEmit` / `npx eslint` クリーン。`scripts/verify-abandonment.ts` は
既知の1件（`highschool-championship/2026` の期待値が古い。別タスクで対応中）以外 PASS で、
coverage の `status` 判定が全ケース従来どおりであることを確認。

## 5. 学び

- **分母は「データにある数」ではなく「あるべき数」で持つ**。前者は入力の進み方（追記型か
  一括生成型か）に依存するので、同じ文言の信頼度が大会ごとに変わってしまう。
- 「開催中の大会でしか出ない表示」は過去データの検証では見つからない。
  [打ち切り対応（2026-07-26）](./2026-07-26-abandoned-tournament-ui-design.md) で
  `winnerEntryNo` の `-1` 問題を踏んだのと同じ構造で、**進行中・開催前の状態は
  実データで1度は目視する**しかない。
- 参加数さえあれば総試合数が確定するという性質（N−1）は、ブラケット復元
  （`lib/bracketLayout.ts`）を通さずに済むという点でも効いた。復元は87大会で失敗しうるが、
  この計算は失敗しない。
