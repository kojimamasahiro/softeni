# 全日本ミックスダブルス選手権 2021年度（第2回）一般 予選リーグのPDF取り込み

日付: 2026-09-04
入力: `2021_A03_40b.pdf`（16p, 第2回 全日本ミックスダブルス選手権大会）（ユーザー提供）
出力: `data/tournaments/details/zennihon-mixed/2021/doubles-none-mixed.json`（新規）
      / `tools/zennihon-mixed-2021/doubles-none-mixed.initialPlayers{,ByGroup}.json`（新規）
スクリプト: `scripts/pdf/zennihon_mixed_results.py`（新規）
手順: skill `tournament-pdf-to-results`

ユーザーの依頼は「2020年のミックスダブルスの一般の男女／ラウンドロビン／1〜8ページのみ」。
**年は2020ではなく2021**だった（下記）。1〜8ページは一般の予選リーグ（総当たり）で、
9ページの決勝トーナメントは今回の対象外。10〜16ページは年齢別（35〜70歳）で、これも対象外。

## 年の同定 ― 依頼の「2020年」は誤り

- PDFの内部メタデータ `Title` が `第2回 全日本ミックスダブルス選手権大会`、
  `CreationDate` が `D:20210622...`。
- 既存データが 2022=第3回・2026=第7回 なので、第2回=2021 で連続する。
- 決め手は JSTA の年度別結果ページ。
  [2021年度(令和3年度) 大会結果](https://www.jsta.or.jp/result/result2021) に
  **第2回 / 愛媛県松山市 / 6月19日(土)〜20日(日) / `2021_A03_40b.pdf`** と載っており、
  **ファイル名が今回の入力と完全一致**する。

要項・日程が結果PDF本体に一切書かれていない様式なので、
`information` に足す `location` / `startDate` / `endDate` はこのページから採った。

## 様式（skillの「5つの問い」）

| 問い | 実際 |
|---|---|
| (a) テキスト層 | **あり**。Excel 2019 出力。座標も素直 |
| (b) 勝者スコア | **あり**（丸数字 ④）。敗者は裸の数字、棄権は `R` |
| (c) 1ページの構成 | 3〜5ブロックの星取表。トーナメントのドローではない |
| (d) ページ最終戦 | 該当なし（総当たり） |
| (e) 準々決勝以降 | p9 の決勝トーナメント。**今回は取り込まない** |

ドロー表の幾何を追う既存パーサ（`zennihon_championship_results.py` /
`highschool_championship_results.py`）は**どれも使えない**。星取表は
「行＝エントリー、列＝対戦相手」の Excel 表なので、行と列を復元するだけで済む。
`tournament_results_common.py` も使わない（`build()` はノックアウト専用で、
`matchId` の採番規約も `nextMatchId` の張り替えも総当たりには要らない）。

### 1ブロックの構造

```
<ブロック番号> 氏 名 所 属 <entryNo…> 勝率 差 順位     ← ヘッダ行
              上段の選手（姓 名 / 県 / 所属）
              星取セル…  勝率  差  順位                ← セル行
<entryNo>                                             ← 番号はセル行の直下
              下段の選手
```

1エントリー＝3行（上段選手 / セル＋集計 / 下段選手）で、エントリー番号だけが
セル行より 3pt 下の別行に落ちる。ペアの2人は男女どちらが上段かが決まっていない。

### 落とし穴: 勝率・差・順位の x はブロックの人数でずれる

3人組と4人組で列幅の割り付けが変わり、**4人組では星取セルが x≈355 まで伸び、
勝率／差／順位が右へ約30pt ずれる**（p5 ブロック19 = entry 55-58）。
最初 x を固定値で書いたら 4人組のブロックだけ「セル行 0 件」で落ちた。
ヘッダ行の `勝率` と `差` の実座標から毎回レンジを引き直すようにして解決。

同じ理由で、星取セルの列割り当ては**ヘッダの entryNo の中心x への最近傍**で行う
（許容 12pt。それ以上ずれたら例外）。

### そのほか実際に踏んだもの

- ヘッダ行の `所 属` だけが別行に落ちるブロックがある（p1 ブロック2/3 など）。
  ヘッダの検出は `勝率` の有無だけで行う。
- 決勝トーナメントページの列見出しに単独の `ブロック` という語があり、
  `…ブロック` で拾うと `int("")` で落ちる。
- 全角数字が混じる（`３` `０`：p5 ブロック19）。`unicodedata.normalize("NFKC")` で吸収。

## 検算

### 検算1（本命）: 各ブロックの1位 ↔ p9 決勝トーナメントの出場ペア

p9 は「Ｎブロック １位」＋ペア名の一覧になっている。**予選リーグ側とは完全に独立**に
これを読んで突き合わせ、**33ブロックすべてで一致**（`--knockout-page 9`）。

これは順位の読み取りだけでなく、**「どの選手2人がどのエントリーか」という行の対応付け**を
33件ぶん検証したことになる（上下の選手行を1行ずらすと必ず落ちる）。

### 検算2: 勝率の分子 ＝ 星取セルの丸数字の数

エントリーごとに突き合わせ、**101件すべて一致**。分母のほうは2件ずれるが、これは
PDF側の誤記だと確認した（下記）。

### 検算3: 順位と勝数が矛盾しないか

「順位が上なのに勝数が少ない」組み合わせを全ブロックで総当たりに探して 0 件。

### 検算4: 目視（p8 全体）

p8（ブロック30-33、entry 89-101）を画像に起こして抽出結果と1件ずつ照合。
4人組ブロック32、`R` を含むブロック33、rank 4 の entry 96 まで一致。

### 数の整合

- ブロック 33 / エントリー 101（31ブロック×3 ＋ 2ブロック×4）
- 選手 202 = 101×2
- 丸数字 ④ の総数 104 ＝ 出力した試合数 104。
  総当たりなら 31×3 + 2×6 = **105** で、差の1件は下記の両者棄権。

## PDF側の誤り・特異例（そのまま残したもの）

| 箇所 | 内容 | 扱い |
|---|---|---|
| ブロック2 / 5 vs 6 | 双方 `R`（両者棄権）。勝者が決まらない | **試合を出力しない**（103ではなく104試合になる理由） |
| ブロック11 entry33 | 勝率 `0/3` だが 3人組なので分母は 2 のはず | セルは `0` と `3` で一義。**誤記として無視** |
| ブロック26 entry77 | 勝率 `1/1` だが 2試合している | 同上。**誤記として無視** |

いずれも順位には影響しておらず、検算1（p9との突き合わせ）も通る。
分子は全件合っているので、**誤記は分母だけ**。

`R` は 16 箇所。片側が `R` の試合は `retired: true` とし、
敗者スコアは読めないので 0 とした（`4R` のような「Nゲーム時点で棄権」表記は今回は無し）。

## 出力の形

予選リーグだけなので `knockoutDraw` を持たず、`results[].tournament` は全件 `null`、
`matches[].stage` は全件 `roundrobin`。
`primaryschool-championship/2025/*` や `zennihon-university-indoor/2025/*` と同じ形。
`retired` は true のときだけ置く（`zennihon-university-indoor` に合わせた）。

## 追記（2026-09-04）: initialPlayers を出した

ユーザーの本来の依頼は `initialPlayers.json` のほうだった（結果ではなくエントリー）。
details が既にあるので `details_to_initial_players.py` にそのまま通した。

- `tools/zennihon-mixed-2021/doubles-none-mixed.initialPlayers.json` … 101件のフラット配列
- `tools/zennihon-mixed-2021/doubles-none-mixed.initialPlayersByGroup.json` …
  33ブロック（`"1"`〜`"33"`）に分けた `tools/roundrobin` 向けの形

**総当たりの大会は `initialPlayersByGroup` が要る**ので、
`details_to_initial_players.py` に `--by-group` を足した。グループは
`results[].roundrobin.group` から採る（グループ名が数字なら数値順に並べる）。
先例は `tools/korea-cup-2026/09_womens_doubles_groups_A-L.json`。

`tempId` は4項目（`--tempid-with-prefecture`）。
[2026-09-04-zennihon-championship-2016-pdf-entries-import.md](2026-09-04-zennihon-championship-2016-pdf-entries-import.md)
で決めた方針に合わせた。docstring の「既定は3項目」という記述も
「新規は必ず4項目」と読めるよう直した。

### 氏名分割は不要だった

この様式は姓と名が**別の語として別x座標に印字される**ので、
「姓は先頭2文字」のような長さヒューリスティックも座標しきい値も使っていない
（インターハイ・全社で問題になった経路そのものが無い）。
1文字の姓（`林` `桂` `菅` `加`）と1文字の名（`崚` `茜` `宙` `駿` `葵` 等）が
合わせて25件あるが、いずれも紙面どおり。`check-name-splits` も 0 件。
