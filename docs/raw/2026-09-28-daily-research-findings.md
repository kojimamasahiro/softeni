## 2. GA4（サイト内検索クエリ・past 28日）

### 発見1（バグ）: `/players` の検索URLで `?q=` がほぼ毎回二重になっている

保存済み探索「ページクエリ」で `/players/?q=` を含むページパスを表示回数順に見ると、

`page_view` イベントの `page_path` / `page_location` の組み立てで二重化している疑い**
（`src/pages/_app.tsx` の `routeChangeComplete` ハンドラ、または `lib/analytics.ts`）。
原因は未特定。

これにより [ユーザーの課題を体系的に見つける](./2026-09-06-idea-user-problem-discovery.md) の

## 追記: GA4 `?q=` 二重化の原因特定（同日）

本番 `/players/` で検索し、gtag が実際に送った `/g/collect` を `fetch` / `sendBeacon` をフックして取得した。
`dataLayer` に積まれた値（`page_path` / `page_location`）はどちらも正しく、上の「`url` 引数がずれている」仮説は外れ。

「佐藤」で1回検索したときの送信（`en=page_view` が2本）:

| | 送信元 | `dp`（page_path） | `dl`（page_location） |
|---|---|---|---|
| ① | `_app.tsx` の手動送信 | `/players/?q=佐藤` | `https://softeni-pick.com/players/?q=佐藤` |
| ② | 拡張計測（履歴イベント、`_eu=AEAAAAQ`） | `/players/`（着地時のパス） | `https://softeni-pick.com/players/?q=佐藤` |

通常のリンク遷移（`/players/` → `/players/69/results/`）でも同じく2本出て、②の `dp` は `/players/` のままだった。

原因は2つ:

1. **`page_path` にクエリを含めて送っていた**。GA4 は `dp` をパスとし `dl` のクエリを後ろに足して
   「ページパス + クエリ文字列」を作るとみられ、① は `/players/?q=佐藤` + `?q=佐藤` になる。
   二重化した両側が常に同じ語であることとも合う（デバウンス途中の値なら食い違うはず）。
   GA4 サーバー側の組み立ては直接は見ていない（送信値と記録値の一致からの推定＝Assumption）。
2. **`config` に `page_path: window.location.pathname` を渡していた**。config の値は以後の全イベントに残るため、
   拡張計測の page_view も `internal_link_click` も、SPA 遷移後は着地ページのパスで記録される。
   加えて拡張計測がオンなので、SPA 遷移の page_view が毎回2本（二重計上）。

「上位100件の9割が二重」という比率が ①②半々にならない理由は詰めていない。

対応: `page_path` を2か所とも削除し、`check-search-misses.mjs` は `?q=田中?q=田中` を `?` で切って
過去データも読めるようにした。拡張計測の履歴イベントのオフは管理画面の操作なのでユーザー待ち。
