# 対戦詳細「畳んでいること」の見せ方（2026-09-19）

[2026-09-01 の畳み込み](./2026-09-01-idea-list-representation-and-result-page.md)の続き。
同日に入れた「**上位（ベスト8以上）の組はカードを開いた状態で始める**」の副作用を直した。

## 何が起きたか

上位8組を開いた状態にしたぶん節が縦に伸び、下端の「その他の組（40組）を表示」が遠くなった。
ユーザーの指摘は「テキストボタンが目立たなくなった」。

実測（インターハイ2024 男子団体・48組・1024×768）: **`<details>` は h2「対戦詳細」から 6,048px 下**
＝ **7.9画面**。上位8組を読んで離脱する人には、事実上存在しない。

問題は3つが重なっていた。

1. **状態がプロースの中にある** — 「既定では上位に入った組だけを出しています」は検索窓の上の
   小さい灰色の説明文で、読み飛ばされる場所に状態（48組中8組）とやることが埋まっていた。
2. **トリガーが8枚ぶん下にある** — 上記の 7.9画面。
3. **トリガーの見た目が慣例から外れていた** — `text-link` の素のテキスト。
   `players/[id]/results.tsx` に残る 2026-08-07 の修正記録（「地味すぎるとトリガーの存在感が
   無くなり見落とされた」→ ピル型チップへ）と**同じ失敗を繰り返していた**。
   `PlayerMajorResults.tsx` の「リンク色にすると遷移に見えるため使わない」にも反していた。

## 検討した案

| 案 | 内容 | 判断 |
|---|---|---|
| A | 件数を明示した状態1行＋チップを上下2か所 | **採用**（ユーザー確定） |
| B | 「ベスト8以上 / すべて」のセグメント切替を検索窓の横に | 却下。2026-09-01 に `<details>` へ置き換えて**意図的に消したUI**で、戻すなら判断の上書きの記録が要る |
| C | 節内スティッキーバー | 却下。モバイルの縦幅を食い、この1節のためにスクロール制御を足すのは重い |
| D | 開く枚数を優勝・準優勝・ベスト4の4枚に減らす | 却下（同日の変更と逆行）。A で足りなければ次善 |

## 実装（`MatchResults.tsx`）

- 説明文は「1 組ずつの勝ち上がりとスコアです。」だけに戻し、**状態は検索窓の直下の1行**に出す。
  - 既定: `全48組のうち、ベスト8以上の8組を表示しています。`
  - 開いた後: `全48組を表示しています。`
  - 検索中: `「広島」に一致する1組を表示しています。`（0件のときは出さない。下の空状態が受ける）
  - 上位ラベルが0件の大会: `組数が多いので、全51組を畳んでいます。`
- 同じ行にチップ `その他の40組を表示 ▼`。上位ラベルが0件の大会は `全51組を表示`。
- **上のチップは押しても消さず、ラベルを `隠す ▲` に入れ替える**。消すと押した直後に
  フォーカスが body へ飛ぶ。`aria-expanded` ＋ `aria-controls="match-results-rest"`。
- **検索中は上のチップを出さない**。`restOpen = showRest || query.length > 0` で強制的に
  開いており、押しても閉じられないため。
- **開いたら `<details>` の位置へ送る**（`scrollIntoView` ＋ `scroll-mt-4`）。変化が数画面下で
  起きるので、送らないと「押したのに何も起きない」に見える。`<details>` 自身の位置は開閉で
  変わらないので、state の反映を待つ必要はない。
- 下端の `<summary>` も同じピル型チップにし、▼▲ を `group-open` で入れ替える
  （`players/[id]/results.tsx` / `players/index.tsx` と同じ形）。**リンク色はやめた**。

## 検証（dev・1024×768）

| ケース | 結果 |
|---|---|
| インターハイ2024 男子団体（48組） | 上位8枚が開、状態行＋チップ、下端チップ |
| 上のチップを押す | `<details>` 開・`scrollY 0 → 9,145`（details が上端から16px）・ラベル `隠す ▲`・`aria-expanded=true`・状態行が「全48組を表示しています。」・その他40枚は畳んだまま |
| 検索「広島」 | チップ消滅・状態行「「広島」に一致する1組を表示しています。」・`<details>` 強制オープン |
| 検索0件「zzzz」 | 状態行を出さず、既存の空状態（理由＋検索をクリア）だけ |
| 検索クリア | 自分で開いた状態は保持（`showRest`）。開いていなければ畳んだ状態へ戻る |
| アジア大会予選2025 男子トーナメント（51組・上位ラベル0件） | 「組数が多いので、全51組を畳んでいます。」＋「全51組を表示」 |
| 同 男子準決勝（8組・畳まない） | 状態行もチップも `<details>` も無し。ベスト8ラベルの4枚だけ開 |

`tsc --noEmit` / eslint クリーン。

## 詰まったこと（本題ではない）

`next dev` が **HMR の無限フルリロード**に入った。ブラウザが古いハッシュの
`_next/static/webpack/<hash>.hot-update.json` を取りに行って 404 → full reload → 同じハッシュ、
の繰り返し。`.next` を消してサーバを再起動すると直る。ソースを1回編集するたびに再発したので、
**計測やスクリーンショットは編集を止めてから**やる。
