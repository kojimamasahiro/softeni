# アイデア: 記録中に「すごい」と思った1本をピックし、X 投稿文を作る

## 状況

Idea Backlog。発散フェーズ（2026-09-28）。使う人・印を付けるタイミング・目的までは決まった。
ピックの印と感想の保存・見返しは実装済み（下の「実装」）。リンク先・AI の使い方は未決。

## 目的

- 記録中に主観で「すごいプレーだ」と思った1本に印を付け、動画リンクと感想を添えて X に投稿する。
  **フォロワーが増えたらいい程度**の軽い目的。
- 印を付けること自体を、手間のかかる記録作業を続ける**モチベーション**にする。
- 投稿文は AI にそれらしく作ってもらう。

## ユーザーが興味を持った点

原文（2026-09-28）:

- 「ショート動画の切り抜きではないが、ピックアップできるポイントを記録したい。そしてそのポイントに対して
  Xに投稿用できるような要点のようなものを生成できるようにしたい」
- 「公開された動画のリンクとピックしたポイントの何がすごかったかの感想を添えてXに投稿するイメージだった。
  フォロワーがそれで増えたらいいかなという程度のものだった」
- 「印をつけるのは記録中で、今の記録を進める上で一つのモチベーションになるかと思った」
- 「希少イベントはあくまでデータ上のもので、定量的なものではなく主観の定性部分で、すごいプレーだ、
  ポイントだと思えるシーンをXに投稿したいと思っていた」
- 「何かしらそのポイントをAIで解析してそれっぽいXへの投稿文を考えて欲しかった」
- リンク先は「YouTubeへの直接のリンクを考えていたが、本サイトに飛ばすのもありかと思った」

## 既存機能との違い

- [希少イベント検知](../wiki/rare-events.md)は**データ上の希少さ**（最長ラリー等）を機械が選び、定型文を出す。
  本案は**人の主観で選ぶ**。数字に出ないプレー（前衛のポーチ、粘りのロブ等）が対象。
- [ラリー共有リンク](./2026-09-25-idea-rally-share-link.md)（`?pointId=`、開くとそのラリーだけ再生）は
  リンク先としてそのまま使える。本案はそこに「選ぶ」と「言葉を添える」を足す。

## わかっていること（2026-09-28）

- ポイントには自由記述の `point_note` 列がすでにあり、動画レビューの候補メモが入る
  （`lib/videoReview.ts`）。公開中の 1,272 ポイントで入力は 0 件。ピックの有無を持つ列は無い。
- 記録画面は `src/pages/beta/matches/[matchId]/input.tsx` と `video-review.tsx`。
- AI は動画を見ていない。**何がすごかったかはユーザーの感想が唯一の情報源**で、AI が足せるのは
  データから分かる状況（スコア・ゲームカウント・デュース/マッチポイント・ラリー数・連続得点・
  大会・ラウンド・選手名）だけ。感想なしで書かせるとプレー内容を作り話しやすい。
- ADR-005 はニュース文面について「テンプレートのみ・LLM 不使用」。本案は人が投稿前に必ず読む
  手動投稿で、主役は本人の感想なので同じ制約は当てはまらない（Assumption。採るなら ADR で範囲を明記）。

## 課題・未解決

- リンク先: YouTube のタイムスタンプ付き URL か、本サイトの `?pointId=` か（両方併記もあり）。
  - YouTube: X で動画のカードが出る。ただし再生はそのラリーで止まらない。
  - 本サイト: そのラリーだけ再生、スコアの文脈も見える、GA4 で効果を測れる。OGP は試合共通。
  - Assumption: X は外部リンク付き投稿の表示を絞ると言われる。リンクをリプライに回す手もある。
- AI をどこで動かすか: Claude Code の skill／スクリプト（費用・鍵の管理なし、本人専用）か、アプリ内のボタンか。
- 感想を必須にするか（一言だけでも AI の質が大きく変わる）。
- ピックを試合詳細ページに「記録者のピック」として公開表示するか。
- 保存先: `point_note` を感想に流用し、ピックの有無は新しい列にするか。

## 目指したい方向性（まだ発散フェーズ）

1. 記録画面にピックボタン（★）と任意の一言を足す。この試合のピック数を見せる。
2. 試合を記録し終えたら、ピックごとに「状況（データ）＋感想」から AI が投稿文案を 140 字以内で数案出す。
   人が選んで直し、手動で投稿する。
3. 反応を見て、アプリ内の生成やサイトでのピック表示に広げるか決める。

## 実装（2026-09-28、ユーザー確認済みの範囲）

ユーザー原文:「まずは、一言は任意にして、ボタンを追加とそれが後からわかるようにするだけでお願い。
本サイトにはまだ反映しない」「ボタンは『ポイントを記録』の下に置くのはどうか？」

- 記録画面の「ポイント記録」ボタンの下にピックのトグルと任意の一言欄を置いた。
- 保存先は新しい列 `is_pick` / `pick_note`。`point_note` は公開の試合詳細（`/beta/matches-results/[matchId]`）に
  表示されているので流用しなかった。静的 JSON の書き出しでも2列を外す。
- 見返す場所は記録画面のゲーム履歴だけ。投稿文の生成・リンク先の判断はまだ。
- 仕様は [score-feature.md](../wiki/score-feature.md)「ピック」。
