# data/ 全体の姓名分割ゆれ 棚卸し（2026-08-29）

## きっかけ

[2026-08-29-intercollegiate-name-split.md](./2026-08-29-intercollegiate-name-split.md) の
女子ダブルス変換で、**同じ人が既存データに複数の割り方で登録されている**ことが見つかった
（谷明日里・温品芽叶子・堀早弥夏・伊東月・津波古莉央・﨑羽姉妹・森未唯菜の7名）。
誤っているほうは決まって過去の `zennihon-university` 取り込みだった、という観察がついていた。
その 7 名以外にどれだけあるかを `data/` 全体で数え、正しい割り方を決めて直した回。

## なぜ実害があるか

選手ページの id 解決は `姓::名` の**完全一致**（`lib/playersIndex.ts` の
`getPlayerNameToId`）。分割がぶれると 1 人の戦績が 2 つの id に割れる。
`data/players/index.json` の `count>=5` が結果ページ生成の閾値なので、
**割れたせいで両方 5 未満になり、結果ページ自体が存在しない**選手が出る。

実測: 147 件の衝突のうち **両方の変種が `count>=5` だったものは 0 件**。
つまり「1 人が 2 ページに分裂」ではなく、**片方が沈んで片方だけが残る**形で効いていた。
修正後に `count` が 5 を跨いで結果ページが新規に立つ選手が **35 名**いる。

## 走査（147件）

`data/` 配下の全 JSON を再帰的に見て、`lastName`+`firstName` を持つオブジェクトを集め、
**連結後の氏名が同じで切り位置が違う**組を列挙した（`temp/` は取り込み途中の作業ファイルなので除外）。

- 氏名（連結後）: 23,963 種
- 分割が 2 通り以上ある氏名: **147 件**
- 出現元: `data/tournaments/details` 1,024、`data/players/index.json` 274、`data/st-league` 6

スクリプト化して `scripts/check-name-splits.mjs` に置いた（未登録の衝突だけ出す。あれば exit 1）。

## どちらが正しいかの判断材料

多数決は使えない。**多数派が誤っていた例が 12 件**あった
（森優士郎・佐久間凜・新日菜子・辻紗弥香・隈田原蓮・上津遊嘉成・北川ジャン瑠加・
川崎谷凌・東圭史郎・森萌々花・西中京太郎・飴󠄀井咲有）。
`primaryschool-championship/2024` のように、誤った側が 1 大会で 10 件以上を占めることがあるため。

実際に効いた材料は次の 3 つ。

1. **出典の独立性**（多数派の件数ではなく、**別系列の大会がいくつ支持しているか**）。
   1 回の取り込みが 10 ファイルに分かれていると件数は簡単に水増しされる。
   例: 谷明日里は `谷|明日里` が 6 系列（インターハイ・ジャパンカップ・西日本・
   全日本選手権・全日本シングルス・インカレ）、`谷明|日里` は `zennihon-university` のみ。
2. **コーパス内の姓・名の頻度**（自分自身を除いた実人数）。
   ただし単独では決まらない。境目を右にずらした誤りは「存在しない姓＋よくある短い名」
   （`森優|士郎`＝姓0/名1）を、左にずらした誤りは「よくある姓＋存在しない名」
   （`小野|寺結`＝姓66/名0）を作るので、**姓の頻度だけ・名の頻度だけを見ると逆の結論が出る**。
3. **別人による姓の裏づけ**。これがいちばん強い。
   - `小津和|悠` … 別人の `小津和|翔`（嬉野・佐賀）が存在する
   - `上津遊|嘉成` … 別人の `上津遊|由真`（久留米クラブ）が存在する（**少数派が正しかった**）
   - `一法師|優吾` … 別人の `一法師|彰太`（大分商）が存在する
   - `羽田野|吏功` … 別人の `羽田野|央祐` `羽田野|結梨` が存在する

最終的な判断は「**もう一方の切り方が日本語の氏名として成立しない**」で決めたものが大半。
`寺結` `木姫菜` `々花`（踊り字始まり）`ャン瑠加`（カタカナ途中切り）`こ|ころ`（かな途中切り）など。

# 追記: 衝突検出だけでは足りない（同日）

「他の大会にも適用できるか」を確かめたところ、**上の走査は原理的に取りこぼす**と分かった。

`scripts/check-name-splits.mjs` は「同じ氏名が2通りの切り方で同居している」ことを見る。
これは**照合の相手がいて初めて成り立つ**。実測すると、`data/tournaments/details` の
氏名 23,889 種のうち **15,214 種（64%）は 1 つの大会シリーズにしか出ない**
（1 大会×1 年だけなら 13,035 種・55%）。1 回きりの取り込みに紛れた誤分割は、
どれだけ走査しても見えない。

## 辞書照合を足した（検出器B）

代わりに、**コーパスを姓・名の辞書として使う**検出を足した。条件は 2 つ。

1. 現在の切り方の**片側**（姓または名）が、自分を除いてコーパスに 1 例も無い
2. **別の切り位置**なら、姓・名の**両方**に実例がある

1 だけでは弱い。「姓も名も他に無い」で絞っても 1,134 件（5%）当たり、
その大半はローマ字表記の外国人選手だった。2 を足すと**22 件**まで落ちる。

確定済みの 141 件で後ろ向きに測ると、誤り側は
**姓が他に無い型 72% / 名が他に無い型 64%**（両方無いのは 37%）。
つまり**片側だけ見る実装は 3 割前後を落とす**ので、両方向を見る必要がある。

実際に挙がったもの（既に人が判断済みの氏名と、検出器Aで出ているものは除外している）:

| 現在 | 別解 | 別解の裏づけ |
|---|---|---|
| 伊藤あ\|かり | 伊藤\|あかり | 姓208 / 名17 |
| 森耕\|太郎（4件） | 森\|耕太郎 | 姓89 / 名2 |
| 日下\|部悠真 | 日下部\|悠真 | 姓10 / 名32 |
| 三井\|田蓮 | 三井田\|蓮 | 姓2 / 名54 |
| 野見\|山颯太 | 野見山\|颯太 | 姓2 / 名35 |
| 西奏\|音 / 西浩\|太朗 | 西\|奏音 / 西\|浩太朗 | 姓23 |
| 菅は\|な | 菅\|はな | 姓5 / 名7 |

`西奏音` と `西浩太朗` は
[2026-08-29-intercollegiate-name-split.md](./2026-08-29-intercollegiate-name-split.md) が
**PDFの座標から**「既存データ側の誤り」と指摘した 3 件のうちの 2 件で、
座標を見なくてもコーパスだけで同じ結論に届いた。検出器の妥当性の裏づけになる。

一方 `五升\|田大冴` `永\|友輔` のように、現在の切り方にも別解にも実例が 1 人しかない組は
機械では決められないので、その旨を明示して人に回す。

## 運用

  `data/players/index.json` には誤分割側の行が `count: 0` で残るので、
  混ぜると**誤りを正例として学習してしまう**。

## 壊れたデータが自分の誤りの裏づけを作っていた

`林|楓恋` を検出器Bが疑ったのは「別解 `林楓|恋` の姓が 1 人実在する」ためだったが、
その 1 人の正体は**同じ誤りの別レコード**だった。

`zennihon-secondaryschool-versus/2024/doubles-none-girls` のエントリー114（土浦クラブ）は、
**ペアの2人の氏名の境目**が 1 文字ずれていた:

```
林楓 | 恋荒  ＋  川 | 琴美      （誤）
林   | 楓恋  ＋  荒川 | 琴美    （正）
```

`林楓恋・荒川琴美` の連結を切り違えたもの。これで `林楓` が姓として辞書に載り、
正しい `林|楓恋` のほうが疑われていた。**裏づけ件数が 1 の別解は、

# 追記3: ゲート化と、検出器Cを足した経緯（同日）

`node scripts/check-name-splits.mjs --strict` を `package.json` の `prebuild` に入れた
（`check-highschool-pipeline-freshness.mjs` の次。実行 0.7 秒で、既存チェック並み）。

## 入れる前に退行を注入したら素通りした

ゲートが本当に効くか確かめるため、確定済みの `西|奏音` をわざと `西奏|音` に戻して回したところ、
**A も B も 0 件で終了コード 0** だった。原因は 2 つの検出器の設計そのもの:

- **A** は「2 通りが同居」を見る。1 件だけ戻ってきたなら同居しないので掛からない。
- **B** は「人が判断済みの氏名」を除外する。判断済みだからこそ除外していたのに、
  その判断と食い違うデータが入ってきた場合まで見逃していた。

**一度直した誤りが取り込みで戻ってくる**のは、ゲートが最も止めたい事象そのものだった。
テストせずに入れていたら、緑のまま素通りするゲートを信用することになっていた。

## 検出器C（既知の誤分割の再混入）

表で `aliases`（＝誤り）と決めた綴りがデータにあれば挙げる。人が誤りと断定済みなので
ヒューリスティックではなく、**`--strict` の有無に関わらず常に終了コード 1**。
出力は該当ファイルまで名指しし、`normalize-name-splits.mjs` を実行するよう促す。

同じ注入で再試験すると `[C] 既知の誤分割の再混入 1 件` で止まり、
指示どおり `normalize-name-splits.mjs` を回すと**注入前のファイルとバイト単位で一致**した
（往復で元に戻ることを確認）。

## 3 つの検出器の分担

| | 見るもの | 効く場面 | 盲点 | 終了コード |
|---|---|---|---|---|
| A 分割衝突 | 同じ氏名の 2 通りが同居 | 複数大会に出る選手 | 1 シリーズにしか出ない氏名（全体の64%） | 常に |
| B 辞書照合 | 片側が辞書に無く、別解は両側ある | 新規取り込み直後・1 度しか出ない氏名 | 判断済みの氏名／別解が無い誤り | `--strict` のみ |
| C 既知の再混入 | 表で誤りと決めた綴りの出現 | 直した誤りの出戻り | 表に無い誤り | 常に |

いずれも**ペアの境界ずれ**（追記2）は拾えない。ここは未着手のまま。
