# 「ソフトテニス インカレ 2026」の掲載順位を上げる（2026-09-09）

## きっかけ

ユーザーからの指摘:

> 「ソフトテニス インカレ 2026」といったワードで検索されるようになってきた。
> ただ、掲載順位が20位台なので、もう少し上げることはできないか検討したい

[2026-09-03 のインカレ alias 対策](2026-09-03-incare-search-alias-seo.md)の事後検証にあたる。
alias 投入によって**圏外から20位台までは来ていた**ので、「literal が無くて圏外」の段階は
終わっており、次の律速は別のところにあるはず、という前提で調べた。

なお会期は 2026-09-05〜09-09 で、**指摘を受けた当日が最終日**だった（悪天候で
選手権ダブルスが 9/9 に延長）。需要のピーク上での実測になっている。

## SERP実測（2026-09-09・in-app browser で直接確認）

「ソフトテニス インカレ 2026」で当サイトが出るのは**3ページ目・概ね28位前後**。

```
/tournaments/university/zennihon-university/2026/singles/none/girls/
```

**女子シングルス**。6種目ページのうち最も需要の小さいものが選ばれていた。

（差は「男子/女子」「ダブルス/シングルス/対抗」だけ）で並んでおり、Google 側に
「インカレ2026」の受け皿を決める材料が無い状態だった。

|---|---|---|

## 律速になっていた3点

### 1. 強いページが「2026」を名乗っていない

ビルド済み `out/` の内部リンク実測（`href` 完全一致）:

| ページ | 被リンク | title に「2026」 |
|---|---:|---|
| ハブ `/zennihon-university/` | **863枚** | なし（歴代のみ） |
| 2026 女子ダブルス | 69枚 | あり |
| 2026 男子シングルス | 45枚 | あり |
| 2026 女子シングルス | 44枚 | あり |
| 2026 男子ダブルス | 28枚 | あり |
| 2026 男子対抗 | 12枚 | あり |
| 2026 女子対抗 | 11枚 | あり |

[seo.md 追記3（2026-08-06）](../wiki/seo.md)でインターハイ vs 全日本シングルスの順位差の
主因と特定したのと同じ構造。**年を名乗るページに評価が集まっておらず、評価が集まる
ページが年を名乗っていない**。

なお高校ハブには 2026-08-01 に「開催中モード」（title/h1/description を
「{通称}{年} 結果・途中経過」へ切替）を入れたが、これは
`/highschool/tournaments/[tournament]` 専用で、**汎用ハブには入っていない**。
インカレ・全中・全日本選手権など汎用ルートの大会は全部この恩恵を受けていなかった。

「結果」「トーナメント表」は SERP に一度も表示されていなかった。冒頭22文字を
`headingName`（＝`略称（正式名称）`）に使い切っている。

| | 枚数 | 中央値 | 最大 | 30全角超 |

| 汎用ハブ | 69 | 38.5全角 | 47.5全角 | 68 (99%) |
| 年度別結果 | 476 | 42.0全角 | 60.5全角 | 476 (100%) |

[seo.md「title の字数超過」（2026-09-09・選手ページ）](../wiki/seo.md)と同じ病気が
大会ページ側にもあった。**あちらは実績フレーズの予算、こちらは名前の予算**で、
原因は別だが症状は同じ。

### 3. 「組み合わせ」を literal で持っていない

関連検索に2回出る語なのに、title / description に literal で0回。
当サイトは 585ペア＋84選手の完全なドローを構造化データで持っている（競合は PDF と
X 投稿）のに、**その資産を検索語で名乗っていなかった**。
「トーナメント表」は同義語であって検索語ではない。

速報クエリで farm と正面勝負しない方針（[seo.md](../wiki/seo.md) #8 / #11）は維持する。
「組み合わせ」はそれとは別で、**farm が PDF リンクしか持てない領域**なので正面から取れる。

### 付随して見つかった取りこぼし2件

- **展望記事** `/news/zennihon-university-2026/` は 6,081字のユニークな本文を持つが、
  title が `label` 直参照で「インカレ」が**ページ全体で0回**。
  `buildTournamentSearchNames` を通しているのはハブと年度別ページの2ルートだけだった。
- **ハブへの内部リンク869本のうち867本**がアンカーテキスト「全日本学生選手権大会」。
  「インカレ」は0本。`out/` 全体で「全日本学生選手権大会」を含むページ925枚のうち
  **808枚が「インカレ」を1度も含まない**（トップページ・選手ページ約800枚を含む）。

## 実装（2026-09-09）

ユーザー選択により、1〜3＋展望記事の4点を実施。**汎用ハブへの開催中モード移植は見送り**
（インカレの会期は当日終了で、優勝確定と同時に自動で歴代モードへ戻る設計のため
2026年分には間に合わない。次の会期前に別途検討する）。

- `lib/tournamentSearchNames.ts`: `titleLeadName`（略称 → 検索名 → label）を追加。
  title の先頭に置く短い名前。`headingName` は h1 / description 側に残す
- 汎用ハブ: title を `{titleLeadName}{最新収録年} 結果・歴代優勝者` に。
  年は**前年以降のときだけ**出す（収録が古い大会で年を出すと「そこで止まっている」
  表示になるだけなので）。判定用の `buildYear` は `getStaticProps` で確定させる
  （コンポーネント側で `new Date()` を呼ぶと年またぎで hydration mismatch）
- 年度別結果ページ: title を `{titleLeadName}{年} {種目} {結果・組み合わせ}` に。
  結果が1件も入っていない種目（`ResultCoverage.status === 'not_recorded'`）は
  「結果」を名乗らず「組み合わせ」だけにする（#11 の開示ルールと同じ扱い）。
  description は「トーナメント表」→「組み合わせ（トーナメント表）」に
- 展望/結果記事（`lib/newsArticle/`): `tournamentMetaOf` が `searchLabel`/`searchAliases` を
  返すようにし、title は `titleLeadName`、description は `headingName` を使う

## 残っている懸念・宿題

- **効果の実測は未実施**。次のクロール・インデックス反映後に GSC で
  「ソフトテニス インカレ 2026」系クエリの掲載順位・表示回数を確認する。
  会期は終わっているので、比較対象は「会期後の残存需要」になる
- **結果データの取り込みが最優先**。title をどう変えても、
  「インカレ2026 結果」で勝つには結果そのものが要る。対抗戦は入っているが
  ダブルス/シングルスは 2026-09-09 時点で「組み合わせ掲載・結果は今後反映予定」のまま
- **汎用ハブへの開催中モード移植**は未着手（今回見送り）。
  全日本選手権・全中・全日本社会人など汎用ルートの大会の次回会期前が期限
- **高校大会の news 記事は今回の恩恵を受けない**。高校全国大会の略称マスタは
  `lib/highschoolNationalTournamentMeta.ts` 側にあり、`index.json` の
  `searchLabel`/`searchAliases` が空のため、`/news/highschool-championship-2026/` の
  title は「全国高等学校総合体育大会2026 展望…」のままで「インターハイ」literal が無い。
  マスタが3つに分かれている問題（`tournamentSearchNames.ts` 冒頭のコメント参照）が
  そのまま出ている
- **内部リンクのアンカーテキスト**（867本が「全日本学生選手権大会」）は未着手。
  「同じフレーズの機械的な反復」への警戒（seo.md #2 追記）があるので、
  展開するなら主要導線に限るなどの設計が要る
- `.claude/launch.json` に `autoPort: true` を足した。ポート3000 を別プロセスが
  掴んでいる状態でも検証用 dev サーバを起動できるようにするため
