# X（旧Twitter）の投稿から見たユーザーの課題（2026-09-17）

## きっかけ

ユーザーの依頼: 「Xに投稿されている内容で、アイデアとして使えそうな課題のようなものがないか調べてほしい」。

[ユーザーの課題を体系的に見つける](./2026-09-06-idea-user-problem-discovery.md) の続き。
あちらの信号の棚卸しは GA4 / GSC / `out/` / 問い合わせで、**X は入っていなかった**。
X は「サイトに来る前の人」の声を直接読める唯一の場所で、GA4 が「来た人が何を探したか」を
示すのと補い合う。

## 方法

- Web 検索（`site:x.com`）は**発信者のアカウントしか出ず、困りごとの投稿は拾えない**。
  X 内の検索（ログイン済みの Chrome）で「最新」タブを読んだ。
- 13本の検索（「教えて／分かる方」「配信＋見れない」「結果＋どこ」「組み合わせ＋見づらい」
  「戦績／ランキング＋知りたい」「ソフテニ」「アプリ／サイト＋欲しい」「スコア＋アプリ」
  「タイムテーブル／進行／コート割」「PDF／画像＋見にくい」「オーダー＋教えて」
  「歴代／過去の結果」「出身中学／ペアだった」）で延べ506件を集め、目視で仕分けた。
- 読んだだけで、いいね・返信・投稿などの操作はしていない。
- **限界**: X 検索は網羅的でなく、並び順も不透明。件数は「需要の大きさ」ではなく
  「そういう声が実在する」ことの証拠としてだけ使う（Assumption）。
- `@its_raining_now` の投稿は softeni-pick.com へのリンクを貼っており、**当サイト自身の告知と
  思われる**ため、需要の証拠から外した（Assumption）。

## 追記（2026-09-17・同日）: 高校選抜のオーダー読み取りの試作

ユーザーの判断: 「試作からお願い」。対象は全日本高校選抜の JSTA 記録 PDF（2025・2022 の男女4ページ）。
試作スクリプトはセッションのスクラッチ領域に置いた（リポジトリには未追加）。以下は方法と結果。

### 方法

1. `pdftotext -bbox` で語ごとの座標を取る。2022 女子は**1文字ずつ別の語**になっているので、
   同じ行で間隔 4.5pt 未満の1文字の語をつなぐ（名前の中の字間は約3pt、姓と名の間は約7pt）。
2. 「－」1つを1対戦とみなし、同じ行の語を最も近い「－」に割り当てて左右に分ける。
   **「・」が無い行は学校単位の本数の行なので捨てる**（決勝の「東北 1 － ② 高田商」など）。
   トーナメント線の横の本数が名前の行に紛れ込むので、名前からは数字を除く。
3. 同じ x で縦に並ぶ3つの「－」を1試合の塊にする。
4. 塊を当サイトの試合（`matches`）に割り当てる。
   - **両校とも初戦の試合**は、塊が2校のエントリー行の中間（±4pt）にあるので位置で決まる。
   - それ以外は**選手の重なり**で決める（左の選手が a 校の、右の選手が b 校のこれまでの選手と重なる塊）。
     同点なら勝敗の一致、次に位置の近さ。決勝はページ中央の塊。
   - 3回戦以降の塊は2校の中間に来ない。位置だけで決めると、準々決勝の塊が別の2回戦の中間と
     偶然重なって取り違えた（2025女子で発生）。
5. 左のペア＝エントリー番号の小さい学校、右＝大きい学校（全塊で成立）。

### 結果
