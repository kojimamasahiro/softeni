# 2022年全日本社会人 一般男子: アウトライン化PDFをOCRなしで取り込んだ

## 前提（前回の結論をひっくり返した）

[2026-08-20-zennihon-workers-2022-pdf-entries-ocr-finding.md](2026-08-20-zennihon-workers-2022-pdf-entries-ocr-finding.md)
で「1〜8ページ（一般男子）はテキスト層が無く、tesseractでは氏名の誤読率が高すぎるので見送り」と
判断した。この判断は **「画像化してOCRにかける」という前提でしか検証していなかった**。
今回その前提を外したところ、OCRを一切使わずに全325エントリーを取り込めた。

## 何が見えていなかったのか

`page.get_drawings()` が返す 2140 個の fill path は、**1 path = 1文字**にきれいに対応している。

- `even_odd` 塗りで、口や日の「穴」も同じ path の中に入っている（＝文字が分割されない）
- 文字の外接矩形がそのまま取れる（＝文字の切り出しに推定が要らない）
- 同じ文字は同じベクター形状（＝同一性の判定が、画像認識ではなく形状の一致で済む）

つまりこのPDFは「文字が読めないPDF」ではなく **「文字コードだけが落ちたPDF」** だった。
OCRが解くべき問題（文字の位置を見つける・文字を切り出す・同じ文字かどうか判断する）のうち、
最後の1つ以外はPDFの中にデータとして残っていた。ここを見落として画像化した瞬間、
その情報を全部捨てて、tesseractに一から解かせていた。

**教訓**: テキスト層が無いPDFを見たら、まず `get_drawings()` を数えて、パス数が文字数と
同じオーダーかを確認する。同じなら「アウトライン化されただけ」で、OCRは要らない。
本当にOCRが要るのはスキャン画像（パスではなくビットマップが1枚入っている）のとき。

## 実際の手順

`scripts/pdf/zenshakai_outlined_glyphs.py` に実装した。

### 1. 構造の抽出（座標だけで完結）

括弧 `(` `)` が固定X座標にあるので、これを各エントリーのアンカーにする。
氏名 / 都道府県 / 所属 / エントリー番号は列のX範囲で分ける。

**検算になった性質**: ページ順 → 左半分→右半分 → 上から下 に並べると、エントリー番号は
1から通し番号になるはず。**エントリー番号の数字の桁数**（1桁/2桁/3桁）が、全325件で
期待値と一致した。文字が読めない段階で構造の正しさだけ確認できるのが良かった。

なお本大会は **314ではなく325エントリー**だった（前回メモの314は誤り）。

### 2. 同じ文字をまとめる

6858文字を、レンダリング画像の類似度（32×32 平均プーリング + 3×3 ぼかしのコサイン類似度、
閾値0.975、字高・字幅の差 0.9pt 以内）でクラスタリングして **約1240クラス**に圧縮。
1文字ずつ読む必要がなくなり、かつ「同じクラスは必ず同じ文字」なので**表記が勝手にブレない**。

### 3. 9ページ目を正解セットにする（ここが効いた）

9ページ目「男子＜ベスト64＞」は通常のテキスト層を持ち、しかも**エントリー番号つき**で
64組128名の氏名・都道府県・所属が読める。これを1〜8ページのグリフ列に位置で突き合わせると:

- 325エントリー分のエントリー番号の数字（867文字）
- ベスト64の氏名・都道府県・所属（1139文字）

が機械的に確定する。**1240クラス中523クラスが自動でラベル付けされ、氏名欄の文字の77%が
読み取り不要になった**。しかも「1クラスに2つの異なる文字が入る」矛盾が(Latin大小の全半角を
除いて)出なかったので、クラスタリングの正しさの裏取りにもなった。

### 4. 残りをビジョンで1回ずつ同定

残り613クラスだけを1セル150pxで並べた画像（18枚）にして読ませた。1文字が大きく、
1クラス1回で済むので、tesseractに小さい文字を延々読ませるのとは別物の難易度になる。

**モンタージュは字高で正規化する**（幅で正規化してはいけない）。幅で正規化すると
土と士が完全に同じ絵になり、見分けられなくなる。ここで一度間違えた。

### 5. 紛らわしい字はベクターの実寸で決める

土/士、末/未 のように「棒の長さの比だけが違う」字は、**目で見ると間違える**（実測: 72文字の
盲検で唯一の誤りがこれ）。ベクターがあるので、横棒の実寸を測れば確定する。

- 土 = 上の棒381 / 下436、士 = 上432 / 下398（60倍描画時のピクセル幅）
- 末 = 437/396/437（1本目が長い）、未 = 401/445/436（2本目が長い）

さらに重要なこととして、**この2字はクラスタリングでも同一クラスに混ざる**（正規化すると
形状が一致してしまう）。クラスの代表ラベルを信じず、1文字ずつ測り直す実装にした。
これで entry 36「畑本理士」・entry 307「福士大生」・entry 198「富士通小山」が直った
（クラス代表ラベルのままだと全部「土」になっていた）。

### 6. 文脈でしか決まらないもの

同形なので画像では決まらない字は、前後の文字種で寄せる（全件を要確認リストに列挙）。

- 小書きカナ: 字高が行の8割未満 → ッ ャ ュ ィ（ヨネックス、ホールディングス等）
- 同形の漢字→カタカナ: 前後がカタカナのときだけ 二→ニ, 工→エ（浜松ホトニクス、フェニックス）
- 同形の漢字→英字: 前後が英字のときだけ 乙→Z（ZERO）
- 中黒 `・` か句点 `.` か: 下端の中央値（＝ベースライン）からの高さ
  ※ 最大値でベースラインを取ると g/y のディセンダに引っ張られて誤判定する
- 英字の大小: 行の最大字高との比（C/c O/o S/s は字形が同じ）

## 精度（実測）

### 盲検テスト

ベスト64の64エントリーのうち**32エントリーを正解セットから外し**、そこで新たに必要になった
102クラスをビジョンだけで同定して、9ページ目の正解と突き合わせた。

| | 結果 |
|---|---|
| 氏名の完全一致 | **64/64 (100%)** |
| 文字単位 | **252/252（誤読0文字）** |

同じ画像に対する `tesseract -l jpn --psm 10` は **5/72（7%）**。

### 最終データの検算

- 9ページ目の正解と: 氏名 128/128、都道府県 128/128、所属 128/128
- 所属名224種すべてが本プロジェクトの既存大会データに実在する表記と一致（新規表記ゼロ）
- 都道府県41種すべてが実在の都道府県名
- `npm run check:entries` エラー0
- 既存選手辞書（18,543名）に無い氏名201名のうち、**姓が辞書に一度も出てこない26件は
  PDF原本を拡大して1件ずつ目視照合**（すべて印字どおり）

### 正解セット自体の誤記

9ページ目のテキスト層は万能ではなかった。entry 36 は9ページ目では「畑本理土」だが、
ドロー表の実測は「理士」で、本プロジェクトの選手辞書にも「畑本理士」がある。
**正解セットも一次資料の1つでしかない**（ドロー表とベスト64表で版が違う可能性がある）。
