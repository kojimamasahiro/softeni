# インカレの姓名分割 4件の修正（2026-09-11）

## きっかけ

ユーザーから「2022年の選手名を修正してほしい」として4件の指定。

| 指定（誤 → 正）|
|---|
| 新 \| 和日菜 → 新和 \| 日菜 |
| 磯美 \| 咲希 → 磯 \| 美咲希 |
| 横江 \| 川澪 → 横 \| 江川澪 |
| 平駿 \| 一 → 平 \| 駿一 |

## 実際の所在は2022年だけではなかった

依頼は「2022年の」だったが、誤分割の実体は**2022〜2026年に散っていた**。

| 誤 | 正 | 所在 |
|---|---|---|
| 新 \| 和日菜 | 新和 \| 日菜 | 2022 女子ダブルス |
| 平駿 \| 一 | 平 \| 駿一 | 2022 男子ダブルス |
| 磯美 \| 咲希 | 磯 \| 美咲希 | **2023・2024** 女子ダブルス |
| 横江 \| 川澪 | 横江川 \| 澪 | **2024・2025・2026** 女子ダブルス |

**2022年だけ直すと年跨ぎの同一人物性が壊れる**（`磯美|咲希` は2022年が既に `磯|美咲希` で、
2023/2024だけが誤りだった）。年を限定せず全件直した。

`scripts/check-name-splits.mjs --strict` は**4件すべてを事前に検出していた**
（[A] 分割衝突 2件 ＝ 新／磯美、[B] 辞書照合の疑い 2件 ＝ 横江／平駿）。
依頼を受けてから探すのではなく、このチェッカを定期的に見ればよい。

## 横江の1件だけコーパスと食い違った

ユーザーの当初の指定は `横 | 江川澪` だったが、`data/tournaments/details/**` の
`participants` を全数集計すると裏づけが無かった。

| 分割 | 姓の他の実在数 | 名の他の実在数 |
|---|---|---|
| 横 \| 江川澪 | **0** | **0** |
| 横江 \| 川澪（現状）| 7（横江忠彦）| 0（本人のみ）|
| 横江川 \| 澪 | 1（**横江川黎**・滋賀短期大学）| 15 |

`check-name-splits.mjs` の別解も `横江川 | 澪` を提示していた。
これを提示したところユーザーが `横江川 | 澪` に訂正。**別人による姓の裏づけ**
（wiki が「いちばん強い」とする根拠）が効いた形。

他3件はコーパスとユーザー指定が一致（`平 | 駿一` はチェッカの別解とも一致）。

## 手順

wiki `team-player-identity.md` の既定の流れどおり。

1. `data/players/name-split-aliases.json` に `canonical` / `aliases` / `reason` を追記
2. `node scripts/normalize-name-splits.mjs --dry-run` → `node scripts/normalize-name-splits.mjs`
   - 前半3件: 4ファイル / 12箇所、後半1件: 3ファイル / 9箇所
3. `tools/incare-2022/*.initialPlayers.json` と `tools/incare-2026/doubles-none-girls.initialPlayers.json`
   の `lastName` / `firstName` / `tempId` も手で揃えた（再取り込み時の再混入を防ぐため）
4. チェッカ再実行: 分割衝突0 / 辞書照合の疑い0 / 再混入0

`tempId` は `姓_名_所属_都道府県` の**4項目**なので、姓名を変えたら tempId も変わる。

## 踏んだ落とし穴: `extract-players.mjs` を回してしまった

`normalize-name-splits.mjs` は `data/players/index.json` の **`count` しか更新しない**ため、
誤分割の行（`磯美|咲希` id=6422、`横江|川澪` id=6476）が `count: 0` で残った。
これを直そうとして `node scripts/extract-players.mjs` を実行したところ:

```
wrote 30161 players (preserved 18543 existing, appended 11618 new players)
```

**11,618人を一気に新規採番**してしまった。wiki に「丸ごと再生成しない」と明記があり
（2026-08-29 時点の見積もりは5,523人）、取り込みが進んで**倍以上に増えていた**。
バックアップから戻し、該当2行だけ文字列置換で改名した（id は保持、count は実データで3）。

### さらに: JSON を読み書きし直すと差分が爆発する

戻したあと Python の `json.dump(indent=2)` で書き直したところ、
`index.json` の**1行1エントリの整形が崩れて 111,258行の差分**になった。
元の形式は `  { "id": 1, "lastName": "…", "firstName": "…", "count": 15 },` の1行。
**行単位の文字列置換で直すこと。** 最終的な差分は25行に収まった。

## 副次的な確認

- `data/ratings/current.json` と `data/rankings/*.json` は
  **姓名を連結した `playerName`**（`新和日菜` 等）で保持しているため、分割の変更で壊れない
- `平 | 駿一` は index.json に**元から行が無い**（誤分割側も正しい側も）。
  上記の未採番11,618人に含まれる。今回は1人だけ足すことはせず放置した
- 高校データは1件も触っていないので `npm run highschool:pipeline` の再実行は不要
- `check-tournament-entries` / `check-tournament-insights` / `check:orphans` はいずれも問題なし
