# 大学カテゴリ: チーム名データの下ごしらえ（棚卸しと修正）

2026-08-12 棚卸し、**2026-08-14 適用済み**。
[大学カテゴリの公開ページ検討](./2026-08-12-idea-university-category-pages.md)の前提条件として、
大学のチーム名を全数点検して修正した。

## 適用の結果（2026-08-14）

| 指標 | 修正前 | 修正後 |
|---|---|---|
| 大学チーム数 | 186 | **163** |
| 収録試合の中央値 | 20 | **25** |
| 試合5未満の割合 | 25.8% | **16.6%** |
| 試合15以上 | 103 | 103 |

`check-identity-health.mjs`: `playerIds 参照切れ 0` / `participant id 重複 0`。
統合してはいけないペア（`成蹊大学`/`大阪成蹊大学` ほか）はすべて無傷。
残る「別名のまま残る出場 4」は本作業と無関係の既存項目。

保留したものは末尾の「保留中」節にまとめてある。

## 最大の教訓: 大学大会だけを見ていては足りなかった

**初回の棚卸しは大学専用3大会（`zennihon-university*`）しか見ておらず、取りこぼしがあった。**
大学生は一般大会（全日本選手権・全日本シングルス・東日本・西日本・国際予選）にも出るので、
**大学名は大学大会の外にも現れる**。適用後に `teams.json` を再生成して初めて
`神松蔭大学` `神戸松蔭学院大` `立教大` `石川工業高専` が見つかった。

次にカテゴリを増やすときは、**そのカテゴリの専用大会ではなく
「そのカテゴリの所属として現れる全出場」を母集団にして棚卸しすること**。
大学の場合は `participants[].prefecture` が `日本学連` / `学連` になるのでこれで拾える。

## 対象と規模

対象は大学専用大会3種（`zennihon-university` 2023–2025 / `zennihon-university-indoor` 2025 /
`zennihon-university-ouza` 2026）の `participants[].team`。

- 生のチーム名 **186種 / 延べ 5,959件**
- **要修正 67件（1.1%）／ 26種**
- 修正後のユニーク校は **約160校**

**当初「表記ゆれはほぼ0」と評価したのは誤り**だった。単純な正規化（括弧除去・語尾除去）で
突き合わせると0件に見えるが、実際の壊れ方が「**先頭1〜2文字の脱落**」なので、
`岡大学`（← 福岡大学）のように**正規化後も別キーのまま残る**。中学の表記ゆれ（出典差による
略称 vs 正式名称）とは壊れ方が違い、検出方法も違う。

## 校名の分裂（誤りではないが、ページ化の前に判断が要る）

`神戸松蔭女子学院大学` は **2025年に `神戸松蔭大学` へ改称**しており、データにも両方が出る
（本間友里那・石原愛菜など複数の選手が両方に出現）。上記1・3の誤りを直しても
**正しい表記が2つ残る**。

- 1校1ページにするなら「改称は同一エンティティ」として統合が要る
- 高校カテゴリには同型の前例が無い（高校の改称は収録期間に発生していない）
- 大学ページを作るなら**改称の扱いを最初に決める**べき論点。他大学でも今後起きる

## 適用の手順（実施済みの順序）

既存の仕組みがそのまま使えた。同じ作業を他カテゴリでやるときの手順として残す。

1. **`教大学` の2ペアを先に手で直す**（位置指定）。同一表記が2校に対応するため
   alias 表では扱えない。`participants[].team` / `.id` / `entries[].playerIds` の3箇所を
   直前の `"id"` 行の人物で判定して置換した。**alias 表に `教大学` を入れてはいけない**
2. `data/tournaments/team-name-aliases.json` に 1対1で直せるぶんを追加する。
   ADR-013 に従い `scope: { tournamentPrefix: [...] }` を付ける
   （`西大学` `理大学` のような断片は文脈外で当たると危険なため）
3. `node scripts/normalize-team-names.mjs --scope=<大会> --dry-run` → 本適用。
   **`--scope=all` は使わない**（無関係の大会に既存の未スコープ alias が当たる）
4. `scripts/build-team-master.mjs` で `teams.json` を再生成
5. **再生成後の `teams.json` をもう一度点検する**。ここで初めて一般大会側の漏れが見つかった
6. `scripts/check-identity-health.mjs` で `playerIds 参照切れ` / `id 重複` が 0 であることを確認

## 再現方法

集計はワンショットのPythonで実施し未保存。再現するには
`data/tournaments/details/{zennihon-university,zennihon-university-indoor,zennihon-university-ouza}/{year}/*.json`
の `participants[].team` を集め、

- 「他のチーム名の**末尾一致の断片**になっている名前」を探す（先頭欠落の検出）
- 「他のチーム名の**先頭一致の断片**になっている名前」を探す（末尾欠落の検出）
- `unicodedata.normalize('NFKC', name) != name` を探す（異体字の検出）
- 各候補について**同一選手が他の年に所属している正準名**を突き合わせて確定する

とすればよい。**選手照合が決め手**で、名前の一意性だけでは `西大学` `教大学` `淑徳大学` を
誤って寄せてしまう。
