## 読み取り方

公式サイトは Vue の SPA で、日程データは JSON の HTTP リクエストとしては見えなかった（WebSocket 等と推測。**Assumption**）。
画面の `main` の innerText を行に分けて読んだ。1試合は
`時刻 / 種目 / 組 / Match N / 会場 / コート / (NOC, 名前...) ×2 / 状態` の並び。

- 団体は NOC の次の1行が国名。個人は NOC の次に「姓（大文字）/ 名」が人数ぶん並ぶ
- **姓が3文字（KIM・LEE・ALI）だと NOC と区別できない**ので、NOC かどうかを文字の形で判定せず、
  種目から人数（シングルス1・ダブルス2）を決めて読み進めた
- 131試合を読み、うち対戦カードありが96試合。日本の組の37試合を `tools/asian-games-2026/draw.json` に転記した

## 実装

- `tools/asian-games-2026/build_details.py` が `draw.json` から 5種目の details を作る。
  「組が総当たりとして完全か（n(n-1)/2 試合・重複なし）」「各組に日本がいるか」「participants と entries の参照が一致するか」を検査し、
  食い違えば止まる
- 日本選手の id は 2026年の全日本シングルスの表記に揃えた（`天間_麗奈_日本体育大学_日本学連` など）。
  黒坂・天間・前田は所属が大学なので都道府県欄は `日本学連`
- 検査: check-tournament-entries / check-orphan-entries / check-duplicate-placements / bracket:verify（不一致0）/
  check:upcoming / check-name-splits --strict すべて問題なし
- **prebuild の高校データ鮮度チェックが落ちた**。02result は index.json に載っていて details を持つ大会を全部読むので、
  大会フォルダが増えるとハッシュが変わる。`npm run highschool:pipeline` で解消（コリアカップと同じ扱い）。
  worktree ではシステムの python3 に `pykakasi` が無く、本体の `.venv` を PATH に通して流した

## 見つかった不具合: 未実施の試合が集計と表示に入っていた

prebuild の差分で、上松・黒坂・丸山の `analysis.json` の試合数が増え、勝率が下がっていた
（上松 273 → 277 試合、勝率 91.2% → 89.9%。「最新の試合」もアジア大会になった）。

- 原因: `lib/playerStats/facts.ts` が `winnerEntryNo` の無い試合を `result: 'draw'` として数えていた
- **既存データにも同じ形の試合が18件あった**（日本代表予選会2025の準々決勝8件・東海ブロック2026の準々決勝8件・
  全日本社会人2026の2件。いずれも勝者なし・スコア空）。上松の 273 は本来 272（249勝23敗）で、既に1試合多かった
- 修正後、差分が出た9人全員で「試合数＝勝ち＋負け」になった（広岡・黒坂・丸山・長江・塚本・上田・上松・上岡・矢野）
- 結果ページでも同じ試合が「0-0」と出ていた。`MatchRow.unplayed` を足して「未実施」と表示
- 最初は `typeof winnerEntryNo === 'number'` で判定したが、結果ページでは直らなかった。
  `lib/packedPageData.ts` の unpack が勝者なしを `-1` にするため。「勝者が対戦者に含まれるか」で判定するようにした。
  勝者が対戦者に含まれずスコアも空の試合は既存データに0件なので、集計への追加の影響は無い
