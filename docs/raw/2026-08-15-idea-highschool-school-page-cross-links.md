# アイデア: 高校学校ページの回遊強化（横リンクの新設）

## 状況

Idea Backlog / 発散フェーズ（2026-08-15）。SEO（M4検証まで一巡）の次のテーマとして「回遊を高める」を
検討した最初のノート。目的と着手先はユーザー決定済み、モジュールの設計と検証方法は未確定。

## 目的

**PV増＝AdSense収益**（ユーザー選択）。検索から深いページへ着地したユーザーに「次の1クリック」を作る。
SEO（GSC）とは別の物差しが要るテーマで、これまで回遊が単独テーマとして扱われたことはない
（ADR-006の2ペインナビ、ADR-009のSTリーグのリンク化、選手一覧ページ改修はいずれも別施策の副産物）。

## ユーザーが興味を持った点

「SEOの次は回遊を高めたい。どこからどういうふうに攻めたらいいか検討して」。
目的の選択肢（PV/AdSense・内部リンクによるSEO底上げ・リピーター化）のうち **PV増＝AdSense収益** を選択。
着手先は3案（高校学校ページの横リンク／計測基盤を先に／薄いページの中身を埋める）のうち
**高校学校ページ698枚に横リンク** を選択。

## わかっていること（ビルド済み `out/` 4,243枚の実測・2026-08-15）

計測方法: `out/**/*.html` の `<main>` 内の `href="/..."` のみを対象（サイドナビ `aside[data-sidebar]`・
フッターは `<main>` の外なので自動的に除外される）。重複リンク先は1本に畳んでいる。

### 構造的な欠落（3点）

1. **横移動（同種ページ間のリンク）が選手ページにしか存在しない**。
   `player:results → player:results` は 6.0本/枚あるが、`hs:school → hs:school` は **0本**、
   `jhs:team → jhs:team` も **0本**。学校ページのFAQには「同じ都道府県の他校も見られますか？」という
   設問が既にあるのに、答えは県ページへ1本戻すだけ（＝他校まで2クリック）。
2. **着地の主力ほどリンクが薄い**。高校学校ページ698枚のうち **68%（472枚）が本文リンク10本以下**
   （p10=5 / p25=5 / med=7 / p75=14 / p90=29）。中央値ページ（帯広農・男子）の内訳はトップ・県・性別・
   大会一覧の定型4本＋大会年度別3本で、実質的な「次の1クリック」は3本しかない。
   一方、強豪校は最大115本（尽誠学園・男子）まで伸びており、**薄さは長いテール側に集中**している。
   選手結果ページは10本以下が0枚。
3. **器が空のページ群**（今回の着手先ではないが記録）。大会ハブ127枚の25%が本文105字未満、
   チーム年度ページ306枚が438字。回遊の行き止まり以前に、そもそも中身がない。

### 学校ページに足せる「横リンクの在庫」の実測

高校の全国3大会（IH・ハイジャパ・選抜）＋東海選抜＋9ブロック大会の details 94ファイルから、
参加者の `team`/`prefecture` を学校ページURLへ解決して集計。

| 候補モジュール | 全698枚での件数 | 薄い472枚での件数 | 判定 |
|---|---|---|---|
| 同県の他校（ページが実在するもの） | med=7 / p25=5 / p75=10 / **0件のページ0枚** | med=7（同左） | **唯一、全ページで成立** |
| 団体戦で直接対戦した学校 | med=0 / **0件が361枚（52%）** | **0件が344枚（73%）** | **棄却**（薄いページを救えない） |
| 同じ大会・同じ種目に出た学校 | med=184 | med=159 | 多すぎて絞り込み設計が別途必要 |

- 「直接対戦」が使えないのは、多くの学校が**個人戦のみの出場**で団体戦に出ていないため。
  DB由来で一番面白い切り口だが、薄いページを厚くするという当初の狙いとは対象が逆。
- 「同県の他校」の規模: 県×性別グループは94、1グループの学校数は min=3 / med=7 / max=18。
  同県他校が3校未満のページは698枚中12枚のみ。
  追加される内部リンク総数は **上限5校で3,293本 / 上限8校で4,472本 / 上限10校で4,884本**。
- 既存資産の再利用が効く。`getPrefectureTopSchools`（`lib/highschoolRanking.ts`、
  モジュールスコープキャッシュ付き）が既に都道府県ページの「県内強豪校」上位5校で使われており、
  同じ関数で学校ページ側にも出せる。**新規URLはゼロ**（seo.md の「新規URLを増やさない」方針に適合）。

### 選手ページへのリンクは上限15%（別要因）

学校ページ698枚には**メンバーが延べ8,264名**掲載されているが、選手結果ページへのリンクは
**1,237本＝15.0%** しかない。メンバー節を持つ676枚のうち **437枚は選手リンク0本**。
ただしこれは ADR-009 型の「断線バグ」ではなく、**選手ページの生成閾値**（`data/players/index.json`
の `count >= 5`）による構造的な上限。全18,543選手の内訳は count=1 が9,690人、2〜4が6,937人、
5以上が1,916人で、**ページが存在するのは10.3%**。学校ページ側の実装を直しても15%は動かない。

## 課題・未解決

- **PVを増やす目的に対して「同県の他校」が本当にクリックされるか**が未検証。全ページで成立する在庫では
  あるが、クリック動機の強さは「直接対戦した学校」より弱いと考えられる（Assumption）。
  一方で県ページ経由の2クリックを1クリックに縮めるので、2本目のクリックが発生する確率自体は上がるはず。
- **絞り方が未決**。(a) 同県の強豪校 上位5校（`getPrefectureTopSchools` そのまま）、
  (b) 同県の他校を全列挙（med=7・max=18なので全部出しても成立する）、(c) 両方の混成。
  (b) は都道府県ページの学校一覧の再掲になるため、県ページのPVを食う可能性がある。
- **計測手段が無い**。SEOにはGSCという共通の物差しがあり、M4検証ランブックまで作れたが、回遊にはそれが無い。
  GA4は導入済みだが consent default denied ＋ 目視確認のみで、「どのページに着地して何本目で離脱したか」
  を読む手順書が存在しない。施策の合否を判定できる状態を作らないと、打っても棄却も採択もできない。
  最低限、着手前後で読む指標（着地ページ別のセッション数・エンゲージメント・1セッションあたり閲覧数）と、
  できれば内部リンクモジュールのクリックイベントを決めておく。
- 中学チームページ293枚（`jhs:team → jhs:team` も0本、88%が10本以下）は同じ処方が効くはずだが、
  今回はスコープ外。高校で効果が確認できてから横展開する。

## 追記（2026-08-15・計測手段を先に整備した）

上の「課題・未解決」のうち**計測手段**を先に片付けた。ユーザーの選択は「絞り方より計測から」。
成果物は [回遊検証ランブック（GA4 / AdSense）](../wiki/circulation-verification.md)。M4検証ランブックの構成に揃えている。

設計の要点（詳細はランブック本体）:

- **主指標を、同意状態に依存しない「モジュールCTR」に置いた**。`internal_link_click` ÷ `page_view` の
  イベント比なので、セッション結合が成立しない未同意ユーザーが混ざっても比として読める。
  当初想定していた「1セッションあたり閲覧数」は副指標に降格。理由は下記。
- **Consent Mode の実装自体は正しかった**（`_app.tsx` は default denied ＋ `wait_for_update: 500` ＋
  再訪ユーザーの復元を初回 page_view より前に実施）。問題は実装の質ではなく、
  **同意したか拒否したかを一度も送っていないので同意率が分からない**こと。未同意でも cookieless ping で
  イベントは届くが `_ga` cookie が無く client_id が固定されないため、**セッション系の指標は同意率が
  動いただけで上下する**。Google のモデリングはトラフィック要件があり当サイト規模では適用されない見込み（Assumption）。
- **対照群を選手結果ページ1,916枚に取る**。施策は学校ページにだけ入れるので、同期間の選手結果ページとの
  差分で季節変動・同意率変動・アルゴリズム変動を打ち消せる。M4と同じく母数が小さくp値判定はできないため、
  **閾値判定＋対照群**で代替する。複数種別に同時に施策を入れると対照群が消えるので、1種別ずつ入れる。
- **最終判定はPVではなくAdSense収益総額**。回遊で増えるのは2ページ目以降のPVで、検索着地ページより
  ページRPMが低くなりやすい（Assumption）。**PVが増えてもRPMが希釈されて収益が横ばい**があり得るため、
  PV・RPM・収益の3つをセットで記録する。
- **ベースラインは平常期（2026年9月末〜10月上旬の連続28日）**に取る。8月はインターハイ2026（会期最終日8/7）で
  着地ページの構成が平常期と別物になるため。M4の平常期チェックと同じタイミングに寄せて一度の作業で済ませる。

### 実装が要る前提（手順0・未着手）

1. `src/pages/_app.tsx` の `handleAccept` / `handleDecline` に `consent_accept` / `consent_decline` イベント（各1行）
2. 回遊モジュールのクリックイベント `internal_link_click`（`module` / `from_type` / `to_type`）。
   **既存の本文内リンクにも付ける**と、新モジュールが既存リンクのクリックを食っただけなのか判別できる
3. GA4 のカスタムディメンション登録（`module` / `from_type` / `to_type`、イベントスコープ）。
   **登録前のデータは遡って探索で使えない**ので、1・2 のデプロイ前か同時に登録すること

### 残る未決

- 絞り方（(a)同県の強豪校 上位5校 / (b)同県の他校を全列挙 / (c)混成）は未決のまま。
  ランブックの手順2-2（経路データ探索）でベースラインの次クリック先の偏りを見てから決めると、

### 設計判断（なぜこの形にしたか）

- **個々のリンクコンポーネントを触らず、`<main>` への委譲リスナー1つにした**。
  リンクは4,243ページに散らばっており、1つずつ計装すると差分が巨大になるうえ、
  付け忘れたリンクが静かに欠測になる。委譲なら**既存の本文内リンクが最初から全部計測対象**になり、
  手順4の「共食い判定」（新モジュールが既存リンクのクリックを食っただけか）が初回から成立する。
- **モジュール分離は `data-link-module` 属性**。新しい節を作るときに属性を1つ足すだけで `module` が分かれ、
  付けなければ `unclassified` にまとまる。計装のためにコンポーネントのAPIを変えなくて済む。
- **計測対象を `<main>` 内に限定**したのは、サイドナビ（`aside[data-sidebar]`）とフッターが
  全ページ共通の定型リンクで「そのページが次のクリックを作れたか」の測定対象ではないため。
  この線引きは `out/` の静的解析と同じ定義にしてあり、**静的リンク本数と GA4 のクリック数を
  直接突き合わせられる**（例: 学校ページの本文リンク中央値7本に対して何クリック出るか）。
- **capture フェーズで拾う**。React のルーティングが先に走っても取りこぼさないため。
- **同意状態を見ずに常に送る**。未同意でも cookieless ping でイベントは届き、
  イベント比である主指標はセッション結合の成否に影響されないため。
