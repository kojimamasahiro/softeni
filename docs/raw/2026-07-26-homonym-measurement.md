# 実測: 同姓同名（名寄せ）の規模と、機能別の誤マッチ率

## 状況

2026-07-26 実施。`news-context-blocks.md` の Open Questions 3 件
（`milestone` 語彙確定 / `head-to-head` 導入可否 / 世代跨ぎ照合の解禁条件）が
すべて「名寄せ精度」という単一の根に帰着することが棚卸しで判明したため、
**設計に入る前に問題の大きさを測る**目的で実施した。

## なぜ測ったか

> 「問題の大きさが分からないまま検証方法を設計すると、過剰にも過小にもなりがち」

Open Question の文言は「名寄せ精度の**検証方法**が無い」だったが、実際には
`scripts/check-identity-health.mjs` という既存の物差しがあり、それが「未登録の同姓同名: 0」と
報告していた。まずこの 0 が本当かを確かめるところから始めた。

## 方法

`data/tournaments/details` 全 455 ファイル（`temp/` 除く）を走査し、
**別人であることが証明できる**同姓同名だけを数えた。疑わしきは数えない（下限を出す方針）。

- **検出器E: 出生年レンジ矛盾** — 1 観測（`generationId` ＋ `categoryId` の age 部 ＋ 開催年）から
  出生年の許容レンジを引き、同一氏名の全観測でレンジの積集合が空なら別人確定。
  レンジは**わざと広め**に取る（例: 成年区分は `[Y-60, Y-14]`）。広い＝矛盾しにくい＝過小検出側。
- **検出器F: 同一大会 × 異なる都道府県** — 1 人が同じ大会・同じ年に 2 県を代表することは不可能。
  実在 47 都道府県のみで判定（`学連` / `高体連` / `日本学連` 等は所属区分であり県ではないため除外。
  この除外をしないと 183 件に膨らむが、大半が誤検出だった）。
  所属校名は略称ゆれ（`北海道科学大学`/`北科大`）があるため**校名では判定しない**。

## 結果1: 問題の規模

| 検出器 | 件数 | 未登録 |
|---|---|---|
| 既存 D（同一年 × 非隣接段階） | 12 | 0 |
| E: 出生年レンジ矛盾 | 33 | 21 |
| F: 同一大会 × 異なる都道府県 | 37 | 37 |
| **合計（重複除く）** | **70** | **58** |

- `homonyms.json` の登録は 16 名。うち今回の検出と重なるのは 12 名 → **カバー率 17%**。
- 検出 70 名は**下限**。E は世代差、F は県差を信号にしているため、
  **同世代かつ同一都道府県**の同姓同名は 3 検出器とも原理的に盲点。
  F が「両者が同じ大会に同時出場」を要求する点でも取りこぼしが大きい。

### 既存の物差しが 0 と報告していた理由

`check-identity-health.mjs` チェックD の判定は「**同一年** かつ 段階 ORD 差 2 以上」。このため:

1. 年をまたぐ矛盾を見ない
2. `catOf()` が `null` を返す大会（`zennihon-championship` / `east-japan` / `zennihon-mixed` 等）が対象外
3. `overNN` のマスターズ区分が対象外
4. 都道府県シグナルはチーム側にしか使われていない

**物差しが無かったのではなく、感度が足りず 0 と出ていた**というのが実態。
E / F は同スクリプトに実装済み（2026-07-26）。実行結果は E=21 / F=37 で本測定と一致。

### id 融合の実態

`data/players/index.json` は **18,543 名前 = 18,543 id**（同姓同名に別 id が 1 つも無い）。
つまり検出した 70 名は全員**1 つの選手ページに複数人の戦績が融合**している。

- 61 名が id を持つ
- **37 名は結果ページが生成済み**（`count >= 5`）
- **4 名は `totalMatches >= 15` で index 対象**（[seo.md](../wiki/seo.md) #2）

`homonyms.json` への登録は「危険な名前の記録」であり id の分割ではない
（`lib/playerStats/identity.ts` は `homonymRisk` フラグとして UI 注記に使うのみ）。

## 結果2: 機能別の誤マッチ率 ← ここが設計判断を変えた

「別人確定 70 名のいずれかを含む試合」の割合:

| 照合の粒度 | 母数 | 該当 | 率 |
|---|---|---|---|
| 選手単位・全データ | 32,043 試合 | 936 | **2.92%** |
| 選手単位・地区大会のみ | 1,940 試合 | 41 | **2.11%** |
| ペア単位（地区大会 → IH2026） | 352 カード | 8 | 2.27% |

**「スコープを狭めれば安全」は否定された。** 地区大会に限っても 2.92% → 2.11% にしか下がらない。
同姓同名は世代・地域に関係なく一様に分布するため、範囲を絞っても率は動かない。
（この見立ては 2026-07-26 に一度 `news-context-blocks.md` の Open Questions へ
「補助線」として書いてしまったもので、同日に本測定で訂正した。）

**効いたのは照合キーの結合度だった**:

- インターハイ 2026 で**同一の名前セットを持つエントリは男女とも 0 件**（316 ペア / 314 ペア）。
  2 名の氏名の結合だけでエントリが一意に定まる。
- 地区大会 → IH の照合で一致した **565 ペアのうち都道府県の不一致 0 件**。
  校名の不一致 32 件はすべて略称ゆれで別人ではない。

上表のペア単位 2.27% は「4 名のうち誰かが**どこかで**同姓同名を持つ名前」という意味であり、
そのカードの照合が誤っているという意味ではない。実際に照合してみると曖昧性はゼロだった。

## 結論

1. `head-to-head` / 前哨戦・再戦は、**ダブルスのペア単位に限れば現在の名寄せ水準でも安全に作れる**。
   優先度 C の凍結理由は、粒度を分けて評価すれば部分的に解除できる。
2. 危険なのは (a) 選手単位に降ろした時、(b) 世代を跨いだ時。この 2 つは `homonyms.json` の
   整備と **id 分割のアプリ統合**を待つべき。カバー率 17% で解禁するのは早すぎる。
3. Open Questions 3 件は「名寄せが終わるまで一括保留」ではなく、
   **照合キーの粒度ごとに個別に解禁可否を判断する**形に組み替えられる。

## 副産物

校名の略称ゆれ 32 件を検出（`北海道科学大学`/`北科大`、`東京農大二`/`東農大二`、
`高岡商業`/`高岡商`、`下山学園`/`下山学園高校`、`浦和一女`/`浦和一女子` 等）。
`check-identity-health.mjs` の「別名のまま残る出場: 54」と重なる案件で、
`data/tournaments/team-name-aliases.json` に追加すれば解消する。**未対応**。

## 対応（2026-07-26・測定当日）

### 1. 検出器 E / F を実装し `homonyms.json` を再生成

`scripts/build-player-homonyms.py` と `scripts/check-identity-health.mjs` の両方に E / F を実装。

- `homonyms.json`: **16 名 → 65 名**（明快 43 / 要確認 22）。既存 16 名の退行なし。
- 各レコードに `detectors`（`["D"]` / `["E","F"]` 等）を追加し、どの信号で挙がったか追えるようにした。
- 人物割り当て（`persons`）の衝突判定にも E / F を組み込んだ。別人確定なのに 1 人にまとまった
  場合は `needsReview: true` になる。
- **効果**: `PlayerStatisticsSections.tsx:339` の警告「※ 同姓同名の別選手の成績が含まれている
  可能性があります。」が出るページが **12 → 39**（index 対象 5）。警告文の実装自体は既にあり、
  発火条件が `homonyms.json` 登録だったため登録漏れの分だけ出ていなかった。
- **副次発見**: 名（`firstName`）が未分割の participant 9 件（中川 / 井上 / 前川 / 平田 / 森本 /
  櫻木 / 竹内 / 藤原 / 近藤）が姓だけで D/E/F に引っかかっていた。これは同姓同名ではなく
  取り込み元の氏名分割の不備なので、両スクリプトで別枠のシグナルに分離した。

### 2. チーム名の略称ゆれ

**根本原因は alias の未登録ではなく `normalize-team-names.mjs` の未実行だった**。
地区大会データが一度も正規化を通っておらず、`四天王寺`→`四天王寺高校`、`多賀`→`多賀高校`、
`下山学園`→`下山学園高校`、`日高`→`日高中学校` は**既に alias 登録済み**なのに適用されていなかった。
ヘルスチェックの「別名のまま残る出場: 54」がこれを指していた。

対応と効果（地区大会 → IH の 565 ペア照合における所属不一致）:

| 手順 | 不一致 |
|---|---|
| 初期状態 | 32 |
| `normalize-team-names.mjs --scope=all` を実行（11 ファイル・162 箇所） | 26 |
| alias 追加（`北科大`←`北海道科学大学`、`東農大二`←`東京農大二`）＋新規登録（`浦和一女子`/`福井商`/`智翠館`/`上伊那農`）→ 再正規化（15 ファイル・240 箇所） | 15 |
| canonical 短縮（`旭川実業`→`旭川実`、`高岡商業高校`→`高岡商`）＋異体字統一（`米子松陰`→`米子松蔭`）→ 再正規化（21 ファイル・309 箇所） | 6 |
| `理大附属`→`岡山理大附`、`金沢学院`→`金沢学院大附`（改称）→ 再正規化 | **1** |

その後 `build-team-master.mjs` / `build-team-merge-candidates.mjs` / `build-player-homonyms.py` を
[team-player-identity.md](../wiki/team-player-identity.md) の実行順序どおり再実行済み。
ヘルスチェックの合計シグナルは **132 → 34**、「別名のまま残る出場」は 0 になった。

新規 canonical は**全国大会（インターハイ）側の表記に合わせた**。理由は、全国大会のデータが
最も参照・被リンクされる面であり、そちらを動かす方が影響が大きいため。

canonical の短縮（`旭川実業`→`旭川実`、`高岡商業高校`→`高岡商`）は、全国大会の表記に合わせる方針に
加えて**データ実数でも短縮形が多数**であることを確認して実施した（旭川実 51 対 旭川実業 41、
高岡商 132 対 高岡商業高校 56）。`米子松陰`(陰) → `米子松蔭`(蔭) の統一も同様に、正式名称が
「松蔭」であることとデータ実数 222 対 6 の両方で裏付けた（恒久対応は `kanji-variants.mjs` の
対応表だが、当面は alias で吸収する）。

**`金沢学院` は大学ではなく高校の改称だった**。「金沢学院＝金沢学院大学ではないか」という疑いを
データで検証した結果:

1. 同一人物が**同年に両表記**で出現する（久田陸人＝2026 年に北信越地区大会「金沢学院」／
   インターハイ「金沢学院大附」）。両表記にまたがる人物は 8 名。
   金瀬戸のよ・南条舞咲は 2022「金沢学院」→2023「金沢学院大附」で、2022 年の改称
   （金沢学院高校 → 金沢学院大学附属高校）と整合する。
2. **金沢学院大学は別エンティティとして既に分離されている**（`prefecture` が `学連`/`日本学連`、
   `generationId: university`、18 件）。統合後も 18 件は無傷であることを確認済み。

唯一の判断保留は `zennihon-singles 2023` の 1 件（浦利弥・石川県・団体名「金沢学院」）で、
他大会に登場しないため高校生か大学生か決められない。ただし大学側の表記は一貫して
「金沢学院大学」であるため、高校として扱う方が妥当と判断した。

`理大附属`→`岡山理大附` は既知の残課題「内部略称（理大/理科大）」の一例。現データ上
`理大附属` は岡山県・高校の 30 件のみで他県との衝突が無いことを確認して alias 化した。

**保留は `福誠`⇄`誠修`（福岡）の 1 件のみ**（改称の可能性が高いが未確認）。

なお作業中に `team-name-aliases.json` の canonical 重複（`金沢学院大附` が 2 エントリ）が
発生したため、重複マージと自己参照 alias の除去を行った（598 エントリ）。
**canonical の変更は既存エントリと衝突しうる**ので、変更後は重複チェックを回すこと。

### 3. 見送ったもの: 人物別 id の払い出し（id 分割）

`homonyms.json` への登録は**警告表示が正しく出るようになるだけ**で、
`players/index.json` は 1 名前 = 1 id のまま（`identity.ts:26` のコメントにも
「分離は人物別 id 払い出し（P7/設計）が必要」とある）。

今回見送った理由は、id を分割すると `/players/{id}/results/` の URL が変わり、
[seo.md](../wiki/seo.md) #2 で積み上げてきたインデックス面を毀損するリスクと 301 の手当てが
発生するため。警告が正しく出るようになった今、急ぐ理由は薄い。

## 課題・未解決

- 同世代・同一都道府県の同姓同名をどう推定するか（検出できないので規模が分からない）。
  下限 70 に対する真値の見当が付いていない。
- `homonyms.json` を id 分割としてアプリの選手解決へ統合する実装
  （[team-player-identity.md](../wiki/team-player-identity.md) の既知の残課題に既出）。**今回見送り**。
- 略称ゆれの残り 6 校（判断・事実確認が必要。上記「対応」2 を参照）。
- 氏名が未分割の participant 9 件の修正（取り込み元の確認）。
- `homonyms.json` の `needsReview: true` 22 件の人手確認。E / F で新規に挙がった分が多く、
  チーム単位の衝突判定では人物に割り切れなかったケースを含む。
