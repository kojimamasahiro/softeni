# 2026-09-25 試合分析が「再構築したゲームスコアが既存スコアと一致しない」で止まる

適用範囲: 汎用

## 経緯

全日本大学 2026 男子ダブルス決勝（match `381d9c08-…`）の分析ページで
「分析用に再構築したゲームスコアが既存スコアと一致しなかったため、分析表示を停止しています。」
と出る、とユーザーから報告があった。第1・4・6ゲーム（いずれもデュース）で、ポイントが7件しかなく
スコアが 3-4 / 4-3 に組み上がり、保存済みの 3-5 / 5-3 と合わなかった。

## 原因

Supabase の DB 側は正しかった。壊れていたのは書き出した JSON のほう。

`scripts/generate-beta-matches-json.mjs` が全試合の `points` を1クエリ
（`.in('game_id', 全ID).order('point_number')`）で取っており、Supabase の返却上限 1000 行で
切られていた。`point_number` の昇順で切られるため、全試合から8本目以降のポイントが消えていた。

実測（修正前の JSON）: ポイントはちょうど 1000 件で、point_number 1〜4 が各174件、5 が150件、
6 が110件、7 が44件、8 以降は0件。28試合中24試合・55ゲームで食い違い。

## 修正

- `matches` / `games` / `points` を `.range()` でページ送りして全件取る（`fetchAllRows`）。
  ページ送り中に並びが変わらないよう、ソートキーは一意の `id` にする。`matches` の作成日時降順は取得後に並べ直す。
- `.in()` の ID 列は100件ずつに分ける（URL 長対策）。
- 書き出し時に、ポイントの積み上げと `points_a/b` が合わないゲームがあれば失敗させる（prebuild が止まる）。

修正後: ポイント 1,165 件、食い違い0。

## 副作用

`rare-events.json` の中身が変わった。修正前は切られたデータから作っていたため、
「最大の3点差逆転ゲーム」（postable を含む）が並び、最長デュース（全日本社会人 決勝 第2ゲーム・
全24ポイント）や9連続ポイントが漏れていた。修正前の rare events を SNS などへ出していたら、
内容を確かめ直す必要がある。
