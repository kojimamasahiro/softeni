# アジア競技大会2026 混合ダブルスの試合形式と、公式サイトが書いていないこと

## 状況

2026-09-19、ユーザーの問い「公式サイトがわかりにくい。混合ダブルスはどういう形式か。
当サイトはどう表示しているか。補填する方法はあるか」から調べた。
混合ダブルスは **9/21 の1日で予選から決勝まで**行うので、取り込み方針を決める期限が近い。

出典は公式リザルトサイトの Competition > Mixed Doubles（Schedule / Groups / Brackets）と
Schedule > By Event（2026-09-19 時点。全試合 `Scheduled`）。

## 公式サイトから読み取った形式

**19組 → 予選リーグ6組 → 決勝トーナメント（12枠・うち4組は1回戦免除）→ 準決勝で銅2つ。**

予選リーグ（9/21 9:00〜11:00・A組のみ10:00の1試合だけ）:

| 組 | 組数 | 顔ぶれ | 試合数 |
|---|---|---|---|
| A | 2（＋BYE 1枠） | 日本（上松俊貴・天間麗奈）・フィリピン | 1 |
| B | 4 | インド・カンボジア・モンゴル・韓国 | 6 |
| C | 3 | チャイニーズ・タイペイ・インドネシア・パキスタン | 3 |
| D | 3 | 韓国・パキスタン・フィリピン | 3 |
| E | 4 | 日本（前田梨緒・丸山海斗）・カンボジア・ラオス・インドネシア | 6 |
| F | 3 | チャイニーズ・タイペイ・ネパール・モンゴル | 3 |

- **A組は公式の順位表に `BYE` の行がある**（3枠のうち1枠が空）。実質2組・1試合で、
  この1試合は通過の可否ではなく組内順位だけを決める。
- 11か国から19組。**8か国が2組ずつ出していて、同じ国の2組は必ず別の組**に入っている。
- 決勝トーナメント（同じ9/21）: **1回戦 12:30 → 準々決勝 14:00 → 準決勝 15:30 → 決勝 17:00**。
  1回戦は8枠のうち **Match 2・3・6・7 の4試合だけが実在**し、残り4枠は `BYE`（ブラケット画面で確認）。
  したがって決勝Tに入るのは12組で、うち4組は準々決勝から。
- **準決勝に `Medal` が付き、3位決定戦は日程に無い**（＝敗者2組がともに銅。団体戦と同じ）。
- 実施される試合は 予選22＋1回戦4＋準々決勝4＋準決勝2＋決勝1 = **33試合**。

## 公式サイトが書いていないこと（＝わかりにくさの正体）

形式そのものはどのページにも文章で書かれていない。上の表は Groups・Brackets・Schedule の
3画面から組み立てた結果で、**次の点は公式からは決まらない**。

- **各組から何組が通過するのか**。12枠 ÷ 6組 = 2 なので「各組上位2組」と読めるが明記は無い（**Assumption**）。
- **どの組が1回戦免除（BYE）になるのか**。決勝Tの席と予選の組の対応が公開されていない。
- **組内順位の決め方**。順位表の列は `Pts. / Played / Won / Lost` だけで、並んだときの規則が無い。
- **1試合が何ゲーム先取か**。団体戦の実測ではダブルス5ゲーム先取・1ゲーム4ポイント先取（デュースあり）だが、
  混合も同じかは公式に記載が無い（**Assumption**）。
- A組の `BYE` 行が何を意味するか（棄権なのか最初から空き枠なのか）。
- Reports には混合の `Entry List by Event`（C32C）しか無く、**競技方式の文書は置かれていない**。

表示面のわかりにくさ:

- 全編英語・選手名はローマ字の大文字・国は NOC の3文字コード。
- 日別日程は**コートごとに縦に並ぶ**ので、1つの組の3試合が別のコート見出しに分かれる（B組・E組）。
- 形式を知るには Schedule / Groups / Brackets の3タブを行き来する必要がある。
- Vue の SPA で、遷移が終わる前に読むと前のページが残る（[data-import.md](../wiki/data-import.md) 記載済み）。

## 当サイトの現状（2026-09-19 時点）

`/tournaments/international/asian-games/2026/doubles/none/mixed`

- 方式A（日本が入っている組だけ）なので、**19組中6組・7試合**しか持っていない（A組とE組）。
- 表示は「対戦詳細」の一覧だけ。各組は「出場」で、対戦は「予選 / 相手 / 未実施」。
  **`ResultsTable.tsx` などが `match.round ?? '予選'` なので、組（A・E）が画面に出ない。**
  6組が2つの別々の組だということが読み取れない。
- 結果が入れば、団体戦と同じように見出しへ「グループE 2位」が出る（`results[].roundrobin`）。
- 決勝トーナメントのデータは持っていない（席が (組, 組内順位) で決まるため、
  日本の2組だけでは12枠を解決できない。団体戦で全組を持つことにしたのと同じ構造）。
- ハブ（`/tournaments/international/asian-games`）には種目別日程があり、混合は「9月21日（月）・決勝17:00」。

## 追記（2026-09-19・同日）: シングルスも調べた

ユーザー「シングルスも検討したい」。公式の Competition > Groups / Brackets を見た。

| 種目 | 人数 | 組 | 決勝トーナメント |
|---|---|---|---|
| 男子 | 22 | 7組（A〜G。**D組は `BYE` 込みで実質2人**） | 各組1位の7人が準々決勝へ。準々決勝は8枠で Match 1 が `BYE`（1人は準決勝から） |
| 女子 | 23 | 8組（A〜H。**G組が実質2人**） | 各組1位の8人が準々決勝へ。不戦勝なし |

混合と違い、**通過する人数は一意に決まる**（男子は準々決勝に入るのが7人で7組、女子は8人で8組）。
ただし「各組1位」が公式に明記されているわけではないので、`assumptions` には
「人数と組数が一致することからの当サイトの読み取り」と1行だけ残した。

9/23 の日程で準決勝に `Medal` が付き、3位決定戦は3種目とも無いことを確認した。
男子の準々決勝は Match 2・3・4 しか日程に無く（Match 1 が不戦勝の席）、ブラケットの表示とも一致した。

## ユーザー判断（2026-09-19）

- **混合ダブルスは全組へ広げる**（案3）
- **競技方式ブロック（案1）と、対戦詳細に組を出す（案2）を作る**

## やったこと

- **混合を全6組・19組・22試合に**。`draw.json` に B・C・D・F組の15試合を足し、
  `build_details.py` に `ALL_GROUP_EVENTS`（団体2種目＋混合）を足して「日本が居ない組」の検査から外した。
  副作用として、団体戦のオーダーの選手のうち混合に出る7人が名前だけ → 姓・名になった（ADR-020 のとおりで正しい）。
  prebuild の `data/players/**` 差分は0（未実施の試合は通算成績に入らない）。
- **`categories[].format` を新設**（ADR-021）。混合・男女シングルスの3種目に入れた。
  `lib/categoryFormat.ts` ＋ `CategoryFormatNotice.tsx`。出典が無ければ表示せず、推定は本文と分けて出す。
- **ラウンド欄に組を出した**。`lib/roundLabel.ts` の `formatRoundLabel` を作り、
  4か所にコピーされていた `round ?? '予選'` を置き換えた（`ResultsTable` / `MatchResults` /
  `TournamentBracket` / 選手の結果ページ）。`TournamentBracket` だけ行の型が `group` を持っていなかったので足した。
- 検査: `check:entries` / `check:team-match-details`（785試合・2355対戦）/ `bracket:verify`（457大会・不一致0）/
  `check:orphans` / `check:placements` / `bracket:test` / `upcoming:test` / 新設の `format:test`（8件）/
  `tsc --noEmit` / eslint、すべて問題なし。prebuild も通った（`highschool:pipeline` は今回も必要だった）。

### 決勝トーナメントの席はまだ入れていない

**どの組が1回戦免除（不戦勝）になるかが公表されていない**ため。推測で `knockoutDraw` を作ると、
ADR-015 の「席は (組, 組内順位) で指定する」を推測で埋めることになる。
9/21 に公式の1回戦の組み合わせが出てから入れる。

### 踏んだこと: ブラウザでの目視が取れなかった

対戦詳細の行はクリックで開く作りなので SSR の HTML に出ず、開発サーバーのプレビューでも
DOM が操作できなかった（`document.body` が null、要素の座標が 0）。
**結果が入っている団体戦のページは行が最初から開いている**ので、そちらの HTML を直接取って
`予選 グループA` が6件・`グループC` が6件・`グループB` が4件あることで確認した。
競技方式ブロックは SSR に出るので3種目とも HTML で確認済み。

### 気づいたこと（今回は触っていない）

- `data/players/index.json` は `scripts/extract-players.mjs` で作るが **prebuild に入っていない**。
  9/18 に入れた外国選手（DOEUM・CHAUDHARY・ERDEMBILEG）が既に載っておらず、今回の分も載っていない。
  `count>=5` で結果ページを作る判定に使う索引なので、1大会だけの外国選手は元から対象外ではある。
- 年度レコードの `note`（公開しない入力メモ）は、表示されないが `__NEXT_DATA__` には入っている。

## 追記（2026-09-19・同日）: シングルスも全選手にした

ユーザー「シングルスも全選手を載せたい」。公式の 9/22 の日程から全試合を転記した。

| 種目 | 組 | 出場 | 予選の試合 |
|---|---|---|---|
| 男子シングルス | A〜G | 22人 | 25 |
| 女子シングルス | A〜H | 23人 | 22 |

これで**5種目すべてが全組・全試合**になり、当初の方式A（日本が出た試合だけ）は使わなくなった。
個人種目の外国選手は `participants` に入るので、**実質的に方式B**に移っている。
現時点では試合が未実施なので prebuild の `data/players/**` 差分は0だが、
**結果が入れば外国選手も勝敗を持つ**。会期後に選手ページ側の扱いを決める必要がある
（`open-questions.md` に移した）。

### 検査を「日本が居るか」から「組と出場数が合うか」に変えた

方式A のときは「各組に日本が居るか」で取り込み範囲を守っていたが、全組になった時点でこの検査は
何も守らなくなる（全種目が対象外になるため）。代わりに、守るべきリスクが
**「組を1つ転記し忘れる」**に変わったので、`draw.json` に `expected`（種目ごとの組と出場数。
公式の Groups から転記）を置き、食い違えばスクリプトを止めるようにした。

わざと女子H組を落として動かし、
`組が合わない: [A..G] != [A..H]` / `エントリー数が合わない: 20 != 23` で止まることを確認した。

### 名前で気をつけた点

- 北朝鮮の女子に **RI が2人**いる（RI So Hyang＝C組 / RI Jin Mi＝G組）。
  id は `RI_So Hyang_北朝鮮` のように名に空白が入るが、コリアカップに前例がある
  （`LIN_WEI CHIEH_TPE-1` など）ので、そのまま採った。
- 混合・団体と同じ選手が複数種目に出るので id は自然に揃った
  （ARASY Siti・HACNOLATH Souvananh・SANOSA Christy・NUGUIT Sherwin ほか）。
  そのぶん団体戦のオーダーで「名前だけ」だった選手がさらに姓・名になった。

prebuild、すべて問題なし。prebuild の `data/players/**` 差分は0（タイムスタンプ3ファイルのみ）。
