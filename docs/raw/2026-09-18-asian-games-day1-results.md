# アジア競技大会2026 一日目（団体戦）の結果取り込み

## 状況

2026-09-18 に団体戦の全日程（男女の予選リーグと、男子の準々決勝）が終わり、公式リザルトサイトで
全試合が `Official` になった。「一日目の結果が出た。反映できる？」という依頼から取り込んだ。

## ユーザー判断（2026-09-18）

1. **オーダー（第1〜第3対戦の出場ペアとゲーム数）も入れる**。公式サイトに全試合ぶんある
2. **団体戦の決勝トーナメントは全部持つ**（日本のいない 韓国-チャイニーズ・タイペイ も含む）。
   団体戦のエントリーは国なので選手集計に影響しないため

## 2 の帰結: 団体戦は全組を持つことにした

決勝Tの席順（`knockoutDraw`、ADR-015）は **(組, 組内順位)** で席を指定し、`results[].roundrobin` で
実体に解決する。日本のいる A組しか持たないと、B組・C組から上がってきたチームの席が解決できず、
`check:entries` が `knockout-draw-unresolved` を出してブラケットも描けない。
ユーザーが「全部持つ」を選んだ理由が「ブラケットが欠けずに描ける」だったので、**団体戦だけ全組を持つ**ことにした。
個人種目は方式A（日本が入っている組だけ）のまま。

団体戦のエントリーは国なので、組を足しても `participants` に選手は増えない（オーダーの選手は
ADR-020 のとおり `participants` に足さない）。実際 prebuild で `data/players/**/analysis.json` の差分は0だった。

## 団体戦1試合の形

`M1 = ダブルス / M2 = シングルス / M3 = ダブルス` の3対戦。ADR-020 の `type` は `D1` / `S` / `D2` に対応する。

- ダブルスは5ゲーム先取、シングルスは4ゲーム先取。1ゲームは4ポイント先取でデュースあり（実測 `12-10`）
- **予選リーグは決着後も3対戦すべて行う**（3-0 がありうる）。決勝Tは2勝で打ち切り、
  第3対戦は公式サイトで `Cancelled`（＝オーダーだけ出ている）→ ADR-020 の `not_played`

## 男子B組で ADR-020 の状態が足りなかった

ADR-020 の `status` は当初 `completed` / `unfinished` / `not_played` の3つで、次の2つを表せなかった。
どちらも「勝った対戦の数＝親の本数」という不変条件を壊す。

- **途中棄権**（韓国-インドネシア 第3対戦。**3-2 とリードしていた韓国**が棄権し、公式表示は `RET` / `W`）
- **不戦勝**（韓国-ネパール / ネパール-インドネシアの第3対戦。ネパール側が `BYE`。
  団体の本数は 3-0 で、不戦勝も1勝として数える）

**ユーザー判断（2026-09-18）: `retired` と `walkover` を足す。** ADR-020 追記4・追記5。

`retired`（途中棄権）:

- 勝者は**棄権しなかった側**。本数からは決まらない（実測 3-2 で本数の多い側が負け）ので `winner` を必ず持つ
- `games` は**決着したゲームだけ**。中断されたゲーム（実測 `0-0`）は取った側が決まらないので入れない
- 表示は本数の下に「棄権」／相手側の行では「相手が棄権」。**本数だけだと勝敗が逆に読める**ため
- 圧縮（`packedPageData.ts`）は `status` を文字列表で詰めているので変更不要。往復テストにケースを足した

`walkover`（不戦勝）:

- **本数を持たない**。試合が行われていないので、`completed` で 4-0 のように書くと本数の捏造になる
- **ペアを出さなかった側は空配列**。`{ name: '—' }` のようなダミーを入れない（選手名として扱われるため）。
  検査は「空なのは片側だけ」「勝者はペアを出した側」まで見て、人数チェックは空の側だけ飛ばす
- 表示は「不戦勝」／相手側の行では「相手が不戦勝」。空の側の選手欄は「出場なし」（空欄だと読み落とす）

これで男子B組の3試合すべてにオーダーが入った（対戦記録 42 → 51）。
ADR-020 の Open Questions から「不戦勝を表せない」が消えた。

## 読み取りで踏んだ罠: SPA の取り違え

公式サイトは Vue の SPA で、`location.hash` を書き換えて `main` の innerText を読む方式で取った。
**ページ遷移が終わる前に読むと、前のページの内容をそのまま読んでしまう**。1.1〜1.4秒待っても起きた。

最初に29試合ぶんをまとめて取ったところ、**男子A組1回戦の欄に女子B組の試合が入っていた**。
検算（1ゲームのポイント合計＝本数、対戦の勝ち数＝団体の本数）は**通ってしまう**（データとしては整合した別の試合なので）。

対策として、取り込み側で**その試合の2つの国コードを先に渡し、読めた NOC が一致しなければ
最大8回まで読み直す**ようにした。これで26試合すべて1回目で一致し、取り違えは消えた。
**SPA から読むときは、期待する識別子との照合を必ず入れること。** 内容の検算だけでは足りない。

## 成績の付け方

- 予選リーグで敗退したチームは **`tournament: null`（最終成績なし）＋ `roundrobin.{group, rank}`**。
  東北ブロック中学2026 と同じ形。ページには「予選敗退 / グループA 3位」と出る
- 決勝Tに残っているチームは `rank.kind: 'ongoing'`（ADR-007）。準決勝が未実施なので「ベスト4進出」
- 準々決勝で負けた インド・フィリピンは `best/8`（＝ベスト8）。**8枠の決勝Tなので字義どおり**だが、
  実際に決勝Tに入ったのは6チーム。この大会では「準々決勝敗退」の意味で読む
- 組内順位は 勝ち数 → 本数の得失 → 取得本数 で決め、**並びきらなければスクリプトを止める**
  （公式の順位規則を推測しないため）。今回は全5組とも1位から4位まで一意に決まり、
  **準決勝の対戦カード（1位 vs 別組2位）とも一致した**

## 反映状況の文言を直した

女子団体のページが「組み合わせを掲載しています。結果はこれから随時反映予定です(全3試合)」と出て、
title も「女子団体 組み合わせ」になっていた。予選リーグ12試合が確定しているのに、
`computeResultCoverage` が**決勝Tしか見ていなかった**ため（ADR-007 の当初スコープ）。

- `decidedRoundrobinMatches` を足し、**決勝Tが0でも予選リーグが決着していれば `in_progress`** にした
- 文言は「現在の反映状況: 予選リーグ12試合の結果を掲載中。決勝トーナメント(全3試合)はこれから反映します。」
- 進捗率の分母は決勝Tのままにした（予選リーグとラウンド深度は尺度が別物）
- 影響範囲を先に数えた: 全 details を走査して、この条件に当たるのは**この1ファイルだけ**だった

## 出典を公式リザルトサイトに変えた

`information/asian-games.json` の `source` / `sourceUrl` を JOC のページから公式リザルトサイトへ変えた。
結果ページの出典欄は「本ページの**試合結果データ**は、以下の情報をもとに作成しています」なので、
結果が入った今は結果の出典を出すべきという判断。会期・会場・代表名簿の出典が JOC であることは `note` に残した
（代表名簿は `delegations` 側に自前の `source` を持っている）。
