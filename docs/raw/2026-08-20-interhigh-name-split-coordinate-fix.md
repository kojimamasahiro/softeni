# インターハイ2018/2019の姓名分割を座標ベースに切り替え

## 背景

ユーザーが`tools/highschool-championship-2019/doubles-none-boys.json`を目視で確認し、
姓名の区切りがおかしいエントリーを33件（姓1文字が2文字に誤爬15件、姓3文字が2文字に誤爬17件、
文字欠落1件）リストアップして修正を依頼してきた。手作業で全て修正した直後、ユーザーから
「一律、前2文字を苗字にするのではなく、座標で姓名が区切られているのでそれに合わすことは
できる？」と根本対応を求められた。

## 座標ベースで分割できることの検証

修正済み33件を検証用データとして使い、姓の文字ごとのX座標を実測した結果、**姓の文字数
（1〜3文字）に関わらず、姓セルと名セルの間に一貫した固定X座標のしきい値がある**ことを確認した
（左ブロック=約100pt、右ブロック=約405pt。姓の全文字がしきい値未満、名の先頭文字がしきい値
以上に収まる）。

同時に、**字間（gap）の大小だけで境界を判定する方式が本質的に不可能**であることも再確認した:

- entryNo7「奥西／巧」: 奥→西の字間24.2pt、西→巧の字間37.6pt
- 2文字姓「浪岡」の内部字間: 24.6pt（entryNo7の奥→西とほぼ同じ）
- 他の確定済み1文字姓の姓名境界字間: 一貫して約37pt（entryNo7の西→巧とほぼ同じ）

つまり「奥西」という2文字のまとまりの内部字間（24.2pt）が、別の1文字姓+2文字名パターンの
境界字間そのものと見分けがつかない。字間だけを見て「大きい方が境界」と判定するロジックは
原理的に破綻する。固定座標のしきい値であれば、姓が何文字でも一貫して正しく分かれる。

この検証により、ユーザーが手作業で修正したentryNo7「奥／西巧」は誤りで、座標的には元の
「奥西／巧」が正しいことが判明。ユーザーに座標証拠を提示して確認を取り、「奥西／巧」に
差し戻した。

## 実施したこと

`scripts/pdf/highschool_championship_entries.py`を修正:

- `_split_name`（文字数ヒューリスティック: 姓2文字+名残り）を廃止し、`_split_name_by_x`
  （文字ごとのX座標としきい値による分割）を主経路に変更。`_split_name`は氏名が2文字しかない
  ケース（座標でも区別できない）専用のフォールバックとして残す。
- `DBL_LEFT`/`DBL_RIGHT`に`name_split_x`（しきい値）を追加。
- `_fix_leaked_area`（都道府県側への文字付け替え）で氏名文字列が短縮された場合、座標分割も
  短縮後の文字列に対応する範囲（先頭からの文字数）に絞ってから行うよう調整。

2018年・2019年の男女ダブルス（highschool-championship）を元PDFから座標分割で再抽出し、
既存の確定済みデータと突き合わせ:

- **姓名を連結した文字列が完全一致する差分だけを機械的に適用**（分割位置だけが変わるケース）
- 文字列自体が異なる差分（欠落文字を手動で復元済みのケース）は**上書きせず保持**

適用結果:

| ファイル | 適用件数 | 保持（上書きせず）した既存の手修正 |
|---|---|---|
| 2019 doubles-none-boys | 6件 | entryNo 209「會田」, 298「𠮷根」, 305「辻花」 |
| 2019 doubles-none-girls | 48件 | なし |
| 2018 doubles-none-boys | 51件 | entryNo 274「前田」 |
| 2018 doubles-none-girls | 46件 | なし |

合計151件を修正（うち33件はユーザーが今回目視で発見した分、残り118件は今回の座標検証で
新たに見つかった分）。`data/tournaments/details/highschool-championship/{2018,2019}/*.json`と
`tools/highschool-championship-{2018,2019}/*.json`の両方に反映。`npm run check:entries`
エラー0を確認済み。

## 今後の運用

新しい年度のPDFを処理する際、この座標分割ロジックは自動的に効く（スクリプト本体の修正のため）。
ただし**座標分割は「文字の位置」の問題しか直せず、「文字の欠落」（テキストレイヤーから
まるごと落ちている文字）は直せない**。再抽出と既存データを突き合わせる際は、姓名を連結した
文字列が完全一致するかどうかで機械適用/保持を振り分ける運用を徹底すること（今回の実装と
同じロジック）。
