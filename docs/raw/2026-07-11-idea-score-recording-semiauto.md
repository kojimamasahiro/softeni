# アイデア: score記録の半自動化（動画からのポイント抽出支援）

## 状況

Idea Backlog。発散フェーズ・外部事例調査のみ実施（2026-07-11時点）。実装未着手。
2026-08-03に追加調査: 技術的な自動化（OCR/音声）とは別に、競合アプリの「記録のしやすさ・
続けやすさ」の設計を横展開する角度で競合機能を調査（下記「外部事例（収集UX面、2026-08-03）」）。

## 目的

score機能のポイント単位データは手入力が多く、すぐには増えない。希少イベント検知・
プレースタイル分析（姉妹案2件）のデータ源を太くするため、記録コスト自体を下げる。

**前提となる調査結果**: ポイント単位のデータは外部に存在しない。JSTA・各都道府県連盟が
公開するのは勝敗・スコアまで（既に取り込み済みの領域）で、スクレイピング等の外部リソースで
増やせるのは大会結果データだけ。ポイントデータは自前記録以外に源泉が無いため、
方向は「外部から取る」でなく「記録の手間を減らす」になる。

## ユーザーが興味を持った点

原文: 「scoreに関しては、まだまだ手入力が多く、すぐには増えていかない。少しでも自動化や
スクレイピング等外部リソースが使えないかを検討したい」。

## わかっていること

- 既存実装に半自動化の土台がある: `buildHeuristicCandidates`（`lib/videoReview.ts`）が
  動画を等間隔分割してポイント候補を生成し、人がレビューUIで確定する流れが既に動いている。
  自動化は「候補生成の質を上げる」拡張として既存フローに乗る。
- 外部事例（2026-07-11調査）: スコアボードOCRによる放送映像の自動インデックス化は
  テニス・バドミントン・クリケットで前例多数（SmartTennisTV、OCR誘導YOLOセグメンテーション等）。
  スコアボード検出の公開データセット（Roboflow）も存在。ボール追跡（TrackNet系）は
  研究領域でコスト高。
- 外部事例（収集UX面、2026-08-03調査）: 「記録の手間を減らす」を技術（OCR/音声）以外の
  切り口で解いている競合が複数ある。
  - **データテニス**・**ソフトテニス パーフェクトスコア**: どちらも試合を見ながらその場で
    タップするだけの軽量なリアルタイム入力が主形態（○×やワンタップでポイントを記録）。
    データテニスはApple Watch対応・クラウド共有・サーブ率等の自動集計、パーフェクトスコアは
    ゲーム獲得判定やファイナルゲームの判定まで自動化して入力項目を最小化している。
  - **スコアNK**: さらに割り切ったシンプル特化型。○×ボタンのみでゲーム獲得・ファイナルゲームの
    判定を自動処理し、入力の手間を極限まで削っている。
  - **テニス手帳**: スコア記録単体でなく予定・練習内容・用具情報まで扱う総合手帳型。
    「試合の日だけでなく日常的に開くアプリ」にすることで記録が習慣として定着する設計。
  - **GameChanger**（野球・海外、参考事例）: 記録係を1人に固定せず、その場にいる保護者や
    部員の誰にでもスコアラー権限を一時的に付与できる仕組みと、記録内容をリアルタイムで
    家族・ファンに実況配信する機能を持つ。「記録する動機」自体を作る設計として参考になる。
  - 示唆: softeni-pickは動画からの**事後**記録が軸のため、動画が無い練習試合はそもそも
    記録できない弱点がある。競合の多くは試合中その場で完結する**軽量なリアルタイム入力**が
    主形態で、動画事後記録と補完関係になり得る。また記録者を1人に固定しない委任の仕組みは、
    ソフトテニスに記録専業ポジションが制度化されていない構造的弱点（`score-general-availability.md`
    「記録文化が薄い理由」参照）を直接カバーしうる。

## 収集を増やすためのUXアイデア（2026-08-03、未検証・優先度未定）

1. **軽量リアルタイム入力モード**: 動画無しの練習試合でも、その場で○×だけ押して記録できる
   簡易モードを追加する。既存の動画事後記録フローとは別経路とし、後から動画があれば
   video-review側で答え合わせ的に紐づけられるようにする案もあり得る。
2. **記録者の一時委任**: リンク共有等で、その場にいる別の選手・保護者・顧問に一時的な
   記録権限を渡せるようにする。記録専業ポジションが無い競技構造を補う狙い（GameChanger型）。
3. **他アプリからの移行導線**: データテニス等ですでに記録済みのユーザー向けに、CSV等の
   インポート動線を用意し、ゼロから記録し直させない。

## 想定する段階案（未検証）

1. **音声ベースの区切り検出**: 打球音・拍手のピークでラリー境界を推定し、等間隔分割を置換。
   実装コスト小、まず試す価値が高い。
2. **スコアボードOCR**: 配信画面のスコア表示をフレームサンプリング＋OCRで読み、
   「どちらが取ったか＋タイムスタンプ」の候補列を自動生成。人は `result_type` 等の中身だけ足す。
3. **ボール・選手追跡（CV）**: 当面見送り（研究領域）。

## 課題・未解決

- **権利リスク**: 第三者のYouTube配信のダウンロード・機械処理は規約リスクがあり、
  タイムスタンプリンク（希少イベント案の方式）とは別次元。OCR路線の対象は自前録画か
  権利者に話を通した配信に限るのが安全。着手前に整理必須。
- 音声検出の精度が体育館環境（複数コート同時進行・反響）で成立するか未検証。
- スコアボードOCRはソフトテニス配信のスコア表示形式（大会ごとにバラバラ）への頑健性が未知。
- UGC由来データの集計利用（匿名集計でスタイル分析等の母数に使えるか）は ADR-003/004 の
  private 既定と絡む規約設計の論点。別途検討。

## 目指したい方向性

まだ発散フェーズ。次の一歩を切るなら「自前録画1本に対する音声ベース区切り検出の精度検証」が
最小で、既存の video-review フローに候補を流し込めるかまで見る。

## 追記（2026-09-17）: 大会運営側の採点票デジタル化と、score 機能との比較

X の投稿調査（[X投稿から見たユーザーの課題](./2026-09-17-x-posts-user-problem-findings.md) の F）で、
2026-08-03 の競合調査に無かった**大会運営側**の記録（審判が採点票をデジタルで付ける）が見つかった。
「ポイント単位のデータは外部に存在しない」という本アイデアの前提に関わるので、公開情報を調べた。

### 調べたもの（公開情報のみ・2026-09-17）

**raquty Pro**（raquty合同会社。大会運営の自動化 Web アプリ）

- 審判が専用タブレットで**1ポイントごと**にスコアを入力し、終了後にコートから送信する。
  記録はポイント単位で保存され、試合の振り返りや得失点の分析に使える、と PR で説明している。
- 観客向けの「ゲストサイト」でリアルタイムの進行表・オーダーオブプレイ・勝ち上がり・
  選手別戦績・スコア速報を出す。**第71回全日本女子選抜・第10回全日本男子選抜
  （2026-04-04〜05、有明テニスの森）で全試合に導入**し、2日間で約13,000ユーザーが閲覧（PR の数字）。
- 千葉県中学生ソフトテニス選手権でも導入（PR 見出しで延べ880名・2日間。本文は取得できず）。
  X では千葉県中体連が前年から使っているという声がある。
- 運営側: 総当たりの順位計算、勝ち上がりの自動処理、晴天時・雨天時の進行表の切り替え、コート移動の反映。
- 選手向け（raquty.com）: エントリー、セルフチェックイン、選手による結果登録。
  コーポレートサイトの対象競技は「テニスのみ」とあるが、実際にはソフトテニスの団体も加盟している。
- **わからないこと**: 料金、API・エクスポートの有無、ゲストサイトの公開範囲と保存期間、
  ポイントごとに何を記録しているか（得点者だけか、フォルト・決まり方まであるか）。

**BIGCONC**（NPO法人ソフトテニス振興会）

- 「ジャッジペーパーのデジタル化と速報閲覧」を手掛ける。ポカリスエット杯（2025-02）で、審判のアプリ入力を
  観客がスマホで同時に見られる運用をした（X の選手側の投稿）。サイトには仕組みの詳細が無い。

**ソフトテニス 試合記録アプリ**（個人開発・iOS。初版 2026-05、v1.6.0 が 2026-09-07）

- 1球単位で、選手・ショット種類・結果を最短3タップ。コート上の12か所の位置も記録できる。
- サーブ率（1stイン・1st取得・2nd取得・ダブルフォルト）、ショット別のウィナー／エラー、
  サーブコース別の集計、ヒートマップ、選手別の成績。
- **採点票風の PDF（採点票＋分析カードの A4 縦2ページ）を LINE・メール・AirDrop で共有**。CSV の入出力。
- 無料（10試合まで）、全機能は800円の買い切り。
- 同じ作者かは不明だが、2021年の「ソフトテニス スコアシート」「ソフトテニス ジャッジペーパー」
  （aichido）も採点票の作成・PDF 化が中心。**「採点票の形で出す」ことが現場の標準の出口**になっている。

### score 機能との比較

| 観点 | raquty Pro（大会運営） | 試合記録アプリ（個人） | score 機能 |
|---|---|---|---|
| 記録する人 | 大会の審判 | 選手・保護者・指導者 | 選手本人や関係者 |
| 記録のタイミング | 試合中 | 試合中（または動画を見ながら） | 主に動画から事後。その場の入力も可 |
| 粒度 | ポイントごと（項目の中身は不明） | 1球ごと・ショット種類・コート位置12か所 | ポイントごと: 得点チーム、サーバー、ラリー数、1st／ダブルフォルト、決まり方、決めた・ミスした選手、ショット、コース、動画の区間 |
| 見せる相手 | 観客（ゲストサイト） | 本人とチーム（PDF・LINE・CSV） | 公開ページ・成長記録（同意制、ADR-004） |
| 分析 | 公開情報では速報と選手別戦績 | サーブ率、ショット別、ヒートマップ | **局面別**（デュース、ゲームポイント等）と成長のヒント |
| 動画 | なし（公開情報の範囲） | 記載なし | YouTube 連携。ポイントと動画区間が対応 |
| 大会・選手 DB | 自分が運営した大会だけ | なし | 大会結果・選手ページと接続できる |

**score 機能にしか無いもの**: 動画との対応付け、局面別の分析、大会 DB との接続。
2026-08-03 に決めた主軸（成長のヒント）は、競合のどれとも重なっていない。

**score 機能に無いもの**: その場で素早く付ける入力、採点票の形での出力と LINE 共有、
CSV の入出力、観客へのリアルタイム公開。

### 取り入れられそうなこと（未決定）

1. **大会の公式採点票データとの接続**（影響が最大・不確実性も最大）
   - raquty Pro が全日本選抜 2026 の全試合をポイント単位で記録している。当サイトも
     `data/tournaments/details/zennihon-senbatsu/2026/` を収録済みで、**同じ試合を指せる**。
   - パイロット分析（2026-07-11）の指標のうち、サーブ側の得点率・ゲームポイント局面・デュースは
     **得点チームとサーブ側とスコアの推移だけで計算できる**。採点票にある情報で足りる可能性が高い
     （Assumption。採点票に何が記録されるかは要確認）。
     成立すれば、手入力16試合・717ポイントという母数の問題が、トップ選手の公式戦で一気に変わる。
   - 課題: API が公開されていない。公開範囲・規約が不明。取得は raquty との合意が前提になる。
     **外部への問い合わせはユーザーの判断**。
2. **採点票形式の出力と LINE 共有**（コスト小）
   - 現場の出口は「採点票の形」。score 機能は共有 URL だけ。試合詳細を採点票のレイアウトで
     表示・印刷・画像化できれば、指導者やチームに渡しやすい。
3. **CSV の取り込み**（記録コストを下げる本アイデアの目的に直結）
   - 他のアプリで付けた記録を取り込めれば、score 側で入力し直さずに分析と動画の対応付けだけを担える。
     取り込み元の CSV の形式は未確認。
4. **その場で付ける軽量な入力**（2026-08-03 の示唆の再確認）
   - 「最短3タップ」が競合の水準。score の入力はキーボードのショートカットと自動推定まで来ているが、
     スマホでその場で付ける動線は主ではない。
5. **観戦者へのリアルタイム公開**（記録する動機づくり）
   - raquty の約13,000人と、GameChanger の家族向け実況は同じ構図。ただし score の公開は同意制
     （ADR-004）で、未成年の扱いを含め設計が要る。

**取り入れないもの**: エントリー受付・進行の自動化・審判タブレットといった大会運営そのもの。
事業の範囲が違い、raquty と競合するより接続先として扱うほうが筋が良い（Assumption）。
ただし「当日の進行表をどこで見られるか」の案内（X 調査の A）として、
raquty のゲストサイトへのリンクを大会ページに置くのは低コストで両立する。

### 次に確かめること

- 全日本選抜 2026 のゲストサイトを実際に開き、ログインなしで何が見えるか
  （ポイントの推移まで見えるか、ゲームスコアだけか）。
- 採点票に記録される項目（得点者・フォルト・決まり方のどこまでか）。
- 試合記録アプリの CSV の形式。
