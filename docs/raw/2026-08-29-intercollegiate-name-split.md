# インカレのドロー表: 姓名の境目は座標に入っていた（2026-08-29）

## きっかけ

2026年インカレ（三笠宮賜杯全日本学生選手権）男子ダブルスのドロー表PDF（全8ページ・
585エントリー）を `initialPlayers` 形式JSONに変換する作業。

`scripts/pdf-to-players/` の `intercollegiate` プロファイルには、こう書いてあった:

> 氏名は均等割り付けで姓名の境目が座標に無いため分割しない（姓に氏名がまとめて入る）

つまり `lastName: "川﨑康平", firstName: ""` という形でしか出せず、1170名ぶんの
姓名分割が手作業として残る前提になっていた。ユーザーからも
「インカレは姓名の区切りが座標ではわからない。いい方法はない？」と質問があった。

## 分かったこと: 均等割り付けは**姓と名それぞれに**掛かっている

文字の x 座標を実際に見たら、氏名全体が等間隔なのではなく、
**姓の枠と名の枠が別々に均等割りされていて、境目の字間だけが広い**と分かった。

```
松尾奏汰   字間 [10.1, 18.2, 10.0]  → 松尾|奏汰
浅野梨空   字間 [11.9, 14.5, 11.8]  → 浅野|梨空
榎祐希人   字間 [14.6, 11.8, 11.8]  → 榎|祐希人      (1+3)
小田原晃太 字間 [5.5, 5.5, 13.6, 5.5] → 小田原|晃太   (3+2)
山岡昂太郎 字間 [6.8, 9.5, 7.0, 6.8] → 山岡|昂太郎    (2+3)
廣田将     字間 [21.9, 24.4]         → 廣田|将        (2+1)
平凛生     字間 [24.4, 21.8]         → 平|凛生        (1+2)
```

差は 2.5pt 前後。文字数での機械的な半分割りではなく、1+3 も 3+2 も正しく割れる。

**検証**: リポジトリの既存選手データ（`data/` 配下の `lastName`/`firstName`、
23,812組・姓5,937種）と照合できた796名のうち **793名（99.6%）が一致**。
不一致3件はいずれも**既存データ側の誤り**だった:

| 氏名 | 座標 | 既存データ |
|---|---|---|
| 西浩太朗 | 西 \| 浩太朗 | 西浩 \| 太朗 |
| 榎祐希人 | 榎 \| 祐希人 | 榎祐 \| 希人 |
| 西奏音 | 西 \| 奏音 | 西奏 \| 音 |

`西浩` `榎祐` `西奏` はいずれも姓として不自然で、座標のほうが正しい。

## 信号が出ない行の扱い

字間が完全に均一（差 0.1pt 以下）な行が 1170名中43名あった。ここは本当に境目が
座標に無い。**argmax を無条件に採ると `牛尾彗吾` が `牛尾彗|吾` になる**（実際に出た）。
なので「他の字間との差が 1.5pt 以上」を条件にした。実測では信号のある行は 2.5pt 以上、
無い行は 0.1pt 以下ときれいに分かれるので、その谷間に閾値を置ける。

信号が無い43名は、この順で落とす:

1. **既存の選手データに同じ氏名がある**（32名）。割り方が2通りある氏名は決めない
2. **姓の辞書と名の辞書の両方に当たる切り方が1通りだけ**（9名）
3. どれでも決まらなければ**分割しない**（2名）。`firstName` を空のまま
   `review_name_split` に出して人に回す

最終的に残ったのは `池澤渓人` `武井心希` の2名だけ。どちらも名（渓人 / 心希）が
既存データに1件も無いため辞書で決まらなかった。人が見れば一目なので手で割ったが、
**機械には推測させていない**。

## ついでに直った/見つかった2つのバグ

プロファイルを `splits_name=False` から実際に分割する形へ変えたら、p2以降が崩れた。
原因は姓名分割とは別の、既存の2つの問題だった。

1. **エントリー番号の列が氏名の列に飲まれる。** 番号が3桁になると数字が x=74 まで
   伸び、氏名の左端 x=80 との間が 6.2pt しか空かない。プロファイルの `gap=9` では
   両者が1つの列に融合し、番号が「氏名」として拾われて 585 件が 715 件になっていた。
   → `gap=6.0` に変更。
2. **氏名の枠が2列に割れたページを「姓の列と名の列」と誤読する。** 均等割り付けの
   氏名はページによって列検出の割れ方が変わり（1〜3列）、たまたま2列に割れた p2 の
   右段だけ `木|村奏都` のようにずれていた。
   → プロファイルに `name_in_one_column` を追加し、**列がいくつに割れても氏名として
   扱い、姓名の境目は字間で決める**ようにした。列検出の揺れに結果が左右されなくなる。

1 は `gap=9` のままでは番号の列を失うので必須。2 は 1 を直しただけでは残る。

## 結果

- `scripts/pdf-to-players/namesplit.py` を追加（字間 → 既存データ → 辞書 → 未分割）
- `geometry.Row` に `char_boxes` を追加（セル文字列に潰すと座標が失われるため）
- `extract_tournament.py` に `apply_role_overrides()` を切り出し、本番と回帰テストが
  同じ経路を通るようにした（テスト側がパイプラインを再実装していた）
- レポートに「姓名の分割」の内訳を出すようにした。`clean: true` を
  「全部確かめた」と読み違えられないように、**何をどこまで機械が決めたか**を見せる
- 出力: `tools/incare-2026/doubles-none-boys.initialPlayers.json`（585エントリー / 1170名）
- 回帰テスト 65/65 pass。PDFを `fixtures/intercollegiate-2026-men-doubles.pdf` として
  固定し、585件・エントリー1/74/111/585の姓名・未分割2名までを押さえた

## 残っている懸念

- **旧 fixture `intercollegiate-draw.pdf`（団体戦ページを含む別のPDF）が手元に無く、
  `gap=9→6` の影響を再検証できていない。** 件数の期待値（p3が72件・p1が45チーム）は
  そのままにしてあるので、当該PDFを持っている環境で回せば失敗として現れる。
  `name_in_one_column` により氏名の列が割れても害が無くなったので gap を下げても
  問題ないはずだが、**確認はしていない**。
- 女子ダブルス・団体戦は未着手（同じ様式なら同じ設定で通るはず）。

# 追記: 女子ダブルスと、既存データの割り方の揺れ（2026-08-29）

## 女子のPDFは字間が効かない

男子と同じ様式に見えて、**氏名の組み方が違った**。男子は姓と名それぞれに均等割り付けが
掛かるが、女子はほとんどの行が氏名全体を等間隔に置く（字間 `[8.6, 8.5, 8.6]` のように
差が 0.1pt しかない）。字間で決まったのは 664名中42名だけ。

ただし**誤って割ることは無かった**。信号のあった42名は、既存データと照合できた
38名すべてで一致（不一致0）。閾値 1.5pt は、様式が変わっても誤検出を出さないという
意味でも妥当だった。

残りは既存の選手データ（520名）と姓名の辞書（64名）で埋まり、38名が残った。

## 所属まで見て照合する段を足した

残った38名を調べると、**同じ人が既存データに複数の割り方で登録されている**ケースが
あった。しかも誤っているほうは決まって過去の `zennihon-university`（インカレ）の
取り込みだった。

| 氏名 | 割り方A | 割り方B | 備考 |
|---|---|---|---|
| 谷明日里 | 谷\|明日里 13件 | 谷明\|日里 4件 | Bは zennihon-university 2023/2025 のみ |
| 温品芽叶子 | 温品\|芽叶子 7件 | 温品芽\|叶子 1件 | Bは zennihon-university 2023 singles |
| 堀早弥夏 | 堀早\|弥夏 3件 | 堀\|早弥夏 3件 | 大学ではA、高校時代はB |
| 伊東月 | 伊東\|月 2件 | 伊\|東月 1件 | Bは zennihon-university 2024 |
| 津波古莉央 | 津波古\|莉央 6件 | 津波\|古莉央 3件 | **所属で見るとBが3:1で多数** |
| 﨑羽瑠菜 / 﨑羽香菜 | 﨑羽\|X 各1件（大学） | 﨑\|羽X 各1-2件（高校） | 大学と高校で食い違う |
| 森未唯菜 | 森未\|唯菜 1件（大学） | 森\|未唯菜 2件 | 同上 |

そこで **(氏名, 所属) で引く段**を `split_by_team_corpus` として足した。氏名だけで引くと
同姓同名の別人や過去の誤りに当たるが、所属まで合えば同一人物とみなしてよい。
**既存の `playerId` と結びつけるうえでも、その所属で使われている綴りに揃っているほうが
正しい。** 同一人物に複数の割り方があるときは件数の多いほうを採り、同数なら決めない。

これで8名が決まり、未分割は30名に減った。段の順序は 字間 → 所属つき照合 →
氏名のみ照合 → 姓名辞書 → 未分割。

## gap は 4.0 でないと両方通らない

男子で `gap=9→6` にした件は、女子ではさらに厳しかった。女子のp3以降は3桁の番号が
氏名の左端との間に **4.7pt** しか空けない（男子は6.2pt）。`gap=6` だと番号が氏名の列に
飲まれ、332件が395件になる。`gap=4.0` にして両方とも正しい件数になった。

男子は `gap=6.0` の結果と `gap=4.0` の結果が**全585エントリー・1170名で完全に一致**する
ことを確認済み（氏名の列が細かく割れる副作用は `name_in_one_column` が吸収する）。

## 人が決めた分（機械には決めさせていない）

男子2名・女子30名。女子の30名は「姓は明らかだが名が既存データに1件も無い」型で、
`杉浦\|颯夏` `鈴木\|陶子` のように迷う余地の無いものが大半。
確信が持てなかったのは次の2つで、ユーザーに確認を出した:

- `髙時謡`（成蹊大学）… `髙時\|謡` と読んだが `髙\|時謡` の可能性
- `保米本和`（天理大学）… `保米本\|和` と読んだ（保米本は奈良の姓で天理大学と符合する）

加えて、既存データが食い違っていて所属で決めた4件（津波古莉央・﨑羽瑠菜・﨑羽香菜・
森未唯菜）も確認に出した。

## 結果

- `tools/incare-2026/doubles-none-girls.initialPlayers.json`（332エントリー / 664名）
- 男子も `prefecture: "日本学連"` / `tempId: 姓_名_学校_日本学連` に更新
- PDFの生文字から組み直した氏名・所属と**全件一致**（男子1170名・女子664名、差分0）
- 回帰テスト 77/77 pass（女子PDFも fixture 化）

# 追記2: 男子団体（文部科学大臣杯全日本大学対抗選手権）（2026-08-29）

## 別大会なのでプロファイルを分けた

## 見出しがチームとして2件入っていたバグ

**「番号として読める行」**（`to_int` が通る行）に変えて解決。全中・インカレ・
2段組の一覧のいずれも番号の列には数字しか入らないので、この条件は狭めても
既存を壊さない（回帰89/89 pass）。

- PDFの番号1〜96とチーム名の対応を座標から独立に組み直して**全96件一致**（差分0）

# 追記3: 男子シングルスと、大会中の選手交代（2026-08-29）

## シングルスは種目として無かった

`guess_category` は `doubles` / `team` しか返さず、`build_entries` も
「2人そろったら次のエントリー」で組んでいた。シングルスのドロー表を流すと
**2エントリーが1エントリーに潰れる**。

足したのは3点だけ:

- `--category singles` / プロファイルの `category='singles'`
- 組み立てを「1人そろったら次」に読み替える（`per_entry`）
- `name` を `姓 名（所属）` にする。ダブルスは `姓・姓（所属）` だが、シングルスは
  1名なので姓だけでは誰か分からない。既存の `tools/hjs-2026/01_mens_singles.json` が
  半角スペース区切りだったので合わせた
- `checks` の「ペアの2人目が無い」をシングルスでは出さない

**シングルスは自動判定しない。** ドロー表の見た目はダブルスと同じで、違いは
「1つの番号に何名ぶら下がるか」だけ。行のまとまり方が崩れているときも同じ形に見えるので、
機械に見分けさせると崩れをシングルスと誤認する。人が明示する。

## 署名の衝突

`全日本学生シングルス選手権大会` は `intercollegiate`（三笠宮賜杯）の署名
`['三笠宮賜杯', '全日本学生']` の後者に当たってしまう。**別大会なので署名を分けた**:

- `intercollegiate` … `['三笠宮']`（男子=三笠宮賜杯 / 女子=三笠宮妃賜杯 の両方に当たる）
- `intercollegiate_singles` … `['全日本学生シングルス']`

`detect()` は先に一致したものを返すので、部分文字列の包含関係がある署名を並べると
順序に依存する。**署名は「その大会だけに出る語」にすること。**

## 所属名が次の行に溢れる

この様式では所属名が長いと括弧の中が空になり、**すぐ下の行（y+2pt）に所属名だけが
置かれる**。6件あった（石川工業高等専門学校 ×2 / 関西外国語大学 ×4）。
`y_tol=3` で同じ行に取り込まれるので追加の実装は要らなかったが、
**溢れた行のx座標は元の段のx範囲に収まっている**（右段の溢れは右段のx範囲に出る）ので
左右の取り違えも起きない。回帰テストではこの6件のうち3件をスポットで固定した。

## 大会中の選手交代（`--substitutions`）

ドロー表PDFは開幕前に配られる。開幕後の欠場・補欠との差し替えでPDFは出し直されないので、
抽出しただけのJSONは途中から実態とずれる。

出来上がったJSONを直接書き換える案は採らなかった。**PDFから作り直した瞬間に交代が消える**し、
「誰がいつ誰に代わったのか」も残らないため。交代は別ファイルに書いて抽出のたびに上乗せする
（`scripts/pdf-to-players/substitutions.py`）。

```json
[{"id": 12, "note": "2026-08-30 欠場のため補欠と交代",
  "players": [{"lastName": "山田", "firstName": "太郎"}]}]
```

設計で意識した点:

- **`id`（ドローの位置）は動かさない。** 交代しても枠は同じ
- **交代後の全員を書く。** 片方だけ代わったダブルスでも2名書く。差分でなく現在の姿を
  書かせることで、ファイルを見るだけで「いま誰がその枠にいるか」が分かる
- **`team` を省くと元の所属を引き継ぐ。** 同じ大学からの補欠が大半
