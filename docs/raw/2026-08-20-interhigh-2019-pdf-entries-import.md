# 2019年インターハイ結果PDFからのエントリー抽出

## 背景

ユーザーから2019年（令和元年度）全国高等学校総合体育大会ソフトテニス競技大会の記録報告書PDF
（`recordreport_3_03.pdf`, 96ページ）を渡され、`highschool-championship/2019/` の4カテゴリ
（doubles-none-boys / doubles-none-girls / team-none-boys / team-none-girls、既存は2021〜2026のみ）
を追加できるか確認する依頼を受けた。「結果（スコア・勝敗）込みでJSON化できるか」「今後も過去大会を
処理したいのでスクリプト化してほしい」という要望だった。

## PDF構成の調査結果

- 個人戦（ダブルス）: 予選ラウンド（1回戦〜準々決勝前、男子p19-26/女子p56-63）はコンパクトな
  トーナメント表形式で、**敗者側のゲーム数（1桁）のみ**が合流点付近に赤字で印字される。勝者側の
  数字も、対戦カードそのものの再掲もない。
- 個人戦・準々決勝〜決勝（男子p27/女子p64）と団体戦・全ラウンド（男子p30-53/女子p67-90）は、
  ペア/組ごとにゲームスコアが明記され、丸数字（①-⑳）＝そのゲーム/その対戦の勝者という形式で
  完全にテキストから読み取れる。
- 個人戦・入賞者一覧（男子p17/女子p54）、団体戦・入賞校一覧（男子p28/女子p65）が独立した
  正式記録として存在し、上記の答え合わせに使える。

### 予選ラウンドの勝敗が自動判定できない理由

赤い罫線（`non_stroking_color=(1,0,0)`の細い矩形として描画されるブラケット線）を pdfplumber で
座標抽出し、幾何学的にトレースすることも試みたが、以下が判明した:

- 罫線の合流点（勝者が枝分かれする箇所）は、勝者側・敗者側どちらの入力線からも同じ縦線に接続する
  ため、線の接続関係だけでは勝者を判定できない。
- 敗者のスコア数字は「合流点の高さ」付近に破線（ドット矩形の列、`non_stroking_color=0`,
  幅/高さ約0.96ptの小矩形の反復）でリーダー線が引かれて配置されるが、そのX/Y位置は
  ラウンドごとに変化し、かつ列（本人の行の高さに出る＝1回戦の場合／合流点の高さに出る＝2回戦以降
  の場合）で意味が変わる。
- 実際に崎/紙西ペア（女子, entryNo17-18）の「R2」（棄権, 2回戦）表記を手がかりに検証したが、
  1回戦の敗者スコアは「本人の行の高さ」、2回戦以降は「合流点の高さ」という規則性は見えたものの、
  シード・不戦勝・全19エントリーのような奇数draw（byeの位置が非自明）を含めて確実に自動判定できる
  確信が持てなかった。

このプロジェクトの「捏造しない」方針（`scripts/pdf/university_indoor.py` の前例、
[data-import.md](../wiki/data-import.md) 参照）と、過去に不正確なブラケット由来データが
インターハイ2026の誤った大会インサイト公開・取り下げに繋がった実害
（[2026-08-01-bug-bye-derived-matches-not-exported.md](2026-08-01-bug-bye-derived-matches-not-exported.md)）
を踏まえ、ユーザーに状況を説明した。ユーザーの判断は「誤りの可能性があるなら、選手jsonだけでいい」。

## 実施したこと

`scripts/pdf/highschool_championship_entries.py` を新規作成し、エントリー（選手・チーム情報）のみを
抽出するスクリプト化を行った。**matches/results は生成しない**（空配列）。

抽出結果（2019年）:

- `doubles-none-boys`: 参加者632名 / エントリー316
- `doubles-none-girls`: 参加者644名 / エントリー322
- `team-none-boys` / `team-none-girls`: 各48校

`npm run check:entries` はエラー0（新規追加分に起因する警告なし）。

## 抽出ロジックのハマりどころ（今後の年度処理でも起きうる）

- 姓・名の列は文字数に応じて均等割り付けされるため、**姓と名を別のX範囲で切ると、姓内部の
  字間が姓/名境界の字間より広いケースがあり誤爬（誤って別の列に文字が漏れる）が起きる**。
  姓＋名をまとめて1つの範囲で取得し、`姓2文字＋名残り`で分割する方式
  （`scripts/pdf/university_indoor.py` の `split_name` と同じ発想）にした。
- 氏名列と都道府県/学校名列の境界も、同じ理由でページ・行によって数pt前後する
  （実測で最小153.5pt〜最大159ptの幅でブレた）。固定しきい値で追い込みきれず、
  「都道府県が47都道府県の正式表記と完全一致するか」を検証し、不一致なら氏名側から
  都道府県側へ1文字ずつ付け替える補正パス（`_fix_leaked_area`）を入れて解消した
  （接尾辞（県/府/都/道）で終わるかだけのチェックでは、「重県」のような1文字欠落を
  見逃すため、完全一致リストが必須だった）。
- エントリー番号列と氏名列のX範囲は近接/一部重複するため、範囲ではなく「その行の文字が
  全部数字かどうか」で行の種別（エントリー番号行 / 氏名行）を判定する方式に変更した。
- 稀に、ページ最下部（本文と脚注の境界付近）で特定の1文字（例: 「辻」）がテキストレイヤーから
  丸ごと欠落しているケースがあった（entryNo 209, 305 の男子、257 の女子、計3件/1276名）。
  リーダー線・幾何学トレースでは復元できず、既知の欠損として残した。

## 未解決 / 今後の課題

- 予選ラウンドの `matches` / `results`（勝敗・獲得ゲーム数・敗退ラウンド）は未生成。
  過去大会でこれが必要になった場合、`tools/tournament3` のブラウザ入力ツールに
  本スクリプトの抽出結果を `initialPlayers` として渡し、PDFを見ながら人手でスコア入力する
  運用が現実的（[data-import.md](../wiki/data-import.md)「大会結果入力ツール」参照）。
- 3件の氏名欠落（209, 305, 257）は手動で埋める必要がある。
