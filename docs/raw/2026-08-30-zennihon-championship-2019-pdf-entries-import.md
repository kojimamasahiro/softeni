## レイアウトと解き方

```
左ブロック: [番号] [氏名フィールド] ( [都道府県] [所属] ) [スコア]
右ブロック: [スコア] [氏名フィールド] ( [都道府県] [所属] ) [番号]
```

1エントリー = 3行（選手1 / 括弧行 / 選手2）で、エントリー番号は括弧行にある。

### 都道府県・所属の解決（この様式の肝）

**括弧行はペアで共通の値、選手の行は個別の値**。両方が異なるときは括弧の中身が空になる
（`船水颯人 東京 ヨネックス / ( ) / 上松俊貴 日本学連 早稲田大学`）。県だけ共通で
所属が違う場合は、県が括弧行・所属が各選手の行に出る
（`合川幸貴 …ＪＲ東日本盛岡 / 2 (岩手) / 藤森源 …見前ＳＴＣ`）。したがって

> その選手の行に値があればそれを、無ければ括弧行の値を使う

で解ける。これは一般カテゴリ特有で、学校単位の高校・中学の大会には無い構造。

### 姓名分割は「7スロット固定グリッド」で確定する

氏名欄は全角スペース詰めの7スロット（男子ピッチ8.74pt・女子8.51pt）で、
**スロット0-2 = 姓 / スロット3 = 区切り / スロット4-6 = 名**。

| 印字 | 使用スロット | 分割 |
|---|---|---|
| `船　水　颯　人` | 0,2,4,6 | 船水 ｜ 颯人 |
| `藤　森　　　源` | 0,2,6 | 藤森 ｜ 源 |
| `林　　　大喜` | 0,4,6 | 林 ｜ 大喜 |
| `柳　田　賢太朗` | 0,2,4,5,6 | 柳田 ｜ 賢太朗 |
| `嘉味田　裕　樹` | 0,1,2,4,6 | 嘉味田 ｜ 裕樹 |
| `小　茄　子　川　　夏　月` | 0,1,2,3,5,6 | 小茄子川 ｜ 夏月 |

スロット3まで埋まるのは4文字姓のときだけ（全720人で `小茄子川夏月` の1件）。
skillの「姓名分割パターン1〜3」のどれでもない**第4のパターン**で、
座標の動的計算すら要らない（既知の等間隔グリッドにスロット番号で当てるだけ）。

### 行の組み立ては上端でなく「上下中心」で行う

所属欄は列幅に収まらないと**フォントが小さくなる**（8.8pt → 4.7pt まで実測）。
文字の `top` で行をまとめると小さい字が別の行へ流れる。上下中心で揃えれば
サイズ差に影響されない。

### 所属名の折り返し ― 座標では判定できない

`神戸松蔭女子学院大学` が1件だけ `神戸松蔭女子学院大` ＋ `学` の2行に折り返されていた。
これを機械的に見分けようとして失敗した記録:

- **行送り比 gap/size は 1.18 と 1.29 の2値しか無く、折り返しの 1.18 は
  「隣のエントリーの所属行との間隔」と完全に同じ値**だった。
- 最寄りアンカー（氏名行 / 括弧行）との距離でも分けられない。
  所属行はフォントが小さいほどアンカーから離れて置かれ（サイズ4.7で1.46pt、
  5.8で2.13pt）、折り返しの `学`（1.47pt）はその分布のど真ん中に来る。
- 「列幅を使い切っているか」も効かない。折り返し元の右端の余りは4.1ptで、
  折り返していない行にも余り0.0〜3.6ptのものが多数ある。

結論として**座標では原理的に分けられない**ので、最後の判断は
「**1文字だけの所属名は現実には無い**」という意味的な条件に置いた。
取りこぼす方向に倒し、結合したものは必ず警告に出す。
（`data/teams/teams.json` には `巻` `絆` 等の1文字チームが15件あるので、
高校・中学の略称表記が混じる大会にこの条件をそのまま持ち込まないこと。）
