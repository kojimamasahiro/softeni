## 検討した構成

1. **GA4 Data API ＋ GitHub Actions で週1取得 → JSON をコミット → CF Pages が再ビルド**
   - 手動は `workflow_dispatch`。サービスアカウント作成・GA4 への閲覧権限付与・Secret 登録（数値のプロパティID含む）が要る
   - `review-snapshot.yml` の「生成物を書き戻すな」原則との関係: GA4 の数字はリポジトリから再生成できない外部データなので
     書き戻しの対象にしてよい側。`/live/` 案で書き戻しを退けたのは30分ごとという頻度のためで、週1なら当たらない
   - 今回は見送り。ユーザーがまず手で結果を見たいため
2. **prebuild で API を叩く** — 退けた。CF Pages 側に認証情報が要り、GA4 の障害でビルドが落ち、push が無い週は入れ替わらない
3. **CSV を手で取り込む（採用）** — 認証設定ゼロ。1 の取得部分だけ後から差し替えられるよう、
   集計（`lib/popularPages.ts`）と名前解決（`lib/popularPagesData.ts`）は取得方法に依存させていない

## 実装メモ

- JSON（`data/popular-pages.json`）は**並びだけ**。リポジトリが PUBLIC（`kojimamasahiro/softeni`）なので表示回数は残さない
- ページの実在はビルド時にも再判定する。選手の結果ページは `count>=5` で、データ追加で消えることは無いが名寄せで ID が変わりうる
- 固定3人のうち「上松 俊樹」は選手マスタでは「上松 俊貴」。名前をマスタから引くようにしたので表記も直った
- `/players/{slug}/`（プロフィール27件）は `data/players/index.json` で同姓同名が1件のときだけ結果ページへ合算
- `/secondaryschool/pathways/{gender}/` は学校ページと同じ2階層なので明示的に除外
- `readJson` にパス配列を展開して渡す形は nft がリポジトリ全体を走査するため、呼び出し側でリテラルに書いた
  （`lib/secondaryschool.ts` の注記と同じ理由）
- サンプル CSV（実在 ID で作成）で dry-run・dev サーバの表示を確認。**実物の GA4 CSV では未検証**

## 追記（2026-09-14・同日）: 実物の CSV で取り込んで分かったこと

ユーザーが GA4 の探索（自由形式）から書き出した CSV（2026-08-17〜09-13、14,504行）で dry-run した。

### 1位が水増しされていた

最初の結果は「1位 141回 尾田 美桜（YSTC）`/players/4898/results/`」。内訳をユーザーが貼ってくれた:

- `/players/4898/results/` 91回
- `/players/4898/results/#google_vignette` 4回 — AdSense のビニエット広告が付けるハッシュ。同じ閲覧の重複
- `/players/4898/results/?q=...` 46回 — 「お」「おた」「き」「きっさか」「濱田れ」「濱田れん」…と**1文字ずつの入力**。
  中身は尾田ではない選手名が大半

`?q=` は選手・チームのページが使わないパラメータなので、`?q=` と `#google_vignette` の行は数えないようにした
（utm_* 等の他のクエリ文字列は外部からの着地として数える）。直した後の選手の上位は
裏 友輝 121回 / 黒坂 卓矢 95回 / 尾田 美桜 91回。

**結果ページの URL に `?q=` が付く経路は特定できていない。** dev サーバで `router.events` と
`history.pushState/replaceState` を記録しながら「`/players/` で検索 → 結果ページを開く → ブラウザバック」を
たどったが、URL はどの時点でも正しかった（`/players/?q=尾田` → `/players/4898/results/` → `/players/?q=尾田`）。
Next の router も `changeState`（URL 更新）の後に `routeChangeComplete` を出しているので、古い URL が
`page_location` に載る経路ではない。本番にしか無い AdSense（ビニエットがリンクのクリックを横取りする）や
モバイルのスワイプバックが候補だが、Assumption の域を出ない。

### サイト全体でも表示回数の36.6%が検索窓の入力

同じ CSV で、**表示回数 54,333 回のうち `?q=` 付きの行が 19,883 回（36.6%）**、`#google_vignette` が 151 回。
選手・チームのページに付いていたのはそのうち 1,381 回と 17 回。
大半は `/players/?q=` で、`src/pages/players/index.tsx` が 400ms ごとに shallow に URL を書き換え、
`_app.tsx` の `routeChangeComplete` が毎回 `page_view` を送るため。**これは想定どおりの実装の帰結**だが、
PV やモジュールCTR（分母が `page_view`）を読むときに3分の1以上が入力の打鍵という状態になっている。
直し方（`search` イベントに分ける等）は `check-search-misses.mjs` の入力を変えるので、ユーザー判断待ち。

### CSV の形

- 探索の書き出しは期間を `# 20260817-20260913` の1行で持つ（標準レポートの `# 開始日:` 形式ではない）。
  最初の実装は期間を読めず「期間: 不明」になったので、この形も読むようにした
- 総計行は `,54334,総計` の3セル。パスが `/` で始まらないので従来どおり読み飛ばせた
