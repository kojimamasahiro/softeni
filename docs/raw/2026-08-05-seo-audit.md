## A. 確実なバグ（原因まで特定済み）

### A-1. デプロイされる sitemap が常に「1ビルド古い」【最優先】

**症状**: `out/sitemap-0.xml` は 3,369 URL、同時刻に生成された `public/sitemap-0.xml` は
3,461 URL。差分 92 件は全て **index 対象の高校学校ページ**（例
`/highschool/boys/akita/akita/`, `/highschool/girls/hokkaido/asahikawashougyou/`）。
データ上も現存する正規ページで、noindex でもない。

**原因**: `next-sitemap` の `outDir` 既定値は `public/`。一方 `next build`（`output: 'export'`）は
**export の途中で `public/` を `out/` にコピーする**。実行順は

```
next build（public/ → out/ をコピー）  →  postbuild: next-sitemap（public/ に書く）
```

なので、`out/sitemap-0.xml` は「**前回**のビルドが `public/` に残していった sitemap」になる。
`public/sitemap-0.xml` は git 追跡されているため、コミットしていれば遅延は1ビルド、
コミットを忘れればその時点で固定される。

傍証:
- `public/sitemap-0.xml` にのみ `/highschool/boys/akita/akita/` が存在（out には無い）
- HEAD の `public/sitemap-0.xml` は 3,461 `<loc>`（= 今回生成分と一致）
- `scripts/sort-sitemaps.mjs` は `public/` しか読んでいない（`out/` のソートは前回ビルド由来）
- `scripts/filter-noindex-from-sitemap.mjs` は両方見ているので、noindex 除去だけは効いている

**修正案（どちらか）**:
- `next-sitemap.config.js` に `outDir: 'out'` を明示し、`sort-sitemaps.mjs` の対象も `out/` に変更
- または `postbuild` の末尾に `cp public/sitemap*.xml public/robots.txt out/` を足す

**副次的な効果**: 直せば `public/sitemap-0.xml` を git 管理する必要がなくなる（生成物なので
gitignore できる）。

### A-2. `/matches/*` 22 URL が sitemap にあるが canonical は別 URL

score ドメイン用のページ（`src/pages/matches/`）が softeni-pick 側のビルドにも出力され、
**sitemap に載っている**。実体は canonical で `/tournaments/.../matches/<id>/` に寄せてあるため、
GSC で「代替ページ（適切な canonical タグあり）」が 21件出続ける構図。

- `/matches/<id>/` 21件: canonical が別 URL。内部リンク inbound = 0（孤立）
- `/matches/` 一覧: self-canonical・index 対象・inbound 0・title が `試合結果一覧`
  （サイト名サフィックスも「ソフトテニス」も無い唯一のページ）

同一試合が `/tournaments/.../matches/<id>/`・`/beta/matches-results/<id>/`・`/matches/<id>/` の
**3 URL** で出力されている（seo.md #6 は前2者しか想定していない）。

**修正案**: `next-sitemap.config.js` の `exclude` に `/matches`・`/matches/*` を追加。
より根本的には `filter-noindex-from-sitemap.mjs` を **「canonical が自 URL と一致しない
ページも sitemap から除外」** に拡張すると、同種の事故（新しい重複 URL 種別が増えたとき）を
構造的に防げる。判定を1箇所に集約するという同スクリプトの設計意図とも整合する。

### A-3. sitemap に重複 `<loc>` が 8 件

`additionalPaths` が明示追加している `staticPublicPaths`（`/about/`, `/contact/`, `/faq/`,
`/privacy/`, `/st-league/about/`）と `/growth/`・`/growth/<slug>` が、next-sitemap の自動列挙とも
重複し `<url>` が2回出力されている。

コメントには「純粋な静的ページは自動列挙されない」とあるが、**実測では列挙されている**
（Next.js / next-sitemap のバージョン更新で挙動が変わった可能性）。

**修正案**: `additionalPaths` の最後に既出 loc を除外するか、`staticPublicPaths` を削除して
自動列挙に任せる（削除する場合は1ビルド分の実測で消えないことを確認してから）。

### A-4. 高校選抜ページで「（高校選抜）」が二重に出る

`src/pages/highschool/tournaments/[tournament]/index.tsx`:

```ts
const titleName = label === shortLabel ? label : `${label}（${shortLabel}）`;
const headingName = primaryAlias ? `${titleName}（${primaryAlias}）` : titleName;
```

senbatsu は `shortLabel: '高校選抜'` かつ `aliases: ['高校選抜']` なので両方が付く。

実際の出力:
- h1: `全日本高等学校選抜ソフトテニス大会（高校選抜）（高校選抜） 歴代結果・優勝校一覧`
- title: 70字（サイト内最長。SERP で確実に切れる）
- description: `ソフトテニス「…（高校選抜）」（通称「高校選抜」）の歴代優勝校…`

**修正案**: `primaryAlias === shortLabel` のとき alias を付けない（1行）。
championship / japan-cup は影響なし。

## 追記: 「`/matches/*` を外すとどうなるか」（2026-08-05・調査）

Open Questions に挙げた「softeni-pick 側のビルドから `/matches/*` を丸ごと外せないか」への回答。
**丸ごと外すのは不可**。sitemap から `/matches/<id>/` だけを外すのが正解。

### `/matches/**` の現在の役割（`lib/siteConfig.ts`）

`getPublicMatchDetailPath()` は siteLink の有無で分岐する:

- **掲載大会の試合（siteLink あり）** → `/tournaments/.../matches/<id>` が正。
  `/matches/<id>` は同じ内容の重複 URL（canonical で正へ寄せてある）
- **野良試合（siteLink なし）** → `/matches/<id>` が**正の URL**（self-canonical）

つまり `/matches/<id>` は「常に重複」ではなく、**siteLink が無い試合にとっては唯一の公開 URL**。
現時点で野良試合が 0 件なので、たまたま 21枚すべてが重複になっているだけ。

### 丸ごと外した場合に壊れるもの

| 対象 | 影響 |
|---|---|
| `public/_redirects` の `/beta/matches-results/* → /matches/:splat 301` | 301 の飛び先が 404 になる。旧 URL の評価が捨てられる |
| `/matches/`（試合一覧） | 2026-07-04(M3) に正規化した公開一覧。大会配下の試合詳細ページ20枚から内部リンクあり |
| `/matches/growth/`・`/matches/highlights/` | 既に `noindex` だが実ページとして稼働。前者は 30本以上の deep link（`?targetKey=`）あり |
| 将来の野良試合 | 公開先そのものが消える |

### 結論（推奨）

- **ページは残す**。消すのは sitemap のエントリのみ
- `exclude` に `/matches/*` を足す手もあるが、それだと野良試合が出てきたとき
  「正の URL なのに sitemap に無い」状態になる
- **推奨は A-2 に書いた一般化**: `scripts/filter-noindex-from-sitemap.mjs` を
  「**canonical が自 URL と一致しないページも sitemap から除外**」に拡張する。
  - siteLink あり → canonical が別 URL → 自動で除外
  - 野良試合 → canonical が self → 自動で残る
  - 判定をページ側（canonical）に一本化するという同スクリプトの既存の設計思想と一致し、
    将来 3つ目の重複 URL 種別が増えても自動で効く
- `/matches/`（一覧）自体は self-canonical の正規ページなので sitemap に残してよい。
  ただし title が `試合結果一覧` のみでサイト名も「ソフトテニス」も入っていない
  （サイト内で唯一）ので、そこは別途直す
