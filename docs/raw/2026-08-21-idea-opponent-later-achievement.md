# アイデア: 過去に負けた相手のその後の活躍を選手結果ページに出す

## 状況

Idea Backlog。発散フェーズだが、実データで規模を一次検証済み（2026-08-21）。

## 目的

選手結果ページの対戦成績（過去の敗戦を含む）を見たとき、「このとき負けた相手は、その後どう
活躍したか」を能動的に気づかせたい。現状は対戦相手の選手ページへのリンクは既にあるが
（`count>=5` の相手のみ）、そこに「その後の実績」を示すシグナルは無く、気づくには自分で
相手のページを開いて確認する必要がある。

## ユーザーが興味を持った点

- 最初は逆方向で提示（「大学で活躍している選手が高校時代に勝った相手のその後」）したが、
  ユーザーが訂正:
  > 「逆で、高校時代には負けた選手が大学でどのような活躍をしたのかを知りたいと思った。
  > ユースケースとしては、最近強くなった選手の過去の大会を見て、負けていた場合、その勝った
  > 選手が最近どのような活躍をしたかを知りたいと思った。ただ、その選手ページに行けばいいと
  > いう代替手法はある」
- 代替手法（対戦相手ページへの手動遷移）の存在を自覚した上で、「もう少し掘ってみたい」と
  続行を選択。

## 想定運用 / なぜこのスコープか

- 対象は**敗戦の対戦相手**（ユーザーのユースケースに合わせる。勝った相手まで含めるかは未決）。
- 表示場所は選手結果ページの既存の対戦成績・大会結果の行に、実績シグナルを添える案が本命
  （新規ページ・新規URLは作らない）。
- 「実績シグナル」は新規に実績判定ロジックを作らず、既存の勲章カード基盤
  （`lib/nationalTitles.ts`、カテゴリ別ベスト8以上・1,519人分実装済み）をそのまま読む案が本命。
  理由は下記「わかっていること」参照。

## わかっていること

### 名寄せの新規リスクはほぼゼロ

このアイデアは名寄せが必要な箇所が2段階あるように見えるが、実際は**既存機能がすでに
引き受けているリスクの再利用**でしかない。

1. 「ある試合で誰と対戦したか」: 同じ試合記録内の `entries[].playerIds` を読むだけで、
   曖昧さがない（既存の対戦成績表示がすでにやっている）。
2. 「その対戦相手のその後の実績」: 相手自身の選手ページの集計（`count>=5` の場合に存在）を
   読むだけで、これは`data/players/index.json`の姓名一致という**サイト全体で既に使われている
   名寄せ**（[homonym-measurement](./2026-07-26-homonym-measurement.md)で選手単位・全データの
   誤マッチ率2.92%と実測済み・既に受容されているリスク）。

つまり、[head-to-head本体](../wiki/news-context-blocks.md)が凍結されている理由（同姓同名・
名寄せ精度が未検証）とは異なり、本アイデアは**新しい名寄せ面を追加しない**。既存の選手結果
ページが成立している前提の上に、表示を1行足すだけで済む。

ただし homonym-measurement は「選手単位」「世代を跨いだ時」の2つを最も危険な組み合わせと
名指ししており（`docs/raw/2026-07-26-homonym-measurement.md`）、本アイデアはこの**両方**に該当する
（高校→大学と世代を跨ぐ・個人単位）。新規の名寄せ面は増えないが、既存の2.92%という誤マッチ率が
そのまま乗ることは認識しておく必要がある。

### 実データでの規模感（2026-08-21実測）

`highschool-championship`（インターハイ）個人戦ダブルス 2021〜2025年度・全試合の敗者インスタンス
（1試合2名×全敗退カード）を対象に、**その試合の勝者が、後年 `zennihon-university` /
`zennihon-university-indoor`（個人戦・2023〜2025年度＋インドア2025年度のみ収録）で
ベスト8以上に到達しているか**を機械的に突き合わせた（簡易スクリプトでのワンショット集計）。

| 指標 | 値 |
|---|---|
| 高校選手権 個人戦ダブルスの敗者インスタンス総数（2021-2025） | 3,780 |
| うち、勝者が後年に大学カテゴリでベスト8以上（勲章カード基準） | **289（7.6%）** |
| 該当するユニークな敗者（姓名ベース） | **548人** |
| 大学カテゴリでベスト8以上に達した個人（ユニーク、2023-2025+indoor2025） | 100人 |
| うち優勝のみに絞ると | 12人（該当敗者インスタンス98件） |

**この数字は大学カテゴリの収録が浅い（個人戦は2023年度〜の3年分＋インドア2025年度のみ）
状態での下限**。[大学カテゴリの公開ページ検討](./2026-08-12-idea-university-category-pages.md)
でも指摘されている通り、インカレ2026（例年8月末〜9月初旬）の結果投入で母数が増える。
王座（`zennihon-university-ouza`）は団体戦のみで個人名が無いため、この集計には使えない。

### 既存の勲章カード基盤との整合

`lib/nationalTitles.ts`の`majorCategory`はキャリア進行順（ジュニア→高校→大学→総合→
国際大会→シニア）を意図した設計であり、「高校時代の対戦から大学の実績へ」という本アイデアの
時系列方向と自然に一致する。「ベスト8以上」の基準も同じ定義を流用できる。

## 課題・未解決

- **表示の粒度**: 大会結果の行ごとに出すか、対戦成績サマリーに集約するか。
  試合数が多い選手では該当行が散らばり見落とされる可能性がある。
- **時系列条件**: 「勝った試合の年より後」で良いか、それとも「次のカテゴリ（高校→大学）」に
  絞るか。ユーザーの当初の関心は後者（高校→大学）だったが、ユースケースの本質は
  「負けた試合より後にその相手がどう活躍したか」全般なので、カテゴリを跨がない
  「同カテゴリ内でのその後の活躍」（例: 高校内で後から強くなった）を含めるかは未決。
- **対象を敗戦のみに絞るか**: ユーザーのユースケースは敗戦想定だが、勝った相手を含めるかは
  そもそもの動機（意外性のある気づき）次第で判断が変わる。
- **母数の薄さ**: 現状の大学カテゴリ収録（個人戦3年分+indoor1年）では該当件数が全体の一部に
  限られる。インカレ2026投入後に再測定する価値がある。
- **表示条件**: 相手が`count>=5`で結果ページを持つことが前提（既存のリンク付与条件と同じ）。
  該当しない場合は今のところ相手名にリンクすら付かないため、実績シグナルも出しようがない。
- 代替手法（相手ページへの手動遷移）で足りている、という自己評価をユーザー自身がしている。
  「気づきを能動的に与える」以上の価値が無いなら、優先度は低いままで良い。

## 目指したい方向性

まだ発散フェーズ。次の一歩の候補:

- 選手結果ページの敗戦カードに、相手の勲章カード実績（`lib/nationalTitles.ts`基準）を
  小さく添える最小プロトタイプ（新規URLなし、新規名寄せなし）。
- 表示条件・時系列条件（上記課題）をユーザーと詰めてから着手。
