p1-4 男子ドロー（47-48エントリー、5回戦＋準々決勝）/ p5 男子ベスト64 / p6 男子準々決勝〜決勝、

```
  --tools tools/zennihon-championship-2016 --out data/tournaments/details/zennihon-championship
```

## この年で新しかったもの（スクリプトを2箇所直した）

### 1. スコア表の見出しに性別が前置きされる

2017-2019年度は `【準々決勝】`。2016年度は **`男子準々決勝` / `男子準決勝` / `男子決勝`**
（女子も同様）で、見出しの完全一致判定に掛からず「見出しが見つからない」で止まった。
正規化に `男子` / `女子` の除去を足した。**部分一致にはしないこと**——
`男子準々決勝` は `決勝` を含むので、包含判定にすると準々決勝が決勝として扱われる。

### 2. 最終行の試合のスコアが、その行より下へずれて印字される

2017年度の経験から「最終行より下のスコアは**ページ勝者のその後**（準決勝・決勝の本数）だから
落とす」という処理が入っていた。2016年度は**本物の試合のスコアが最終行より4.1pt下に**出る
ページがあり（男子p3・女子p8）、これを落とすと片側のスコアが1個足りずに止まる。

厄介なのは、**同じ p3 に両方が同居している**こと:

| y | x | 値 | 正体 |
|---|---|---|---|
| ybot+4.1 | 335.9 | 3 | **本物**（最終行の2回戦の敗者本数） |
| ybot+7.7 | 300.8 / 309.6 | 5 / 5 | ページ勝者（船水・星野）の準決勝・決勝の本数 |

差は3.6ptしかなく、**幾何では区別できない**。x位置も当てにならない
（2016年度は中央寄り、2019年度は x=252/340 と中央から44pt離れる）。

最初、「足りないときは下のスコアも候補に戻し、どれを捨てるかは総当たりに任せる」と実装したら
**総当たりが「その後」の `5` を試合のスコアとして消費する解を選び、敗者5本という
有り得ない試合が2件できた**（4回戦 132-141 と 5回戦 120-132）。ブロックの勝ち上がりは
正しいままなので、`assert` も準々決勝の照合もすり抜ける。**静かに壊れる典型**。

最終的に「**足りないぶんだけ、最終行に近いものから順に戻す**」に変えた。p3右ブロックなら
1個足りないので ybot+4.1 の1個だけを戻し、ybot+7.7 の2個は戻さない。総当たりの余地が
無くなるので決定的になる。

### 検算の勘所: 敗者本数の分布を見る

9ゲームマッチ（5本先取）なので**敗者本数は0〜4**にしかならない。全試合で
`max(scores)==5 and min(scores)<=4` を確認すると、上の壊れ方が一発で出る。
1回戦から敗者4本が出る（男子10件・女子4件）ので、**全ラウンドが5本先取**であることも
これで裏付けられる（4本先取なら敗者は3止まり）。

## 検算

- **準々決勝がドローページ（p1-4/p7-10）とスコア表（p6/p12）の両方に載る**ので独立に照合。
  男女とも4件が勝者・両者の本数まで完全一致（スクリプトが自動で止める）。
  ドロー側の勝者本数は `--winner-score 5` の補完値なので、**この一致は5本先取の裏付けにもなる**。
- **ベスト64ページ（p5/p11）の64エントリーが、ドローページから計算した2回戦勝者の集合と完全一致**
  （男女とも64/64、過不足ゼロ）。1・2回戦（男子126試合・女子105試合）をまとめて裏付ける、
  抽出ロジックから独立した検算。
  なお p5/p11 をブラケットとして丸ごと読み直す（`last_round=8` で呼ぶ）のは、
  右ブロックの `_own_lines` が合流列を取れずに失敗した。今回は上の集合一致で足りたので深追いしていない。
- ラウンドごとの試合数が枠数の理屈と一致（男子 62+64+32+16+8+4+2+1=189、女子 41+64+32+16+8+4+2+1=168）。
- エントリー数が `tools/` のステージングと一致（190 / 169）。
- 全試合で勝者5本・敗者0〜4本。
- 棄権は男子2件・女子3件（PDFの `R` の数と一致）。
- **2017-2019年度の再生成で `matches` / `results` / `entries` / `participants` が既存と一致**
  （差はチーム名の正規化のみ。今回の改修が過年度を壊していないことの確認）。
- `check-tournament-entries` / `check-orphan-entries` / `check-duplicate-placements` 通過。
  `npm run bracket:verify` は2016年度に不一致なし（既存の不一致2ファイルは
  `highschool-championship/2013` と `zennihon-singles/2017` で、今回とは無関係）。
