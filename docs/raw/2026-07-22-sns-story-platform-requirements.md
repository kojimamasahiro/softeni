## 1. 要求

### 背景

Softeni Pickには大会・学校・選手・試合などの豊富なデータが蓄積されているが、現在は記事や更新情報としての活用が中心であり、SNSで活用しきれていない。

### 目的

データベースから発信価値のあるストーリーを抽出し、LLMによるコンテンツ生成へ利用できる共通基盤を構築する。

### ゴール

- 年内にXフォロワー1,000人を目指す
- データ資産をSNS・SEO・通知などへ横展開できるようにする
- 投稿作成の工数を削減し、継続的な情報発信を実現する

### 解決したい課題

- 更新報告だけでは新規ユーザーへ訴求しづらい
- 投稿ネタを毎回考える必要がある
- データの価値や背景が十分伝わっていない

### 実現したい状態

記事や試合結果などのデータ更新後、発信価値のあるストーリーが構造化データとして生成され、LLMが媒体に応じた文章を生成できる。

### 要求事項

- 利用者がデータを見なくても、そのデータの価値や面白さが伝わる情報を抽出できること。
- 同じストーリーを複数媒体で再利用できること。

## 2. 要件

### 機能要件

#### 2.1 ストーリー抽出

大会・学校・選手・試合などのデータから、発信価値のあるストーリーを抽出できること。

#### 2.2 構造化データ出力

抽出結果はJSONまたはYAML形式で出力できること。
自然文ではなく、機械可読な構造化データとすること。

#### 2.3 事実保持

出力には推測・主観・評価表現を含めず、データベースから導出可能な事実のみを保持すること。

#### 2.4 ストーリー分類

各ストーリーに分類情報を持つこと。
分類は将来的に追加・変更可能であること。

例: Ranking / Record / Comparison / Milestone / Player / School / Trivia

#### 2.5 根拠保持

ストーリー生成の根拠となる対象データを保持できること。

例: 大会 / 試合 / 学校 / 選手 / ランキング

#### 2.6 評価情報

ストーリーごとに発信優先度を判断するための評価情報を保持できること。

例: 希少性 / 季節性 / 話題性 / 保存価値

評価方法は実装に依存しない。

#### 2.7 LLM入力

出力データはLLMへそのまま入力できる形式であること。

#### 2.8 再利用性

生成データは以下の用途へ再利用できること。

- X
- Threads
- SEO記事
- プッシュ通知
- ホーム画面
- メール・ニュースレター

### 非機能要件

- 実装方式に依存しないこと
- 出力フォーマットの拡張が容易であること
- 新しいストーリー分類を追加しやすいこと
- 大会種別に依存せず利用できること
- LLMを変更しても利用可能なインターフェースであること

## 3. 設計で決定する事項（参考）

以下は本要件の対象外とし、設計フェーズで決定する。

- システム構成
- モジュール分割
- JSON/YAMLの詳細スキーマ
- ストーリー抽出アルゴリズム
- 評価値の算出方法
- LLM利用方法
- キャッシュ・永続化方式
- API仕様
