## 入力の取り違え（最初に届いたPDFは別大会だった）

最初に渡された `2016_A02_40.pdf` は**全日本シングルスのドロー表**で、天皇杯ではなかった。
1行1エントリー・選手1名という構成（`1船水颯人(日本学連早稲田大学) … 宮下裕司(兵庫姫路アニマルズ)36`）で、
p5の準々決勝以降も単独名同士の対戦。しかも `tools/zennihon-singles-2016/`（男子287・女子239）と
id・氏名・所属が完全一致しており、**すでに取り込み済みのPDF**だった。
`A02` がシングルス、`A08` が選手権（天皇杯）。ファイル名だけで判断せず、
**1エントリーの行数と準々決勝ページの対戦形式**で見分けるのが速い。

## この年で新しかったもの: 見出しの無い再掲枠

2016年度は**全8ページの下部に、そのページの勝ち上がりペアの再掲枠**が付く。

```
      水　澤　悠　太
47( 広島　NTT西日本広島 )
      長　江　光　一
```

2018年度の「準々決勝戦」のような**見出しが無い**ので `RECAP_HEADINGS` では切れない。
氏名はページ中央に組まれていて本体の氏名グリッドから外れるため**エントリーとしては拾われない**
（`duplicate_players` にも出ない）が、番号 `47` が本体左ブロックの所属列のx範囲に入り、
`attach()` が最も近いアンカー＝直上のエントリーの2人目に付けてしまう。結果、
**p1 の `原 侑輝` の所属が `47`** になった。**エントリー数も欠番も正常なまま所属だけが壊れる**ので、
件数の検算では気づけない。

判定は**本体の括弧列から外れた括弧がページ下部（下端20%）にあること**にした
（`recap_cutoff`）。再掲枠は本文の2つの括弧列とは違うxに組まれるので、これで一意に決まる。
切り落としは括弧行の10pt上から（括弧行の上にある氏名行まで含めるため）。

2017・2018・2019年度の男女6本の出力が**1バイトも変わらない**ことを確認済み。

## 原典側の表記（機械では直さない）

- **男子53 `正岡 一志` の所属欄が `－`**（紙面が `正　岡　一　志 福岡 －`）。無所属の意味と思われる。
  リポジトリに `無所属` も `－` も前例が無いため、**紙面のまま `－` で置いた**。
  `name` が `正岡・奥嶋（－）` になる（`name` は1人目の所属を使う仕様のため）。**要判断**。
- **`井口 雄介`（男子36）と `井口 雄一`（男子120）は別人**。どちらも宮崎・スマッシュイグチクラブ。
  読み取り誤りではなく紙面がそう刷られている（p1 y=433.8 / p3 y=93.7）。
- 半角カナ・半角英字が紙面のまま入る（`昭和ﾎｰﾙﾃﾞｨﾝｸﾞｽ大阪`、`履正社医療ｽﾎﾟｰﾂ専門学校`、
  `川口ISC`）。一方 `ＴＯＤ` `ＨＩＮ－ＨＩＮ` は全角。`teams.json` 側は `TOD` `HIN-HIN` と
  半角なので、表記ゆれの吸収は後段（alias）の仕事。

## tempId を4項目に統一した（同日）

`tools/` のステージングは長らく2系統に割れていた。

| 4項目 `姓_名_学校_都道府県` | 3項目 `姓_名_学校` |
|---|---|
| `zennihon-singles-2016〜2019`, `incare-2026` | `zennihon-championship-2017〜2019`, `highschool-championship-2012〜2017`, `west-japan-2026` |

**正しいのは4項目**。`scripts/pdf/tournament_results_common.py` の `build()` は
`participants[].id` と `entries[].playerIds` を `姓_名_学校_都道府県` で組み直しており
（tempId を見ない）、`data/tournaments/details/**` は**全大会が4項目**で揃っている。
3項目のままでも details 生成経路では実害が出ないが、**`tools/tournament3` に貼って人が入力し、
その出力を書き出す経路だけ**は tempId がそのまま識別子になるため、同じ大会の年度間で
識別子の形がずれる。

ユーザー判断で**天皇杯シリーズ4年度8ファイルを4項目に揃えた**（2016年度の新規ぶんを含む）。
`zennihon_championship_entries.py` も4項目を出すよう変更し、2016・2019年度は
**スクリプト再生成が変換後のファイルと完全一致**することを確認。2017・2018年度は
`git diff` が tempId 行以外ゼロであることを確認した。

**この skill（`tournament-pdf-to-players`）の「tempId は3項目。実データは新旧すべて3項目」
という記述は誤り**（4項目のファイルが10本ある）。正しくは大会シリーズごとに分かれていて、
details に合わせるなら4項目。

未着手: `highschool-championship-2012〜2017`（12ファイル）と `west-japan-2026`（2ファイル）は
3項目のまま。`scripts/pdf/details_to_initial_players.py` の既定も3項目のまま
（4項目にするフラグはある）。
