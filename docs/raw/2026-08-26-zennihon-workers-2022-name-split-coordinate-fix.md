# 全日本社会人の姓名分割を座標ベースに一般化（2022/2023年度・トーナメント表+ラウンドロビン表）

## 背景

ユーザーから「`tools/zennihon-workers-2022/doubles-over35-boys.json`は姓名の区切りが
2文字固定になっているので、インターハイのときと同様に座標で区切ってほしい」と依頼され、
まず2022年度の`2022`レイアウトのみ対応した（本ノートの旧版）。その後「2023年度とラウンド
ロビンも確認してほしい」と追加依頼があり、調査の結果すべて座標ベースに一般化できることが
分かったため、本ノートを全面的に書き直した。

## 発覚した副次的な問題: details JSONが空になっていた

作業に入る前に対象データを確認したところ、
`data/tournaments/details/zennihon-workers/{2022,2023}/`配下の一部ファイル
（2022: over35-boys/over35-girls/over45-boys/over45-girls、2023: 全6カテゴリ）が
`{}`（2バイト）になっていた。一方、対応する`tools/zennihon-workers-{年}/*.json`
（initialPlayers形式）側は実データを保持していた。

セッションログ（`~/.claude/projects/.../bf09344a-....jsonl`）を調査した結果:

- 2026-08-20の元の抽出コマンド実行時点では正しい参加者数で書き出されていたことを確認
  （tool_result記録より）。
- その後、2023年`doubles-over35-boys.json`に1件だけ手修正（entryNo73「関鍵」ペアの
  都道府県表記統一、`埼玉`→`埼玉県`）があった以外、手修正は無い。この1件は
  `node scripts/normalize-prefectures.mjs --scope=zennihon-workers`（都道府県表記の
  正準化バッチ）が同じ結果を機械的に再現するため、再抽出後に同スクリプトを実行すれば
  失われない。
- 空になったタイミング・原因はログからは特定できなかった（原因未確定の環境要因の可能性）。

**復元方法**: PDF抽出は決定論的なため、元のコマンドをそのまま再実行して復元した
（捏造ではなく再導出）。再実行後の参加者・エントリー数は2026-08-20時点の記録と完全一致。

## 座標ベース分割: トーナメント表は「ページ単位の動的しきい値」が必要

2022年度の`2022`レイアウトをまず複数ページ（10, 11, 13, 14, 16, 17）で実測したところ、
氏名は「姓2文字+名2文字」ぶんの固定4スロットに均等割り付けされ、姓名境界のX座標が
ページ間で完全に一致（LEFT≈86.4pt、RIGHT≈392.5pt）していたため、レイアウトごとの
固定しきい値（`name_split_x`）として実装した（本ノート旧版）。

2023年度の`general`/`female`/`age`レイアウトで同じ実測をしたところ、**同じ4スロット
構造は確認できたが、スロットの絶対X座標がページごとに数pt動く**ことが分かった
（例: `general`のLEFT列は1ページ目が[64.4, 81.2, 98.0, 114.8]、2ページ目が
[71.6, 88.4, 105.2, 122.0]と全体的に7.2ptシフトしている）。レイアウトごとの固定
しきい値では2023年度に対応できない。

**さらに重要な発見**: 姓名境界の字間そのものは内部字間と完全に同じ大きさ（例:
姓名とも2文字の「内本隆文」は字間がすべて16.8ptで均一）で、字間の大小だけでは
境界を判別できない（インターハイPDFの教訓と同じ）。一方、**姓の先頭文字は常に
スロット1、名の末尾文字は常にスロット4に来る**（姓・名のどちらかが3文字になる
場合は、中間の空白スロットへ「同じ側の内側だけ」あふれ、反対側には出ない）。
これは姓名合計2文字（1+1）のケースでも成り立つ（例:「堺満」→姓はスロット1、
名は最後のスロット4）。

したがって、**そのページ・列で実際に使われた氏名列文字のX座標の最小値
（=スロット1）と最大値（=スロット4）の中点**が姓名境界になり、ページごとの
座標ドリフトを自動的に吸収できる。2022年度の固定しきい値・2023年度の
`general`/`female`/`age`3レイアウトすべてで、この中点方式が実測値と一致する
ことを複数ページで確認した。

## ラウンドロビン表は逆に「字間の大小」で直接判別できる

ラウンドロビン表（2022: 35歳女子・45歳女子、2023: 同様）の氏名列を同じ方法で
実測したところ、トーナメント表と違い**姓名境界の字間は内部字間よりはっきり大きい**
（実測: 境界≈9〜22pt vs 内部≈6〜13pt、ページ・年度により絶対値は変わるが常に
境界側が明確に大きい）。そのため、行ごとに独立して「最大の字間」を境界とみなす
方式（`_split_name_by_max_gap`）が使え、トーナメント表のようなページ単位の
補助計算すら不要（1行完結で判定できる）。

## 実施したこと

`scripts/pdf/zenshakai_entries.py`を修正:

- `_split_name_by_x(chars, threshold)`: 文字ごとのX座標としきい値で分割（既存）。
- `_dynamic_name_split_x(name_rows)`: ページ・列で実際に使われた氏名列文字の
  X座標の最小/最大の中点を返す（トーナメント表用）。氏名文字が無ければ`None`
  （呼び出し側は`_split_name`の文字数ヒューリスティックにフォールバック）。
- `_split_name_by_max_gap(chars)`: 行内の最大字間を境界とみなして分割する
  （ラウンドロビン表用）。
- `parse_bracket_page`: 各ページ・列ごとに`_dynamic_name_split_x`を計算して使う。
  レイアウトごとの固定`name_split_x`定数は廃止（`general`/`female`/`age`/`2022`
  すべて同じ動的ロジックで対応できるため、年度ごとに実測・追加する必要がなくなった）。
- `parse_roundrobin_page`: `_split_name`の代わりに`_split_name_by_max_gap`を使う。

2022年度の該当5カテゴリ（`doubles-none-girls`, `doubles-over35-boys`,
`doubles-over45-boys`, `doubles-over35-girls`, `doubles-over45-girls`）と、
2023年度の全6カテゴリを再抽出。`node scripts/normalize-prefectures.mjs
--scope=zennihon-workers`と`npm run check:entries`で問題なしを確認済み。

## 今後の運用

- この一般化により、**新しい年度のPDFが来ても姓名分割用の座標を実測・追加する
  必要が無くなった**（`_dynamic_name_split_x`/`_split_name_by_max_gap`が自動対応）。
  ただし「氏名セルが姓2文字+名2文字ぶんの固定スロット」という構造自体が別の年度で
  変わっていないかは、初回だけ本ノートと同じ方法（複数ページで文字ごとのX座標と
  字間を実測）で確認すること。
- トーナメント表とラウンドロビン表で境界の見分け方が逆（前者は絶対位置、後者は
  相対字間）である点を混同しないこと。
