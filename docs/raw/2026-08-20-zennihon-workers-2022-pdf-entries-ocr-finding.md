# 2022年全日本社会人PDF追加分とOCR実測（一般男子は見送り）

## 背景

[2026-08-20-zennihon-workers-2023-pdf-entries-import.md](2026-08-20-zennihon-workers-2023-pdf-entries-import.md)
に続けて2022年度（`2022_A06_40.pdf`）の6カテゴリを追加しようとした。ユーザーからのフィードバック
「基本2文字のものは姓名が1文字ずつである」を反映（`_split_name`を`len==2`のとき`full[0],full[1]`
に分割するよう修正。2023年のentryNo73「関鍵」もこの方針で本人が手直し済み）。

## 2022年PDFで新たに判明したこと

### 座標プリセットは年度ごとに実測が必要（既知の傾向の再確認）

2022年は男子/女子/年代で座標がほぼ揃っており（`Y2022_LEFT`/`Y2022_RIGHT`という1種類のプリセットで
一般女子・35歳男子・45歳男子すべて対応できた）、2023年（`general`/`female`/`age`の3種類が必要
だった）とは傾向が違った。「年度が変われば大抵の場合レイアウトも変わる」という前提を崩さないこと。

### 行クラスタの代表値ズレの二次被害（新パターン）

都道府県・所属が氏名行より**前**の行に浮くケース（`scripts/pdf/zenshakai_entries.py`の既存の
コメントは「後ろに浮く」パターンのみ言及していたが逆方向もある）で、band検索が`t1`側にしか
寄っていないと、都道府県・所属の値を拾い損ねて「エントリー成立の必須条件」を満たせず
ペアがまるごと1つ抜けた（i+=1だけ実行され、以降のペアリングが1つずれる）。
対策: `pref_a`/`team_a`が空のとき`pref_b`/`team_b`から補う、逆方向の補完も追加
（一方向だけの補完では直らない）。

### 列境界の脱落文字がエントリー番号列を汚染する（再発）

インターハイのケースと同型の不具合が、全日本社会人のラウンドロビン列検出（`detect_rr_cols`）
でも再発した。氏名列の先頭文字がエントリー番号列との境界すれすれに来て脱落し、脱落文字が
entry_no帯に混入して`isdigit()`判定を壊す。境界マージンを12pt→16ptへ拡大して解消。
**この種の境界脱落は、マージンを1回広げて満足せず、今後も別のページ・別の年度で再発しうる
前提でチェックすること**（suspects=0を確認するまで安心しない）。

### ラウンドロビンの列検出: 対戦成績列の先頭が"1"とは限らない

45歳女子（40組、2ページに分割）の2ページ目は、グループが前ページから継続するため対戦成績列の
見出しが「22 23 24 25」のように"1"以外から始まる。`detect_rr_cols`が見出し文字列`"1"`を
決め打ちで探していたため2ページ目が0件になった。見出し行（氏の行と同じtop）の数字文字のうち
X座標最小のものを使う方式に変更して解消。**見出しtop<120で単純に数字文字を拾うと、データ行の
エントリー番号（同じくtop<120に収まることがある）を誤って拾う**ため、見出し行そのものの
topに絞り込む必要があった。

## 一般男子（1〜8ページ）はテキスト層が存在しない

`page.chars`がほぼ空（ヘッダーの9文字のみ）で、`page.curves`が2700件超。文字がテキストでなく
**アウトライン化された図形（ベクターパス）として埋め込まれている**。9ページ目以降（準々決勝
詳細・他の全カテゴリ）は通常のテキストで、この8ページだけこの形式だった（原因不明。異なる
生成経路のPDFが挿入された可能性）。

### OCRを実測した（tournament-pdf-to-players skillのOCR経路は「未検証」だったため）

`ocrmypdf`は未インストールのため、`pdfplumber`で高解像度画像化 → `tesseract -l jpn`で直接
検証した（結論のみ得られればよく、PDFへのテキスト層埋め込みまでは不要だったため）。

- 400dpi・ページ全体（`--psm 6`）: 信頼度50%未満の誤読が大量。「船水颯人」→「私水細人」など
  明確な誤認識が多発し、実用に耐えない。
- 1200dpi・1行だけ切り出し（`--psm 7`）: 大幅に改善したが、「船水**颯**人」→「船水**編**人」の
  ように4文字中1文字が誤読された（誤読率約25%）。氏名は1文字違うと別人になるため、この精度でも
  実用レベルではない。

**結論**: 解像度を上げても、この特定PDFの密集した小さいフォントでは選手名を正確に拾うには
届かない。ユーザーに実測結果を提示し、「今回は見送り」の判断を得た。

## 実施したこと

- `scripts/pdf/zenshakai_entries.py`: `_split_name`修正（2文字は1+1分割）、`Y2022_LEFT`/
  `Y2022_RIGHT`プリセット追加、行クラスタのband補完を双方向化、`detect_rr_cols`の対戦成績列
  検出を「見出し行の数字文字の最小X座標」方式に変更（境界マージンも12pt→16ptへ拡大）。
- 2022年5カテゴリ（一般女子/35歳男子/35歳女子/45歳男子/45歳女子）を
  `data/tournaments/details/zennihon-workers/2022/` に生成。全カテゴリ欠番・重複なし、
  `npm run check:entries` エラー0。
- 2023年 `doubles-over35-boys.json` entryNo=73 の参照切れ（`normalize-prefectures.mjs`後に
  `entries[].playerIds`側だけ旧`埼玉`表記が残っていた）を`埼玉県`に統一して修正。
- 一般男子（2022年1〜8ページ）は未対応のまま。将来テキスト層付きの版が手に入れば対応する。

## 追記（同日）: この「見送り」は前提の置き方が間違っていた

一般男子1〜8ページは、**OCRを使わずに全325エントリー取り込めた**。
上の検証は「画像化してOCRにかける」という前提でしか行っておらず、その前提自体が誤りだった。

`page.curves`が2700件超という観察までは合っていたが、その意味の読み方を間違えていた。
このPDFは「文字が読めない」のではなく「**文字コードだけが落ちて、字形はベクターで残っている**」
状態で、`page.get_drawings()` の fill path 1個が1文字にきれいに対応する。
画像化した瞬間に、文字の位置・切り出し・同一性というOCRが苦労する情報を全部捨てて、
tesseractに一から解かせていた。

盲検テストの実測で氏名 64/64・文字 252/252（誤読0）。詳細は
[2026-08-20-zennihon-workers-2022-general-boys-vector-glyph-import.md](2026-08-20-zennihon-workers-2022-general-boys-vector-glyph-import.md)。

**上のOCR実測結果そのもの（tesseractでは実用に耐えない）は今も有効**だが、
その結論から「このPDFは取り込めない」を導いたのが誤りだった。
テキスト層が無いPDFを見たら、OCRの前に `len(page.get_drawings())` を数えること。
