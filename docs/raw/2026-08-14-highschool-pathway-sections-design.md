# 高校学校ページの「人の流れ」節をどう整理するか（進学先大学の追加にあたって）

## 状況

**保留中（2026-08-14）。実装前・コードへの変更なし。**
案A/B/C のどれを採るかが決まっていないため、ここで止めてある。再開はこのファイルの
「選択肢」節を読んで案を決めるところから。
[大学カテゴリの検討](./2026-08-12-idea-university-category-pages.md)で
「進路接続（高校→大学）を先にやる」と決めたが、**着手すると高校の学校ページに
『人の流れ』の節が3つ並ぶ**ことが分かった。並べ方を決めないと着手できない。

対象ページ: `/highschool/[gender]/[prefectureId]/[teamId]`（学校ページ・721枚）

## 何が問題なのか

高校の学校ページには、すでに「人がどこから来て、どこへ行ったか」を扱う節が2つある。
ここに3つ目を足そうとしている。

| 節 | いつ入った | 何が主語か | 出る条件 | **付くグループ数**（校×性別） |
|---|---|---|---|---|
| **主な卒業生** | 2026-07-18 | **選手** | 実績で絞る（全日本ベスト8以上 / STリーグ / 国際大会）＋上位5名 | **66** |
| **選手の出身中学** | 2026-08-12 | **中学** | 網羅（進路データ全件） | **113** |
| **進学先大学**（未実装） | — | **大学** | 網羅（進路データ全件） | **300** |

（`getSchoolAlumni` / `getFeederSchools` を全校に当てた実測。2026-08-14）

### 重なりは実測で69%ある

- 進路（高校→大学）の採用は **1,111人**、主な卒業生は **139人**
- **両方に出る選手が 96人＝主な卒業生の69%**
- 主な卒業生の掲載140件のうち、**最後に確認できた所属が大学なのは77件（55%）**
- 逆に、進路に出ず主な卒業生にだけ出るのは **43人**
  （大学を経ずに社会人へ行った選手、実績が大学以外の選手）

つまり **「主な卒業生」の中身の過半は、すでに大学がらみ**。
このまま「進学先大学」を足すと、同じページの近い位置に同じ選手が2回出る。

### 3つ並べたときの見え方

節の見出しだけを並べるとこうなる。

```
◯◯高校の主な卒業生          ← 選手が主語・実績で絞った5名
◯◯高校の選手の出身中学       ← 中学が主語・網羅
◯◯高校の選手の進学先大学     ← 大学が主語・網羅（追加しようとしているもの）
```

**「出身中学」と「進学先大学」は同じ進路データの前半と後半**であって、
別々の節にする理由が弱い。一方「主な卒業生」は絞り方も主語も違う。

## 選択肢

### 案A: 「進路」1節にまとめ、主な卒業生は残す（推奨）

```
◯◯高校の選手の進路
  ├ 出身中学（どこから来たか）
  └ 進学先大学（どこへ行ったか）
◯◯高校の主な卒業生          ← 実績のハイライトとして別に残す
```

- **同じ進路データの前後を1つの節にまとめる**。読者の関心（「この学校はどういう
  進学ルートか」）とも合う
- 主な卒業生は「網羅」ではなく「ハイライト」なので役割が違うと言い切れる。
  ただし重複を減らすため、**進路側に実績マークを出す**か、
  **卒業生側の説明文を「実績で選んだ」と明示する**かのどちらかは要る
- 節が3→2になる

**懸念**: それでも96人が両方に出る。マークで済ませるか、
卒業生から大学経由の選手を外すか（=43人だけにする）は別途決める必要がある。

### 案B: 3節のまま、文言で棲み分ける

- 実装が一番軽い（既存2節に触らない）
- ただし**「出身中学」と「進学先大学」を分けたままにする理由が説明できない**。
  同じ `pathways` 由来のデータで、向きが違うだけ

### 案C: 進路に一本化し、主な卒業生を畳む

- 主な卒業生を廃止し、進路の中で実績のある選手に印を付けるだけにする
- 節が1つになり最もすっきりする
- **ただし43人分の情報が落ちる**（大学を経ずに社会人へ行った選手・大学以外での実績）。
  この43人はむしろ「主な卒業生」として一番読ませたい層でもある

### 中学カテゴリの決定に照らすとどうか

`/secondaryschool` は**順位づけをするページ・節を持たない**方針で、
理由は「配点が Assumption だった」「残るものをすべて検算できる事実にする」だった
（[secondaryschool.md](../wiki/secondaryschool.md)）。

**「主な卒業生」の掲載条件（全日本ベスト8以上 / STリーグ / 国際大会・上位5名）は
順位づけではないが、運用判断で決めた閾値**であり、同じ性質の Assumption を含む
（`highschool.md` にも「ノイズ最小化を優先した設計（2026-07-18 ユーザー決定）」と明記されている）。

これを重く見るなら案C、既存の判断を尊重するなら案A。**案Aを推す**のは、
43人の情報が落ちるのが実害として大きいのと、
「網羅の進路」と「実績のハイライト」は読者にとって別物として通じるため。

## 進路データそのものの設計（案がどれでも必要）

### 採用条件は ADR-014 をそのまま使う

中学→高校で採った条件が高校→大学にもそのまま当たる。

1. **高校の最終出場年 < 大学の初出場年 <= 高校の最終出場年 + 5**
2. **同姓同名として検出された氏名を除外**（全大会走査で34件）

この条件での採用は **1,111人 / 高校×性別300グループ / 受け皿123大学**。
3名以上を送り出している高校×性別は122。

**ただし ADR-014 の前提が中学より弱い点に注意。** 大学側で
「同一年に2チーム以上へ出現する氏名」は **24 / 3,484（0.69%）**あり、中学の0.00%より高い。
ADR-014 の検証1（ペア継続を正解データにして100%）に相当する裏取りを
高校→大学でもやってから緩和条件を確定すること。**未検証。**

### 索引ページの向き

中学では `/secondaryschool/pathways/[gender]`＝**高校別の出身中学**（高校が主語）にした。
理由は検索需要が高校名に偏るのと、越境集約がこの向きでしか見えないため。

大学では**逆向き（大学が主語＝「{大学名}の選手の出身高校」）**のほうが筋がいいと思われる。

- 大学は134チームしかなく、**大学側にはまだページが1枚も無い**。
  索引が実質的に大学の受け皿になる
- 「{大学名} ソフトテニス部」需要を受けられる
- 高校起点の情報は、高校の学校ページ300グループ側が担当する

**未決**: URL を `/university/pathways/[gender]` にするか、
将来の `/university/[teamId]` を見据えて別の切り方にするか。

### 男女の扱い

高校の学校ページが男女別なので、進路レコードに `highschoolGender` を持たせて出し分ける
（中学と同じ）。`mixed` は男女どちらにも出す。

大学側は**56/134が片側にしか出ない**ので、大学のページを作るときは男女1枚が妥当
（男女別だと13%が薄くなる）。索引の男女分割は要検討。

## 段取り（案）

1. **ADR-014 の条件が高校→大学でも成り立つか検証する**（ペア継続を正解データにする）
2. **節の並べ方を決める**（案A/B/C）
3. `scripts/build-university-pathways.mjs` を作る。
   `build-secondaryschool-pathways.mjs` の構造をほぼ流用できる
4. `lib/highschoolUniversityPathways.ts`（`highschoolFeederSchools.ts` と同型）を作り、
   高校の学校ページへ節を出す
5. 索引ページを作る
6. `npm run build` の完走確認 → GSC 効果測定

**1と2が済まないと3以降は着手できない。**
