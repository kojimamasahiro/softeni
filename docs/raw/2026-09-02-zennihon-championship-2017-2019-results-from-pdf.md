## 読み取りの原理

### ラウンドの切り分けは x 座標では決められない

スコアは各ラウンドの列に並ぶので素直にx座標でラウンドを切りたくなるが、**ページ最終戦の
スコアが1つ手前の列に置かれる**ことがある（2019年女子p6: 4回戦の列に準々決勝のスコアが混ざる）。
代わりに

1. その半分の**枠数**（行数以下で最大の2の冪）から各ラウンドのスコア個数を算出する
   （23行なら 16枠 → 1回戦7試合=14個, 2回戦16, 3回戦8, 4回戦4, 5回戦2）
2. x順に並べてその個数ずつ切る
3. ページ最終戦のぶんが1個余るので、**「その1個を除くと全ラウンドが破綻なく組める」候補を
   総当たり**で探す

とすると安定する。ラウンド内では**y昇順で2つずつ組めば対戦が確定する**
（スコアは自分のラインの上下どちらかに±7pt程度ずれて置かれるが、2つのy順序は
競技者のy順序と一致する）。所属は「そのスコアのyがどの競技者の守備範囲（部分ブラケットの
行range）に入るか」で決める。

余り1個の特定は、左右で**同じy**の候補が1組だけになることを使う（ページ最終戦は左半分の
勝者と右半分の勝者が同じ高さで突き合わされるため）。それでも複数残る場合は
「その半分の最終試合の2つのスコアの間の高さにある」ことを追加条件にする。

### 2017年（勝者スコアが無い）は1回戦の組が数字だけでは決まらない

敗者にしかスコアが無いので、1回戦で負けた行は分かるが**相手が上の行か下の行かが決まらない**
（行1,2,3で2が敗者のとき (1,2) でも (2,3) でも枠数は合う）。

ここはラインの描画を使う。**ラインは自分が負ける合流まで点線、勝ち上がる区間は太い実線**で
引かれており、どちらであれ**最初の合流点で終わる**。帯の左端（右ブロックは右端）から始まる
線分を x方向に連結していけば、その行が最初に合流する列が確定する。1回戦の列で終わる行だけを
拾って隣どうしで組めば1回戦が決まり、あとは枠を2つずつ束ねる普通の二分木になる。

**点線のダッシュはほぼ正方形（0.9 x 0.96pt）なので、幅と高さの大小では横線/縦線を判定できない。**
最初これで判定して、ある行の点線が丸ごと落ち、合流列を17pt先の別の点線列と誤認した。
「y方向に薄いもの」を横線候補にして x方向の連結だけで辿るのが正しい。

### ページの外に印字される「その後」の本数

2017年は**ページ勝者の準決勝・決勝の本数**が、ドローの最終行より下の抜け線の脇に1-2個
印字される（2017年男子p2は優勝ペアのページなので `5` `5` の2個）。本ページの試合ではないので
最終行より下のスコアは落とす。2018年は「ページ勝者の小箱＋準々決勝の別ボックス」がドローの
下に付くので、**帯の中央にある番号の小箱**を見つけてそこから下を切る。

### 棄権

`R` は棄権。**敗者側にだけ現れ、勝者側は通常どおり丸数字が入る**（2017年は勝者スコア自体が
無いので敗者に `R` だけ）。`4R` = 4ゲーム時点で棄権という表記もあり、pdfplumberが1語に
まとめてくるので1文字前提で弾かないこと（2018年女子p10のエントリー16で実際に落ちた）。
出力は `retired: true` ＋ 読めた本数（無ければ0）。

### エントリー番号の列

所属名に数字が入る例（`ｔｅａｍ 87 ｔａｂａ`、2018年女子p14）があるので「ブラケット帯の外側の
数字」では足りない。**左右いちばん外側の桁列**（左は x0<62、右は x1>幅-55）に限定する。

### 準々決勝以降のスコア表

1ブロック=1行で `<番号> <左スコア> …ゲームスコア… <右スコア> <番号>` の形。
**その行の最も左と最も右のスコア字が両者の本数**（間はゲームごとのスコア）。
番号の書き方は年度で違い、2019年は `No 1`、2018年は番号だけを左右の余白に置く。
見出し `【決 勝】` は文字が分かれて入っているので、行内の語を連結してから判定する。

## 検算

- **準々決勝がドローページとスコア表の両方に入っている**ので、独立に読んで突き合わせられる。
  2017/2019は各年8試合（男女各4）が完全一致。2018はドローページに準々決勝が無いので、
  代わりに**8ページの勝者＝準々決勝の顔ぶれ**が一致することを確認した（男女とも一致）。
- エントリー数がすべて `tools/` のステージングと一致
  （2017: 190/179、2018: 178/163、2019: 185/175）。
- ラウンドごとの試合数が枠数の理屈と一致（例: 2019年男子 1回戦57・2回戦64・3回戦32・
  4回戦16・5回戦8・準々決勝4・準決勝2・決勝1 = 184試合 = 185-1）。
- `matchId` / `nextMatchId` / `prevMatchIds` の整合、勝者が次戦に現れること、
  同一ラウンドに同じエントリーが2回現れないこと、`participants` の参照漏れが無いことを検査。
- `npm run bracket:verify` が414大会・34494試合で不一致0。
- `check-tournament-entries` / `check-orphan-entries` / `check-duplicate-placements` も通過。
- 優勝ペアが史実と一致:
  2017 水澤悠太・村上雄人（ＮＴＴ西日本）/ 林田リコ・宮下こころ（文大杉並高校）、
  2018・2019 船水颯人・上松俊貴 / 林田リコ・宮下こころ（2018）・島津佳那（2019）。

## 学校名の正規化（当初落としていた）

details を書いただけでは `尽誠学園高等学校` のようにPDFの表記のまま入る。
`node scripts/normalize-team-names.mjs --scope=zennihon-championship` を通して
既存の団体マスタ（`team-name-aliases.json`）へ寄せた（6ファイル・1626箇所）。冪等。
**これを飛ばすと同じ学校が別チーム扱いになり選手ページの集計がずれる**ので、
details を作ったら必ず通すこと（→ スキル `tournament-pdf-to-results` の手順に組み込んだ）。

## 共通処理の切り出し（2026-09-02 追記）

「PDFの読み方」は大会・年度ごとに違うが、**読み終わったあとの組み立ては全大会で同じ**
だったので `scripts/pdf/tournament_results_common.py` に切り出した
（matchIdの採番、next/prevの張り替え、`entries[].type` の逆算、`results[]` のラベル、
`participants[]` の生成と並び順、および自己検査）。

切り出し後に天皇杯6ファイルを再生成して**バイト単位で一致**することを確認。
さらにインターハイ2014（別大会・団体戦を含む）も同じモジュールで組み直したところ、
`matches` と `results` は4ファイルとも完全一致し、差は学校名の正規化だけだった
（`多賀`→`多賀高校` 等、すべて `team-name-aliases.json` で説明がつく）。

## スキル化（2026-09-02 追記）

インターハイ2014と天皇杯2017-2019で3様式・4大会年度ぶんの経験が溜まったので、
`.claude/skills/tournament-pdf-to-results/` にまとめた。守備範囲は**結果（matches）専用**で、
エントリー抽出は既存の `tournament-pdf-to-players` に任せる（役割分担を明確にし、
両方を短く保つため）。

- `SKILL.md`: 様式を見極める5つの問い → 既存パーサの使い分け → **検算** →
  共通モジュールで組み立て → 学校名の正規化と information 登録 → docs 書き戻し
- `references/layouts.md`: 読み取りの原理（枠数から個数を出して切る／y順で2つずつ組む／
  部分ブラケットの行rangeで持ち主を決める）と、既知の様式カタログ、パーサのフラグ一覧、
  スキャンPDFの扱い

スキルに「落とし穴」として明記したもの（いずれも今回実際に踏んだ）:

- ラウンドの切り分けをスコアのx座標でやると、ページ最終戦のスコアが1つ手前の列に
  置かれる年度で静かにずれる
- 点線のダッシュを幅と高さの大小で横/縦に分類すると、ほぼ正方形の年度で判定が反転する
- `R` を1文字前提で弾くと `4R` が落ちる
- エントリー番号を「帯の外側の数字」で拾うと所属名の数字を拾う
- ドローの外に印字された「ページ勝者のその後」を試合として拾ってしまう
- 選手名を囲む枠が試合の合流と同じ形（入力2・出力1）をしている
- 合流の出力ラインを入力2本の中点と仮定する
