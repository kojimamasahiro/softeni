# 「岡山理大附」と「岡山理科大附高校」が別チームのままだった件と、選手共有シグナルの導入

日付: 2026-09-05
発端: 「`岡山理大附` と `岡山理科大附高校` が同じ高校にならないのはなぜかわかる？」という質問
出力:
- `data/tournaments/team-name-aliases.json`（canonical 2本を1本へ統合 / `春日部クラブ` に `scope` 追加）
- `data/tournaments/details/**` 20ファイル（`--scope=all` の未適用分 1344箇所）
- `scripts/lib/team-player-overlap.mjs`（新規シグナル）
- `scripts/build-team-merge-candidates.mjs` / `check-identity-health.mjs` /
  `apply-auto-merges.mjs` / `build-team-review-html.mjs`
- `docs/adr/ADR-017-team-merge-signal-player-overlap.md`（新規）、ADR-013 に追記

## 原因は3層あった

**1層目: 名寄せの仕組みは「正規化文字列 + エイリアス表」しかない。**
`build-team-master.mjs` のチームキーは `NFKC + 空白除去 + 中黒統一` だけで、
「科」の脱落のような略称差は自動では吸収しない。エイリアス表に手で書いてあるかどうかが全て。

**2層目: そのエイリアス表に、同じ学校が canonical 2本で入っていた。**

```json
{"canonical": "岡山理大附",      "aliases": ["岡山理大附属","岡山理大附高校","岡山理科大学附属高校","理大附属"]}
{"canonical": "岡山理科大附高校", "aliases": ["岡山理科大付高校"]}
```

canonical 同士は決して統合されない。しかも**正式名の「岡山理科大学附属高校」は1本目の alias 側**に
入っていたので、表そのものが自己矛盾していた（正式名は 49番、その略称は 1223番）。
`apply-team-aliases.mjs` は「既存 canonical を alias にしようとした」を競合として弾くので、
正規フローでは直せず、JSON を手編集して canonical を1本削る必要があった。

**3層目: 安全網（マージ候補検出）が素通りする。**
`teamCore()` は接尾辞を落としたコアの完全一致なので:

```
岡山理大附      -> 岡山理大附
岡山理科大附高校 -> 岡山理科大附      ← 「科」1文字差で不一致
```

`build-team-merge-candidates.mjs` にも `check-identity-health.mjs` のチェックBにも
一度も上がったことがなかった。ヘルスチェック自身が
「注: 『内部略称(理大/理科大)』は信号が無く本チェックでは検出不可」と出力していた。

## 同一校である裏取り

`岡山理科大附高校` 名義の8名のうち**7名が `岡山理大附` 名義でも出場**しており、
うち3名（佐藤蒼真・石灘蒼瑛・青木晴弥）は**同一年度に両表記が併存**する
（佐藤蒼真: 2025インターハイ「岡山理大附」/ 2025全日本ジュニア「岡山理科大附高校」）。
高校大会では略称、全日本選手権・シングルス・ジュニアでは別略称、という出典依存の揺れ。

紛らわしい隣接エンティティは `理大OB`（岡山県・1件）だけで、これは同校OBクラブなので対象外。
`岡山理科大学`（大学本体）は現データに存在しない（`理科大` は東京理科大学のみ）ので、
大学を巻き込む余地もなかった。

## 影響が無いと確認したこと（統合前のリスク評価）

- **選手ページのURL/pidは変わらない**。選手同一性は `data/players/index.json` の姓名ベース。
  `participants[].id`（`姓_名_チーム_都道府県`）はファイル内参照専用。
- **/teams のURLも消えない**。`/teams/[teamId]` の paths は `team-name-mappings.json` のキー
  （実業団・STリーグ）由来で、高校は最初から対象外。`teams.json` の数値 id はURLに出ない。
- **公開済みインサイトへの影響なし**。`data/tournament-insights` に「岡山理科大附高校」は0件で、
  `verify-story-text.mjs` の stale alias 警告は出ない。
- 逆に**動くもの**: 岡山理大附の収録数 187→233（別途溜まっていた未取り込み分を含む）。
  全日本選手権・シングルス・ジュニアの成績が高校側に合流する。

## `--scope=all` の未適用分 1383箇所を流したら、ADR-013 と同型の18件目が出た

未適用分が21ファイル・1383箇所も溜まっていた（全日本シングルス2016〜2019が主）。
流した差分の `"team"` 値を集計し、**増えた側に 中学/クラブ/高校 の接尾辞が付いたもの**を見たところ:

| 変化 | 判定 |
| --- | --- |
| `四天王寺` → `四天王寺高校`（インターハイ2012/2013） | 正しい（中学校版は `scope` 付きで分離済み） |
| `多賀` → `多賀高校`（インターハイ2013） | 正しい |
| `春日部` → `春日部クラブ`（インターハイ**2012**） | **誤り** |

`春日部クラブ` は社会人クラブ（全日本実業団・東日本・全日本ミックス over35 にしか出ない）で、
インターハイの `春日部` は高校。`scope: {generation:["all","corporate","masters"]}` を付けて解決した。
ADR-013 の「中学・クラブの文脈でだけ正しいエントリ」17件と同型の18件目。
**社会人クラブの略称も同じ穴を持つ**（中学・小学だけの話ではなかった）というのが今回の学び。

当該インターハイの `春日部` がどの高校か（春日部/春日部東/春日部工業…）は確定できなかったので、
素の表記のまま残した。出場者は吉水悠・中村匡貴。→ open-questions.md

この検出手順（差分の `"team"` 値を集計して接尾辞の付き方を見る）自体が再利用可能なので wiki に書いた。

## 選手共有シグナル（ADR-017）

3層目を構造的に潰すために、**名前の類似度を一切使わないシグナル**を足した:
「同一年度に、同じ氏名の選手が2チーム以上へ出場している」。実在の別チームなら進学・転校でも
同年に両方へ在籍することはないので、同年共起は「表記揺れ」か「同姓同名の別人」に絞られる。
後者を抑えるため共有2名以上を要求する。

### 実は repo 内に既にあった

`scripts/highschool/03list/summary.py` が**まったく同じ規則**で
`inferred-team-aliases.json` を生成しており、`岡山理大附 ← 岡山理科大附高校` は
証拠つきで既に載っていた（2016 上松俊貴・2016 本倉健太郎・2025 石灘蒼瑛）。
それでも本体が直らなかったのは、この出力が高校ページ生成にしか使われず
`team-name-aliases.json` へ還流しないから。**足りなかったのはシグナルではなく還流経路と適用範囲**。

### 実測

- 同年共起ペア 618 → 県一致 & コア不一致 266 → 共有2名以上 127ペア → クラスタ化して **104件**。
- 104件のうち **55件は `inferred-team-aliases.json` に既出**、**49件は新規**（社会人・小学生が中心）。
- 上位は `白鷗大足利`（6表記・共有27名）、`浜松商`/`浜松商業高校`（17名）、
  `北科大`/`北海道科学大学高校`（16名）、`宮崎商`/`宮崎商業高校`（16名）。
- 偽陽性は「同年に同じ選手が両方へ登録される別チーム」型:
  `大館ジュニア`/`大館市協会`、`兼六クラブ`/`能登町役場`。**大会同居の有無では切り分けられない**ので、
  このシグナルのクラスタは `apply-auto-merges.mjs` とレビューHTMLの両方で常に `autoOK = false` にした。
- 副産物として**取り込み時の誤字**が浮いた: `きのくに信用金庫`/`きのくに宿用金庫`/`きのくに用金庫`、
  `岩見沢市立光陵中学校`/`岩見沢光陵中学校拠`。これは alias ではなく元データの修正案件。

### ヘルスチェックの見え方

要対応シグナル合計 201 → 305。増分104は品質低下ではなく**今まで見えていなかった残務の可視化**。
ヘルスチェックの注記も「内部略称は検出不可」→「選手共有シグナルで検出する。ただし
同年に両表記へ出た選手が1人も居ない揺れは依然として検出できない」に書き換えた。
