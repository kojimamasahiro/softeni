# アイデア: 地区大会結果とインターハイnewsプレビューの連携

## 状況

Idea Backlog。発散フェーズ。2026-07-26に着想。

## 目的

地区大会（ブロック大会）の個人戦結果は、そのままでは強豪校ランキングや都道府県ページの
「直近1年の主要大会結果」に混ぜるには収録が薄い（保留中）。しかし別の切り口として、
全国大会（インターハイ）の`/news`プレビュー記事に「地区大会での好成績」を文脈情報として
出せないか、という着想。地区大会→全国大会という物語の連続性を活かせる可能性がある。

## ユーザーが興味を持った点

> 結果が充実していないため、現時点ではランキングや主要大会結果は含めるかは保留としたい。
> ただ、アイデアとして、インターハイのnewsページには何かしら連携できないか検討したいと思っている

## わかっていること

- `news-context-blocks`の④「直近大会の好成績者」(`recentAchievers`)が、まさにこの用途に
  近い既存機構としてすでにある。`lib/newsArticle.ts`の`findRecentTournaments()`が
  `data/tournaments/index.json`（`local_index.json`とは別の、全国・主要大会用マスタ）を
  横断し、プレビュー対象大会の開催日から遡って3ヶ月以内に開催された大会を拾い、
  そこでベスト4以上だった選手を「直近大会の好成績者」として出す設計。
- 9地区大会の2026開催日は関東(5/29)〜近畿(7/18)まで、すべてインターハイ(2026-07-31〜)の
  3ヶ月ウィンドウに収まる。時期的な相性はよい。
- この機構は`highschoolRanking.ts`の`RANKING_TOURNAMENTS`、`highschoolAlumni.ts`の
  `HS_TOURNAMENTS`、`highschool.ts`の`HIGHSCHOOL_TOURNAMENT_PRIORITY`（いずれも別ファイル・
  別allowlist）とは完全に独立している。よってランキング/卒業生集計への統合を保留する判断とは
  無関係に検討を進められる。
- 制約: `RECENT_TOURNAMENT_LIMIT = 2`で「直近大会は最大2件」に絞る設計。`isMajorTitle`優先→
  新しい順で選ぶため、9地区とも`isMajorTitle:false`想定だと開催日が最も遅い2地区
  （近畿・中国あたり）しか候補に上がらず、残り7地区の好成績は拾われない。この定数は
  「全国規模の主要大会が数個ある」世界を想定しており、「同格の地区大会が9個同時にある」
  状況は想定されていなかった。
- `bestPlacement()`は`kind==='winner'`/`'runnerup'`/(`'best'`かつ`bestLevel===4`)のみを
  好成績とみなし、ベスト8は対象外（既存の閾値。地区大会を足しても変わらない）。
- `data/tournaments/index.json`に地区大会9件はまだ未登録（`local_index.json`のみ登録済み）。
- **団体戦も登録予定**（2026-07-26追記）。現状の個人戦ダブルスに加えて団体戦
  （`team-none-boys`/`team-none-girls`）も各地区で登録していく方針。近畿は
  `kinki_boys_team.json`/`kinki_girls_team.json`まで変換済みで未登録。この連携アイデアの
  設計は個人戦だけでなく**団体戦も考慮できる形にする**必要がある。
- `recentAchievers`（④）は「団体は per-player 不可のため対象外」と明記されている
  （`docs/wiki/news-context-blocks.md`）。つまり現状の仕組みは個人戦専用で、団体戦の
  地区大会結果をそのまま流し込んでも拾われない。団体戦を文脈情報として出すなら、
  `historical-winners`/milestoneが団体戦を`championKey`（校単位）で扱っている既存パターンを
  参考に、選手単位とは別の校単位の仕組みを設けるか、`recentAchievers`自体を校単位にも
  対応させる拡張が要る。

## 課題・未解決

- `RECENT_TOURNAMENT_LIMIT=2`の制約をどう扱うか、方向性が未確定。
  - 案A: 既存の「直近大会」枠を地区大会向けに拡張する（例: 主要大会2件＋該当する地区大会は
    別枠で追加）
  - 案B: 地区大会専用の新しい文脈ブロックを作る（選手の出身地区に対応する地区大会結果だけを
    ピンポイントで引く。地区をまたいだノイズが出ない一方、新規実装になる）
  - いずれの案も**団体戦を含む形で設計する**（個人戦のみの`recentAchievers`をそのまま
    流用すると団体戦が構造的に漏れるため、校単位の扱いを別途組み込む必要がある）
- インターハイ2026のプレビュー記事自体が`data/news/`に存在するか未確認（要確認）。
- 地区大会の成績を全国大会の文脈内でどう見せるのが適切か。地区大会は全国出場に直結しない
  （インターハイ出場は都道府県予選が別途決める）ため、「地区大会で好成績＝強い」という
  文脈情報としての伝え方に一定の工夫が要るかもしれない。

## 追記（2026-07-26 その2）: 検証結果と方向転換

### 解決した未確認事項

- **インターハイ2026のプレビュー記事は存在・公開済み**。`data/news/highschool-championship-2026.json`
  （`type:preview` / `state:published` / `categoryId:null`＝全4種目）。開催日 2026-07-31。
  IH2026の`details`は`doubles-none-boys/girls`＋`team-none-boys/girls`が登録済みで、
  `matches`は**1回戦のみ**（男子158試合＝316÷2、`nextMatchId`未設定）、`results`は全件`kind:'ongoing'`。

### `recentAchievers`（④）の真の問題は`RECENT_TOURNAMENT_LIMIT`ではなかった

IH2026の3ヶ月窓（2026-04-30〜07-31）に入る`index.json`の大会と、IH2026出場者の実データ突合:

| 大会 | isMajorTitle | ベスト4以上 | IH出場者と一致 |
|---|---|---|---|
| 全日本ミックス (6/6) | true | 64人 | **1人** |
| 全日本シングルス (5/15) | true | 8人 | **0人** |
| ハイスクールジャパンカップ (6/25) | false | 22人 | 21人 |
| 東日本 (7/18) / 西日本 (7/4) | false | 各16人 | 各0人 |

`findRecentTournaments()`は**`generationId`を見ずに全29大会を走査**し`isMajorTitle`優先でソートするため、
一般カテゴリの2大会が枠を独占する。結果、現状のIHプレビュー④は**実質1人しか拾えていない**。
最も関連性の高いHJCが構造的に弾かれている。

→ **地区大会を`isMajorTitle:false`で登録しても永久に選ばれない**。「登録すれば拾われる」は成立しない。
案A/案B以前に、`generationId`フィルタの欠落が先に効いている。

### 地区大会を`index.json`へ移すのは不可

`data/tournaments/index.json`は15箇所以上（`careerRecord` / `highschoolAlumni` / `nationalTitles` /
`majorTitles` / `playerStats/manifest` / `/tournaments/[generation]`ルーティング /
`generate-players-json`）が読む。地区大会が`local_index.json`にあるのは
`/tournaments/block/[blockId]`を建てるための意図的な配置であり、移動は
「高校カテゴリへ統合しない」判断と衝突する。
→ 連携するなら**`findRecentTournaments`側を両ソース読みに拡張**する。

### 方向転換: ④への統合ではなく「前哨戦・再戦」という新しい表現へ

ユーザーの関心が「地区大会で対戦成績のある対戦がインターハイでも実現している」という
**新規の表現**に移ったため、案A/案B（④への統合）は主軸から外す。

> 「どちらかというと新しい機能として、地区大会の結果から何か新しい表現ができないかを検討したい。
> 例えばだが、地区大会で対戦成績のある対戦がインターハイでも実現しているといった、
> 専用の表現や新しい何かができると思っている」

> 「地区大会で優勝だとインターハイでも優勝候補になるといった表現ができないかとか検討したい」

**実データで成立を確認済み:**

| | 既知対戦カード（両ペアがそのままIH出場） | 対戦履歴を持つIHペア |
|---|---|---|
| 男子ダブルス | 158件 | 197 / 316ペア（62%） |
| 女子ダブルス | 194件 | 220 / 314ペア（70%） |

**IH1回戦で既に1件、再戦が実現している**:
女子ダブルス 野間結菜/竹田羽花（昇陽）vs 竹平碧純/野中萌花 —
両ペアは近畿大会準々決勝で対戦済み（野間/竹田が勝利し、そのまま近畿優勝）。

制約: IH2026の`matches`は1回戦しか登録されていないため、**2回戦以降の再戦は大会進行中に
`matches`が埋まってからしか検出できない**。つまりこれはプレビュー専用ではなく、
**ADR-007の`ongoing`運用と組み合わせて大会中に光る**性質の機能。
- プレビュー時点 → 「地区大会での対戦履歴」352件＋1回戦の再戦
- 進行中 → 試合ごとに「この試合は◯◯大会準決勝の再戦（前回は△△が勝利）」バッジ

副次効果: 名寄せリスクで凍結中の`head-to-head`（優先度C）が、**同一年度・同一世代・同一地区**
という狭スコープでは誤マッチ余地が構造的に小さく、初めて成立しうる。

> ⚠ **この見立ては同日の実測で否定された**。本ファイル下部の
> 「【訂正】「狭スコープなら安全」は実測で否定された」を参照（原文は経緯として残す）。

### 「地区優勝＝IH優勝候補」は現時点では数値で言えない

- **地区大会データは2026年の1年分のみ**（IHは2021-2025もある）。地区優勝→IH成績の基準率が計算できない。
- 16組の地区王者のうち**同一ペアでIH出場は12組**（不在: 男子=東北・中国・九州、女子=関東。
  ペア変更 or 県予選敗退）。「地区優勝＝全国出場」ですらない。
- → 定量的な「優勝候補」表現は**過去年度の地区大会データ投入が前提**。それまでは
  「地区王者一覧」＋前哨戦の事実提示にとどめるのが安全。

### 団体戦

地区側の団体戦`details`は本追記時点で未登録（9地区とも`doubles-*`のみ。ワーキングツリーに
`team-none-*`が未追跡で存在）。前哨戦の考え方は**校単位にそのまま移植可能**で、
IH団体は48校と少ないため密度はむしろ高くなる。方針は「個人戦と同じブロック内に校単位で併記」
（`historical-winners`/milestoneの`championKey`パターンを踏襲）。

### SEOに効かせる置き場所

再戦バッジ自体に検索需要はほぼない（「{選手A} {選手B} 対戦」は検索されない）。
seo.md #2追記（全国大会優勝literal）と同型の「**新規URLを増やさず既存URLの一意性を上げる**」
手法が本命。

| 置き場所 | 判断 |
|---|---|
| 選手結果ページ（既存~1,900） | **本命**。薄いページの情報密度・一意性が上がる |
| 試合詳細ページ | 見送り。`getStaticPaths`が`siteLink`付き試合のみで地区大会は生成されない。薄いページ量産は #2 の教訓に反する |
| preview記事 | 副次。1URLのみだが、ADR-010「farmが構造的に持てないDB由来の文脈」の最強の実例 |

「他にないデータサイトの強み」としては、352件・62-70%カバレッジを**大会単位の横断統計**
（「IH2026は出場ペアの7割に既知の対戦履歴がある」）として出す道がある。
seo.md #8「結果面はハブを強化（歴代横断統計）して受ける」方針と一致。

### 【実装済み】副産物: 地区大会投入で壊れていたnoindex選別を修正

検証中に発見した別件のバグ。`src/pages/players/[id]/results.tsx`の

```ts
const hasHighschoolNational = playerMatches.some(
  (m) => tournamentMeta.get(m.tournamentId)?.generationId === 'highschool');
const shouldIndex = totalMatches >= 15 || hasHighschoolNational;
```

は「全国高校大会出場者は試合数に関わらずindex」の意図だが、`tournamentMeta`の元である
`loadTournamentIndex()`（`lib/tournamentData.ts`）が**`index.json`と`local_index.json`を連結**
して返すため、`local_index`側で`generationId:'highschool'`を持つ**地区大会9件＋東海選抜**まで
「全国高校大会」と誤認していた。

→ 地区大会に1試合出ただけの薄い選手ページが無条件でindex対象になり、seo.md #2
（「クロール済み - インデックス未登録」対策）の設計思想が反転する。

規模: `local_index`の`generationId=highschool`大会のユニーク選手は約3,223人。
現在のページ生成対象（`count>=5`）は1,917人。`data/players/index.json`は7/8時点のもので
地区大会投入前のため**まだ顕在化していない**（次の再生成で顕在化する）。

修正: `lib/tournamentData.ts`に`loadNationalTournamentIds()`（`index.json`収録IDのみ・キャッシュ付き）
を追加し、判定を`nationalTournamentIds.has(tid) && generationId==='highschool'`に限定。
規約の出典は`lib/playerStats/sourceAdapter.ts`の「index.json＝national候補 / local_index＝
常に非national」。

効果測定（全detailsを走査した実測）: `hasHighschoolNational=true`の選手が
**7,625人 → 5,727人（−1,898人）**。この1,898人が本来の`totalMatches >= 15`判定に戻る。

同種の誤判定が他にないかgrep済み。`/tournaments/[generation]/.../index.tsx`の
`generation === 'highschool'`はURLパラメータ由来で学校ページへの内部リンク用途のため別件（問題なし）。

### 【実装済み】`findRecentTournaments()` に `generationId` フィルタを追加（2026-07-26）

上記「④の真の問題」への対処。`lib/newsArticle.ts` の `findRecentTournaments()` が
プレビュー対象大会と**同一 `generationId` の大会のみ**を候補にするようにした。
`readTournamentIndex()` の戻り型に `generationId` を追加。

実装時に判明した決定的な事実として、**現状の④はIHプレビューに誤情報を1件出す状態だった**:

> 全日本ミックス `doubles-over65-mixed` のベスト4「山本幸輝」が、IH2026男子ダブルスで
> フルネームが一意な高校生「山本幸輝（早鞆・山口県）」に `uniqueEntryNoByName`
> フォールバックで紐づき、**over65混合ダブルスの成績が「主要大会」バッジ付きで高校生に
> 表示される**。

このため「同generation優先ソート（除外はしない）」ではなく**厳密フィルタ**を選択した。
世代をまたぐ照合は年齢・所属という手掛かりが効かず同名別人リスクが最大化するため、
ADR-005の「決定的生成・誤り混入ゼロ」原則を優先した。

全4本の公開済みプレビューでの前後比較（実測）:

| 記事 | generation | 修正前の候補 | 修正後の候補 |
|---|---|---|---|
| highschool-championship-2026 | highschool | 全日本ミックス2026[major] / 全日本シングルス2026[major] | **ハイスクールジャパンカップ2026** |
| highschool-japan-cup-2026 | highschool | 同上 | 全日本高等学校選抜大会2025 |
| east-japan-2026 | all | 同上 | 同上（変化なし） |
| west-japan-2026 | all | 同上 | 同上（変化なし） |

好成績者の実数: IH2026は **1人（誤情報）→ 21人（正しい）**。HJC2026は 0→0
（選抜2025は団体戦のみ収録で per-player 不可のため。回帰ではない）。一般大会2本は回帰なし。

フォールバック: プレビュー対象大会が `index.json` に無く `generationId` を解決できない場合は
絞り込まず従来動作を保つ（誤って候補ゼロにするより安全側）。

残課題: 高校生が一般大会で入賞した本物の実績は拾えなくなった。解禁条件を
news-context-blocks.md の Open Questions に起票済み。

### 【訂正】「狭スコープなら安全」は実測で否定された（2026-07-26 その3）

上の「副次効果」節で書いた

> 名寄せリスクで凍結中の`head-to-head`（優先度C）が、**同一年度・同一世代・同一地区**
> という狭スコープでは誤マッチ余地が構造的に小さく、初めて成立しうる。

は**測ったら支持されなかった**。別人確定の同姓同名 70 名を含む試合の割合は、
全データ 32,043 試合中 936 件（**2.92%**）に対し、地区大会のみ 1,940 試合中 41 件（**2.11%**）で
ほとんど下がらない。同姓同名は世代・地域に関係なく一様に分布するため、範囲を絞っても率は動かない。

**効いたのは照合キーの結合度だった**。ペア（ダブルス）単位で照合すると、インターハイ 2026 で
同一の名前セットを持つエントリは男女とも 0 件（316 / 314 ペア）、地区大会 → IH で一致した
565 ペアのうち都道府県の不一致も 0 件（校名不一致 32 件はすべて略称ゆれ）。

よって前哨戦・再戦および `head-to-head` は、**ダブルスのペア単位に限れば現在の名寄せ水準でも
安全に実装できる**。危険なのは選手単位に降ろした時と世代を跨いだ時。

測定の全体は [2026-07-26-homonym-measurement.md](./2026-07-26-homonym-measurement.md) を参照。

### 【実装済み】前哨戦・再戦ブロック（2026-07-26 その4）

方向転換して主軸に据えた「前哨戦・再戦」を実装した。

- **`lib/priorMeetings.ts` を新設**。対象大会の出場ペアどうしが、直近の他大会
  （同一 `generationId`・同一 `categoryId`・3ヶ月以内）で既に対戦していた事実を
  `Map<entryNoペア, PriorMeeting[]>` として索引化する。供給源の主力が地区大会なので
  `index.json` と `local_index.json` の両方を読む。④ `findRecentTournaments` と違い
  **候補大会の件数を絞らない**（9地区が同時に該当するのが正常なため）。
- **ペア単位照合**。実測で安全と確認した粒度に限定し、シングルスと団体戦は対象外
  （空を返す graceful）。
- **プレビューと結果ページで役割を分けた**:
  - プレビュー（`PriorMeetingsSection`）= 起こりうるカード＋カバレッジ
  - 結果ページ（`ResultContextBlocks`）= 実際に組まれた対戦だけを「再戦」として表示
  - seo.md #8 のインテント分割に沿っており、同じデータでもカニバらない。

実測（インターハイ2026）:

| 種目 | 既知の対戦カード | 対戦履歴を持つペア | 結果ページの再戦 |
|---|---|---|---|
| 男子ダブルス | 205 件 | 208 / 316 | 0 件 |
| 女子ダブルス | 251 件 | 230 / 314 | 1 件 |

### 追加実装（同日）: 再戦の有無・団体戦・大会ハブ・meta description

「対戦が行われなかった場合はどうなるか」という指摘から、**当初の実装は今大会の勝敗と
連動しておらず、両者が敗退してもカードが出たまま**になる穴があった。以下を追加した。

1. **`rematchStatus` の 4 状態**（`EntryStanding` と連動）
   - `scheduled` 対戦カードが組まれている／`possible` 両者勝ち残りでまだ起こりうる／
     `gone` 一方が敗退済みでもう起こらない／`unknown` 結果未掲載（大会前）
   - 表示順は scheduled → possible → unknown → gone。`gone` は灰に落とす（消さないのは
     「地区大会で対戦していた」事実自体が成績を読む文脈として有効なため）。
   - 検証: ハイスクールジャパンカップ 2026（終了済み）は 13 件すべて `gone` になり、
     インターハイ 2026（開催前）は 1 件が `scheduled`、残りが `possible` になった。
2. **団体戦（校単位）**。`entryKeyOf` が「1 エントリ = 選手名なし + team」を検出して
   `校名@都道府県` をキーにする。IH 2026 で男子 17 件（25/48 校）・女子 19 件（28/48）を検出。
   校名を選手名として `resolvePlayerId` に渡さない／所属を二重表示しないガードも入れた。
3. **大会ハブへの展開**。最新年度の規模だけを種目ごと 1 行で出し、詳細は年度別結果ページへ
   内部リンク（ハブは年度なしの歴代まとめが主インテントのため。seo.md #4）。
4. **meta description**。前哨戦が算出できたときだけ「直近大会で既に対戦している N 件の
   顔合わせ（前哨戦）も掲載。」を一文追加。IH 2026 は 492 件。

性能は再計測で 333 件・896ms（平均 2.7ms）。

### さらに追加（同日）: 開催前の文言と選手結果ページ

5. **`pending` 状態の追加**。「両者勝ち上がり中」が開催前だと事実に反するという指摘への対応。
   `results` が `kind:'ongoing'`（未実施）でも standing は `alive`／ラベル「勝ち上がり中」に
   なるため、**開催前は全ペアが alive** になってしまう。「1 試合でも勝敗が付いているか」
   （`matches[].winnerEntryNo`）で大会開始を判定し、開催前は `pending`＝「再戦の可能性」
   （空色）に振り分けた。開催前は standing 行も出さない。
   検証: IH2026（開催前）は `scheduled` 1 件＋残り `pending`、HJC2026（終了済み）は全件 `gone`。

6. **選手結果ページへの展開**。大会結果表の対戦相手の下に
   「ハイスクールジャパンカップ 2026 1回戦の再戦（前回は勝利）」のように注記する。
   約 1,900 ページが対象のため、`loadAllPriorMeetings()` が全大会横断の索引を
   プロセス内で 1 度だけ構築してキャッシュする（**1,000 キー・初回 1.0 秒・2 回目以降 0ms**）。
   ページごとに `buildPriorMeetingIndex` を呼ぶ実装は採らない。

   この展開で**高校以外にも効くことが判明**した。索引 1,000 キーの内訳は
   インターハイ 876 / 全日本インドア 50 / 全日本学生インドア 21 / 全日本選抜 16 /
   ハイジャパ 13 / 九州地区 8 / ルーセント東京インドア 8 ほか。実施済みの再戦の例:

   - 九州地区大会 2026 2回戦 坪井結・深浦琉可 対 石井礼都・西駿介
     →「ハイスクールジャパンカップ 2026 1回戦の再戦」
   - 東北地区大会 2026 女子団体 決勝 東北 対 羽黒 →「全日本高等学校選抜 2025 準決勝の再戦」
   - ルーセント東京インドア 2025 橋場柊一郎・菊山太陽 対 上松俊貴・内本隆文

### 仕様確定（2026-07-26 その5）: 窓・世代・照合キー

レビューを受けて 3 点を確定した。

1. **窓は「開催日から 1 年」＋同一 `categoryId`**。3 ヶ月 →「前回開催から」→ 1 年固定と変遷。
   「前回開催から」は周期に自動追従する利点があったが、大会ごとに窓が変わり説明しづらい。
   ただし **1 年ちょうどでは前回開催を落とす**という指摘があり実測で確認:
   インターハイは前回 2025-07-25 → 今回 2026-07-31 で **371 日**、ハイジャパも **370 日**。
   素の 12 ヶ月窓では前回開催が窓外になり、団体戦の検出が 67 → 41 件に減っていた。
   → **窓の下限は「1 年前」と「同一大会の前回開催日」の早い方**とした。
2. **`generationId` では絞らない**。④ が世代を絞るのは選手 1 名の名前で照合するためで、
   ペア単位の本ブロックには当てはまらない。世代跨ぎで増える 1,139 件は実測で全て正当だった。
   これにより**高校専用ではなくなった**（東日本選手権 2026 が 0 → 男女 52/55 件）。
3. **シングルスを `名前@所属` で対象化**（ユーザー決定）。ダブルスの安全性は「名前 2 つの結合」
   由来なのでシングルスには効かない。所属を鍵に足すことで、(a) 所属変更で取りこぼす
   (b) 同姓同名かつ同一所属の別人を誤同一視する、の 2 点を**許容する**判断。
   結果、全日本シングルス 2026 で男女とも約 100 件を検出（うち前回大会由来 63〜71 件）。

**選手結果ページも同じルール**（大会単位の窓をそのまま流用）で確定。

最終規模: 全大会横断索引 **4,482 キー・1.9 秒**（キャッシュ後 0ms）。

### 【訂正】「再戦の可能性」バッジを撤去（2026-07-26 その6）

「決勝まで行かないと当たらない組み合わせにも『再戦の可能性』と書くのは、事実ではあるが
可能性としては低いのではないか」という指摘を受けて検証し、**バッジを撤去した**。

当たるラウンドを推定できないか 3 通り試したが、いずれも不成立:

| 手法 | 結果 |
|---|---|
| `nextMatchId` でブラケットを辿る | **大会前は不可**。IH2026 の `matches` は 1 回戦 158 件のみで `nextMatchId` 全件未設定（完了済みの IH2025 は 314/315 件に設定あり） |
| `entryNo` をブラケット位置とみなす | 的中率 **17〜42%**（IH2025 男子D 42% / 関東地区2026 33% / IH2025 男子団体 17%）。不戦勝で位置がずれる |
| 「1回戦の連続2試合が同じ次戦へ合流」と仮定 | **0/30** で不成立 |

よって「可能性」を定量化する手段が無く、**言えない事は書かない**方針で `pending` は
バッジ無しにした。セクション見出しが「すでに対戦している顔合わせ」なので意味は通る。
残るバッジ（`scheduled` / `possible` / `gone`）はいずれも `matches` / `results` から
確定できる事実のみになった。

### 仕上げ（2026-07-26 その7）: 3回戦フィルタと文言

- **`lib/bracketLayout.ts` を新設**。`entryNo`＋`entries[].type` から 512 枠のブラケットを復元し、
  2 組が最短で当たるラウンドを算出する。**インターハイ 2026 男子ダブルスの実データ 128 試合と
  100% 一致**。開催前は `nextMatchId` が全件付かないため、ツリーを辿る方法では判定できなかった。
- **3 回戦までに当たる組だけを載せる**（ユーザー決定）。実測では該当 0 でインターハイの
  「直近の対戦」は空になるが、**実際に対戦が組まれた／決着したカードは何回戦でも残す**ので、
  大会が進めば再戦が表示される。東日本 2026（男子1・女子2）・西日本 2026（男子4）は
  `scheduled` があるため現時点でも表示される。
- **見出しを「前哨戦」→「直近の対戦」に変更**。供給元が今大会より格上のことがあるため
  （西日本選手権の供給元は全日本選手権・全日本インドア）。大会間の格を前提にしない語にした。
- **規模のサマリ文を削除**。分母が絞り込み前の出場総数で分子と対応せず、
  「直近の 2 大会」も実際の定義とずれていた。エクスキューズは末尾の scopeNote で足りる。
  規模を語るのは大会ハブ側の役割に寄せる。

**未着手**: 「前回は勝利/敗戦」を踏まえた通算対戦成績（head-to-head 本体）の表示。
ペア単位なら安全だが、選手単位に降ろすには名寄せの id 分割が要る。
ドローの 2 回戦以降が `matches` に入るようになれば「早ければ N 回戦で再戦」が言えるようになる
（データ側の課題）。
