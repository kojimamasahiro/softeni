# Idea Backlog 索引の「一言サマリ」整理（2026-09-17）

open-questions.md「ドキュメント運用」の未解決項目
「`docs/wiki/idea-backlog.md` の一言サマリが一言でなくなっている」への対応。

## 実態

- ファイル 39,135 バイト・35行。索引表9行のうち、1セルの最大は約9,000バイト（データモデル行）
- 原因は idea-backlog スキルの手順。「状況が変わったら一言サマリも同期する」を、既存の文を
  書き換えずに `**YYYY-MM-DD: …**` を追記する形で繰り返していた。数値・経緯・判断理由まで入り、
  エリアページの表と raw の中身を二重に持つ状態になっていた

## 決めたこと

- 索引の責務（どのアイデアがどこにあるかを1ページで分かる）は変えない。書き方を制限する
- 1アイデアにつき「アイデア名（状況。残りがあれば一言）」だけを ` / ` でつなぐ。
  数値・経緯・理由・日付つきの追記は書かない。目安は1アイデア40字・1行400字
- 状況が変わったら、追記ではなく括弧の中を書き換える
- この規則を idea-backlog.md の「使い方」と、リポジトリの `.claude/skills/idea-backlog/SKILL.md` に書いた

結果: 39KB → 約6KB（1行あたり最大約250字）。

## 消す前に確かめたこと

索引にしか無い情報を消さないよう、各セルの主な事実がエリアページにあるかを確かめた
（`TWO_LABEL_MAX`・圏外率・`/live/`・一覧表現・ベスト8候補・自律改善・Core Web Vitals・missing literal など）。
すべて各エリアページの表か本文にあった。そのうえで見つかったずれを直した。

- `data-model.md` の表で、中学カテゴリ・小学生カテゴリが「方針決定済み・実装前」のままだった
  → 先頭に「実装済み」と仕様ページへのリンクを足した（元の記述は「方針決定時の記録」として残した）
- `monetization.md` の発展候補アイデア一覧に AdSense 手動広告枠が無かった（索引にしか無かった）→ 追加
- 索引の収益化行の「残タスクはスロットID反映」は古かった（2026-08-25 に全6ユニット反映済み）。
  現在の残り（本番でのアンカー重なり・CLS）に直した
- `raw/2026-09-14-idea-top-popular-pages-ga4.md` がどのエリアの表にも無かった → `public-pages.md` の表に追加
- 索引の選手ページ行に「結果ページの階層化」、公開ページ行に「日体大ページ」「/teams のリンク」が
  入っていなかった → 入れた
