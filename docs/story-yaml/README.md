# 大会インサイト ストーリーYAML

`scripts/generate-story-yaml.mjs` の出力。**手で編集しない**（再生成で上書きされる）。

このディレクトリのファイルは、[過去の事実ベース5分類ストーリー](../raw/2026-08-01-idea-news-fact-based-story-categories.md)
の運用手順ステップ1の成果物。LLMにそのまま渡して読み物に編集させるための構造化データで、
生成そのものは決定的なロジックのみ（LLM不使用）。

**この一連の作業は `tournament-insight` skill にまとめてある**（生成→執筆→照合→公開の順序、
データ健全性チェック、実際に踏んだ落とし穴）。「インサイト」「途中経過」「今日の分をまとめて」
などで発動する。

LLMへの渡し方は [PROMPT.md](./PROMPT.md)。実施例は
[インターハイ2025の投稿案](../raw/2026-08-01-sns-post-drafts-highschool-championship-2025.md)。

## 生成と検証

```bash
# 生成（種目を省略すると当年の全種目を束ねる＝記事の単位）
npm run story:generate -- -t zennihon-championship -y 2025 -o docs/story-yaml/zennihon-championship-2025.yaml

# 検証（必ず通すこと。種目はカンマ区切りで複数指定できる）
npm run story:verify -- -t zennihon-championship -c doubles-none-boys,doubles-none-girls docs/story-yaml/zennihon-championship-2025.yaml -q
```

検証は生成ロジック自体のバグを捕まえるために行う（照合先はYAMLではなく生データ）。
生成物が検証を通ることを、YAMLを更新するたびに確認する。

過去年の記事を検証・公開するときは `-y <year>` でその記事の年を渡す。「N年連続」「N連覇」の
起点をその年に固定し、翌年以降に大会が続いて記録が伸びても公開済みの過去記事が不一致にならない
ようにするため（詳細は `docs/raw/2026-08-02-bug-verify-streak-unbounded-by-article-year.md`）。
`check-tournament-insights.mjs` は `data/tournament-insights/**/*.json` の `year` を自動で
`-y` に渡すので、公開後の運用では何もしなくてよい。手元で照合するときだけ明示する。

```bash
npm run story:verify -- -t highschool-championship -c team-none-boys,team-none-girls,doubles-none-boys,doubles-none-girls -y 2022 draft.md -q
```

## 大会が進行中のとき（`--in-progress`）

```bash
npm run story:generate -- -t highschool-championship -y 2026 --in-progress -o /tmp/day2.yaml
```

**通常のkindは大会の終盤まで一切使えない**。順位（ベスト8以上）が確定するのは準々決勝以降で、
それ以前は `rank.kind: 'ongoing'` のまま（ADR-007）。男子ダブルスは315試合のうち順位が付くのが
最後の7試合だけなので、途中で語れるのは「誰が勝ち残っていて、誰が消えたか」に限られる。

| kind | 分類 | 条件 |
|---|---|---|
| `watched-eliminated` | 衰退 | 注目主体が敗退した（確定事実。どのラウンドで誰に負けたか＋過去の成績） |
| `watched-advancing` | 継続 | 注目主体が勝ち残っている（突破した最深ラウンド＋過去の成績） |
| `watched-school-progress` | 継続／衰退 | **個人戦のみ**。前年ベスト8以上の学校ごとに「何組残って何組消えたか」を集約 |
| `watched-title-watch` | 継続／成長 | この種目で過去に優勝歴がある学校が、まだ生き残っている（前回優勝年・何年ぶりか） |
| `watched-self-best` | 成長 | **個人戦のみ**。注目選手が、残存数から確定した順位ですでに自己最高に並んだ／上回った |
| `watched-school-peak` | 成長 | 学校が、残存数から確定した順位ですでに学校としての歴代最高（ピーク）に並んだ／上回った |

後発3つは「残り何組か」から**すでに確定した順位**だけを使う（まだ決まっていない試合を
先読みしない）。ラウンド名ではなく残存エントリー数で判定する — ラウンド名は種目・年で
深さがずれる（2026年女子ダブルスは6回戦でベスト8が確定した）ため、名前ではなく
「残り2／4／8」で「少なくとも準優勝／ベスト4／ベスト8」を導く。
`watched-title-watch` は前回優勝年との差が1年なら「連覇のかかった学校」、2年以上なら
「◯年ぶり優勝のかかった学校」として書ける（数字は`yearsSinceTitle`）。
`watched-self-best`／`watched-school-peak` は「並ぶ可能性がある」ではなく「すでに並んだ・
上回った」の形でしか出さない（ADR-005の推測禁止に合わせる）。
「日本代表」のような外部タグや、ベスト8未満の細かい順位（例: 5位）は元データに存在しないため
検知できない。

`watched-school-progress` が要る理由: **個人戦は選手単位だと卒業で枯れる**。
インターハイ2026女子ダブルスの実測では、2025年ベスト8以上の16人のうち2026年も出場するのは
**3人**で、選手単位のストーリーは2件しか出なかった。学校単位に広げると材料は出るが、
ペアごとに1件出すと23件になってノイズになるため、**学校ごとに集約**する（実測で4件）。

**`unknown`（勝敗不明の組数）に注意**。どの試合にも現れないエントリーは `alive` にも
`eliminated` にも数えない。`unknown > 0` の学校について**「勝ち残りが無くなった」とは
書けない**（生成側でも文言を切り替えている）。インターハイ2026女子ダブルスでは
就実の3組目が試合データに無く、初版で「全滅」と誤って断定して公開後に取り下げた。
**この種の誤りは `verify-story-text.mjs` では検出できない**（「何組残っているか」は
照合できる主張の型に無い）。機械照合は万能ではない。

**注目主体 = 直近の確定年にベスト8以上だった選手・学校**。プレビュー記事の「ピックアップ選手」
（ADR-005）と同じ考え方。全エントリーを追うと敗退イベントだけで1大会362件になるが、
この絞り込みで**10件前後**まで落ちる。

件数の実測（2025年のデータを途中で切って検証）:

| 時点 | 男子団体 | 男子ダブルス | 全4種目 |
|---|---|---|---|
| 3回戦終了 | 8件（勝5・敗3） | 3件（勝3・敗0） | 23件 |
| 準々決勝終了 | 8件（勝4・敗4） | 3件（勝1・敗2） | — |

**1日1本の記事にちょうど収まる量**で、絞り込みの追加ロジックは要らない。
結果が1件も入っていない状態（開幕前）では `stories: []` を返すだけで落ちない。

### 大会期間中の1日の手順

1. その日の全種目が終わってから結果を入力し、`data/tournaments/details/**` を更新する。
2. `npm run story:generate -- -t <tid> -y <year> --in-progress -o /tmp/dayN.yaml`
3. [PROMPT.md](./PROMPT.md) の「進行中版」の構成でLLMに書かせる。
4. `npm run story:verify` で照合 → `data/tournament-insights/**` に `state: published` で置く。
5. ビルド・デプロイ（1日1回）。

**SEO上の狙いは速報クエリではなくロングテール**（「{学校名} インターハイ 2026」等）。
`seo.md` #8 の「結果速報では farm と正面勝負しない」方針は維持する（詳細は `seo.md` #11）。

なお `next-sitemap.config.js` は大会の終了日をそのまま `lastmod` にしていたため、
開催中の大会が**未来日**を出して鮮度シグナルが効かない状態だった（2026-08-01 に修正）。
日次更新の効果はこの修正が前提になる。

## 組み込んであるガード

- **姓のみの選手は選手単位の判定から除外**する（同姓同名の衝突率が跳ね上がるため）。
  除外が発生した場合は生成時に標準エラーへ警告を出す。
- **連続は暦年で判定**する。掲載年に欠落がある大会（例 2019, 2022-2025）で
  2022年を2019年の翌年として数えない。
- **混成ペアがある種目では学校を主語にしない**。「◯◯所属の選手は」という文言に切り替え、
  scopeNote で「学校の成績ではない」と明示する。インターハイの個人戦は混成ペア0.00%なので
  「◯◯高は」と書き、天皇賜杯では「◯◯所属の選手は」になる。
