# ストーリーYAMLをLLMに渡すときのプロンプト

`docs/story-yaml/*.yaml` をLLMに渡して投稿文を書かせるための手順とテンプレート。
設計の根拠は [過去の事実ベース5分類ストーリー](../raw/2026-08-01-idea-news-fact-based-story-categories.md) 5.

## 渡し方の要点

### 1. YAMLは丸ごと貼る（要約しない・抜粋しない）

| | サイズ |
|---|---|
| ストーリーYAML 1本 | 13〜18KB（約7〜9千トークン） |
| 元の大会データ（1大会5年分） | 約4MB |

**260分の1に圧縮済み**なので、コンテキストを気にして絞る必要がない。
むしろ抜粋すると `related` で結ばれた相手が欠けて、繋がった筋が書けなくなる。
生データ（`data/tournaments/details/**`）を直接渡すのは避ける。量の問題だけでなく、
LLMが自分で集計して誤るため（そのための生成スクリプトである）。

### 2. `records` は渡さない

`--no-records` で生成する。`records`（初ベスト8の一覧）は**リスト表示用で執筆対象ではない**と
設計で決めた枠。渡すとLLMがそこから文章を作ろうとしてノイズになる。

```bash
npm run story:generate -- -t highschool-championship -y 2025 --no-records -o /tmp/for-llm.yaml
```

### 3. 出力に必ず story id を併記させる

これが運用上いちばん効く。どの事実から書いたかが追跡でき、照合スクリプトが警告を出したときに
原因のストーリーを一発で特定できる。

### 4. 「評価語を使うな」を明示的に禁止する

YAMLヘッダのコメントだけでは足りない。LLMが最もやりがちな逸脱が
「強豪校の尽誠学園が」「悲願の初優勝」のような修飾語の混入で、これはADR-005の
「事実のみ・推測を含めない」に直接反する。禁止語を並べて明示する。

### 5. 選定と執筆を分けるかは候補数で決める

実測では1大会あたり18〜25件しか出ないので、**1回のプロンプトで選定と執筆をまとめてよい**。
ただし「どれを選んだか」を先に出力させて、本文はその後に書かせる。選定理由が見えないまま
文章になると、後から筋の良し悪しを判断できない。

## プロンプトテンプレート

> 添付のYAMLは、ソフトテニスの大会データから機械的に抽出した「確定した事実」です。
> これを元にX（Twitter）向けの投稿を3本書いてください。
>
> **絶対の制約**
>
> - YAMLに書かれている事実だけを使うこと。新しい数値・成績・年・人名・学校名を足さないこと。
> - 推測を書かないこと。理由・心境・背景・今後の見通しは、YAMLに無い限り書かない。
> - 評価語・修飾語を使わないこと。禁止例:「強豪」「名門」「王者」「悲願」「雪辱」「復活」
>   「圧巻」「驚異的」「注目の」「実力者」。順位と年数だけで語ること。
> - 選手名・学校名・年・成績（優勝／準優勝／ベスト4／ベスト8）は、YAMLの表記をそのまま使うこと。
> - 「N年連続」「N連覇」の数字はYAMLの `streakYears` の値をそのまま使い、自分で数え直さないこと。
>
> **構成（重要）**
>
> 年表の読み上げにしないこと。**小規模なニュース記事の順序**で書くこと。
>
> 1. **今年何が起きたか**を最初に書く（`kind: title-won` のストーリー）。優勝したのは誰で、
>    決勝の相手とスコアはどうだったか。ここが記事の主語になる。
> 2. **その勝ち上がりの具体**（準決勝の相手とスコア、`giant-killing` があればそれ）。
> 3. **過去との関係**（`best8-streak` / `school-best8-streak` / `streak-stopped` /
>    `recurring-matchup`）。ここで初めて経年の話に入る。過去の話から始めない。
>
> 主役は1組（1校）に絞ること。複数の主語を並列に並べると年表になり、記事にならない。
>
> **書き方**
>
> - 1本140字前後。年ごとの成績は改行して縦に並べてよい（数字が読みやすくなる）。
> - `related` で結ばれたストーリーは同じ筋なので、**1本の投稿にまとめること**。
>   別々の投稿に割らない。
> - 各投稿の末尾に「※当サイト掲載分（YYYY年〜）」を1行入れること（年はYAMLの `scope` から）。
>
> **出力の形式**
>
> まず選定を書いてください。
>
> ```
> ## 選定
> 投稿1: <使うstoryのid（複数可）> — <なぜこの筋を選んだか1行>
> 投稿2: ...
> 投稿3: ...
> ```
>
> その後に本文を書いてください。各投稿の末尾に、使ったstoryのidを `used:` として列挙すること。
>
> ```
> ## 投稿1
> <本文>
> used: <id>, <id>
> ```
>
> ---
>
> ```yaml
> <ここにYAMLを丸ごと貼る>
> ```

## 大会が進行中のとき（日次まとめ）

`--in-progress` で生成したYAMLは `inProgress: true` と `asOf`（種目ごとの「ここまで確定」
ラウンド）を持つ。プロンプトは上のテンプレートを使い、**構成の指示だけ差し替える**。

> **構成（進行中版）**
>
> 1. **その日いちばん大きかった動き**から書く。`watched-eliminated`（前年入賞者の敗退）が
>    あればそれが最優先。無ければ `watched-advancing` の中で過去成績が最も上の主体。
> 2. 残った注目主体が**どこまで勝ち残っているか**を1〜2行でまとめる。
> 3. `asOf` のラウンドを必ず明記する（「3回戦終了時点」）。**まだ決まっていないことを
>    決まったように書かない**。順位・最終成績には一切触れない。
>
> 追加の禁止事項: 「優勝候補」「本命」「有力」など、これから起こることの予想を書かないこと。
> YAMLにあるのは過去の成績と、確定した勝敗だけ。

順位は準々決勝が終わるまで確定しないため、**`best8-streak` や `self-best` のような
経年kindは進行中のYAMLには入っていない**。無い事実を補おうとしないこと。

## 受け取ったら必ず検証する

```bash
# LLMの出力をファイルに保存してから
npm run story:verify -- -t highschool-championship \
  -c team-none-boys,team-none-girls,doubles-none-boys,doubles-none-girls \
  draft.md -q
```

- `ERROR` が出たら、`used:` のidを見て該当ストーリーとつき合わせる。
- `WARN`（未検証）は、掲載範囲外の事実を書いたか、機械が主語を特定できなかったか。
  どちらかを人が判断する。
- 種目は**カンマ区切りで全種目**を指定する。1種目だけ指定すると、他種目の事実が
  すべて不一致として報告される。
